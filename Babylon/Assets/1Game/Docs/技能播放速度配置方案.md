# 技能播放速度配置方案

> 本文档记录技能释放速度（castSpeed）的配置架构设计，以及从原型期到正式制作期的演进路线。

---

## 一、当前架构（原型期）

### 1.1 两级配置体系

| 层级 | 文件 | 字段 | 作用 |
|------|------|------|------|
| **全局默认** | `GameConfig.asset` (`Scripts/Core/GameConfig.cs`) | `skillCastSpeed` | 所有技能的默认速度倍率 |
| **单技能覆盖** | `SkillData.asset` (`Scripts/Combat/SkillData.cs`) | `castSpeed` | 单个技能独立速度倍率 |

### 1.2 优先级逻辑

位于 `PlayerCombat.UseSkill()` 中：

```csharp
// 优先使用技能自身配置，否则使用全局配置
float castSpeed = skill.castSpeed > 0.01f ? skill.castSpeed : 1f;
var config = GameConfig.Instance;
if (config != null && Mathf.Approximately(castSpeed, 1f))
    castSpeed = config.skillCastSpeed;
```

- 如果 `SkillData.castSpeed` 已设置（非默认 1.0），则使用技能自身的值
- 如果技能未单独配置（保持 1.0），则回退到 `GameConfig.skillCastSpeed` 全局值

### 1.3 速度应用方式

通过 `animator.speed` 控制动画播放速度：

```csharp
_playerAnim.PlaySkill(castSpeed);
// 内部设置 animator.speed = castSpeed
```

### 1.4 配置文件位置

```
Assets/1Game/
├── Resources/
│   └── GameConfig.asset          ← 全局配置（含 skillCastSpeed）
├── Data/Skills/
│   └── 落石术.asset              ← 单技能配置（含 castSpeed）
```

## 二、演进路线

### 阶段总览

| 阶段 | 速度配置位置 | 控制方式 | 适用场景 |
|------|------------|---------|---------|
| **原型期**（当前） | `SkillData.castSpeed` | `animator.speed` | 快速迭代，验证手感 |
| **中期**（有正式动画） | `SkillData.castSpeed` | Animator 参数 `speedMultiplier` | 多 Layer 动画不互相干扰 |
| **后期**（Timeline） | `SkillData.castSpeed` + Prefab | `PlayableDirector.SetSpeed()` | 动画/特效/音效精确同步 |

> **核心原则**：数值配置始终放在 `SkillData.asset` 中，不会变。变的只是"速度值怎么被应用"。

---

## 三、中期方案：Animator 参数控制

### 3.1 为什么升级

`animator.speed` 是全局的，会影响所有 Animator Layer 的所有动画。当角色有多层动画（身体层 + 上半身层 + 表情层等）时，改 `animator.speed` 会导致所有层一起变速。

### 3.2 实现方式

在 Animator Controller 中，为技能动画状态添加 `Speed Multiplier` 参数：

1. 在 Animator 中创建 Float 参数 `SkillSpeed`
2. 在技能动画状态的 Inspector 中勾选 `Speed → Multiplier`，绑定 `SkillSpeed` 参数
3. 代码中通过参数控制：

```csharp
animator.SetFloat("SkillSpeed", castSpeed);
```

这样只影响绑定了该参数的动画状态，不影响其他动画。

## 四、后期方案：Timeline + Prefab

### 4.1 为什么用 Timeline

复杂技能需要精确同步多种表现：
- 角色施法动画
- 粒子特效（蓄力、释放、命中）
- 音效（施法语音、技能音效、命中音效）
- 伤害判定时机
- 镜头震动 / 特写

`animator.speed` 无法控制这些非动画元素的时间轴，而 Timeline 可以统一管理。

### 4.2 技能 Prefab 结构

```
Assets/1Game/Prefabs/Skills/
├── 落石术_Skill.prefab
│   ├── PlayableDirector (Timeline)
│   │   ├── AnimationTrack    → 角色施法动画
│   │   ├── ParticleTrack     → 落石粒子特效
│   │   ├── AudioTrack        → 施法音效 + 落地音效
│   │   └── SignalTrack       → 伤害判定时机信号
│   └── VFX (子物体)
│       ├── CastCircle        → 地面指示圈
│       └── RockMesh          → 石头模型
│
├── 御剑术_Skill.prefab
│   ├── PlayableDirector (Timeline)
│   │   ├── AnimationTrack    → 角色御剑动画
│   │   ├── ParticleTrack     → 剑气轨迹
│   │   ├── AudioTrack        → 剑鸣音效
│   │   └── SignalTrack       → 投射物生成时机
│   └── VFX (子物体)
│       └── SwordTrail        → 剑气拖尾
```

### 4.3 速度控制方式

Timeline 阶段使用 `PlayableDirector` 的速度控制，而非 `animator.speed`：

```csharp
// SkillData 中新增引用
public GameObject skillPrefab;  // 包含 PlayableDirector 的技能 Prefab

// 释放技能时
var instance = Instantiate(skill.skillPrefab);
var director = instance.GetComponent<PlayableDirector>();

// 通过 PlayableGraph 控制整体速度
director.playableGraph.GetRootPlayable(0).SetSpeed(skill.castSpeed);
director.Play();
```

这样 **一个速度值同时控制** 动画、特效、音效的播放速度，保持完美同步。

### 4.4 配置职责分工

| 层级 | 文件 | 控制内容 | 负责人 |
|------|------|---------|--------|
| **数值层** | `SkillData.asset` | 伤害、CD、castSpeed、范围 | 策划 |
| **表现层** | `Skill_xxx.prefab` + Timeline | 动画、特效、音效时序编排 | 美术 / TA |
| **全局层** | `GameConfig.asset` | 全局速度倍率（用于 buff/debuff 加减速效果） | 程序 |

### 4.5 Signal 信号机制

Timeline 中的 SignalTrack 用于在精确时间点触发游戏逻辑：

```
Timeline 时间轴:
0.0s ──── 0.3s ──── 0.6s ──── 1.0s ──── 1.5s
│          │          │          │          │
▼          ▼          ▼          ▼          ▼
开始施法   蓄力完成   伤害判定   特效高潮   技能结束
           (可取消)   (Signal)   (震屏)     (清理)
```

通过 Signal Receiver 组件接收信号并调用对应方法：

```csharp
// 挂在技能 Prefab 上的信号接收器
public class SkillSignalReceiver : MonoBehaviour
{
    public void OnDamageSignal()
    {
        // 执行伤害判定
    }

    public void OnSpawnProjectile()
    {
        // 生成投射物
    }
}
```

## 五、迁移注意事项

### 5.1 从原型期迁移到 Timeline

需要修改的代码范围很小，主要是 `PlayerCombat.UseSkill()` 方法：

```csharp
// 原型期（当前）
_playerAnim.PlaySkill(castSpeed);

// Timeline 期（未来）
var instance = Instantiate(skill.skillPrefab);
var director = instance.GetComponent<PlayableDirector>();
director.playableGraph.GetRootPlayable(0).SetSpeed(skill.castSpeed);
director.Play();
```

### 5.2 `SkillData` 的变化

只需新增一个字段，原有字段全部保留：

```csharp
[Header("表现")]
public GameObject vfxPrefab;        // 保留（简单技能仍可用）
public GameObject skillPrefab;      // 新增：Timeline 技能 Prefab
public float vfxDuration = 1.5f;
```

### 5.3 兼容策略

可以同时支持两种模式：
- 如果 `skillPrefab` 不为空 → 使用 Timeline 模式
- 如果 `skillPrefab` 为空 → 回退到当前的 `animator.speed` 模式

```csharp
if (skill.skillPrefab != null)
{
    // Timeline 模式
    var instance = Instantiate(skill.skillPrefab);
    var director = instance.GetComponent<PlayableDirector>();
    director.playableGraph.GetRootPlayable(0).SetSpeed(skill.castSpeed);
    director.Play();
}
else
{
    // 传统模式（向后兼容）
    _playerAnim.PlaySkill(castSpeed);
}
```

---

## 六、总结

- **数值配置位置不变**：始终在 `SkillData.asset` 的 `castSpeed` 字段
- **应用方式逐步升级**：`animator.speed` → `Animator Parameter` → `PlayableDirector.SetSpeed()`
- **迁移成本低**：只需修改 `UseSkill()` 中几行代码
- **向后兼容**：新旧模式可共存，逐步迁移
