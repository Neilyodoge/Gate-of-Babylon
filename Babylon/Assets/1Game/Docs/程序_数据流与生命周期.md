# 🔄 数据流与生命周期

> 本文档面向程序员和AI Agent，详细说明仙途梦境项目的启动流程、对象生命周期、数据传递路径。
> 最后更新：2026-04-15

---

## 一、游戏启动流程

### 1.1 场景加载顺序

```
Unity 加载 Demo1.unity 场景
  │
  ▼
Demo1Setup.Awake()
  ├── 创建 GameManager (单例)
  ├── 创建 ObjectPool (单例)
  ├── 创建 PlayerResources (单例)
  ├── 创建 AudioManager (单例)
  ├── 创建 LevelTransition (单例)
  ├── 创建 DebugConsole (单例)
  └── 创建 PostProcessSetup (单例)
  │
  ▼
Demo1Setup.Start()
  ├── 加载 GameConfig.Instance (Resources.Load)
  ├── 创建玩家 GameObject
  │   ├── PlayerController + CombatStats
  │   ├── PlayerCombat + 技能槽位
  │   ├── PlayerAnimator + Animator
  │   ├── CharacterController
  │   ├── ItemInventory
  │   └── SpiritSlotSystem
  ├── 创建 UI Canvas
  │   ├── GameHUD (血条/技能CD/闪避/连招/敌人计数)
  │   ├── InventoryUI (灵物背包)
  │   ├── SkillBarUI (技能栏)
  │   └── Minimap (小地图)
  ├── 创建 TopDownCamera
  ├── 配置后处理 (PostProcessSetup)
  └── 装备默认技能 (Q=落石术, E/R=空)
  │
  ▼
GameManager.Start()
  ├── 从 GameConfig 读取难度参数
  ├── 订阅事件 (RoomCleared, PlayerDied, EnemyKilled)
  └── StartNewRun()
      ├── GenerateLevelLayout() → 生成6层房间布局
      ├── Minimap.Initialize() → 初始化小地图
      └── SpawnCurrentRoom() → 生成第一个房间
```

### 1.2 ScriptableObject 加载时机

| SO | 加载时机 | 加载方式 |
|---|---|---|
| `GameConfig` | 首次访问 `GameConfig.Instance` | `Resources.Load<GameConfig>("GameConfig")` |
| `AudioConfig` | 首次访问 `AudioConfig.Instance` | `Resources.Load<AudioConfig>("AudioConfig")` |
| `MonsterPrefabs` | 首次访问 `MonsterPrefabs.Instance` | `Resources.Load<MonsterPrefabs>("MonsterPrefabs")` |

## 二、房间生命周期

### 2.1 战斗房间

```
SpawnCurrentRoom()
  │
  ▼
new GameObject("BattleRoom_Lv{n}")
  → AddComponent<BattleRoom>()
  → room.Initialize(level, enemyCount, hpMul, dmgMul, itemPool, width, depth)
  │
  ▼
BattleRoom.Initialize()
  ├── RoomBuilder.Build() → 生成地面/墙壁/障碍物/陷阱
  ├── 生成可破坏物 (Destructible × GameConfig.可破坏物数量)
  └── room.StartBattle()
      ├── 生成普通敌人 (EnemyBase/Ranged/Charger/Mage)
      ├── 可能生成精英怪 (EnemyElite, 30%概率, 第2层起)
      └── 发布 EnemyCountChanged 事件
  │
  ▼
战斗循环
  ├── 敌人死亡 → EnemyKilled 事件
  │   ├── TryDropItem() → 5%概率掉灵物
  │   ├── TryDropSkill() → 3%概率掉功法
  │   └── GameManager 奖励碎片
  ├── 可破坏物被摧毁 → 40%概率掉碎片
  └── 所有敌人死亡 → RoomCleared 事件
  │
  ▼
通关奖励
  ├── 25%概率掉灵物 (SpawnClearReward)
  ├── 25%概率掉功法
  └── 生成传送门 (LevelTransition)
  │
  ▼
玩家进入传送门
  → CleanupLeftoverPickups() → 清理残留掉落物
  → Destroy(currentRoomGo)
  → SpawnCurrentRoom() → 下一个房间
```

### 2.2 商店房间

```
SpawnShopRoom()
  → AddComponent<ShopRoom>()
  → room.Initialize(level, itemPool, skillPool)
  │
  ▼
ShopRoom.Initialize()
  ├── RoomBuilder.Build() → 生成房间
  ├── 生成散修商人NPC
  ├── 生成灵物展示台 (3个灵物 + 2个功法)
  │   ├── 按品阶权重随机选择
  │   └── 价格 = 基础价 × 品阶系数
  └── 生成出口触发器
  │
  ▼
玩家交互
  ├── 靠近商品 → 显示价格/属性提示
  ├── 按F购买 → 扣除碎片 → 装备/入包
  └── 走到出口 → RoomCleared 事件
```

### 2.3 休息/宝箱房间

```
RestRoom: 灵泉恢复50%生命 → 走到出口 → RoomCleared
TreasureRoom: 靠近宝箱 → 开箱动画 → 获得灵物 → 走到出口 → RoomCleared
```

## 三、敌人生命周期

### 3.1 普通敌人 (EnemyBase)

```
BattleRoom.SpawnEnemy()
  → Instantiate / new GameObject
  → AddComponent<EnemyBase>()
  → enemy.Initialize(hpMul, dmgMul, level, itemPool)
  │
  ▼
EnemyBase.Initialize()
  ├── 从 GameConfig 读取基础属性
  ├── 应用难度倍率 (hp × hpMul, dmg × dmgMul)
  ├── 创建模型 (MonsterPrefabs 或 Capsule)
  ├── 创建血条 (EnemyHealthBar)
  └── 设置 Tag = "Enemy"
  │
  ▼
Update() 循环 — AI状态机
  ├── 检测玩家距离
  ├── 追踪 → 移向玩家
  ├── 攻击范围内 → 攻击（带预警指示器）
  ├── 绕行状态 → 30-50%概率闪避
  └── 硬直中 → 暂停行动
  │
  ▼
OnDamage(damage, hitPoint, attacker)
  ├── CombatStats.TakeDamage() → 减伤计算
  ├── 受击闪白 (MaterialHelper)
  ├── 击退 (AddForce)
  ├── 硬直 (_stunTimer = 0.3f)
  ├── HitStop 顿帧
  ├── DamageNumberRequested 事件 → 飘字
  └── 若死亡 → OnDeath()
  │
  ▼
OnDeath()
  ├── 死亡缩小动画
  ├── TryDropItem() → 概率掉灵物
  ├── TryDropSkill() → 概率掉功法
  ├── EnemyKilled 事件
  └── Destroy(gameObject, delay)
```

### 3.2 精英怪 (EnemyElite)

在普通敌人基础上额外：
- 血量 × 3倍，伤害 × 1.5倍
- 金色外观
- 随机2个词缀：

| 词缀 | 效果 |
|------|------|
| 狂暴 | 攻击速度提升 |
| 铁壁 | 减伤增加 |
| 分裂 | 死亡时分裂出小怪 |
| 雷电 | 攻击附带雷电伤害 |
| 吸血 | 攻击回复生命 |
| 冰霜 | 攻击减速玩家 |

### 3.3 Boss (EnemyBoss)

多阶段行为模式：
- 普通攻击（近战）
- 跳跃攻击（抛物线重击）
- 震荡波（扩散环击退）
- 血量阶段切换

## 四、灵物数据流

### 4.1 灵物从创建到生效

```
Demo1DataCreator (编辑器)
  → 创建 ItemData.asset (ScriptableObject)
  → 自动配置到 Demo1Setup.itemPool
  │
  ▼
运行时：敌人死亡
  → EnemyBase.TryDropItem()
  → GameConfig.RollRarity(floorLevel) → 选择品阶
  → 从 itemPool 筛选对应品阶灵物 → 随机选一个
  → 实例化 ItemPickup (世界空间)
  │
  ▼
玩家靠近 ItemPickup
  → 显示提示UI (Canvas + BillboardUI)
  → 按F → ItemInventory.AddItem(itemData)
  │
  ▼
ItemInventory.AddItem()
  ├── 加入持有列表
  ├── RecalculateStats() → 重算属性加成
  │   ├── 遍历所有持有灵物
  │   ├── 累加 attackBonus, maxHpBonus, critRateBonus 等
  │   └── 应用到 PlayerController.Stats
  ├── CheckQualitative() → 检查质变
  │   ├── 同类灵物 ≥ 3 → 小质变效果
  │   └── 同类灵物 ≥ 5 → 大质变效果
  ├── SynergySystem.Check() → 检查组合
  │   └── 满足条件 → SynergyActivated 事件
  └── ItemPickedUp 事件 → UI更新
```

### 4.2 品阶权重与层数关系

`GameConfig.RollRarity(int floorLevel)` 的权重计算：

| 品阶 | 基础权重 | 每层变化 | 第1层 | 第3层 | 第6层 |
|------|---------|---------|-------|-------|-------|
| 凡品 | 50 | -10/层（最低5） | 40 | 20 | 5 |
| 灵品 | 30 | +5/层 | 35 | 45 | 60 |
| 玄品 | 15 | +3/层 | 18 | 24 | 33 |
| 地品 | 4 | +1.5/层 | 5.5 | 8.5 | 13 |
| 天品 | 1 | +0.5/层 | 1.5 | 2.5 | 4 |

## 五、技能系统数据流

### 5.1 技能装备与释放

```
SkillPickup 拾取 / 商店购买
  → PlayerCombat.EquipSkill(skillData, slotIndex)
  → _equippedSkills[slot] = skillData
  → _skillCharges[slot] = skillData.maxCharges
  → SkillEquipped 事件 → SkillBarUI 更新
  │
  ▼
玩家按 Q/E/R
  → PlayerCombat.TryUseSkill(slotIndex)
  → 检查充能 (_skillCharges[slot] > 0)
  → _skillCharges[slot]--
  → ExecuteSkill(skillData)
  │
  ▼
ExecuteSkill() — 根据 skillType 分发
  ├── AreaDamage → 范围伤害 (Physics.OverlapSphere)
  ├── Projectile → 发射投射物 (ObjectPool.Get)
  ├── Dash → 位移 + 路径伤害
  ├── Buff → 增益效果 (临时属性修改)
  ├── Heal → 生命恢复
  └── Summon → 召唤物
  │
  ▼
充能恢复 (Update循环)
  → _skillChargeCDs[slot] -= Time.deltaTime
  → 恢复完成 → _skillCharges[slot]++
  → SkillCooldownUpdate 事件 → UI更新
```

### 5.2 技能充能系统

```csharp
// SkillData 中的充能配置
maxCharges = 1;    // 默认1层（等同于传统CD）
chargeTime = 5f;   // 每层恢复时间

// 特殊技能示例
影步: maxCharges = 2, chargeTime = 3f  // 2层充能，每层3秒恢复
```

## 六、闪避充能系统

```
PlayerController.Update()
  │
  ▼
检测 Space 键
  → _dashCharges > 0 ?
  → _dashCharges--
  → 执行闪避 (位移 + 无敌帧)
  → DashChargeUpdate 事件
  │
  ▼
充能恢复 (Update循环)
  → _dashCharges < maxCharges ?
  → _dashRechargeTimer -= deltaTime
  → 恢复完成 → _dashCharges++
  → DashChargeUpdate 事件 → GameHUD 更新
```

配置：`GameConfig.闪避充能层数`（默认2层），`GameConfig.闪避冷却时间`（每层恢复时间）

## 七、场景切换与清理

### 7.1 房间切换

```
RoomCleared 事件
  → GameManager.OnRoomCleared()
  → LevelTransition.SpawnPortal(pos, callback)
  → 玩家进入传送门
  → callback: SpawnCurrentRoom()
    ├── Destroy(currentRoomGo)     ← 销毁旧房间
    ├── CleanupLeftoverPickups()   ← 清理残留掉落物
    │   ├── FindObjectsOfType<ItemPickup>() → Destroy
    │   ├── FindObjectsOfType<SkillPickup>() → Destroy
    │   └── FindGameObjectsWithTag("Enemy") → Destroy
    └── 生成新房间
```

### 7.2 重新开始

```
GameManager.Restart()
  ├── Destroy(currentRoomGo)
  ├── LevelTransition.DestroyPortal()
  ├── PlayerController.Inventory.Clear()
  ├── PlayerController.SpiritSlots.Clear()
  ├── PlayerController.Stats.ResetHp()
  ├── PlayerResources.Clear()
  ├── GameEvents.Clear()          ← 清空所有事件订阅
  └── SceneManager.LoadScene()    ← 重新加载场景
```

## 八、性能注意事项

### 8.1 对象池使用

以下对象通过 `ObjectPool` 管理，避免频繁 GC：
- 投射物 (`Projectile`, `EnemyProjectile`)
- 打击特效 (Hit VFX)
- 刀光特效 (Slash VFX)
- 伤害飘字 (`DamagePopup`)

### 8.2 事件系统

- 所有事件类型为 `struct`（值类型），发布时零堆分配
- 订阅者必须在 `OnDestroy` 中取消订阅

### 8.3 材质缓存

`MaterialHelper` 内部缓存 Shader 引用，避免重复 `Shader.Find()`

### 8.4 FindObjectsOfType 使用

仅在以下低频场景使用（非每帧）：
- 房间切换时清理残留物 (`CleanupLeftoverPickups`)
- Debug清除所有敌人 (`KillAllEnemies`)
