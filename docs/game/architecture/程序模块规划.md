## 2. 目标数据流

```text
输入层
  → 载体层：武器／术法／身法执行动作
  → 回路层：器灵产生、响应、转化
  → 战斗层：伤害、状态、投射物、召唤与表现

空间层：Edgar生成、拓扑、房间和NavMesh
  → 生态层：区域状态、邻接传播、躁动与器灵迁移
  → 遭遇层：敌人、事件、结契与灾相
  → 流程层：目标、出口、撤离与结算

本局运行态
  → 撤离提交载荷
  → 永久存档
```

旧系统只能单向适配到新系统，ProjectR模块不得反向依赖旧模块UI或无暮王城专用规则。

## 3. 模块编号与职责

### M-CORE：基础设施

职责：

- 游戏生命周期门面。
- 配置、对象池、FeatureFlags和通用事件设施。
- 组合根与运行时服务装配。

当前锚点：

- `Core/GameManager.cs`
- `Core/GameEvents.cs`
- `Core/ObjectPool.cs`
- `Core/FeatureFlags.cs`

约束：

- 不承载具体器灵、回路、生态或奖励规则。
- `GameManager`只做门面和协调，不继续吸收系统实现。

### M-INPUT：输入协调

职责：

- 读取玩家输入。
- 将输入翻译为载体命令。
- 管理输入锁、瞄准意图和动作取消。

当前锚点：

- `Player/PlayerController.cs`
- `Player/PlayerCombat.cs`

目标目录：

- `Player/Input/`

约束：

- 不计算伤害。
- 不直接访问器灵规则或存档。

### M-CARRIER：动作载体

职责：

- 武器、术法和身法定义。
- 技能充能、蓄力和载体执行。
- 输出统一的动作结果和命中事件。

当前锚点：

- `Combat/SkillData.cs`
- `Player/PlayerCombat.cs`
- `Combat/Projectile.cs`

目标目录：

- `Combat/Carriers/`
- `Combat/Execution/`

目标接口：

- `ICarrierAction`
- `ICarrierDefinition`
- `CarrierContext`
- `CarrierResult`
- `CarrierSlot`

约束：

- 载体必须在没有器灵时独立可用。
- 载体只发布结果，不决定器灵响应。

### M-SPIRIT：器灵领域

职责：

- 器灵种族配置与永久实例。
- 性格、关系、悟法池和载体适应。
- 出战编队、附着布局和本局借契。

目标目录：

- `Spirits/`

目标对象：

- `SpiritDefinition`
- `SpiritInstance`
- `SpiritInstanceSave`
- `SpiritRoster`
- `SpiritAttachment`
- `AttachmentLoadout`
- `SpiritContractState`

约束：

- 永久实例使用稳定GUID。
- 种族配置ID与实例GUID必须分离。
- 新结契实例在撤离前不得进入永久契匣。

### M-CIRCUIT：战斗回路

职责：

- `CircuitEvent`及标签字典。
- 源／应／化规则调度。
- 因果链、递归深度、同类重复和单帧频率预算。
- 伤害来源与战后分析数据。

当前参考：

- `Modules/ModuleChain.cs`
- `Modules/TriggerTracker.cs`
- `Core/GameEvents.cs`

目标目录：

- `Combat/Circuit/`

目标对象：

- `ICircuitBus`
- `CircuitBus`
- `CircuitEvent`
- `CircuitDepthGuard`
- `CircuitFrequencyBudget`
- `DamageAttributionRecorder`
- `SpiritCircuitRuntime`

约束：

- 每个派生事件必须保留来源实体、载体、器灵、因果链ID和深度。
- 回路不得直接调用UI。
- 配置不得执行任意代码。

### M-COMBAT：战斗结算

职责：

- 属性、伤害、状态、投射物、召唤和碰撞结果。
- 命中反馈和通用战斗执行器。

当前锚点：

- `Combat/`
- `Enemy/EnemyBase.cs`
- `Player/PlayerController.cs`

约束：

- 不知道器灵关系和洞府状态。
- 通过标准事件返回结果，供回路和UI观察。

### M-DUNGEON：空间与房间

职责：

- Edgar布局生成、Seed和节点拓扑。
- 房间实体、Socket、门、回访状态与NavMesh。

当前锚点：

- `Core/Level/IMapProvider.cs`
- `LevelDesign/Edgar/EdgarMapProvider.cs`
- `LevelDesign/Edgar/EdgarDungeonRuntime.cs`
- `Room/RoomRuntimeController.cs`

目标接口：

- `IMapTopologyReadOnly`
- 现有 `IMapProvider` 的最小空间／流程桥接能力。

约束：

- 空间层不决定生态传播。
- 同一空间Seed必须得到同一布局和节点关系。

### M-ECOLOGY：蜂巢生态

职责：

- 区域离散状态和邻接传播。
- 模糊情报、躁动和器灵迁移。
- 层目标、出口条件与灾相可用状态。

目标目录：

- `LevelDesign/Ecology/`

目标对象：

- `IHoneycombEcologyService`
- `RegionState`
- `RegionSnapshot`
- `IAdjacencyPropagationEngine`
- `IAgitationScheduler`
- `ISpiritMigrationService`
- `LayerObjectiveTracker`

约束：

- 只读取空间拓扑，不控制Edgar生成。
- 同一Run Seed和操作序列必须得到同一生态结果。
- 本层状态默认属于本局运行态。

### M-ENCOUNTER：遭遇与灾相

职责：

- 房间内容解析、敌人和事件执行。
- 器灵栖息、结契和灾相机制。
- 根据生态快照调整遭遇。

当前锚点：

- `Room/BattleRoom.cs`
- `LevelDesign/RoomContentResolver.cs`
- `Enemy/`

约束：

- 遭遇层只读取固化的区域快照。
- 回访房间不得重新抽取遭遇。
- 灾相不是唯一出口钥匙。

### M-SAVE：存档与撤离提交

职责：

- 永久存档DTO和版本迁移。
- 本局运行态生命周期。
- 撤离提交的原子合并边界。

当前锚点：

- `Core/SaveData.cs`
- `Core/SaveSystem.cs`
- `Core/GameManager.cs`
- `Items/CaveInventory.cs`

目标目录：

- `Save/`
- `Run/`

目标对象：

- `RunBuildState`
- `ExtractionPayload`
- `ExtractionCommitService`
- `SaveMigration`
- `RunSettlementOrchestrator`

约束：

- 永久档只存ID、数量和结构化快照，不存ScriptableObject引用。
- 局内载体、附着、临时悟法和待结契实例不能提前写入永久档。
- 撤离／通关是新器灵实例唯一提交入口。

### M-UI：界面与表现

职责：

- HUD、回路预览、邻接情报和战后分析。
- 只通过查询模型和事件获取状态。

当前锚点：

- `UI/`
- `Modules/ModuleAssemblyUI.cs`
- `Modules/ProcBarsHUD.cs`

目标对象：

- `CircuitPreviewUI`
- `PostCombatAnalysisUI`
- `HoneycombIntelPresenter`
- `LayerObjectiveHUD`

约束：

- UI不得直接写存档。
- UI不得向下转型为 `EdgarMapProvider` 获取业务状态。

### M-LEGACY：冻结旧路径

范围：

- `Modules/`玩家可见增强链。
- Q/E/R一技能一链规则。
- 无暮王城白昼／永夜专用事件与流程。
- 旧发现即永久解锁和旧模块UI。

允许行为：

- 修复阻断性Bug。
- 为新系统提供只读适配。
- 在切换闸门通过后分批删除。

禁止行为：

- 增加新内容。
- 让ProjectR模块依赖旧UI和旧故事规则。

- `PlayerCombat` → `PlayerCombatInput + CarrierExecutor + CombatVfx + 薄门面`。
- `ModuleChain` → 保留为Legacy编译参考，不作为器灵回路运行时。
- `ModuleSlotManager` → `AttachmentLoadout + SpiritCircuitRuntime`。
- `TriggerTracker` → `CircuitBus + 响应规则 + FrequencyBudget`。
- `ModuleAssemblyUI` → `CircuitPreviewUI`。

- `EdgarMapProvider` → 空间桥接 + `ILevelMapMode`委托；生态放在独立服务。

## 7. 变更影响矩阵

修改以下契约前必须进行代码图影响检查：

- `GameEvents`：战斗、敌人、房间、UI和回路。
- `SaveData / SaveSystem`：主菜单、暂停、洞府、奖励、结算和旧档迁移。
- `PlayerCombat / SkillData`：输入、动画、投射物、敌人反应、HUD和房间升级。
- `ModuleSlotManager / ModuleChain`：模块UI、奖励、调试、HUD和种子配置。
- `IMapProvider / EdgarMapProvider`：GameManager、房间工厂、事件、商店、Debug和关卡UI。
- `IDamageable / CombatStats`：玩家、全部敌人、可破坏物、状态和伤害反馈。
- Seed公式：布局、房间内容、遭遇、生态和存档复现。
- FeatureFlags：新旧路径可逆性与存档兼容。

代码图不能覆盖的影响：

- Prefab挂载组件。
- Inspector序列化字段。
- UnityEvent回调。
- `Resources.Load`字符串路径。
- 反射和菜单命令。
- 动画事件和Timeline。

这些项必须结合Unity引用搜索、编译和Play Mode验证。
