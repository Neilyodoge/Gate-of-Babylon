# 动作与回路

> 状态：垂直切片设计  
> 上位文档：[ProjectR GDD](../GDD_秘境探索.md)
> 文件名为兼容历史链接暂不修改；玩家侧不再使用“载体”概念，程序内部 `Carrier*` 仍作为实现命名保留。

## 核心关系

玩家选择“执行什么动作”，灵宠决定“这个动作额外显化什么规则”。

### 动作与灵宠边界

- **玩家动作**占用 `LMB / Q / E / R / SPACE`，拥有输入、动画、基础目标、基础伤害与冷却；不附着灵宠也必须能独立使用。
- **灵宠显化**不占独立按键，不能脱离所附着动作主动释放；只改变触发条件、范围、次数、元素或追加结果。
- 移除灵宠后原动作仍然存在；灵宠改附到其他动作后保留身份、关系与悟法，只改变显化方式。
- 玩家文案统一使用“武器动作／术法动作／身法动作／灵宠显化／回路联动／天赋成长”，不把灵宠显化称为“灵宠技能”。

判断标准：需要玩家单独按键并拥有完整施放流程的是玩家动作；必须依赖所附着动作产生事件才发生的是灵宠显化。

```text
玩家输入
  → 玩家动作
  → 灵宠产出可用事物
  → 其他灵宠看到后触发动作
  → 第三只灵宠改造该动作
  → 新事件可继续进入回路
```

## 玩家动作

- 武器动作：普通攻击与特殊攻击。
- 术法动作：主动能力。
- 身法动作：闪避、格挡、瞬移或钩索。

动作必须独立可用。灵宠附着后改变规则和表现，但不能用自动战斗取代玩家操作。

世界内没有额外的“载体装置”。灵宠借结契者主动执行动作时产生的明确意图，把自身规则翻译为当前世界可以接受的结果。武器、术法和身法只是不同动作来源，不是玩家需要理解的第二套抽象分类。

## 灵宠联动语言

每种灵宠由以下能力组成：

1. 产出：制造火花、护甲、标记、回声或召唤物等可用事物。
2. 触发：看到命中、暴击、穿越、聚集、破碎、受伤或消耗后追加动作。
3. 改造：将正在发生的动作变成爆炸、传导、复制、治疗、固化或再生。
4. 动作显化：附着于不同动作时怎样改变表现。
5. 性格偏置：触发时机、目标和风险收益变化。

所有运行时事件至少记录来源实体、动作引用、灵宠、标签、深度和因果链 ID，防止无法追踪的递归触发。程序内部的动作引用当前仍由 `Carrier*` 合同承载。

## 附着结构

- 分开附着（`1＋1＋1`）：三只灵宠分居三个动作，适合覆盖较长的联动。
- 双宠同挂（`2＋1`）：两只灵宠集中改变一个动作，另一只负责接续。
- 三宠同挂（`3＋0`）：三只灵宠共居一个动作，形成集中构筑。

首批同一动作上的多只灵宠只叠加各自规则，不额外产生融合技能。三种结构应改变操作和构筑关系，而不是只改变数值效率。

P2.20C首批运行规则：

- `1＋1＋1`需要玩家依次完成产出、触发、改造三只灵宠所附动作，形成较长输入回路。
- `2＋1`中同挂动作上的相邻职责会在一次动作内连续处理，只需另一动作接续。
- `3＋0`在同一动作满足火花积累后可直接完成整条回路，集中但受单一动作节奏约束。
- 改附只在脱战时进行，并清空尚未完成的临时火花／复响；灵宠等级、天赋点和已点亮节点不受影响。
- 中间火花最多保留1份、等待12秒；中间复响最多保留1份、等待10秒。同类再次产生时覆盖旧状态并刷新时间，不叠加库存。
- HUD显示当前蓄势进度；产生火花后提示响响鸮所附动作，产生复响后提示弹弹胶所附动作，同时高亮对应动作槽。状态到期或完成回路后提示自动消失。

## 局内成长

### 改附动作

改变灵宠借哪个动作显化。改附后，灵宠本局已经点亮的天赋不丢失。

### 灵宠天赋

- 产出天赋：改变制造什么或积累速度。
- 触发天赋：改变观察条件或追加动作。
- 改造天赋：改变动作形态，但不能脱离前置事件单独启动。

每只灵宠拥有固定天赋树。局外永久开放候选节点，局内升级时只点亮有限路线，避免联动不可读。详见：[灵宠天赋树](灵宠天赋树.md)。

### 动作演变

只改变玩家动作本身，例如范围终结、跟随旋涡、碎盾投射和蓄力反击。

### 灵宠联动

当一只灵宠持续消费另一只的产物时累积默契，后续可解锁保留产物、再次触发、双宠合击或三宠联动；这些专属内容不进入首批原型。

## 构筑节奏

- 0–10分钟：选定主要动作和第一次附着，形成两段互动。
- 10–25分钟：接通三宠联动，获得默契效果。
- 25–35分钟：形成稳定循环、三宠同挂或终结变化。

成熟路径应是：

```text
能互动 → 能连锁 → 能闭环 → 能产生受控的失控爆发
```

## 防爆与可读性

- 每条事件链限制最大深度和同类重复次数。
- 自动触发必须有频率或预算上限。
- 回路UI显示产出、触发、改造和断点。
- 可选战斗统计能按玩家动作、灵宠和回路触发追溯主要伤害、防御、治疗与资源来源。
- 灵宠附着的世界空间常驻表现只使用动作部位流动特效：例如水属性附着武器时让剑身流动蓝色能量，不在角色、武器或身体部位额外挂灵宠图标。
- 灵宠触发可以追加笔触、音效或极短显形，但不要求灵宠长期悬浮在人物身后。
- 灵宠身份、附着动作和多宠同挂统一由现有技能栏／HUD挂件表达；世界内只显示必要的混合属性笔触，不用图标或长距离能量带占据战斗画面。
- 失控附身只增加能量溢出、属性流动异常与人物动作异常，不另造一套复杂视觉语言。
- 通用规则覆盖约80%组合，招牌融合只覆盖少量高契合组合。

### 战斗统计

战斗统计是结算页中的可选数值详情，不是家园设施，也不承担教学主流程。

- 显示总伤害、承受伤害、有效治疗、有效护盾和关键资源产出。
- 可按玩家动作、灵宠显化与回路联动查看贡献。
- 对每种来源显示伤害或收益数值、占比、触发次数和最高单次效果。
- 回路伤害归到实际造成结果的来源，同时保留“由谁触发”的关联，避免同一份伤害重复计入总量。
- 默认结算只显示少量摘要；玩家展开详情后才查看完整来源。
- 不给出强制评分或“唯一正确构筑”结论，只帮助玩家理解本局哪些机制真正生效。

## 垂直切片范围

- 2套武器动作、4个术法动作、2个身法动作。
- 先做火花狸、响响鸮、弹弹胶3只工作名灵宠及产出／触发／改造天赋，再扩至4只。
- `1＋1＋1`、`2＋1`、`3＋0`都能完成有效构筑。
- 1套回路预览、实时触发反馈和战斗统计摘要。

## 验收标准

- 玩家能在首次获得三只灵宠后，用“它造了什么、谁接着动、谁把动作变了”解释整条联动。
- 同一灵宠改附到不同动作后明显改变玩法。
- 改附动作不会抹掉灵宠成长投资。
- 三种附着结构都有独立使用理由。
- 任意回路不会产生无限递归或不可解释伤害。
