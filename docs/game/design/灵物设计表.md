## 1. 分类目标

增强道具分三类：

| 分类 | 作用 | 示例 |
|------|------|------|
| **数值堆叠** | 提供可读、可叠的基础战力 | 攻击、生命、移速、冷却、暴击 |
| **机制增强** | 强化已有模块或战斗行为 | 种子更多、背击更久、护盾破裂爆炸 |
| **机制改造** | 改变模块行为，接近改造件但以掉落道具形式出现 | 投射物连锁、毒雾扩散、傀儡分流 |

旧“宝石系统”的生产价值并入 **改造件 / 机制改造类增强道具**，不再作为独立系统。

## 2. 品质建议

| 品质 | 出现概率 | 设计职责 |
|------|---------|---------|
| 普通 | 50% | 基础数值、轻量堆叠 |
| 稀有 | 30% | 小机制增强 |
| 精良 | 15% | 明显改变手感 |
| 史诗 | 4% | 形成流派核心 |
| 传说 | 1% | 改变 Build 方向 |

## 6. 与模块的关系

| 模块层 | 增强道具如何影响 |
|--------|----------------|
| **触发器** | 降低触发条件、延长状态、增加层数上限 |
| **效果器** | 增强范围、伤害、持续时间、目标选择 |
| **改造件** | 提供额外改造、降低副作用、增加可叠次数 |
| **起始模板** | 改变推荐掉落权重，但不硬锁掉落池 |

---

## 7. 设计边界

- 增强道具是局内 Build，不是局外永久成长。
- 同一效果优先做行为变化，少做纯百分比膨胀。
- 机制改造类增强道具和改造件可以复用效果，但 UI 上要说明来源不同：
  - 改造件：模块配置的一部分。
  - 增强道具：本局掉落带来的额外改写。
- 不再设计“必须活着撤离才能带回”的道具资源。结算资源统一进入经验值池。
