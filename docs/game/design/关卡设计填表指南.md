# 关卡设计填表指南

> **适用范围**：GDD §12 关卡设计系统的 6 张 JSON 配置表
> **表格位置**：`Babylon/Assets/1Game/Resources/LevelDesign/`
> **改完直接运行即可生效，不需要改代码。**

所有表格格式统一为 `{ "Rows": [ ... ] }`，每行是一条记录。

---

## 1. Map_Structure_Config.json — 区域地图结构

控制每个 Act（章）的 TreeMap（仙山舆图）长什么样。

| 字段 | 类型 | 含义 | 填法 |
|---|---|---|---|
| `ID` | int | 唯一编号 | 递增即可 |
| `ActID` | int | 对应第几章 | 1=练气→筑基, 2=金丹→元婴, 3=化神→渡劫 |
| `MaxFloor` | int | 树状图总层数（含起点层和 Boss 层） | 6=短, 8=中, 10=长 |
| `MinNodes` | int | 每层最少节点数 | 2~3 个选择 |
| `MaxNodes` | int | 每层最多节点数 | 3~4 个选择 |
| `NormalWeight` | int | 普通房（战斗/精英）权重 | 75=大部分战斗 |
| `SpecialWeight` | int | 特殊房（商店/事件）权重 | 25=偶尔出现 |
| `EliteMinCount` | int | 整个 Act 精英房保底数量 | |
| `EliteMaxCount` | int | 精英房最多数量 | |
| `EventMinCount` | int | 事件房保底数量 | |
| `ShopMinCount` | int | 商店房保底数量 | |
| `RoomPoolID` | int[] | 可用的房间配置 ID 列表 | 引用 Room_Socket_Group_Config 的 ID |

**示例 — 让第 2 章更长、更多事件**：

```json
{
  "ID": 2,
  "ActID": 2,
  "MaxFloor": 10,
  "MinNodes": 3,
  "MaxNodes": 4,
  "NormalWeight": 60,
  "SpecialWeight": 40,
  "EliteMinCount": 2,
  "EliteMaxCount": 3,
  "EventMinCount": 3,
  "ShopMinCount": 2,
  "RoomPoolID": [1, 2, 3, 4, 5, 6, 7]
}
```

## 2. Room_Socket_Group_Config.json — 房间配置

定义每种房间节点的具体内容（敌人、掉落、是否挂事件）。TreeMap 生成时按 `Weight` 从同类型的配置中抽取。

| 字段 | 类型 | 含义 | 填法 |
|---|---|---|---|
| `ID` | int | 唯一编号 | |
| `SceneName` | string | 场景名（预留） | 目前填 `"Demo1"` |
| `RoomType` | int | 房间类型 | **0**=起点, **1**=战斗, **2**=精英, **3**=商店, **4**=事件, **5**=Boss |
| `EnemySquadID` | int[] | 敌人编队 ID（预留） | `[]` 或 `[1]` |
| `ItemDropIDs` | int[] | 掉落物品 ID 列表 | 引用 Item_InRun_Config 的 ID |
| `ItemDropWeights` | int[] | 对应掉落权重（与 ItemDropIDs 等长） | 权重越高越容易出 |
| `EventID` | int | 挂载的事件 ID | 0=无事件；填 Event_Story_Config 的 ID |
| `EventTriggerRate` | int | 事件触发概率（%） | 事件房填 `100`；战斗房可填 `25`=25%概率 |
| `Weight` | int | 被选中的权重 | 同类型多个配置时，权重越高越容易被抽到 |

**示例 — 加一个"高难度战斗房"，25%概率触发事件**：

```json
{
  "ID": 7,
  "SceneName": "Demo1",
  "RoomType": 1,
  "EnemySquadID": [3],
  "ItemDropIDs": [2001, 2002],
  "ItemDropWeights": [60, 40],
  "EventID": 1003,
  "EventTriggerRate": 25,
  "Weight": 50
}
```

> **注意**：新加的房间配置需要把它的 ID 加到 Map_Structure_Config 的 `RoomPoolID` 数组里，否则不会被 TreeMap 使用。

## 3. Event_Story_Config.json — 事件配置（最常填的表）

| 字段 | 类型 | 含义 | 填法 |
|---|---|---|---|
| `ID` | int | 唯一编号（建议 1001 起） | |
| `Name_CN` | string | 事件名（显示在 UI 标题 `· 奇遇 · xxx ·`） | |
| `Type` | int | 事件类型 | **1**=多选, **2**=单选, **3**=条件事件 |
| `PrereqFlag` | string | 前置条件表达式 | 空=无条件；`saved_yeXiu=1`=需要之前救了叶修 |
| `Text_CN` | string | 事件正文（支持 `\n` 换行） | |
| `Options` | array | 选项列表（1~N 个） | 见下方 |

### Options 每个选项的字段

| 字段 | 类型 | 含义 | 举例 |
|---|---|---|---|
| `Text` | string | 按钮文字 | `"取走风灵珠"` |
| `FlagName` | string | 写入的 Boss Flag 名 | `"betrayed_yeXiu"`（空=不写 Flag） |
| `FlagValue` | int | Flag 值 | 通常填 `1` |
| `RewardID` | int | 奖励物品 ID | 引用 Item_InRun_Config，`0`=无奖励 |
| `CostID` | int | 代价物品 ID | `0`=无代价 |
| `KarmaChange` | int | 因果变化 | 正数=增加因果债, 负数=消减 |
| `DaoxinChange` | int | 道心变化 | 正数=道心上升, 负数=下降 |
| `LifespanChange` | int | 寿元变化 | `-10`=消耗10年寿元 |

> **UI 显示**：KarmaChange/DaoxinChange/LifespanChange/RewardID/CostID 非零时会自动在按钮上显示彩色标签（如 `因果 +1 · 道心 -5 · 有奖励`），玩家可以看到选择的代价。

### 条件事件（Type=3）

`PrereqFlag` 填写条件表达式，只有满足时事件才会触发。支持语法：

```
saved_yeXiu=1           → Flag 等于 1
karma_debt>=3            → Flag 大于等于 3
daoxin<=20               → 道心小于等于 20
flagA=1&flagB>=2         → 两个条件同时满足（AND）
```

不满足条件时该事件被跳过，不会弹出。

### 完整示例 — 加一个"神秘商人"事件

```json
{
  "ID": 1004,
  "Name_CN": "神秘商人",
  "Type": 1,
  "PrereqFlag": "",
  "Text_CN": "一个面容模糊的行商出现在前方，他的摊位上摆着两样东西：一枚散发幽光的丹药，和一张泛黄的符箓。\n\n「每人只能选一样。」他说。",
  "Options": [
    {
      "Text": "选择丹药（获得回灵丹）",
      "FlagName": "chose_pill",
      "FlagValue": 1,
      "RewardID": 2002,
      "CostID": 0,
      "KarmaChange": 0,
      "DaoxinChange": 0,
      "LifespanChange": 0
    },
    {
      "Text": "选择符箓（获得逆命符）",
      "FlagName": "chose_talisman",
      "FlagValue": 1,
      "RewardID": 9001,
      "CostID": 0,
      "KarmaChange": 0,
      "DaoxinChange": 0,
      "LifespanChange": 0
    },
    {
      "Text": "什么都不要，转身离去",
      "FlagName": "",
      "FlagValue": 0,
      "RewardID": 0,
      "CostID": 0,
      "KarmaChange": 0,
      "DaoxinChange": 2,
      "LifespanChange": 0
    }
  ]
}
```

### 让事件出现在游戏中

事件写好后，需要挂到某个房间配置上：

1. **方式 A — 挂到事件房（100%触发）**：在 Room_Socket_Group_Config 中找一个 `RoomType=4` 的房间配置，把 `EventID` 填你的事件 ID，`EventTriggerRate` 填 `100`
2. **方式 B — 挂到战斗房（概率触发）**：在某个 `RoomType=1` 的战斗房配置上填 `EventID` + `EventTriggerRate`（如 `25` = 清场后 25% 触发）
3. **方式 C — 线性调度（精确控制）**：改代码 `LevelDesignBootstrap._linearEventSchedule` 字典（格式：`(境界, 房间索引) → EventID`）

## 4. Boss_Phase_Config.json — Boss 形态

控制 Boss 出场时根据玩家之前的选择变化形态。**满足条件的形态中 Priority 最高的被选中**。

| 字段 | 类型 | 含义 | 填法 |
|---|---|---|---|
| `ID` | int | 唯一编号 | |
| `BossID` | int | 属于哪个 Boss | 目前只有 `1`（青云宗长老） |
| `PhaseName` | string | 形态名 | 日志 + 对白标题用 |
| `RequiredFlags` | string | Flag 条件表达式 | 空=默认兜底形态；语法同事件 PrereqFlag |
| `Priority` | int | 优先级（高胜出） | **0**=兜底, **10**=普通条件, **20**=高优先 |
| `DialogueLines` | string[] | 出场对白 | 屏幕下方逐行显示 |
| `StatModifier` | string | 数值修正 | `hp*1.3,atk*1.5,spd*1.1` 格式，空=不修正 |
| `SkillSetID` | int | 技能组 ID（预留） | |
| `SummonSquadID` | int | 召唤小怪编队 ID（预留） | 0=不召唤 |

### RequiredFlags 表达式写法

```
betrayed_yeXiu=1               → 玩家背叛了叶修
saved_yeXiu=1                  → 玩家救了叶修
karma_debt>=3                  → 因果债 ≥ 3
daoxin<=20                     → 道心 ≤ 20（心境低迷）
betrayed_yeXiu=1&karma_debt>=2 → 同时满足两个条件
```

### StatModifier 格式

用逗号分隔，每项格式为 `属性*倍率`：

```
hp*1.3          → 血量 ×1.3
atk*1.5         → 攻击力 ×1.5
spd*0.8         → 移动速度 ×0.8
hp*1.3,atk*1.5  → 同时修正多项
```

### 形态选择逻辑

1. 遍历同 `BossID` 的所有形态
2. 检查每个形态的 `RequiredFlags` 是否满足
3. 满足的形态中取 `Priority` 最高的
4. `RequiredFlags` 为空 + `Priority=0` 的行作为**兜底**（没有任何条件满足时使用）

### 示例 — 加一个命格触发的特殊形态

```json
{
  "ID": 6,
  "BossID": 1,
  "PhaseName": "青云宗长老 · 道祖识途",
  "RequiredFlags": "fate_道祖转世=1",
  "Priority": 25,
  "DialogueLines": [
    "「您……您莫不是道祖转世？」",
    "「老朽有眼不识泰山！」"
  ],
  "SkillSetID": 6,
  "StatModifier": "atk*0.5,spd*0.8",
  "SummonSquadID": 0
}
```

## 5. Item_InRun_Config.json — 局内道具

事件奖励/代价引用的物品定义。如果 `Name_CN` 与项目中某个 `ItemData` ScriptableObject 的 `itemName` 同名，奖励时会直接添加到玩家背包。

| 字段 | 类型 | 含义 | 建议 ID 范围 |
|---|---|---|---|
| `ID` | int | 唯一编号 | 2001+=消耗品, 3001+=稀有品, 9001+=特殊道具 |
| `Name_CN` | string | 道具名 | |
| `Text_CN` | string | 描述 | |
| `Type` | int | 类型 | **1**=消耗品, **2**=被动, **3**=特殊 |
| `Icon` | string | 图标名（预留） | |
| `MaxStack` | int | 最大堆叠数 | |
| `EffectID` | int | 效果 ID（预留） | |
| `Duration` | float | 持续时间秒（预留） | |

## 快速操作速查

| 我想要... | 改哪张表 | 要做什么 |
|---|---|---|
| 加一个新事件 | `Event_Story_Config` | 追加一行 |
| 让事件出现在游戏里 | `Room_Socket_Group_Config` | 某个房间的 `EventID` 填新事件 ID |
| 给 Boss 加一个新形态 | `Boss_Phase_Config` | 追加一行，写好 RequiredFlags 和 Priority |
| 让地图更长 / 更多选择 | `Map_Structure_Config` | 调 `MaxFloor` / `MinNodes` / `MaxNodes` |
| 增加事件 / 商店出现率 | `Map_Structure_Config` | 调大 `SpecialWeight` 和 `EventMinCount` / `ShopMinCount` |
| 加一种新的事件奖励道具 | `Item_InRun_Config` | 追加一行，然后在事件 Option 的 `RewardID` 引用它 |
| 加一个新房间配置 | `Room_Socket_Group_Config` | 追加一行 + 把 ID 加到 Map_Structure 的 `RoomPoolID` |
