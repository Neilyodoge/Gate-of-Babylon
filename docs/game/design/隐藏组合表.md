> **文档版本**：2026-04-28
> 没有"流派"标签，没有"你是剑修"这种身份。
> 只有：灵物 + 灵物 = 效果，效果 + 效果 = Build。

## 1. 触发规则

代码：`Babylon/Assets/1Game/Scripts/Items/SynergySystem.cs`，静态类，注册式。

`ItemInventory.AddItem / RemoveItem` 调用 `CheckSynergies`：
1. 统计每个 `ItemCategory` 的灵物数量
2. 遍历预定义 `SynergyDef`，检查 `requiredCategories + requiredCounts`
3. 满足且未激活 → `applyEffect(stats)`，发布 `SynergyActivated`
4. 不满足且已激活 → `removeEffect(stats)`

| 触发类型 | 说明 | 当前实现 |
|---------|------|---------|
| 分类计数触发 | 各分类达到指定数量 | ✅ 已实现，全部 10 个组合都用这种规则 |
| 特定道具组合触发 | 指定的 2~4 件灵物同时持有 | ❌ 未实现（设计目标） |
| 标签触发（五行） | 集齐特定五行标签组合 | ❌ 未实现（无五行系统） |
| 条件触发 | 满足游戏状态（如连续 N 房间没拿） | ❌ 未实现 |

## 3. 协同与质变的关系

| 维度 | 协同（Synergy） | 质变（Qualitative） |
|------|---------------|---------------------|
| 触发条件 | 多种分类组合（计数） | 同一灵物达到阈值 |
| 注册方式 | `SynergySystem.RegisterDefaultSynergies` 集中静态注册 | `ItemInventory.ApplyQualitativeEffect` 按灵物名分发 |
| 机制运行 | 直接改 `stats` 或调 `QualitativeEffectRunner` | 同样直接改 `stats` 或调 `QualitativeEffectRunner` |
| UI 提示 | 屏幕闪光 + `SynergyActivated` 事件 | 飘字 + `QualitativeTriggered` 事件 |
| 失效恢复 | 灵物减少时 `removeEffect` 反向恢复 | 一旦触发不可逆（无 deactivate 流程） |

> 设计上两者并行：协同是"多种灵物组合"，质变是"单种灵物堆量"。后期合并到 `StatsCalculator` 后行为会更一致。
