## 1. 游戏概述

### 1.1 一句话描述

> 一款冒险题材的 Roguelike Top-down 3D ARPG（参考《梦之形》视角风格），玩家扮演立志终极挑战成功的冒险者，在基地休整修炼与关卡历练之间循环，通过为核心技能装配"触发器 + 效果器 + 改造件 + 万能件"的增强链，构建无限可能的 Build，探索秘境探索的终极真相。

### 1.2 参考作品分析

**《Shape of Dreams / 梦之形》的不足（我们要解决的问题）：**

| 问题 | 我们的解决方案 |
|------|--------------|
| Build 多样性有限，几局后见过所有东西 | 万能件 + 自由拼装 + 局外解锁，理论 Build 数近乎无限 |
| 宝石系统偏数值，缺乏机制深度 | 不做独立宝石系统；将其降级为"模块改造件 / 符文"，作为触发器和效果器的第三层修饰 |
| 叙事/世界观薄弱 | 冒险世界观 + 自适应怪物生态（反制系统）+ 多结局抉择，碎片化剧情 + 终极悬念 |
| 缺乏长期目标（Meta Progression） | 完整的局外成长系统：模块解锁 + 前哨蓝图 / 容错强化 |
| 重玩价值低 | 解锁初始配置 × 随机模块 × 万能件自由拼装 = 每局体验差异化 |

### 1.3 文档制作规范
目前随着策划的加入，对表格的需求也愈发重要，因此在此设计好一系列规范和准则，让整个流程可以更好地与其他人协调制作，下面进行说明；
- **关于表格的制作说明**：
大部份设计会添加表格进行控制，控制范围会针对每项功能进行定制；
未提及表格的功能则默认不制作表格；
制作表格时，可根据说明的核心需求自行判断是否增加表格的控制范围，但需要在每次更新后进行详细说明（可直接修改文档进行说明）；
设计表格目的是为了可以在各个功能中进行灵活的控制和调整，方便策划或其他人进行修改；

## 2. 世界观与叙事

玩家扮演一名进入危险关卡探索的冒险者。基地是玩家的休整、配置与长期成长场所；关卡是玩家进行长局构筑、挑战 Boss、获取经验值和解锁线索的主要场景。

叙事目标是服务 Roguelite 循环：每一次死亡、返回或通关都会让玩家更理解世界、更接近终局真相。剧情通过 Boss、事件、记忆碎片、基地 NPC 和多结局逐步展开。

关卡目标采用「**区域可识别、路线与遭遇可变化**」的结构：玩家能够逐渐熟悉一个区域的地标、分区与奖励主题，但每局的降落点、连接关系、Boss 具体位置、事件和敌群都会变化。局内 Build 仍在每局结束后清空；普通战斗房可产出能够带回基地的材料，材料的局外用途与死亡结算规则暂不在本阶段展开。

**关卡 A · 无暮王城（局部故事）**：

- 无暮王城曾以死者残留的力量维持永恒白昼。最后一次加冕仪式失控后，整座城市被困在“白昼表象”与“永夜牢城”两个相反阶段。
- 本关只承担一段可独立理解的地方悲剧，不把玩家身份、世界终局或整部游戏的最终反派绑定在此。玩家进入王城的直接目标是取得通往后续区域所需的王冠碎片。
- 首次阶段为白昼：守卫、供能设施和加冕秩序仍在重复运转；完成该阶段后，王城状态反转为永夜，同一空间显露亡者收容设施与被掩盖的历史。
- 白昼摄政者主张继续牺牲死者维持城市；永夜引渡者主张终止循环，即使王城因此灭亡。二者都是本关 Boss，不承担整部游戏的善恶终审。
- 玩家在前一阶段对通路、供能设施和危险封存物的处理，会在反转后的阶段形成可见结果；完成永夜阶段后，本轮地方故事闭环并进入后续关卡。
- 关卡 A 在重复刷取时以完整双阶段为一个循环：永夜通关后清除本轮阶段结果，并把无暮王城重置为白昼；不会永久停留在永夜，也不在首版开放自由选阶段。

## 3. 核心循环

```text
基地
  → 结算经验值
  → 解锁模块 / 在配置 NPC 处配置带入局内的初始模块 / 配置前哨与补给
  → 带入配置好的初始模块进入关卡

关卡
  → 获取触发器 / 效果器 / 改造件
  → 拼出本局 Build
  → 阶段返回、死亡或通关
  → 按不同倍率结算经验值
```

**基地空间 MVP**：
- 基地采用独立 Prefab，不再由通用房间墙地临时拼接。Prefab 必须提供 `PlayerSpawn / RealmPortal / PreparationStation / CaveStation / MapTablet` 五类功能插槽，正式美术只能替换空间与视觉，不改变插槽语义。
- 秘境之门就是正式入口：交互后原地打开初始技能三选一，确认后直接进入关卡首个落点，不再经过独立准备房。永夜待续信息仍显示在入口；左侧整备位首版接藏经阁，右侧洞府位接阵法台。
- `Tab` 只打开左侧常规 Debug 菜单，其中提供“事件提示”按钮；点击后在右侧按白昼 / 永夜、Layout / Strength 展示四项事件与十二个选项。当前可选为蓝色、已经选择为绿色，本局未分配、已处理及未到对应昼夜阶段统一置灰。

**结算结果**：

| 结果 | 经验倍率 | 设计目的 |
|------|---------|---------|
| 死亡 | 0.5x | 失败也能推进局外成长，但收益明显低于主动返回 |
| 阶段返回 | 1.0x | 玩家主动收手，保守结算 |
| 通关 | 2.0x | 奖励完整长局与高风险挑战 |
| 完美通关 | 3.0x | 额外奖励无死亡 / 高难度挑战表现 |

其中，“阶段返回”包含未击败 Boss 时通过主动撤离或特殊撤离口离开；“通关”必须击败本局 Boss，并进入随后生成的最终出口。

**局外成长**：
- 经验值是唯一通用局外资源。
- 来源标签只影响经验转化方向，例如战斗、模块、流派、探索、情报、Boss。
- 成长出口包括模块解锁、前哨蓝图、容错强化和剧情推进。

### 3.1 基础数值系统

模块系统必须建立在统一基础数值上，后续所有模块只修改这些字段。

| 字段 | 初始值 | 规则 |
|------|-------|------|
| **生命值 HP** | 100 | 归零后进入死亡结算；可被治疗、护盾和复活类模块影响 |
| **护盾 Shield** | 0 | 先于生命承伤，默认不自然回复，只由模块或房间奖励提供 |
| **移动速度 MoveSpeed** | 5.0 单位 / 秒 | 可被模块临时修改，上限 150% |
| **攻击速度 AttackSpeed** | 100% | 影响普攻动作时长，上限 150%，不压缩输入缓冲到 150ms 以下 |
| **暴击率 CritRate** | 5% | 默认暴击伤害为 150% |
| **技能冷却 Cooldown** | 由模块定义 | 冷却缩减上限 50% |
| **闪避充能 DodgeCharge** | 2 层 | 可被模块临时提高，上限 4 层 |

生命、护盾、攻速、移速和冷却是模块平衡的基础字段；没有写入这些字段的模块，不应直接修改底层战斗表现。

## 4. 初始配置与局外成长

### 4.1 初始配置

开局不再使用固定流派模板，改为一套可直接运转的初始模块：

- **测试版本**：开局直接给一套"种子"初始模块（触发器 + 效果器 + 改造件各一，保证开局即可运转），玩家无需选择。
- **配置 NPC**：玩家可在旁边配置 NPC 处手动替换、调整带入局内的初始模块，自由组合已解锁模块。
- **后续版本**：以新手教学关卡引导玩家上手，不再依赖固定模板流派划分。

初始模块只解决"开局有一组能用的东西"，不限制局内发展——玩家在关卡中可以捡到其他模块并完全转向。

### 4.2 局外解锁系统

局外成长以**解锁**为主，不修改模块数值。当前触发器、效果器、改造件、万能件四类模块**均不可升级**。

| 机制 | 说明 |
|------|------|
| **模块解锁** | 局外解锁新模块后，可在配置 NPC 处将其选入带入局内的初始模块，局内再通过掉落发展 |
| **带入配置** | 玩家在配置 NPC 处手动挑选已解锁模块组成初始装配，每局带入数量有限 |
| **解锁来源** | 经验值、Boss、剧情、情报等（具体解锁条件后续补充） |

> 局外成长不包含数值升级（模块熟练度已移除）和固定流派模板（起始模板已移除），长期目标聚焦在"解锁更多模块、丰富带入组合、前哨与容错强化"上。


## 5. 模块化技能系统（核心技能 × 增强链 · Proc → Consume）

> **V0.1.12 方向变更**（原 V.08）：模块链不再"自己释放技能"。技能的主导权回到玩家按键上：核心技能是玩家主动释放的招式，模块链挂在核心技能上做**增强器**。Trigger 决定**什么时候把增强上膛（Proc）**，玩家按下对应技能才**开火（Consume）**并消费增强。这一改动解决了 V0.1.11（原 V.07）"装配即战斗、操作感缺失"的方向性问题。
>
> **取代的旧系统**：本章取代了历史「灵物 / 御灵五系 / 化身 / 天赋树 / 宝石 / 秘术」等系统，详见 §10.3 历史归档。

### 5.1 核心逻辑：核心技能 × [触发] → [效果] → [改造]

战斗由两层构成：

1. **核心技能层**：Q/E/R 三个槽位各装一个核心技能，玩家主动按键释放（伤害、动画、目标选择都由核心技能决定）。起始固定 3 个，关卡内可替换。详见 5.12。
2. **增强链层**：每条增强链挂在一个核心技能上，由三类模块拼装：
   - **触发器 (Trigger)**：定义**什么时候这条链上膛**（Proc），并自带 `consumeKind` 声明消费模型。
   - **效果器 (Effect)**：定义**消费时给核心技能附加什么**（增伤倍率、附加范围爆炸、改元素、控制、自愈等）。
   - **改造件 (Modifier)**：定义**这个加成如何变形**（蓄力等级、爆炸半径、Proc 概率、层数上限）。
3. 另有第四类**万能件 (Universal)**：无固定职责，放入哪个槽就当哪个，详见 5.10。

```
核心技能「剑气」 + [触发器: 暴击时·Single] + [效果器: +120% 伤害]
  = 暴击后剑气图标冒火，下次按 Q 释放 +120% 伤害剑气

核心技能「落雷」 + [触发器: 移动 10 米·Stacks(3)] + [效果器: 附加范围爆炸] + [改造件: 爆炸半径 +50%]
  = 跑动累层（最多 3 层），每按一次落雷附带一次放大爆炸，消耗一层

核心技能「突刺」 + [万能件(当触发器: 闪避后·Window 5s)] + [万能件(当效果器: 改为火属性)]
  = 闪避后 5 秒内按下突刺附带火属性，整条链全由万能件组成
```

**裸技能规则**：未挂增强链的核心技能仍可正常释放，只是没有加成。降低上手门槛，玩家可逐步为喜欢的技能配链。

**一技能一链规则**：一个核心技能槽位最多挂一条增强链；不同技能可同时各挂一条互不干扰。最小可玩版本不开放多链叠加。

### 5.2 模块分类总规则

所有局内 Build 部件统一叫**模块**，分四大类：

| 大类 | 负责问题 | 设计边界 | 例子 |
|------|---------|---------|------|
| **触发器** | 增强什么时候上膛（Proc）/ 用什么状态承载 | 不负责主要伤害，只提供 Proc 条件、节奏或状态载体；自带 `consumeKind` | 暴击时·Single、移动 X 米·Stacks、每 N 秒·Window、种子生成 |
| **效果器** | 消费时给核心技能附加什么 | 不改变核心技能的触发条件，只定义附加的增伤、范围、元素、控制、自愈等结果 | +120% 伤害、附加范围爆炸、改火属性、回血 |
| **改造件** | 这个加成如何变形 | 不单独成为技能，必须依附触发器或效果器生效 | 连锁、扩散、延迟、分裂、左侧强化 |
| **万能件** | 视放入槽位决定职责 | 无固定大类，放入触发器槽即当触发器、放入效果器槽即当效果器；详见 5.10 | 万能"种子/引爆"件、万能"落雷/条件"件 |

每个模块都必须有标签，标签用于掉落权重、兼容判断和局外解锁。

| 标签维度 | 用途 | 示例 |
|---------|------|------|
| **模块大类** | 判断槽位位置 | Trigger / Effect / Modifier / Universal |
| **功能标签** | 判断玩法类型 | Damage / Defense / Heal / Mobility / Summon / Control / State |
| **触发标签** | 判断 Proc 来源 | Attack / Move / Hit / Kill / Time / Dodge / State |
| **形态标签** | 判断改造兼容性 | Projectile / Area / Melee / Aura / Chain / Object |
| **节奏标签** | 判断 Proc / Consume 节奏 | Single / Window / Stacks / Proc |
| **流派标签** | 用于推荐掉落 | Seed / Backstab / Puppet / Lightning / Poison |

### 5.3 触发器分类 (Trigger Types)

触发器决定**增强什么时候上膛（Proc）**或承载什么状态。触发器只分两层：**条件型**和**状态型**。每个触发器必须声明 `consumeKind`，决定消费模型（详见 5.6）。

| 子类 | 说明 | 示例 | 必填字段 |
|------|------|------|---------|
| **战斗行为触发** | 根据攻击、命中、暴击、连击等行为 Proc | 攻击 X 次、暴击后、连击第 3 段 | 行为类型、计数阈值、冷却、是否消耗层数、consumeKind |
| **移动 / 闪避触发** | 根据移动距离、冲刺、闪避窗口 Proc | 移动 X 米、闪避成功、冲刺结束 | 距离阈值、窗口时间、冷却、方向限制、consumeKind |
| **受击 / 防御触发** | 根据受到伤害、格挡、护盾破裂 Proc | 受击时、护盾破裂时、低血量时 | 伤害条件、生命阈值、冷却、防重复触发规则、consumeKind |
| **时间 / 节奏触发** | 根据固定时间、蓄力、房间节奏 Proc | 每 X 秒、蓄力满、进入新房间 | 时间阈值、是否受冷却缩减影响、初始延迟、consumeKind |
| **击杀 / 事件触发** | 根据击杀、拾取、开箱、Boss 阶段等事件 Proc | 击杀后、精英死亡、Boss 进入二阶段 | 事件来源、目标限制、触发次数上限、consumeKind |
| **状态型触发** | 创建标记、层数、召唤物或计数器作为 Proc 载体 | 种子生成、种子引爆、背击标记、傀儡计数 | 状态名、层数上限、持续时间、默认状态展示 |

条件型触发器包含战斗行为、移动 / 闪避、受击 / 防御、时间 / 节奏、击杀 / 事件五个子类；状态型触发器单独作为第六类。

状态型触发器只提供**无伤害状态展示**，例如种子落点、破绽标记、傀儡计数 UI、蓄力层数。它们不造成伤害、不治疗、不控制敌人；主要强度必须来自接上的效果器和改造件。

**consumeKind 选择建议**：
- 高频 Proc（暴击、命中）→ 优先 `Stacks`，避免频繁浪费。
- 中频事件（受击、击杀、每 N 秒）→ 优先 `Single`，制造"等一个时机"的博弈感。
- 低频周期（长 CD、移动累计、阶段事件）→ 优先 `Window`，给玩家足够反应窗口。
- 辅助 / 光环 / 挂机 build → `Auto`，条件满足自动释放绑定技能，玩家 hands-free。

### 5.4 效果器分类 (Effect Types)

效果器定义**消费时多出来的东西**。V0.1.12 把 Effect 拆成两个明确子类，把 V0.1.11 的 Effect 词汇全部接住：

| 子类 | 语义 | 例子 |
|------|------|------|
| **增强型 (Enhancement)** | 改**这次按键的核心技能本身**的表现 | +120% 伤害、改火属性、单体→链锁、直线→环绕、最近→最远、瞬发→蓄力、释放时回血/护盾 |
| **附加型 (Add-on)** | 这次按键**额外放一个独立世界效果**，跟核心技能并行 | 附加范围爆炸、附加落雷、附加毒雾、附加召唤傀儡、附加突刺位移、附加眩晕 |

两者都在 Consume 时生效。区别只是：增强型改"这次核心技能打出去是什么样"，附加型是"核心技能打出去的同时，旁边再多放一个东西"。

**增强型 Effect 子类**：

| 子类 | 说明 | 示例 | 常用标签 |
|------|------|------|---------|
| **增伤倍率** | 乘到核心技能伤害上 | +120% 伤害、暴击伤害 +50% | Damage / Scaling |
| **改元素** | 覆盖或附加核心技能的元素与异常 | 改为火属性、附加寒冰减速、附加易伤 | Element / State / Debuff |
| **改形态** | 改变核心技能的覆盖方式 | 单体→链锁、直线→环绕、追加投射物、扇形→圆形 | Chain / Projectile / Area |
| **改目标** | 改变目标选择逻辑 | 最近→最远、单体→范围、前方→周围 | Targetable |
| **改节奏** | 改变核心技能的释放节奏 | 瞬发→蓄力、追加段数、追加后摇爆发 | Charge / Cooldown |
| **自益** | 消费时给玩家生存收益 | 释放时回血、附加护盾、短暂无敌 | Defense / Heal / Buff |
| **状态操作** | 消费时操作已有状态或资源 | 引爆种子、刷新层数、获得充能、刷新闪避 | State / Consume / Charge |

**附加型 Effect 子类**：

| 子类 | 说明 | 示例 | 常用标签 |
|------|------|------|---------|
| **附加伤害** | 在核心技能命中点/目标处 spawn 一个独立伤害效果 | 附加范围爆炸、附加落雷、附加冲击波 | Damage / Area / Burst |
| **附加场物** | 消费时 spawn 一个持续存在的单位或区域 | 附加召唤傀儡、附加炮台、附加毒池、附加陷阱 | Summon / Object / Area |
| **附加位移** | 消费时给玩家附加一次位移 | 附加突刺、附加闪现、附加拉拽敌人 | Mobility / Position |
| **附加控制** | 消费时在命中点附加独立控制效果 | 附加眩晕、附加击退、附加冰冻 | Control / Debuff |
| **附加 DoT** | 消费时在命中点附加持续伤害区域 | 附加毒雾、附加火墙、附加雷域 | DoT / Area |

**字段语义双轨**：`ChainConfig.damage` 在两种子类下含义不同——增强型 = `damageMult`（乘到核心技能伤害上，1.2 = +20%），附加型 = 附加效果自身的伤害（附加落雷打多少）。Effect SO 需声明 `effectRole`（Enhancement / Addon），装配 UI 据此显示"增强"或"附加"角标。

**设计边界**：
- 链不再当主伤害来源。纯召唤 / 纯位移 / 纯范围 DoT 流派以**核心技能**为主体（详见 5.12），链只做附加或增强。
- 一个 Effect 应当能用一句话说清"消费后这次按键多出了什么"。
- 增强型与附加型可在同一链中由改造件互相转换（如"附加落雷 → 增强为链锁落雷"），但单个 Effect SO 只能是其中一种角色。

### 5.5 改造件分类 (Modifier Types)

改造件是原"宝石 / 槽位修饰"的重定位。它们不作为独立系统出现，而是作为增强链的第三层，调整**加成的形态与强度**。

| 子类 | 作用 | 示例 | 兼容规则 |
|------|------|------|---------|
| **形态改造** | 改变加成覆盖方式 | 爆炸 → 火墙；附加范围 → 环形范围；落雷 → 雷域 | 需要 Area / Projectile / Object 标签 |
| **目标改造** | 改变加成的目标选择 | 单体加成 → 链锁加成；最近敌人 → 最远敌人；前方 → 环绕 | 需要 Targetable 或 Projectile 标签 |
| **数量改造** | 改变加成的次数或投射物数 | 额外触发 1 次加成；投射物 +2；附加爆炸 +1 | 需要可重复执行的效果 |
| **节奏改造** | 改变 Proc / Consume 的节奏 | Single → Window；Stacks 上限 +2；Proc 概率 +20% | 需要 consumeKind 字段 |
| **状态改造** | 附加元素、异常或状态交互 | 加成附带火焰、寒冰、雷击、毒蚀、击退、易伤 | 需要 Damage / Control / State 标签 |
| **槽位改造** | 根据模块相邻位置改变收益 | 左侧强化、右侧强化、双重投射、上下联动 | 属于环境型改造件，需要读取槽位布局和相邻模块标签 |
| **代价改造** | 用风险换强度 | 消耗生命提高加成；延长重新 Proc 换范围；降低防御换连锁 | 必须明确代价、上限和 UI 提示 |

**设计边界**：
- 改造件不提供独立长期成长，长期强化交给局外解锁的模块 / 解锁节点。
- 改造件不单独占用一个系统入口，统一在技能模块界面内配置。
- 改造件可以来自局内掉落、模块经验标签解锁、前哨改造或特殊事件。
- 如果一个改造件只能写成 `伤害 +10%`，它就不该成为改造件；至少要改变形态、目标、节奏或策略。
- 改造件分为**依附型**和**环境型**。依附型只读取被连接模块；环境型可以读取相邻模块或槽位布局，但必须在 UI 上高亮影响范围。

> **V0.1.12 实现状态**：已落地改造件 SO 清单（8 个）——`M_伤害强化`(DamageScale, 数量改造, 伤害×1.4) / `M_扩散`(RadiusScale, 形态改造, 范围×N) / `M_连锁`(CountScale, 数量改造, 投射发数×N) / `M_额外飞弹`(ExtraProjectile, 数量改造, +N 发) / `M_链锁弹射`(TargetChain, 目标改造, 命中后寻敌反弹 2 次，搜索半径 9、伤害衰减 0.8/跳、不重复命中) / `M_环绕射击`(TargetSurround, 目标改造, 360° 均分环绕发射，至少 8 发) / `M_余烬地带`(Sustained, 节奏改造, 落点持续地带 4s/0.5s tick/每 tick 35% 技能倍率 DoT + 附加状态) / `M_延迟轰爆`(DelayedBlast, 节奏改造, 落点 0.8s 预警延迟重爆 ×1.5 + 元素 + 附加状态)。**V0.1.13 补齐**：`TargetFarthest`（`M_远锁`：挂载且非环绕时核心投射技锁定 22m 内最远敌，否则保持鼠标瞄准，化解语义冲突）与 `ShapeWall/Ring/Zone`（`M_火墙`平行成墙 / `M_火环` 360° 外散 / `M_火域` 飞弹落点生成持续区域，程序化表现）已全部落地，形态/目标改造件不再有 no-op。

### 5.6 消费模型 (consumeKind)

V0.1.12 用 `consumeKind` 取代 V0.1.11 的"被动 / 主动执行模式"。**所有增强都由玩家按键消费**，区别只在"就绪后能消费几次、持续多久"。这是模块链属性，由触发器声明，装配 UI 直接标注。

| consumeKind | Proc 后表现 | 消费方式 | 重新 Proc 时机 | 适用 Trigger |
|------|-----------|---------|--------------|---------|
| **Single** | 增强就绪，图标冒火 | 下次按下对应技能生效 1 次 | 消费后重新累计 Proc 条件 | 受击、暴击、击杀、每 N 秒 |
| **Window** | 增强就绪，图标边框出现倒计时环 | 就绪后 N 秒内按下都生效（仅首次按下消费） | 窗口结束（无论是否消费）重新累计 | 长 CD 周期、移动 N 米后、阶段事件 |
| **Stacks** | 增强就绪，图标显示当前层数角标 | 每按一次对应技能消耗 1 层、附加 1 次加成 | 持续 Proc 累层至上限 M | 连击 N 次、命中累加、持续战斗 |
| **Auto** | Proc 即自动释放绑定的核心技能（带增强） | 无需按键，自动消费 | 自动消费后重新累计 Proc 条件 | 挂机 build、辅助光环、低频自动补刀 |

**规则**：
- Single / Window / Stacks 由玩家主动按键消费，战斗主导权在玩家手里。**Auto 是例外**——保留 V0.1.11"条件满足自动释放"的被动 build 原型，玩家放弃手动择时机换取 hands-free 操作。Auto 链增强的仍是绑定的核心技能（自动触发该技能的释放 + 增强注入），不是链独立放自己的效果。
- 一条增强链的 `consumeKind` 由其触发器声明，整条链共享；效果器与改造件可以读取该字段调整自身行为（如"仅在 Single 模式下 +50% 强度"）。
- Demo 阶段不开放局内自由切换 `consumeKind`，由设计表绑定到触发器，避免 UI 与数值复杂度失控。
- 装配 UI 必须在链卡片上明确标注 `[单发]` / `[窗口 5s]` / `[叠层 ×3]` / `[自动]`，零猜测。

> 历史：V0.1.11 的"被动模式（条件满足自动释放）"在 V0.1.12 中保留为 `Auto` consumeKind，作为可选的挂机 build 原型；其余三种 consumeKind 把消费权交还玩家按键，解决"装配即战斗"的方向性问题。

> **V0.1.12 实现状态**：四种 consumeKind 状态机全部落地——Single / Window / Stacks 由 `TriggerTracker` 实现累计→就绪→消费循环；Auto 由 `ModuleSlotManager` 自动触发回调 → `PlayerCombat` 自动释放绑定技能 + 增强注入。`windowSeconds` / `maxStacks` 字段已支持。`TriggerTracker` 暴露 `ThresholdProgress` 供 HUD 读取充能进度。**V0.1.13 补齐**：consumeKind 身份加成三角已接线——Single 增伤 ×1.25 / Window 增伤 ×1.10 + 范围 ×1.20 / Stacks 中性（收益在层数）/ Auto 增伤 ×0.80，同源系数作用于增强+附加字段，装配 UI 链预览显示「◇ XX 联动」提示。

### 5.7 模块配置字段规范

后续策划表中，每个模块至少需要配置以下字段：

| 字段 | 说明 |
|------|------|
| **ID / 名称** | 唯一 ID 和展示名 |
| **模块大类** | Trigger / Effect / Modifier / Universal |
| **子类** | 使用上文分类，例如战斗行为触发、增伤输出、目标改造；万能件声明双面子类 |
| **标签** | 用于兼容、掉落、推荐和局外解锁 |
| **稀有度** | Common / Rare / Epic / Legendary，用于掉落价值和强度预期 |
| **基础参数** | 伤害、范围、持续时间、层数、冷却、触发阈值等；万能件需分别声明触发面/效果面参数 |
| **effectRole**（仅效果器） | Enhancement（增强型，改核心技能）/ Addon（附加型，spawn 独立效果）；决定 `damage` 字段语义 |
| **damage 双语义** | 增强型 = 伤害倍率（1.2 = +20%）；附加型 = 附加效果自身伤害 |
| **consumeKind**（仅触发器） | Single / Window / Stacks / Auto；Window 需配 `windowSeconds`，Stacks 需配 `maxStacks` |
| **兼容条件** | 可连接哪些模块标签，不能连接哪些模块标签 |
| **掉落来源** | 普通房间、精英房、商店、事件、Boss、前哨补给 |
| **解锁条件** | 默认开放、经验值解锁、Boss 解锁、剧情解锁 |
| **解锁项** | 局外解锁该模块所需的条件（当前模块不可数值升级） |
| **UI 描述** | 玩家能直接看懂的一句话效果 |

### 5.8 插槽与组合逻辑 (Socket Logic)

每条增强链**挂在 Q/E/R 三个核心技能槽位之一**。基础规则只允许一条清晰的模块链：

```text
[核心技能槽位] ← 挂载 ← [触发器 Trigger] → [效果器 Effect] → [改造件 Modifier 0-2 个]
```

| 连接方式 | 规则 | 是否属于基础规则 |
|---------|------|----------------|
| **链 ↔ 技能绑定** | 一条增强链挂在一个核心技能槽位；一个技能最多挂一条链 | 是 |
| **主链连接** | 1 个触发器连接 1 个效果器，形成可消费的增强 | 是 |
| **改造连接** | 0-2 个改造件依附在触发器或效果器上，改变加成行为 | 是 |
| **环境读取** | 环境型改造件读取相邻模块标签或槽位位置 | 是，但仅限明确标注的改造件 |
| **万能件占位** | 万能件可放入触发器槽或效果器槽，承担对应槽位职责 | 是 |
| **裸技能** | 未挂链的核心技能槽位仍可释放裸技能，无加成 | 是 |

普通增强链只产生模块描述中的基础加成。

> **V0.1.12 实现状态**：`ModuleSlotManager.EquipChain` 接受部分链（仅触发器 / 仅效果器）并持久化，但 `_hasChain[slot]` 与 `_trackers[slot]` 仅在链 `IsValid` 时才置真。允许装配 UI 显示「待补」状态，避免测试中误丢模块。

### 5.9 局内重组（自由拼装）

增强链上的每个模块都可在**非战斗状态下随时重组**，无需任何代价：

| 操作 | 规则 |
|------|------|
| **取出 / 替换** | 链上任意模块可取出到背包，空槽可放入任意同类模块（万能件可放入触发器或效果器槽） |
| **链 ↔ 技能换绑** | 整条链可从一个核心技能槽位换挂到另一个；一个技能最多挂一条链 |
| **丢弃** | 模块可扔到地上，作为可拾取场物保留，玩家可随时走过去捡回 |
| **时机限制** | 仅非战斗状态（含休息房）可重组；进入战斗后链锁定，避免战斗中临时换链破坏节奏 |
| **槽位约束** | 替换仍需满足槽位职责：触发器槽只接受触发器或万能件，效果器槽只接受效果器或万能件 |

> 设计意图：拼错零惩罚。玩家可大胆尝试任意增强组合，不满意的随时换、随时扔、随时捡回，鼓励自由探索而非保守取舍。

> **V0.1.12 实现状态**：`ModuleAssemblyUI` 已重做——卡片网格背包 + Q/E/R 三列竖向链布局；含全息预览、人类可读链效果预览、安装 toast（链激活 / 还差 X 成链）、三态配色（已激活 / 待补 / 空）、拖拽安装/卸载、明确「安装/卸载」提示；`GetBoundCoreSkillName` 显示链当前绑定的核心技能。`Demo1Setup` 保证开局 Q/E/R 三个核心技能无空窗（未配置则从 `Data/Skills` 兜底挑选）。**V0.1.13 补齐**：模块占位图标改为按子类单字字形 + 元素/类别配色兜底（仍非真图美术，但已有辨识度）；起始模板系统已实现——`StartTemplate` SO + `StartTemplateSelectUI`（UITK，主菜单「开始」弹出）+ 3 默认模板（近战爆发/元素范围/投射连锁），选中重装 3 技能 + 应用档案 + 发起手模块，取代旧化身开局差异化。

### 5.10 万能件 (Universal Module)

万能件是第四类模块，没有固定职责，**放入哪个槽就承担哪个槽的职责**，是自由拼装的核心扩展件。

**核心规则**：

| 规则 | 说明 |
|------|------|
| **槽位决定职责** | 放入触发器槽 → 当触发器（只提供 Proc 条件/状态载体，不含主要伤害）；放入效果器槽 → 当效果器（定义消费时附加的增伤/元素/控制等结果） |
| **双面配置** | 同一万能件内部同时声明"作为触发器时如何"与"作为效果器时如何"两段描述，只有匹配当前槽位的那段生效 |
| **职责守恒** | 当触发器时仍遵守 5.2/5.3 触发器边界（不负责主要伤害），当效果器时遵守 5.4 效果器边界；槽位裁剪其可用能力，不破坏现有分类规则 |
| **稀有度** | 因双面配置更灵活，默认偏高稀有度（Rare 起），避免开局满手万能件削弱流派感 |
| **不可改造件槽** | 万能件只能放入触发器槽或效果器槽，不能放入改造件槽 |

**例子**：
- 万能件"种子/引爆"放入触发器槽 → 当"种子生成"触发器，只显示种子落点、不造成伤害。
- 同一件放入效果器槽 → 当"种子引爆"效果器，消费时引爆种子状态造成伤害收割。
- 一条链 `万能件(当触发器: 闪避后·Window 5s) → 万能件(当效果器: 改为火属性)` 挂在「突刺」上 = 闪避后 5 秒内按下突刺附带火属性，整条链完全由万能件组成。

**设计边界**：万能件提供的是"同一件多用途"的便利与组合弹性，不应当作数值更强的双料件；当两个位置的能力不应同时生效。

### 5.11 操作模型

```
【近战普攻】—— 鼠标左键，三段连招
  → 三段连招：Attack1 → Attack2 → Attack3
  → 段伤害倍率：1.0 / 1.2 / 1.5
  → 基础动作时长：0.4s / 0.4s / 0.5s
  → 攻速加成上限：150%
  → 扇形判定：半径 2.5，角度 120°
  → 攻击中"霸体"：轻击受击不打断连招
  → 250ms 输入缓冲：流畅连段
  → 每段带前冲 Lunge 位移

【核心技能 × 增强链】—— Q / E / R 三个槽位
  → 每个槽位装一个核心技能（起始固定 3 个，关卡内可替换）
  → 每个槽位最多挂一条增强链：[触发器] + [效果器] + [改造件 0-2]
  → 战斗中走位/攻击/受击让某条链上膛（Proc），对应技能图标冒火
  → 玩家按下该技能消费增强（Consume），技能附带加成释放
  → 裸技能（无链）也可正常释放，无加成
  → 一个技能最多一条链；不同技能链互不干扰

【闪避】—— Space 键
  → 距离 5 单位，持续 0.2s
  → 无敌帧共 0.3s：闪避前摇 0.05s + 闪避持续 0.2s + 收尾 0.05s
  → 2 层充能，每层 CD 1.5s；模块可临时提高到最多 4 层
```

### 5.12 核心技能 (Core Skill)

核心技能是玩家**主动按键释放**的招式，是战斗的主导层。模块增强链挂在核心技能上做加成（详见 5.1）。

| 维度 | 规则 |
|------|------|
| **槽位** | Q / E / R 三个核心技能槽位 |
| **起始配置** | 测试版开局固定给 3 个核心技能（保证无空窗、即开即玩） |
| **关卡内获取** | 通过 SkillPickup 拾取新核心技能，可**替换**某个槽位的现有技能；旧技能丢弃到地上可捡回 |
| **链绑定** | 每个核心技能槽位最多挂一条增强链；换技能时链可保留或一并卸下到背包 |
| **裸技能** | 未挂链的核心技能可正常释放，仅无加成 |
| **核心字段** | 伤害倍率、动作时长、动画、目标选择基础规则（最近敌人 / 自身 / 方向锥等）、冷却 |

**核心技能池需覆盖 Build 原型**：V0.1.12 链永远依附一次核心技能按键，纯召唤 / 纯位移 / 纯范围 DoT 流派不再以链为主体，必须由对应的核心技能承载。起始 3 个 + 关卡内 SkillPickup 池应共同覆盖以下原型，避免某些 build 路线无核心技能可挂：

| Build 原型 | 对应核心技能示例 |
|------|---------|
| 直伤近战 | 剑气、横扫、突刺 |
| 直伤远程 | 落雷、火球、箭雨 |
| 范围 DoT | 毒雾、火墙、雷域 |
| 召唤 | 召唤傀儡、炮台部署 |
| 位移 | 闪现突进、拉拽牵引 |
| 控制 | 重击眩晕、冰冻震击 |
| 自益 | 治疗祷言、护盾姿态 |

每个原型至少 1 个核心技能可选；关卡内 SkillPickup 池按层数解锁更高级原型技能。

**核心技能 vs 增强链 的职责切分**：
- 核心技能决定"我按下 Q 大致会发生什么"（一个完整的招式：动画 + 基础伤害 + 基础目标选择）。
- 增强链决定"这次按键比平时多出了什么"（增伤倍率、附加效果、形态扩展）。
- 核心技能不依赖增强链存在；增强链离开核心技能无意义。

> **V0.1.12 实现状态（核心技能实现字段）**：
> - **增益类（`SkillType.Buff`）**：`CastBuffSkill` 泛化，由 `SkillData` 的 `buffDuration` / `buffAttackSpeedPct` / `buffMoveSpeedPct` / `buffAttackPct` / `buffDamageReduction` 字段组装 `StatusEffect` 经 `StatusEffectController` 应用；字段全空时兜底减伤 +50%（保旧金钟罩行为）。含特殊分支：`armLethalGuard`（受致命伤拦截）/ `heavenEarthShift`（乾坤倒转·伤害反弹 + 攻击转治疗）。
> - **区域类（`SkillType.Zone`）**：`ActiveSkillZone` 通用组件支持 周期伤害 / 减速 / 黑洞吸引 / 灼烧 / 随玩家移动；`SkillData` 区域字段 `zoneDuration` / `zoneRadius` / `zoneTickInterval` / `zoneDamagePerTick` / `zoneSlowPct` / `zonePullSpeed` / `zoneFollowPlayer` / `zoneBurnDPS`；`CastZoneSkill` 调度接入（落点 / 随身二选一）。
> - **其他已支持 `SkillType`**：`Melee` / `AreaDamage` / `Projectile` / `Dash` / `Summon` / `Charge`。
> - **配表基础设施**：`Skill_Base_Config.csv` + `ConfigDatabase.GetSkillBase` + `SkillTuning.EffectiveCooldown` / `EffectiveBaseDamage`，按 `SkillData.configId` 查表覆盖 CD / 伤害；规则 = 对 SO 基础伤害的百分比乘区，与 UpgradeRoom 升级共存、不写回 SO。
> - **已实现核心技能 SO 清单**（东方奇幻命名风格保留，非修仙概念残留）：御剑术 / 落石术 / 九天玄火阵 / 傀儡术 / 影步 / 烈焰掌 / 寒冰诀 / 天雷引 / 回春术 / 雷锁链 / 镜花水月 / 混沌吞噬 / 天罡北斗阵 / 冥河召唤 / 轮回一击 / 水镜术 / 土遁术 / 寒冰封印 / 金钟罩 / 等约 20+ 个。当前 Q/E/R 起始固定为 落石术 / 九天玄火阵 / 傀儡术（详见 §5.9 装配 UI 的 `Demo1Setup` 兜底逻辑）。
> - **核心技能掉落**：`SkillPickup.Spawn` 单一出口（覆盖杀怪 / 宝箱 / 商店 / 战斗奖励所有来源），无化身门控（化身系统已退出，任何角色都能拾取任何核心技能）；可拾取后替换某槽位现有技能，旧技能丢弃到地上可捡回。

> **V0.1.12 实现状态（增强注入实现路径）**：核心入口 `PlayerCombat.HandleSkills` 统一为核心技能按键 → Proc 则 `BeginEnhancement(slot)` → `UseSkill()` → `EndEnhancement()`，普通 / 蓄力 / Auto 三路径接入。
> - `BeginEnhancement` 从 `ChainConfig` 读 `effectRole`/`enhanceDamageMult`/`enhanceRadiusMult`/`enhanceProjectileMult`/`enhanceExtraProjectiles`/`enhanceChainCount`/`enhanceSurround`/`enhanceSustained`/`enhanceDelayedBlast` 填入玩家瞬态字段。
> - `EndEnhancement`：增强型走自益（治疗/护盾/无敌/净化，复用 `ExecuteChainHeal/Shield/Invincible` + `StatusEffectController.ClearDebuffs`）+ 控制/状态作用到 `_enhHitTargets`；附加型走 `ExecuteChainEffect` spawn 独立世界效果。`_enhWorldDelegated` 标记避免与投射物命中/区域 tick 重复施加。
> - 投射物 payload：`Projectile.SetEnhancement(cfg)` + `SetChain(count, mask)`；对象池复用时 `Initialize` 重置 payload；命中时施加控制/状态 + 链锁寻敌反弹。
> - 持续区域 payload：`ActiveSkillZone.SetEnhancement(cfg, elementOverride, radiusMult)`；每 tick `SkillModifierApplier.ApplyEnhancementStatus`；`SpawnCustom(...)` 重载供 Sustained 改造使用。
> - 延迟重爆 payload：新增 `DelayedAreaBlast` 组件（预警 0.8s → 范围伤害 ×1.5 + 元素表现 + 附加状态）。
> - 共享真源：`SkillModifierApplier.ApplyEnhancementToEnemy()` / `ApplyEnhancementStatus()` 被 PlayerCombat / Projectile / ActiveSkillZone / DelayedAreaBlast 共用，消除重复。
> - 元素覆盖：链有元素（效果自带或 灼烧→火/冰冻→冰/雷→雷/毒→土）时覆盖核心技能本次命中元素（`EnhElem(skill)` helper）。

### 5.13 增强就绪视觉标识 (Proc VFX)

Proc → Consume 模型要求玩家**清晰感知"现在哪个技能可以爆了"**。视觉标识是这个模型的必要锚点，不是装饰。

**主指示器：角色旁三竖条（最小可玩版本核心）**

| 维度 | 规则 |
|------|------|
| **位置** | 角色右侧（或头顶）浮空，World Space Canvas，billboard 始终面向摄像机 |
| **结构** | 3 个竖条并排，左→右对应 Q / E / R；每条底部一个小字键名（Q/E/R） |
| **实现** | 1 个 World Space Canvas + 3 个 Image（Filled vertical）+ 3 个 Text；订阅 `ModuleChainChanged` 事件刷新；按 Effect 元素配色（火=橙红 / 雷=蓝白 / 冰=青 / 范围=黄 / 控制=紫） |

**状态映射**：

| 状态 | 表现 |
|------|------|
| 无链 / 未 Proc | 竖条暗灰 |
| `Single` 就绪 | 整条亮起，Effect 元素色，呼吸光（sin 驱动 alpha） |
| `Window` 就绪 | 整条亮起，填充从满到空随窗口倒计时下沉 |
| `Stacks` | 竖条按层数比例分段填充（1/M、2/M…M/M），每层一段 |
| `Auto` 触发 | 整条闪亮一次后熄灭（表示自动消费了） |
| 消费后 | 回到暗灰 |

**优点**：余光可一眼看出"哪个技能可以爆了"、三条同时可见信息密度高、按 Effect 元素配色统一认知、实现成本低。

**HUD 图标层（可选补充）**：技能图标在 HUD 上同步显示就绪状态（边框变色 / 角标 / 倒计时环 / 层数），供玩家需要精确查看时使用。如果与三竖条重复信息过多，Demo 阶段可只做三竖条、砍掉 HUD 图标变色以减少 UI 噪音。

**消费爆发层**（后续版本，最小可玩不做）：按下消费瞬间，对应竖条爆闪 + 角色身上特效一闪 + 屏幕轻微震动，作为爽点收尾。

**装配 UI 联动**：装配台预览链时，应静态展示该链 Proc 就绪后的三竖条样式（变色 + 填充），让玩家"装配时就知道战斗里会看到什么"。

> **V0.1.12 实现状态**：`ProcBarsHUD` 已落地——屏幕空间 overlay 跟随角色，按 Q/E/R 显示三竖条；状态映射实现无链/未 Proc（暗灰）、Single 就绪（元素色 + 呼吸光）、Window 就绪（填充随窗口倒计时下沉）、Stacks（按层数比例分段填充）、Auto 触发（闪亮一次后熄灭）、消费后（回暗灰）；元素配色 火=橙红 / 雷=蓝白 / 冰=青 / 范围=黄 / 控制=紫；由 `Demo1Setup.CreateHUD` 挂到 GameCanvas。**V0.1.13 补齐**：消费爆发层已实现——`PlayConsumeBurst` 在任意 Proc 被消费瞬间（Enhancement/Addon 皆触发）产生元素色爆闪点光 + 特效环 + 按 consumeKind 分级震屏（Single/Window 中震、Stacks/Auto 轻震），程序化零美术。

## 6. 局内协同（预留）

本版**暂不设独立的隐藏组合系统**。原"隐藏组合/Synergy"机制已移除，相关质变效果后续可通过以下途径承载（具体设计待定）：

- **特殊道具**：触发并升级某些特定模块组合。
- **装备系统**：通过装备的特殊机制产生组合质变。

普通模块链只产生模块描述中的基础效果，不再有"满足额外条件产生质变"的隐藏层规则。后续如恢复协同系统，再单列章节。

## 7. 关卡设计

### 7.1 房间类型

| 房间 | 作用 | 主要产出 |
|------|------|---------|
| **普通战斗房** | 基础战斗、模块掉落与材料采集 | 普通模块、经验值、可带出材料 |
| **精英房** | 强于小怪、略弱于 Boss 的高风险高收益挑战 | 高稀有度模块、精英材料、Boss 来源标签经验 |
| **事件房** | 提供取舍、代价、特殊模块线索 | 特殊模块、情报标签经验 |
| **商店房** | 消耗局内货币换模块或治疗 | 指定模块、回血、刷新机会 |
| **休息房（后续）** | 低压恢复和调整 Build | 最小完整体验不生成，后续按续航压力决定是否恢复 |
| **Boss 房** | 标准通关目标；击败后生成最终出口 | 高倍率结算、Boss 标签经验、剧情推进 |

### 7.2 层级结构

> **最小完整体验目标（2026-08-17 修订，部分实现）**：首个验证关卡为 **关卡 A：无暮王城**，采用同一“12 个核心房 + 1 个断桥后可选支路房”的白昼 / 永夜双阶段结构。首阶段完成后可直接进入反转状态，也可先返回基地并于下次从反转阶段继续；首测验证区域探索、材料刷取、事件即时反馈、最多两个阶段结果延续和双阶段 Boss 结算。关键建筑在布局模板的局部坐标中保持稳定关系，整张地图允许整体旋转；出生房与房内落点在安全候选集合中相对随机。

关卡 A 分为三个空间层级：

| 分区 | 定位 | 固定内容 |
|------|------|----------|
| **外环牢区** | 牢房、仓库、刑具房等外围区域；战斗空间相对开阔 | 外环 Boss 候选房、外环故事槽、多个降落候选点 |
| **连接区** | 铁闸、城门、地下通道与捷径，承担内外区过渡 | 至少一条必通路线、可变化的门与捷径 |
| **内环祭殿** | 祭坛、墓室与藏书区等高风险区域 | 内环 Boss 候选房、内环故事槽、多个降落候选点 |

#### 7.2.1 首版每局房间构成（冻结）

关卡 A 最小完整体验每局固定生成 **12 个主体房间**，走廊和门厅连接件不计入房间数。玩法房型与空间 Prefab 不一一绑定：同一个空间布局可以在一局中重复出现，也可按本局注入结果成为普通战斗、精英或事件房；玩家定位依赖宏观拓扑和连接关系，而不是要求每个房间都有唯一外形。

| 分区 | 基础普通战斗 | 精英 | 事件 | 商店 | Boss 候选 | 小计 |
|------|-------------:|-----:|-----:|-----:|----------:|-----:|
| **外环牢区** | 2 | 1 | 1 | 0 | 1 | 5 |
| **连接区** | 1 | 0 | 0 | 1 | 0 | 2 |
| **内环祭殿** | 2 | 1 | 1 | 0 | 1 | 5 |
| **生成配额** | **5** | **2** | **2** | **1** | **2 选 1** | **12** |

每局只激活一个 Boss 候选建筑；出生区从外环或内环随机决定，再把该区距离连接区商店最远的普通房叠加为 `Landing` 角色。未激活的同区 Boss 候选房转为普通地标房，不承担出生职责。运行时实际构成为 **普通 / 降落 6 / 精英 2 / 事件 2 / 商店 1 / Boss 1 = 12**。

- 首测外环固定从 `O4`、内环固定从 `I3` 降落，保证商店不是出生后紧邻内容；随机性保留在出生区、房内 2～4 个安全 `PlayerSpawn` 和整图四档旋转。后续增加降落候选时，同样必须先满足到商店的最小图距离。
- Boss 位于出生区对侧：外环出生激活内环 Boss A，内环出生激活外环 Boss B；击败当前 Boss 后才生成或启用其房内的最终 `ExitPortal`。
- 休息房、军械库与装备 A 固定来源不进入最小完整体验。
- 材料直接注入 6 个普通战斗房的 `Material` 内容槽，不新增材料房。每个普通房清场后固定出现 2 个按 Encounter Seed 选材的采集点，同房回访不重复生成；普通怪 8%、精英 40% 和 Boss 固定掉落继续作为额外奖励，不替代房间采集来源。
- 12 个核心房仍是主路节奏基线；第 13 个 `B0`“巡礼封藏室”随地图开局一同生成，但默认由断桥阻断，只作为 1004 Layout 事件解锁的可选探索收益，不计入标准 Boss 必经路线。

1. 普通主体房提供 2～4 个 Edgar `Doorway`；Boss 候选房提供 1～2 个，避免关键房成为无意义交通枢纽。
2. 可作为降落候选的普通房提供 2～4 个 `PlayerSpawn`；实际出生点从安全候选中抽取，并与怪物刷新范围保持至少 5m 距离，不得正对远程敌人无遮挡射线。
3. 小怪主落位使用可调体积范围而非大量固定点：每个主体房至少设置中央近战区、后场远程区和侧翼法术区，分别声明分类、权重、区域容量、玩家安全距离和怪物间距；离散 `EnemySpawn` 只作为范围采样失败时的兼容回退。
4. 所有主体房至少保留一块无遮挡战斗核心区；装饰、柱体与刑具不得封死 Doorway 到核心区的导航。
5. 外环使用牢狱、仓储和刑具语汇；连接区突出铁闸、地下通道和高差；内环使用祭坛、墓室和藏书语汇。仅换装饰不算新增空间模板。
6. 每个模板必须通过 Edgar Grid3D 房间诊断、Doorway 朝向检查、碰撞检查和实际 PlayMode 进出房验证后，才能进入正式模板池。
7. 空间模板必须优先表达“主路 / 上侧支路 / 下侧支路 / 端点 / 连接区”等布局关系；相同模板允许复用，不要求为每个节点制作唯一房间。

**精英怪战斗定位**：

- 精英怪不是强化版普通小怪，而是拥有独立战斗节奏的重型敌人：单体强度明显高于小怪，玩家不能沿用清杂方式快速处理。
- 精英怪的伤害压力与关键招式接近 Boss，但综合强度略低于 Boss；主要差距来自耐久更低、机制更少、没有完整多阶段流程，也不承担最终出口门槛。
- 单场精英战聚焦 `1 个核心机制 + 1 个辅助机制`，允许少量小怪协同，但不能用大量杂兵堆出伪难度。
- 精英房位于可绕行支路，不要求通关必杀；玩家一旦主动触发战斗，房间按战斗规则封锁，击败后才领取对应高价值奖励。
- 精英战应让成型中的 Build 承受明显压力，但不应消耗到玩家必须依赖固定恢复房才能继续挑战 Boss。
- 精英默认拥有受控闪避：登场 3 秒内不闪；只在近战起手、危险技能、投射物正面来袭或 1 秒内连续受击后检查；基础触发率 40%，冷却随机 6～8 秒，连续错过 2 次或 10 秒未闪后的下一次有效威胁保底触发。
- 闪避位移约 2.75m / 0.3s，中段提供约 0.15s 无敌窗，结束后至少 0.25s 不可无预警反击。方向优先左右、其次斜后与正后；落点必须通过胶囊路径和地面检查，禁止穿墙、闪出地板或向玩家正面贴近。

**敌群协同与技能决策规则**：

- 近战敌人只在远距离直接追踪目标；进入约 2.2 倍攻击距离后改为短时观察、停顿或带少量前压的自由侧移，不使用固定环形槽位，也不持续黏着玩家位置。
- 同一目标默认最多允许 3 名近战敌人同时进入攻击预警。未取得攻击名额的敌人继续侧移，攻击完成或受击打断时立即归还名额。
- 普通近战完成攻击后短暂后撤再重新寻找窗口，形成“接近—出手—让位”的节奏。Edgar 完成整图旋转与 5 倍缩放后按房间/走廊 Collider 构建运行时 NavMesh；六类敌人的追击、后撤和战术侧移均向导航目标移动，无法投射到导航面时停步告警，不再回退为直线穿墙。
- 实机节奏以“移动可停、攻击不断”为准：近战攻击冷却约 1 秒、精英/Boss 近战约 0.9 秒，普通近战最多 3 名同时预警；远程、法师与冲锋的基础间隔分别约 2.0 / 2.8 / 3.2 秒。观察停顿不得额外阻塞已就绪攻击。
- Boss 与精英的技能释放条件统一使用 `EnemyAbilityProfile`：每项能力可声明优先级、随机率、初始延迟、冷却、次数上限、距离、生命区间、战斗阶段、昼夜、附近友军数量及所需 / 禁止 Boss Flag。
- 条件选择器只回答“当前应释放哪项能力”，具体动作由 Boss / 精英自己的执行器完成。后续新增专属技能时扩展动作执行，不复制冷却、阶段和 Flag 判断；技能未配置时保留当前行为作为兼容回退。
- 精英的首个核心机制为“闪避反击”：成功完成受控闪避后储存一次反击，在恢复窗结束且目标位于 1～8m 时以 0.55 秒青色直线预警发动突进斩；反击有独立 6 秒冷却，命中使用技能倍率，未触发闪避则不可直接释放。
- 白昼 Boss P2 最终技能“冠光裁决”：预警三条固定扇形光路后同时结算；摧毁冠光仪会禁用该技能，偏转镜组使光路按 Boss 朝向发射而不再追踪玩家。永夜 Boss P2 最终技能“狱链封步”：在玩家脚下预警可逃离区域，未及时离开者受到伤害、3.5 秒减速并被实体狱链环暂时封锁。

**Boss、阶段推进与撤离规则**：

- 外环与内环各预留一个 Boss 候选房，每局只激活出生区对侧的一个。
- 外环出生激活内环 Boss A；内环出生激活外环 Boss B，保证结算目标与降落点之间有完整探索距离。
- 出生区同侧的 Boss 候选建筑转为普通地标房；安全降落房从该区普通候选房中独立抽取，离开降落房后才进入正常战斗节奏。
- 白昼 Boss 被击败后完成第一阶段，并在 Boss 房生成阶段出口。玩家可选择直接进入永夜，保留当前 Build 与携带物继续挑战；也可先返回基地安全结算，王城状态保存为永夜，下次从永夜阶段重新构筑进入。
- 无论直接追入还是经基地再次进入，永夜都从原出生区的安全降落端重新落地，不从白昼 Boss 房原地续跑；地图仍复用同一生成 Seed、出生区、Boss 节点与整图旋转。
- 玩家在永夜阶段死亡或主动返回时，王城继续停留在永夜，不要求重打已完成的白昼阶段；永夜 Boss 被击败后才视为关卡 A 完整通关，并开启前往后续关卡的最终出口。
- 永夜完整通关后，本轮待落位结果与回顾清除，关卡 A 的重复挑战状态重置为白昼，并重新抽取下一循环的降落点与地图 Seed。
- 白昼阶段完成时提交本阶段事件结果；地图反转成功后在永夜落位，阶段结果在永夜通关后清除。不得因打开选关界面、预览传送门或生成失败而提前消费。
- 关卡允许存在不击败 Boss 的离开方式，但统一归类为“主动撤离 / 特殊撤离”，不算通关、不发放 Boss 击杀奖励，也不推进要求击败 Boss 的故事条件。
- 非 Boss 撤离口只能来自明确的固定规则、稀有事件或故事模板，生成时必须在 `Story Manifest` 中说明条件；普通随机捷径、开门事件和地图断路修复不得顺带生成免费撤离口。
- 主动撤离与第一阶段返回沿用“阶段返回”结算档位；可带出材料比例仍由经济章节后续确认。只有永夜 Boss 后的最终出口沿用“通关”结算档位。
- 首测 Boss A/B 使用共享材料掉落，避免随机出生区阻碍定向刷取；专属掉落与 Boss 定向选择后续再评审。

### 7.3 难度递增

- 敌人生命、伤害、数量随本局推进深度、已完成区域与故事模板阶段递增，不再只依赖固定层数。
- 难度增长应主要来自行为变化，而不是单纯数值膨胀。

### 7.4 自适应怪物生态（反制系统）

怪物会根据玩家的 Build 进化出对抗机制，使"自适应怪物生态"从卖点落到具体规则。核心是不让玩家一套 Build 通关到底，但也不让 Build 直接报废。

**反制判定**：系统读取玩家当前已装配模块的标签（伤害来源、形态、节奏），从反制池中挑选匹配机制投放，随层数提高反制强度与频率。

| 玩家 Build 特征 | 可能投放的反制机制 |
|----------------|------------------|
| 远程 / 投射物为主 | 自动闪避投射物、投射物偏转、近身冲锋 |
| 召唤 / 场物为主 | 范围清场技能、对召唤物的溅射、召唤物上限削减 |
| 持续伤害 / DoT 为主 | 高频净化、移除状态、护盾抗持续伤害 |
| 高爆发 / 蓄力 | 打断施法、压制窗口、强制位移打断节奏 |
| 依赖触发条件（闪避/受击） | 反触发：骗触发后反制、降低有效触发次数 |

**三条设计边界**（防止反制把玩家逼死）：

1. **反制不等于免疫**：反制机制压制某类 Build 的效率（如降低命中、削减收益），但**不免疫**该伤害类型——玩家的核心输出仍能打掉血，只是更费力。绝不出现"纯远程 build 对某怪 0 伤害"的情况。
2. **反制有预告与窗口**：反制机制通过怪物行为预告（如蓄力姿态、特效），玩家可主动规避或换策略，而非隐形惩罚。
3. **反反制手段**：玩家可通过**局内重组换链**（5.9）调整 Build、或在掉落中获取针对性改造件 / 万能件应对；不要求玩家带"全 Build"以防被反制，鼓励动态调整而非预先堆抗性。

**投放节奏**：
- 普通房：偶发轻反制，提示玩家 Build 有盲区。
- 精英 / Boss：定向反制玩家主输出标签，但保留可被换链破解的弱点。
- Boss 阶段切换时可更换反制机制，考验玩家是否能在阶段间快速重组。

> 设计目标：让"自适应怪物"成为推动玩家**用自由拼装动态应对**的压力源，而不是惩罚特定流派的墙。反制的存在恰恰凸显 5.9 局内重组的价值。

### 7.5 关卡 A 的固定与随机边界

设计原则不是隐藏所有复用，而是让玩家「能记住区域，不容易背出本局路线」。

| 固定内容 | 随机内容 |
|----------|----------|
| 布局局部坐标：外环—连接区—内环及关键建筑关系 | 整体世界朝向与各区普通房的局部连接 |
| 外环 / 内环各有一个 Boss 候选房 | 本局按出生区激活哪一个对侧 Boss |
| 商店、Boss 候选建筑、事件支路与精英支路的相对方向 | 出生区、该区降落候选房与房内 `PlayerSpawn` |
| 至少一条内外区可通路线 | 铁闸、地下通道与捷径的开启状态 |
| 各分区的美术主题和经典地标 | 普通房连接、敌群、事件、材料点和装饰 |
| Boss 的共享材料奖励主题 | 普通模块品质、局内临时奖励与遭遇组合 |

**关键建筑相对关系（布局局部坐标固定）**：

- 布局模板先建立自己的局部坐标系；例如模板规定“地标 A 在地标 B 左侧”，该关系在任何 Seed 中都不能反转。
- 整张地图允许绕世界 Y 轴整体旋转；A、B 与所有房间一起旋转，因此世界坐标中的东南西北可以改变，但布局局部坐标中的 A/B 关系保持不变。
- 外环 Boss 候选建筑保持在局部外环远侧，内环 Boss 候选建筑保持在局部内环远侧；商店保持在两区之间的连接区。
- 事件房总体位于各城区局部主轴上侧，精英房总体位于局部下侧；允许随 Seed 小幅偏移、改变距离或前后次序，但不得跨区或互换相对侧。
- 关键建筑之间约束的是布局局部坐标中的“左 / 中 / 右、上 / 下、近 / 远”，不要求锁死到唯一世界坐标。
- 出生区先随机，再在该区普通房候选集合中选择降落房与房内 `PlayerSpawn`；出生位置不得替代关键建筑，也不得让 Boss 与出生点直邻。
- 随机性主要来自降落位置、普通房连接、局部门状态、单房旋转、敌群、事件具体内容、材料点和装饰。

**仅靠布局的空间定位目标**：

- 暂不依赖美术主题、贴图、灯光或文字路牌，玩家应能通过关键建筑之间的关系判断自己处于外环、连接区还是内环，并知道自己在主路、事件侧支路、精英侧支路或关键建筑附近。
- 定位依据按优先级为：`关键建筑相对关系 → 与商店 / Boss 建筑的图距离 → 支路侧向 → 房间连接数量与来路方向 → 局部高差或环路`。
- 玩家不必仅凭房间外形识别精确节点编号；最低要求是能回答“我在哪个区域、Boss 在哪一侧、回连接区该往哪走、这是事件支路还是精英支路”。
- 同一种空间布局允许在地图中出现多次。若两个重复房间拥有相同门数和形状，生成器必须通过其前后连接、支路方向或与固定锚点的距离形成不同语境，避免出现完全对称且无法判断方向的镜像段。
- 商店、两处 Boss 候选建筑、事件侧支路和精英侧支路是结构锚点；即使整图旋转或复用普通房模板，这些锚点在布局局部坐标中的关系也不得因 Seed 颠倒。

**旋转与镜像边界**：

- 优先随机普通房连接、单 Boss 激活结果与事件注入。
- 单个房间可按 Socket 约束使用 `0 / 90 / 180 / 270°` 旋转。
- 整张地图可按布局根节点绕 Y 轴整体旋转，首测使用 `0 / 90 / 180 / 270°`；整体镜像会反转地标左右关系，默认禁止。
- 带有文字、方向性机关或不对称叙事的单房模块同样禁止镜像。

### 7.6 布局模板、故事模板与事件影响分类

地图空间和故事内容必须拆成两套正交模板，避免每新增一组故事就复制一整张地图。

**布局模板（Layout Template）**负责：

- 外环、连接区、内环的宏观拓扑。
- 房间模块池、Doorway / Socket 兼容与候选连接。
- 降落候选点、两个 Boss 候选点、事件槽与捷径槽。
- 主路径长度、支路数量、最小图距离和旋转约束。

**故事模板（Story Template）**负责：

- 本局出生区对应的单 Boss ID。
- 必选故事事件、随机事件池、Boss 对白和阶段变化。
- 铁闸 / 机关的叙事状态与奖励主题。
- 与布局模块的兼容标签，例如 `Prison / Ritual / Undead`。

布局模板与故事模板按兼容标签组合。目标是以少量布局模板和多组故事模板形成交叉变化，而不是为每个故事模板制作一张独立地图。

**首版概略设定**：

- `Layout_A_双区主轴`：当前为 12 个核心房加 1 个可选封藏室。固定外环—连接区—内环主轴，`C0` 为中央商店，`O1/I1` 为事件房，`O3/I2` 为精英支路，`O0/I4` 为两端 Boss 候选建筑，`O4/I3` 为远距降落候选；`B0` 固定连接在 `O1` 断桥之后。允许 Edgar 改变具体走廊形状、房间间距和四档整体旋转，但禁止镜像及关键建筑换侧。
- `Layout_B_中央辐射`：以四门中庭为核心，把事件、精英、连接区和 Boss 纵深分散到不同辐射支路，强调完成长支路后返回中庭。
- `Layout_C_大环寻宝`：基础实体图保持可稳定求解的树结构，在外环 `O2` 与内城中庭 `I0` 之间配置仅本 Layout 生效的双向受控通道，形成探索回环；待异形房和专用闭环连接模板扩充后，再评估替换为实体走廊闭环。
- `Layout_D_商店必经`：`C0` 位于降落端与对侧 Boss 的唯一主路上，玩家进入内城纵深前必经商店；事件与封藏室组成短支路。
- 四套 Layout 均保留稳定的玩法语义节点，但具体连边、图深度与枢纽位置不同；四图等权进入当局随机池。`C0 ↔ C1` 为首批可伸缩边，有 38% 概率插入 1 个无战斗连接房，使基础 13 房变为 14 房。
- 每套 Layout 在 `O1 / I1 / O2` 提供 3 个建筑槽，从四座候选建筑中按权重无放回抽取三座：王城档案馆（`Archive`）、冠光观星台（`Ritual`）、禁卫兵营（`Barracks / Combat`）、狱城转运院（`Transit`）。`B0` 继续固定为断桥后的巡礼封藏室，不参与建筑池。
- 当前 MVP 仍由 `O1 / I1` 按阶段固定承载 `1 Layout + 1 Strength`：白昼 1004 / 1005，永夜 1007 / 1006；第三座建筑位于 `O2`，提供普通探索或战斗。按建筑兼容标签随机事件属于下一轮内容扩容，不把现有四事件强塞到不兼容建筑。
- Layout Template 最少声明：`LayoutID`、关卡图、兼容标签、降落候选、Boss 候选、事件槽、精英槽、商店节点、关键图距离、允许旋转、禁止镜像及各节点允许使用的空间标签。布局只回答“房间在哪里、如何连通”，不决定具体事件正文、Boss 形态和奖励。
- MVP Story 固定为 `Story_昼夜机关`：白昼与永夜各重新填装两个事件槽，每个阶段都固定包含 1 个 Layout 与 1 个 Strength 事件。相同节点可在昼夜承载不同事件，并保留白昼已提交的实体后果。
- 正式 Story Template 仍需资产化，并至少声明 `StoryID`、兼容布局标签、分阶段事件池、互斥事件、Boss ID、Boss Flag 映射及对白/阶段组。当前固定 Story 用于验证四事件与双阶段结果叠加。

**房间标签、注入和捷径合同**：

- `DungeonRoomAuthoring.RoomTags` 是空间能力声明，使用英文稳定键；`RoomContentRow.PrefabTags` 是内容的必需标签。内容先按 `Role / District / 图深度` 筛选，再要求全部有效标签命中；若多条都兼容，只在标签数量最多的最专用候选中按权重抽取，避免 `Archive` 专用内容被普通 `Combat` 内容稀释。
- Boss 候选的 `RequiredRoomTag` 同时读取实体 Prefab `RoomTags` 与内容行旧标签，统一归一化后匹配；不得再只用 Content 侧标签冒充实体空间标签。
- 旧表中的“战斗 / 精英 / 首领 / 事件”兼容映射到 `Combat / Elite / Boss / Event`；“外环 / 连接区 / 内环”继续由 `District` 约束，不重复算标签。缺少标签候选时直接报错，不允许忽略标签回退。
- 图变换发生在“选择基础 Layout”之后、“Edgar 空间生成”之前：先按限定 Layout 与概率把指定边替换为 `A → 连接房 → B`，再对建筑槽执行按权重无放回抽取，最后应用特殊叶子房注入。叶子注入规则声明概率、数量、阶段、房间角色、事件编号、房间模板、锚点必需 / 禁止标签；节点现有连接数已占满门数时不得参与注入。
- 受控回环使用明确的 `SourceNode / TargetNode / RequiredFlags / Phase / 单双向 / Socket` 规则生成关卡内快捷通道，不依据世界距离自动连边。1007 升降井已经迁入该规则：修复为双向，斩断配重为单向；传送不推进房间、阶段或结算。
- `DungeonGenerationProfile` 是运行时总控：候选布局、连接段伸缩、建筑池、特殊房注入与捷径规则均从同一资产读取，所有抽取由当局 Seed 复现。当前 `Layout_A/B/C/D` 均已登记并等权启用。

> **📊 实现现状（2026-08-19）**：已新增「仙途秘境/关卡工具/生成多 Flow 关卡图」，可重复生成 B/C/D、Flow 专用枢纽/连接房和四座建筑白膜；「布局、注入与节奏校验」可直接修改各项默认值，并提供随机预览、同 Seed 重生成和清除预览。节点语义已从固定名字判断迁入每个 Layout 配置；A/B/C/D 均通过整图连通、Boss 深度 `5～10`、关键路径连续战斗上限 `3`、事件房 `2～3`、地标、死胡同和捷径收益校验。

事件不再只按“通路 / 供能 / 封存”三个题材并列，而是按其**主要玩法影响**归入以下三类。单个事件允许附带次要效果，但必须声明一个主要类型，供事件池配额、UI 提示和结果落位使用：

1. **单局强度事件（Strength）**：改变本次探索中的玩家强度或 Boss 强度。玩家侧包括攻击、生命、技能伤害、恢复与临时机制；Boss 侧包括生命、攻击、移速、招式、随从和场地压力。高收益选项应绑定明确代价，不能只有纯增益。若玩家经基地重新构筑后从永夜继续，需要延续的强度结果必须从阶段记录重新应用，不能只修改白昼玩家实例。
2. **关卡布局事件（Layout）**：真实改变可探索空间或通行方式，包括开关门、修复断桥、开启捷径、封闭支路、启用机关、改变危险区域或房间状态。结果必须同步修改可见模型、碰撞、地图提示与寻路合同；不得切断唯一 Boss 主路，失败或拒绝处理时仍需保留标准通关路线。
3. **道具获取事件（Item）**：以取得消耗品、材料、关键道具或稀有局内物件为主要目的。需要独立定义物品用途、携带规则、死亡损失、跨阶段保存及重复领取规则，不能仅用通用 RewardID 代替完整设计。

**本次 MVP 只实现 Strength 与 Layout 两类**：

- 两个 `EventSlot` 每个阶段都保证 `1 Layout + 1 Strength`：白昼为 1004 / 1005，永夜为 1007 / 1006；昼夜重载时更换事件内容，而不是关闭其中一个事件槽。
- Strength 事件至少清楚改变“玩家强度 / Boss 强度”之一；Layout 事件至少产生一处真实、可验证的空间变化。两类结果都允许在永夜继续兑现。
- Item 类先写入事件框架但不进入 MVP 随机池。Strength / Layout 事件可附带少量补偿材料，但“拿道具”不能成为其主要决策价值。
- 当前事件库为 1004“断裂巡礼桥”、1005“冠光仪”、1006“禁卫召集阵”、1007“狱城升降井”；旧 1005“失能设施”内容与通路 / 供能 / 封存三模板已移除，编号 1005 被新 Strength 事件复用。
- 每个阶段结果在选择完成后立即写入关卡阶段记录，最多保存四项；永夜 HUD 的“上次行动”只回顾两项白昼结果，永夜结果用于本阶段重试恢复。完成永夜后统一清除。

#### 7.6.1 白昼 / 永夜双阶段与回顾

- 首次进入关卡 A 固定为白昼；完成白昼 Boss 后将关卡阶段提交为永夜。直接继续时保留当前 Build，返回基地或死亡后再次进入则按现行规则重新构筑，但关卡仍从永夜开始。
- 进入永夜一律执行“重新降落”：清理上一阶段房间遭遇状态，从白昼保存的出生区安全降落端重新进入；直接继续只保留玩家 Build 与携带物，不保留其 Boss 房世界坐标。
- 昼夜复用同一次生成的地图：`Layout Seed`、出生区、激活的 Boss 候选建筑、13 节点拓扑、整图旋转、关键建筑位置与 Doorway 连接全部保持不变。`B0` 始终存在，只有 `O1 → B0` 的桥梁通行状态按白昼结果变化；主路径碰撞保持一致。
- 永夜期间，HUD 左下角长期显示“上次行动”，只列出实际影响当前阶段的最多两个结果，例如“东侧闸门已被强拆”“内殿核心已被取走”。提示持续到永夜阶段完成，不使用额外三秒摘要、强制镜头或重复对白。
- 若玩家从白昼返回基地，或在永夜死亡 / 返回，基地的关卡入口传送门必须显示：`无暮王城当前处于永夜`、上次造成的变化，以及`本次将从永夜阶段继续`。玩家确认后才进入。
- 直接从白昼阶段出口进入永夜时，不再重复弹入口确认；反转地图完成加载后立即显示左下角长期提示。
- 第一次反馈与第二阶段后果必须同时成立：事件选择当下至少产生一个可见结果，永夜则通过路线、物件、敌群、奖励或 Boss 压力兑现后续影响，禁止只保存 Flag 而没有实体变化。
- 永夜 Boss 完整通关后，阶段状态固定重置为白昼；下一次进入开始新的双阶段循环并重新生成，不提供阶段选择。

**事件房与随机事件解耦**：

- “事件房”是布局中的 `EventSlot`，只承诺存在合法事件交互空间与 `EventSocket`，不代表固定事件内容。
- 当前 MVP 固定节点职责：`O1` 在昼夜分别承载 1004 / 1007 两个 Layout 事件，`I1` 分别承载 1005 / 1006 两个 Strength 事件；1004 因唯一连接 `B0` 不再随出生区换侧。
- 两个事件房可以使用完全相同的空间 Prefab；运行时由 `DungeonEventVariantRoot` 同时启用当前事件和该节点已提交的白昼结果，正式美术不得把事件逻辑永久绑死到房间 Prefab。
- 事件若需要额外门、可破坏物、敌群或宝箱，必须通过通用 Socket 和激活对象落位；不得为了单个事件复制一份永久绑定内容的房间 Prefab。
- 只有明确声明区域限制的事件才绑定外环或内环；其余事件可出现在任一事件槽。主要事件与辅助事件均为随机内容，但主要事件优先选择能改变路线、Boss 机制或高价值战斗的事件。

**最小完整体验的事件边界**：

- 白昼与永夜各开放 1 个 Layout 和 1 个 Strength 事件；完整昼夜循环共四项，不生成 Item 事件。
- Strength 选择必须在属性、能力、敌群或 Boss 压力中产生可核验变化；Layout 选择必须立即改变对应关卡实体。白膜事件房继续通过 `DungeonEventSceneObject` 与通用 Socket 表达结果，正式美术替换不得改写事件执行合同。
- Item 类只保留设计占位，等待物品用途、携带、死亡损失和跨阶段规则确认后再进入事件池；MVP 中材料只能作为 Strength / Layout 选项的次要补偿。
- 昼夜不再每局独立随机。关卡 A 使用固定阶段顺序 `白昼 → 永夜`；只有白昼 Boss 通关并提交阶段后才反转，普通死亡、预览入口或生成失败不得切换。
- 只保存下一阶段需要的最小关卡状态：当前阶段、白昼是否完成、用于复现同一地图的 Layout Seed / 旋转、出生区与 Boss 节点、最多四项事件结果。普通敌人、材料拾取和无关可破坏物不跨阶段保存。
- 白昼桥梁 / 冠光结果进入永夜后重放；永夜召集阵 / 升降井结果在选择完成后记录。需要前置战斗的分支只有清场后才提交最终 Flag。永夜死亡不清除已提交结果，下次仍从永夜继续。

### 7.7 关卡 A 的生成顺序与约束

```text
选择关卡 A
  → 读取关卡阶段（首次为白昼；白昼完成后为永夜）
  → 白昼：按权重选择已启用 Layout / 故事模板、出生区与 Boss 节点
  → 永夜：恢复白昼提交的模板、Layout Seed、出生区、Boss 节点与整图旋转
  → 按锚点标签注入本局特殊叶子房，形成最终区域节点图
  → 运行图节奏校验：连通性 / Boss深度 / 连续战斗 / 事件与地标配额 / 死胡同收益
  → 随机选择外环或内环作为出生区
  → 在出生区普通候选房中抽取安全降落房与房内 PlayerSpawn
  → 激活对侧 Boss 候选建筑，并将同侧候选建筑转为普通地标房
  → 生成必经路线、支路与门状态；条件捷径在对应 Flag 成立后启用
  → 拼接房间模块并旋转
  → 选择整图旋转角，把布局局部坐标整体映射到世界坐标
  → 读取房间 Prefab 的 RoomTags，筛选最专用的兼容 RoomContent
  → 从兼容建筑 / 事件池无放回抽取两个不同事件
  → 注入当前阶段敌群、事件、材料与装饰
  → 若为永夜，使已提交的阶段结果落位并生成左下角回顾
```

生成结果必须满足：

1. 降落房及实际 `PlayerSpawn` 到当前 Boss 不得紧邻，需跨越连接区并保留基本构筑与探索空间。
2. 当前 Boss 必须可从降落点到达，且至少存在一条内外区连通路线。
3. 降落房必须无即时战斗并能看见至少一个结构锚点或明确主路；对侧 Boss 房击败后生成标准通关出口，同侧未激活 Boss 候选房不得伪装成第二个 Boss。
4. 同类普通战斗房不得连续过多；精英与事件内容按节奏插入。
5. 开启捷径后必须真实缩短回程或跨区距离。
6. 任意 Seed 不得出现不可达 Boss、断路、重叠房间或 Doorway 朝向不匹配；非 Boss 撤离必须由显式规则生成，不能由异常拓扑形成。
7. 相同房间 Prefab 可以重复使用，但重复段不得形成无法通过连接关系判断方向的完全对称结构。
8. 两个事件房允许使用相同空间 Prefab，但同一局必须注入不同 `EventId`；事件与房间模板不得形成永久一对一绑定。
9. 关键建筑在布局局部坐标中的相对方向不得翻转；整图允许刚性旋转但不得镜像，旋转前后地标之间的图距离、侧向关系与先后关系必须保持。
10. 白昼 / 永夜必须使用兼容的拓扑和 Doorway 合同；允许关键模块改变物件、局部门状态与敌群，但不得让已提交结果因布局不兼容而无法落位。

### 7.8 普通战斗房与材料

- 材料不单独占用「材料房」类型，直接刷新在普通战斗房。
- 房间 Prefab 通过 `MaterialSocket` 或等价内容槽声明材料候选位置；生成时按房间表配置决定种类、数量与启用概率。
- 材料可采用「探索时可拾取」「清场后出现」或两者混合；首版优先使用清场奖励，保证战斗与产出的因果清晰。
- 材料可以带回基地，但具体用途、死亡损失比例、稀有材料保护和基地建设内容暂缓，后续单独补充 §8。
- 普通战斗房仍承担白色 / 基础模块的主要获取，材料不能挤占基础 Build 成型所需的奖励频率。
- 战斗房清场奖励统一以世界掉落实体发放；不再弹出过关三选一，技能、模块与材料均由掉落/拾取链路承接。

### 7.9 休息房、军械库与装备 A（首测暂缓）

- 最小完整体验不生成休息房和军械库，也不验证装备 A 固定来源。
- 首测先用普通战斗、双精英、双事件、商店与单 Boss 验证探索—构筑—结算闭环。
- 若 Playtest 出现续航不足、路线缺少固定地标或定向装备需求，再分别恢复休息房与军械库；不得在验证前占用主体房预算。

### 7.10 地图系统目标与当前实现边界

目标地图需要表达「同时存在的区域节点图」，而非只表达线性房间序列：

- 区域节点需记录 `District（Outer / Transition / Inner）`、`Role（Landing / Battle / Event / BossCandidate / Exit）`、邻接关系、房间 Prefab、旋转、内容槽和显式 Boss ID。
- 单个激活 Boss ID 来自故事模板与出生区组合，不再由 Act / 层数隐式决定。
- 房间几何在入场时按区域图一次性生成；玩家进入房间后再激活该房的敌群、锁门和清场逻辑，已生成房间不因前往下一房而销毁。
- `RoomType`、战斗房、敌人、奖励和 Boss 阶段系统可继续复用；silverua 单共享 Boss 拓扑、线性事件索引和逐房销毁/重建流程需要被区域地图 Provider 取代或适配。
- 当前下一步目标为「12 房区域节点图 + 分区标签 + 对侧单 Boss + Story Template + 白昼 / 永夜阶段持久化」；实体拼接继续采用 Edgar PRO Grid3D。

| **经验值** | 局外通用资源 | 是，按结算倍率折算 | 模块解锁、剧情推进 |
| **来源标签** | 经验值标签 | 是 | 决定经验值倾向，例如模块、探索、Boss、情报 |
| **局内货币** | 本局临时资源 | 否 | 商店购买、刷新、治疗 |
| **模块** | 本局 Build 部件 | 默认否 | 构成本局技能链 |
| **情报** | 线索型来源标签 | 是 | 解锁 Boss 线索、特殊模块提示、剧情节点 |
| **材料** | 局外持久资源 | 是（具体死亡结算待定） | 刷新于普通战斗房；局外用途、稀有度与消耗规则暂缓 |

### 8.2 模块掉落与推荐

模块掉落采用“基础权重 + Build 相关性 + 保底修正”的方式：

```text
最终权重 = 基础权重 × 稀有度权重 × 来源权重 × Build 相关性 × 保底修正
```

| 因素 | 规则 |
|------|------|
| **基础权重** | 每个模块表内配置 |
| **稀有度权重** | Common 高、Legendary 低 |
| **来源权重** | 普通房偏基础模块，精英 / Boss 偏高稀有度模块 |
| **Build 相关性** | 当前已装配标签越匹配，权重越高，但不超过 2.0x |
| **保底修正** | 连续 3 次未出现可用效果器时，提高效果器权重 |

推荐逻辑只影响候选池权重，不强制玩家进入固定流派。

## 9. 术语表

| 术语 | 定义 |
|------|------|
| **模块** | 局内 Build 部件总称，分触发器、效果器、改造件、万能件 |
| **触发器** | 定义发动条件或状态载体，不提供伤害、治疗、控制 |
| **效果器** | 定义发动后的结果，例如伤害、治疗、位移、控制 |
| **改造件** | 改变触发器或效果器的形态、目标、数量、节奏、代价 |
| **万能件** | 无固定大类的模块，放入触发器槽即当触发器、放入效果器槽即当效果器，槽位决定其职责 |
| **局内重组** | 非战斗状态下随时取出 / 替换 / 丢弃链上模块的自由拼装机制 |
| **前哨** | 局外配置、局内消耗的临时支援点，用于补给、休息或调整模块 |
| **容错强化** | 提高单局容错的局外成长项，例如复活次数、死亡后保留部分结算倍率 |
| **情报** | 来源标签之一，来自事件、Boss 线索、隐藏房和剧情节点 |
| **阶段返回** | 关卡中途主动结束本局并按 1.0x 结算 |

### 11.4 V0.4.1 版本计划
> 本次 V0.4.1 主要围绕局内关卡、永久解锁和多存档体验调整。玩家每局临时构筑 Build，但整套 Build 不会保存或带到局外；技能、模块只要在局内首次获取，便永久解锁到当前玩家进度存档。

简述：玩家从局外进入肉鸽关卡，在本局中通过技能、模块三选一持续构筑 BD。某个技能或模块第一次被玩家实际获取时，立即登记为当前进度存档的永久解锁内容；死亡、主动退出或通关后，本局已装配的技能、模块和组合关系全部清空，不生成 Build 快照，也不能在局外装备后带入下一局。局外承担存档选择、解锁内容查看和后续成长承载，不再设置《暗黑破坏神 3》式大秘境或其他“携带局内 BD 进行数值验证”的关卡。

#### 11.4.1 局外调整
1. 维持局外安全屋设计，取消大秘境入口、大秘境缓冲区、Build 装备台以及相关进入门槛。
1.1 局外增加技能/模块解锁内容的查看入口，用于展示当前进度存档已经发现并永久解锁的内容。
1.2 局外解锁只代表“该内容已被发现并记录”，不保存当局等级、已装配位置、增强链连接关系或整套 Build，也不允许玩家穿戴后带入下一局。
1.3 玩家每次进入新一局时仍以挂空状态开始（保留基础普攻，Q/E/R 核心技能与增强链为空），通过本局奖励重新构筑。

#### 11.4.2 存档功能

1. 只保留“玩家进度存档”一种存档类型，不再存在局内 BD 存档、Build 快照或 Build 背包。每个进度存档独立保存游戏进度、永久解锁列表、设置所需状态和统计数据。

1.1 三槽存档界面：
- 1.1.1 存档选择界面固定提供 3 个存档槽，并采用从上到下的纵向卡片布局，不再横向排列。
- 1.1.2 空槽显示“新存档”；已有存档显示存档名称、主要进度、累计游玩时间和最后保存时间。
- 1.1.3 点击空槽创建新存档；点击已有存档直接读取并进入该进度。删除或覆盖必须通过独立操作按钮触发，并进行二次确认，避免把正常读取误操作为覆盖。
- 1.1.4 开始界面的“继续游戏”读取最近一次使用的存档；“开始游戏/选择存档”进入三槽纵向存档界面。
- 1.1.5 自动存档至少在首次解锁技能/模块、进入关卡、返回局外和重要进度变化时触发；暂停菜单保留手动存档按钮，始终写入当前槽位。

1.2 永久解锁记录：
- 1.2.1 技能或模块在局内第一次被玩家实际获取时，立即把其唯一 ID 写入当前进度存档的永久解锁列表，不要求玩家通关或主动退出后才结算。
- 1.2.2 同一内容重复获取不会重复解锁，只更新必要的发现统计。
- 1.2.3 永久解锁列表与局内运行态严格分离：局内已装备技能、模块、增强链和替换记录不会写成可恢复或可装备的 Build。
- 1.2.4 死亡、主动退出或通关后清空本局 Build；已触发的永久解锁保留，并可在局外解锁界面查看。

#### 11.4.3 核心循环

局外选择进度存档 → 挂空进入肉鸽关卡 → 本局获取技能/模块并构筑 BD → 首次获取内容立即永久解锁 → 死亡/退出/通关后清空本局 Build → 返回局外查看解锁并开始下一局。当前版本不包含大秘境、Build 装备或局外 Build 数值验证环节。

#### 11.4.4 局内调整；
1. 玩家现在初始状态改为无技能，并且当前功能有BUG，进入肉鸽关卡缓冲区后技能三选一的技能没有装备在技能上；
2. 商店添加模组可给玩家进行购买，商店的物品总数扩充至7个；
3. 商店添加通过消耗“基础货币”可进行刷新功能；

#### 11.4.5 局内关卡调整；
1. 局内关卡现在共3层，每层仍旧维持3跳路线，但每条路线需要确保玩家必须走过12个关卡，其中第12关为BOSS关卡，中间则可以是事件关、战斗关、精英关等，而在整条路线中精英关卡不能超过2个，而商店关不能超过4个；
2. 关卡内现改为不在掉落任何东西，每完成战斗、精英、事件后有概率会出技能或模组三选一，选择完毕后进入下一关，事件有固定的BD选项，而战斗和精英则是分别以70%和90%的概率出现三选一；
3. 技能或模组选时，玩家一定要做出选择后才可进入下一关，同时添加一个“退出”按钮用来退出三选一界面，玩家可以不选择任何技能或模组就直接进下一关；
4. 根据2中的设计，新增一个替换功能，若玩家此有装备技能，且已全部装备满，则可以通过按键选择来替换之前的技能，若出现此情况，则需要添加一个额外提示“是否替换当前技能？”若玩家选择是则完成替换，并根据替换折算成货币可以在商店使用，若选择否则无视替换操作；

#### 11.4.8 V0.4.1 方案修订（2026.08.03）
> 本节为 §11.4 当前最高优先级结论，与旧的大秘境、Build 快照或 Build 背包描述冲突时，以本节及修订后的 §11.4.1～§11.4.3 为准。

1. 局内 Build 不带出；死亡、主动退出或通关后都清空本局技能、模块和增强链组合。
2. 技能/模块在局内首次实际获取时，立即永久解锁到当前玩家进度存档，不以通关为前提。
3. 取消大秘境入口、缓冲区、层数选择、挑战、奖励、Build 装备和 Build 背包。
4. 玩家进度采用 3 个独立存档槽，存档选择界面从上到下纵向展示。
5. 大秘境与 Build 快照旧实现已物理删除；v2 存档中的 Build/遗产模块只在加载时迁移为永久发现记录，随后清空。
6. “装备或替换后技能栏立即变化”继续作为通用交互要求保留，与 Build 是否能带出无关。

**📊 实现现状（2026.08.03）**
- `SaveDataV1` 已升级 schema v3，按槽保存技能/模块永久解锁与累计游玩时间；旧 Build 数据幂等迁移为发现记录。
- `SaveSlotSelectUI` 已改为纵向 3 卡，读取、覆盖、删除分离，破坏性操作均二次确认。
- 初始选择、战后奖励、世界拾取、商店购买和模块入包/自动装配均接入“首次获取即解锁并立即存档”。
- `CodexUITK` 按当前槽显示已发现详情，未发现内容只显示占位。
- 回基地与新开局会清空 Q/E/R、模块背包和增强链；模块链变更会即时刷新技能栏。
- `BuildSnapshot`、Build 背包 UI、村庄大秘境入口、`Scripts/Rift/` 与普通秘境准备区均已删除；基地入口直接承担技能确认和进关。
