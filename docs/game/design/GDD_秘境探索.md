## 1. 产品定义

ProjectR 是一款 PC 单人 Roguelite 3D ARPG。玩家在不断变化的蜂巢秘境中结识并培养器灵，将它们附着于随机获得的武器、术法与身法，通过“源／应／化”和多灵叠契构筑战斗回路，并决定继续深入挑战灾相，还是带着新伙伴安全撤离。

### 创意定位

ProjectR结合《梦之形》式局内技能组合、《宝可梦／洛克王国》式长期伙伴身份、《幻兽帕鲁》式轻量栖息表现，以及系统化游戏中“产物—响应—转化”的实验乐趣。差异点不是把技能换成宠物，而是让永久器灵寄宿于每局变化的动作载体中。

### 核心幻想

器灵是拥有长期身份、性格与关系的伙伴。同一只器灵在不同载体上会显化为不同玩法，并能与其他器灵形成新的战斗回路。

游戏持续制造两个问题：

1. 让这只器灵寄宿进这件东西，会发生什么？
2. 继续深入完善构筑，还是先把刚结契的伙伴安全带回洞府？

### 目标玩家

- 喜欢探索、收藏、地图彩蛋和环境推理。
- 喜欢组合实验、动作反馈和创造个人Build。
- 喜欢长期伙伴关系，但不想维护复杂流水线。

### 设计支柱

1. 器灵是完整机制，不是稀有度词条。
2. 构筑是一条能产生、响应、转化并闭合的回路。
3. 探索会改变相邻生态，而不只是选择房间奖励。
4. 灾相有多种解法，不是唯一进度钥匙。
5. 洞府增加选择和关系，不提供无限强度。

设计取舍测试：

- 机制行为优先于更高数值。
- 环境线索优先于直接标明奖励。
- 主要强化必须改变回路、操作或组合关系。
- Boss准备可以降低门槛，但不能成为指定器灵硬锁。

### 反支柱

- 不做个体值、完美胚子和强制繁殖。
- 不做三角色轮换战斗。
- 不做持续维护的自动化生产链。
- 不用大量百分比增伤冒充构筑。
- 不要求每局全清或必须击败Boss。
- 不做现实时间等待、永久死亡和强制休息。

### 📊 实现现状

- 已确认：ProjectR 全面替代旧《仙途秘境／秘境探索》产品方向。
- 已有：Unity URP工程、基础动作战斗、敌人、配置和UI基础。
- P0已建立：载体执行契约、Legacy增强快照适配、`CircuitEvent`因果载荷，以及默认关闭的载体／回路／生态开关；尚未接管任何运行时行为。
- P1.1已建立：Q／E／R术法通过 `SkillCarrierAction`获得统一可回滚入口；开关默认关闭，具体技能效果仍委托现有实现。
- P1.2已建立：三个术法槽位的充能、逐层冷却、冷却缩减与上限加成由独立 `SkillChargeRuntime`维护；UI继续消费原 `SkillCooldownUpdate`事件。
- 待实现：器灵实例、回路运行时、永久器灵存档；蜂巢生态因关卡策划冻结暂不实施。

## 2. 核心循环

```text
洞府选择3只器灵与准备
  → 进入蜂巢秘境
  → 探索、战斗、结契
  → 获取并更换载体
  → 获得悟法与铭刻
  → 接通三灵回路
  → 撤离／深入／挑战灾相
  → 提交器灵、蓝图与材料
  → 洞府关系、悟法沉淀与下局准备
```

单局目标时长25–35分钟。失败不会丢失已有器灵；新结契器灵必须成功撤离才能永久获得。

### 📊 实现现状

- 可复用：基地、场景切换、三槽存档、本局缓存和结算框架。
- 待替换：旧“模块发现—Boss通关—经验结算”循环。

## 3. 玩家操作与基础数值

### 输入

- 普通攻击：当前武器动作。
- 特殊攻击：当前武器的资源、蓄力或姿态动作。
- 术法一、术法二：两个主动能力。
- 身法：闪避、格挡、瞬移或钩索。
- 交互：拾取、机关、结契和撤离。

器灵不占用额外技能按钮。它们通过附着改变已有动作，并在触发时显形、发声或留下清晰笔触。

### 数值原则

- 基础数值用于保证动作手感，不承担构筑深度。
- 主要强化必须改变动作、回路或组合关系。
- 局外生命和基础伤害成长总量约10%–15%，快速封顶。
- Boss难度以可观察机制、准备收益和操作空间为主，不以血量膨胀为主。

### 📊 实现现状

- 已有：生命、伤害、暴击、护盾、状态、投射物、HitStop、震屏和伤害数字。
- 待做：特殊攻击统一接口、身法载体化和回路来源追踪。

## 4. 器灵与结契

器灵永久保存种族、性格、羁绊、关键关系、载体适应、悟法池、外观和故事状态。种族决定机制，性格改变时机与风险偏好，不设置传统个体值。

获取路径：

- 战斗降服。
- 性格结契。
- 解谜或剧情结契。
- 腐化净化。
- 灵卵与残器。

局内新器灵可以收入契匣、临时替换出战器灵或留在生态区。临时使用的新器灵只有成功撤离后才进入永久存档。

详见：[器灵与结契](systems/器灵与结契.md)。

### 📊 实现现状

- 待实现：`SpiritDefinition`、`SpiritInstance`、契匣、结契状态机和永久提交。
- 垂直切片：4只器灵，每只2种性格表现；3种结契实例。

## 5. 载体与回路

载体分为武器、术法和身法。载体负责动作，器灵负责规则。

### 回路语言

- 源：产生狐火、护甲、标记、回声、召唤物等。
- 应：响应命中、暴击、穿越、聚集、破碎、受伤和消耗。
- 化：将已有状态转为爆炸、传导、复制、治疗、固化或再生。

### 附着结构

- `1＋1＋1`：三只器灵分居三个载体，形成长回路。
- `2＋1`：双灵叠契形成融合能力，单灵辅助。
- `3＋0`：三灵共居一个载体，形成极端构筑。

### 局内成长

- 更换载体：改变动作，器灵悟法不丢失。
- 器灵悟法：改变源、应或化。
- 载体铭刻：改变载体动作本身。
- 联契反应：消费其他器灵产物并累积共鸣。

通用规则覆盖约80%组合，约20%高契合组合获得专属动作、造型和名称。

详见：[载体与回路](systems/载体与回路.md)。

### 📊 实现现状

- 可复用：`GameEvents`、`ModuleChain`、`TriggerTracker`、`SkillData`和状态／投射物系统。
- 待重构：`PlayerCombat`拆分；旧模块UI和一技能一链规则。
- 待实现：带来源、标签、因果链和预算的回路事件。

## 6. 单局成长节奏

### 前期：寻找方向（0–10分钟）

获得新载体与第一次悟法，形成两段互动。迁灵与替换成本低。

### 中期：接通回路（10–25分钟）

获得更多悟法、联契和特殊载体。三只器灵形成完整连接，新结契器灵可能迫使玩家重组队伍。

### 后期：觉醒与取舍（25–35分钟）

构筑进入高频循环、三灵共器或强力终结。玩家权衡挑战灾相、继续深入或带着新伙伴撤离。

目标体验：

```text
能互动 → 能连锁 → 能闭环 → 能产生受控的失控爆发
```

### 奖励原则

- 世界中的行为和地点决定主要奖励来源。
- 每2–3区提供一次整备和迁灵机会。
- 前期多给方向，中期多给连接器，后期集中给质变。
- 纯世界拾取与“世界拾取＋灵龛选择”的比例仍待确认。

## 7. 蜂巢秘境

> **策划冻结（2026-09-02）**：关卡结构、蜂巢生态、首个区域、房间规模、推进与出口规则目前均为讨论草案，暂不继续细化，也不进入程序、美术或配表实施。后续专题讨论确认后再解除冻结；以下内容仅保留上下文，不视为已定案。

每层由9–12个互联小区域组成。玩家获得相邻区域的模糊情报；开闸、敲钟、净化、战斗和放生等行为会改变邻区状态、器灵迁移和结契条件。

不存在持续倒计时。每完成若干区域，秘境推进一次躁动：污染扩散、器灵迁移、猎手追踪、通路改变、奖励和撤离风险提高。

完成随机目标中的任意两项即可开启出口，灾相不是强制目标。

保留的技术合同：

- 布局与故事／生态正交。
- Seed可复现。
- 房间Socket与Encounter Seed稳定。
- 房间状态回访不重抽。
- 实体、碰撞、提示与NavMesh结果一致。

详见：[蜂巢秘境与灾相](systems/蜂巢秘境与灾相.md)。

### 📊 实现现状

- 已有：Edgar Grid3D、Layout A–D、区域生命周期、事件Flag、门与NavMesh。
- 暂缓：区域状态、邻接传播、模糊情报、迁移、躁动、出口和撤离；冻结期间不实施。
- 待讨论：关卡总体结构，以及无暮王城完全归档或改造成首个生态区。

## 8. 灾相

灾相不是等待捕获的大型野生器灵，而是失控规则、执念或灵力循环：

- 失控聚合体：约40%。
- 秘境现象：约25%。
- 敌对御灵者：约25%。
- 可结契古老器灵：约10%。

灾相拥有可观察、可干扰和可拆解的回路。玩家可以直接战斗，也可以通过探索、救援和改变区域状态削弱它。

### 📊 实现现状

- 可复用：Boss阶段条件、技能选择、预警、血条和战斗反馈。
- 计划迁移：The Archer中选定Boss的模型、动画、VFX与战斗逻辑；接入ProjectR现有伤害、事件、对象池和敌人能力框架。
- 待制作：1个失控聚合体灾相、可破坏节点和探索削弱路径。
- 关卡冻结期间只允许整理Boss战斗资产与独立战斗能力，不确定其关卡位置、强制性或探索削弱关系。

## 9. 洞府与局外成长

洞府以3–5分钟的关系养成和下局准备为核心。

- 从契匣选择3只器灵。
- 配置有限悟法候选。
- 每局最多选择3项准备。
- 处理关键关系事件。
- 成功撤离后沉淀一项有效悟法。
- 重复个体可以工作、探索、迁居或归野，不作为经验材料。

详见：[洞府与局外成长](systems/洞府与局外成长.md)。

### 📊 实现现状

- `EnableCaveMeta=true`，但旧洞府内容不等于ProjectR洞府。
- 可复用：基地Prefab、插槽、存档和本局材料缓冲。
- 待实现：契匣、关系、悟法池、3项准备和撤离提交。
- `EnableSpiritItems=false`：旧“灵物”继续屏蔽，与ProjectR“器灵”不可混用。

## 10. 美术与音频

视觉锚点为“灵墨显形”：

- 低饱和3D水墨箱庭承载世界。
- 高彩器灵、交互目标和关键回路承担焦点。
- 每只器灵使用稳定轮廓、笔触、运动和音效编码。
- 回路传递以短暂墨线和统一符号表示方向。

The Archer迁移范围：

- 必需：主角模型、骨骼／Avatar、动画、材质与纹理。
- 必需：垂直切片采用的普通怪物模型、动画、材质、纹理和配套表现。
- 必需：选定Boss的模型、动画、VFX、音频和招式逻辑。
- 可选：投射物表现、通用预警、命中／受击／死亡反馈。

其 Built-in RP 材质必须在隔离场景完成URP转换。Boss逻辑按选定个体迁移并适配ProjectR战斗接口，不搬运The Archer整套关卡、成长、存档、对象池或静态服务架构。

架构边界见：[ADR-003](../architecture/decisions/ADR-003-TheArcher选择性迁移.md)。

## 11. 垂直切片

必须包含：

- 4只器灵，每只2种性格表现。
- 2武器、4术法、2身法。
- 源／应／化与三种附着结构。
- 1个蜂巢生态区。
- 3种结契实例。
- 1名敌对御灵者精英。
- 1个失控聚合体灾相。
- 25–35分钟完整单局。
- 轻量洞府与完整撤离提交。
- 回路预览、触发反馈和战后来源分析。

不做繁殖、个体值、自动化生产链、联机、大型主线、多生态区长期内容和现实时间机制。

详见：[垂直切片交付计划](../delivery/垂直切片计划.md)。

## 14. 垂直切片验证问题

1. 玩家能否快速理解“源—应—化”？
2. 同一器灵附着不同载体是否明显改变玩法？
3. 三只器灵能否形成可读且兴奋的回路？
4. 玩家是否愿意在换载体时重构？
5. 生态变化是否让结契比普通房间奖励更有意义？
6. 玩家是否会记住具体器灵个体，而非只比较效率？
7. 灾相回路能否被观察和拆解？

执行清单见：[游戏测试清单](../playtest/游戏测试清单.md)。

## 15. 主要风险

- 组合丰富但难理解：回路预览、来源追踪和战后分析必须与核心战斗同步制作。
- 内容成本乘法增长：通用规则覆盖多数搭配，只给少量高契合组合制作专属动作。
- 器灵身份被效率吞没：性格、关系和共同经历进入机制，但不能随机破坏一局。
- 蜂巢探索拖慢节奏：控制区域尺度，提供模糊情报和快捷连接，以躁动制造软压力。
- 局外成长破坏重置：永久成长主要增加选择，基础数值快速封顶。
