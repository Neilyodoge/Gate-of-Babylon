## 1. 游戏概述

### 1.1 一句话描述

> 一款冒险题材的 Roguelike Top-down 3D ARPG（参考《梦之形》视角风格），玩家扮演立志终极挑战成功的冒险者，在基地休整修炼与关卡历练之间循环，通过为核心技能装配"触发器 + 效果器 + 改造件 + 万能件"的增强链，构建无限可能的 Build，探索秘境探索的终极真相。

### 1.2 参考作品分析

**《Shape of Dreams / 梦之形》的不足（我们要解决的问题）：**

| 问题 | 我们的解决方案 |
|------|--------------|
| Build 多样性有限，几局后见过所有东西 | 万能件 + 自由拼装 + 局外解锁，理论 Build 数近乎无限 |
| 宝石系统偏数值，缺乏机制深度 | 不做独立宝石系统；将其降级为"模块改造件 / 符文"，作为触发器和效果器的第三层修饰 |
| 叙事/世界观薄弱 | 冒险世界观 + 自适应怪物生态（反制系统）+ 多结局抉择，碎片化剧情 + 终极悬念 |
| 缺乏长期目标（Meta Progression） | 完整的局外成长系统：模块解锁 + 前哨蓝图 / 容错强化 |
| 重玩价值低 | 解锁初始配置 × 随机模块 × 万能件自由拼装 = 每局体验差异化 |

目前随着策划的加入，对表格的需求也愈发重要，因此在此设计好一系列规范和准则，让整个流程可以更好地与其他人协调制作，下面进行说明；
- **关于表格的制作说明**：

设计表格目的是为了可以在各个功能中进行灵活的控制和调整，方便策划或其他人进行修改；

## 2. 世界观与叙事

玩家扮演一名进入危险关卡探索的冒险者。基地是玩家的休整、配置与长期成长场所；关卡是玩家进行长局构筑、挑战 Boss、获取经验值和解锁线索的主要场景。

叙事目标是服务 Roguelite 循环：每一次死亡、返回或通关都会让玩家更理解世界、更接近终局真相。剧情通过 Boss、事件、记忆碎片、基地 NPC 和多结局逐步展开。

## 3. 核心循环

```text
基地
  → 结算经验值
  → 解锁模块 / 在配置 NPC 处配置带入局内的初始模块 / 配置前哨与补给
  → 带入配置好的初始模块进入关卡

关卡
  → 获取触发器 / 效果器 / 改造件
  → 拼出本局 Build
  → 阶段返回、死亡或通关
  → 按不同倍率结算经验值
```

**结算结果**：

| 结果 | 经验倍率 | 设计目的 |
|------|---------|---------|
| 死亡 | 0.5x | 失败也能推进局外成长，但收益明显低于主动返回 |
| 阶段返回 | 1.0x | 玩家主动收手，保守结算 |
| 通关 | 2.0x | 奖励完整长局与高风险挑战 |
| 完美通关 | 3.0x | 额外奖励无死亡 / 高难度挑战表现 |

**局外成长**：
- 经验值是唯一通用局外资源。
- 来源标签只影响经验转化方向，例如战斗、模块、流派、探索、情报、Boss。
- 成长出口包括模块解锁、前哨蓝图、容错强化和剧情推进。

### 3.1 基础数值系统

模块系统必须建立在统一基础数值上，后续所有模块只修改这些字段。

| 字段 | 初始值 | 规则 |
|------|-------|------|
| **生命值 HP** | 100 | 归零后进入死亡结算；可被治疗、护盾和复活类模块影响 |
| **护盾 Shield** | 0 | 先于生命承伤，默认不自然回复，只由模块或房间奖励提供 |
| **移动速度 MoveSpeed** | 5.0 单位 / 秒 | 可被模块临时修改，上限 150% |
| **攻击速度 AttackSpeed** | 100% | 影响普攻动作时长，上限 150%，不压缩输入缓冲到 150ms 以下 |
| **暴击率 CritRate** | 5% | 默认暴击伤害为 150% |
| **技能冷却 Cooldown** | 由模块定义 | 冷却缩减上限 50% |
| **闪避充能 DodgeCharge** | 2 层 | 可被模块临时提高，上限 4 层 |

生命、护盾、攻速、移速和冷却是模块平衡的基础字段；没有写入这些字段的模块，不应直接修改底层战斗表现。

## 4. 初始配置与局外成长

### 4.1 初始配置

开局不再使用固定流派模板，改为一套可直接运转的初始模块：

- **测试版本**：开局直接给一套"种子"初始模块（触发器 + 效果器 + 改造件各一，保证开局即可运转），玩家无需选择。
- **配置 NPC**：玩家可在旁边配置 NPC 处手动替换、调整带入局内的初始模块，自由组合已解锁模块。
- **后续版本**：以新手教学关卡引导玩家上手，不再依赖固定模板流派划分。

初始模块只解决"开局有一组能用的东西"，不限制局内发展——玩家在关卡中可以捡到其他模块并完全转向。

### 4.2 局外解锁系统

局外成长以**解锁**为主，不修改模块数值。当前触发器、效果器、改造件、万能件四类模块**均不可升级**。

| 机制 | 说明 |
|------|------|
| **模块解锁** | 局外解锁新模块后，可在配置 NPC 处将其选入带入局内的初始模块，局内再通过掉落发展 |
| **带入配置** | 玩家在配置 NPC 处手动挑选已解锁模块组成初始装配，每局带入数量有限 |
| **解锁来源** | 经验值、Boss、剧情、情报等（具体解锁条件后续补充） |

> 局外成长不包含数值升级（模块熟练度已移除）和固定流派模板（起始模板已移除），长期目标聚焦在"解锁更多模块、丰富带入组合、前哨与容错强化"上。


## 5. 模块化技能系统（核心技能 × 增强链 · Proc → Consume）

> **V0.1.12 方向变更**（原 V.08）：模块链不再"自己释放技能"。技能的主导权回到玩家按键上：核心技能是玩家主动释放的招式，模块链挂在核心技能上做**增强器**。Trigger 决定**什么时候把增强上膛（Proc）**，玩家按下对应技能才**开火（Consume）**并消费增强。这一改动解决了 V0.1.11（原 V.07）"装配即战斗、操作感缺失"的方向性问题。
>
> **取代的旧系统**：本章取代了历史「灵物 / 御灵五系 / 化身 / 天赋树 / 宝石 / 秘术」等系统，详见 §10.3 历史归档。

### 5.1 核心逻辑：核心技能 × [触发] → [效果] → [改造]

战斗由两层构成：

1. **核心技能层**：Q/E/R 三个槽位各装一个核心技能，玩家主动按键释放（伤害、动画、目标选择都由核心技能决定）。起始固定 3 个，关卡内可替换。详见 5.12。
2. **增强链层**：每条增强链挂在一个核心技能上，由三类模块拼装：
   - **触发器 (Trigger)**：定义**什么时候这条链上膛**（Proc），并自带 `consumeKind` 声明消费模型。
   - **效果器 (Effect)**：定义**消费时给核心技能附加什么**（增伤倍率、附加范围爆炸、改元素、控制、自愈等）。
   - **改造件 (Modifier)**：定义**这个加成如何变形**（蓄力等级、爆炸半径、Proc 概率、层数上限）。
3. 另有第四类**万能件 (Universal)**：无固定职责，放入哪个槽就当哪个，详见 5.10。

```
核心技能「剑气」 + [触发器: 暴击时·Single] + [效果器: +120% 伤害]
  = 暴击后剑气图标冒火，下次按 Q 释放 +120% 伤害剑气

核心技能「落雷」 + [触发器: 移动 10 米·Stacks(3)] + [效果器: 附加范围爆炸] + [改造件: 爆炸半径 +50%]
  = 跑动累层（最多 3 层），每按一次落雷附带一次放大爆炸，消耗一层

核心技能「突刺」 + [万能件(当触发器: 闪避后·Window 5s)] + [万能件(当效果器: 改为火属性)]
  = 闪避后 5 秒内按下突刺附带火属性，整条链全由万能件组成
```

**裸技能规则**：未挂增强链的核心技能仍可正常释放，只是没有加成。降低上手门槛，玩家可逐步为喜欢的技能配链。

**一技能一链规则**：一个核心技能槽位最多挂一条增强链；不同技能可同时各挂一条互不干扰。最小可玩版本不开放多链叠加。

### 5.2 模块分类总规则

所有局内 Build 部件统一叫**模块**，分四大类：

| 大类 | 负责问题 | 设计边界 | 例子 |
|------|---------|---------|------|
| **触发器** | 增强什么时候上膛（Proc）/ 用什么状态承载 | 不负责主要伤害，只提供 Proc 条件、节奏或状态载体；自带 `consumeKind` | 暴击时·Single、移动 X 米·Stacks、每 N 秒·Window、种子生成 |
| **效果器** | 消费时给核心技能附加什么 | 不改变核心技能的触发条件，只定义附加的增伤、范围、元素、控制、自愈等结果 | +120% 伤害、附加范围爆炸、改火属性、回血 |
| **改造件** | 这个加成如何变形 | 不单独成为技能，必须依附触发器或效果器生效 | 连锁、扩散、延迟、分裂、左侧强化 |
| **万能件** | 视放入槽位决定职责 | 无固定大类，放入触发器槽即当触发器、放入效果器槽即当效果器；详见 5.10 | 万能"种子/引爆"件、万能"落雷/条件"件 |

每个模块都必须有标签，标签用于掉落权重、兼容判断和局外解锁。

| 标签维度 | 用途 | 示例 |
|---------|------|------|
| **模块大类** | 判断槽位位置 | Trigger / Effect / Modifier / Universal |
| **功能标签** | 判断玩法类型 | Damage / Defense / Heal / Mobility / Summon / Control / State |
| **触发标签** | 判断 Proc 来源 | Attack / Move / Hit / Kill / Time / Dodge / State |
| **形态标签** | 判断改造兼容性 | Projectile / Area / Melee / Aura / Chain / Object |
| **节奏标签** | 判断 Proc / Consume 节奏 | Single / Window / Stacks / Proc |
| **流派标签** | 用于推荐掉落 | Seed / Backstab / Puppet / Lightning / Poison |

### 5.3 触发器分类 (Trigger Types)

触发器决定**增强什么时候上膛（Proc）**或承载什么状态。触发器只分两层：**条件型**和**状态型**。每个触发器必须声明 `consumeKind`，决定消费模型（详见 5.6）。

| 子类 | 说明 | 示例 | 必填字段 |
|------|------|------|---------|
| **战斗行为触发** | 根据攻击、命中、暴击、连击等行为 Proc | 攻击 X 次、暴击后、连击第 3 段 | 行为类型、计数阈值、冷却、是否消耗层数、consumeKind |
| **移动 / 闪避触发** | 根据移动距离、冲刺、闪避窗口 Proc | 移动 X 米、闪避成功、冲刺结束 | 距离阈值、窗口时间、冷却、方向限制、consumeKind |
| **受击 / 防御触发** | 根据受到伤害、格挡、护盾破裂 Proc | 受击时、护盾破裂时、低血量时 | 伤害条件、生命阈值、冷却、防重复触发规则、consumeKind |
| **时间 / 节奏触发** | 根据固定时间、蓄力、房间节奏 Proc | 每 X 秒、蓄力满、进入新房间 | 时间阈值、是否受冷却缩减影响、初始延迟、consumeKind |
| **击杀 / 事件触发** | 根据击杀、拾取、开箱、Boss 阶段等事件 Proc | 击杀后、精英死亡、Boss 进入二阶段 | 事件来源、目标限制、触发次数上限、consumeKind |
| **状态型触发** | 创建标记、层数、召唤物或计数器作为 Proc 载体 | 种子生成、种子引爆、背击标记、傀儡计数 | 状态名、层数上限、持续时间、默认状态展示 |

条件型触发器包含战斗行为、移动 / 闪避、受击 / 防御、时间 / 节奏、击杀 / 事件五个子类；状态型触发器单独作为第六类。

状态型触发器只提供**无伤害状态展示**，例如种子落点、破绽标记、傀儡计数 UI、蓄力层数。它们不造成伤害、不治疗、不控制敌人；主要强度必须来自接上的效果器和改造件。

**consumeKind 选择建议**：
- 高频 Proc（暴击、命中）→ 优先 `Stacks`，避免频繁浪费。
- 中频事件（受击、击杀、每 N 秒）→ 优先 `Single`，制造"等一个时机"的博弈感。
- 低频周期（长 CD、移动累计、阶段事件）→ 优先 `Window`，给玩家足够反应窗口。
- 辅助 / 光环 / 挂机 build → `Auto`，条件满足自动释放绑定技能，玩家 hands-free。

### 5.4 效果器分类 (Effect Types)

效果器定义**消费时多出来的东西**。V0.1.12 把 Effect 拆成两个明确子类，把 V0.1.11 的 Effect 词汇全部接住：

| 子类 | 语义 | 例子 |
|------|------|------|
| **增强型 (Enhancement)** | 改**这次按键的核心技能本身**的表现 | +120% 伤害、改火属性、单体→链锁、直线→环绕、最近→最远、瞬发→蓄力、释放时回血/护盾 |
| **附加型 (Add-on)** | 这次按键**额外放一个独立世界效果**，跟核心技能并行 | 附加范围爆炸、附加落雷、附加毒雾、附加召唤傀儡、附加突刺位移、附加眩晕 |

两者都在 Consume 时生效。区别只是：增强型改"这次核心技能打出去是什么样"，附加型是"核心技能打出去的同时，旁边再多放一个东西"。

**增强型 Effect 子类**：

| 子类 | 说明 | 示例 | 常用标签 |
|------|------|------|---------|
| **增伤倍率** | 乘到核心技能伤害上 | +120% 伤害、暴击伤害 +50% | Damage / Scaling |
| **改元素** | 覆盖或附加核心技能的元素与异常 | 改为火属性、附加寒冰减速、附加易伤 | Element / State / Debuff |
| **改形态** | 改变核心技能的覆盖方式 | 单体→链锁、直线→环绕、追加投射物、扇形→圆形 | Chain / Projectile / Area |
| **改目标** | 改变目标选择逻辑 | 最近→最远、单体→范围、前方→周围 | Targetable |
| **改节奏** | 改变核心技能的释放节奏 | 瞬发→蓄力、追加段数、追加后摇爆发 | Charge / Cooldown |
| **自益** | 消费时给玩家生存收益 | 释放时回血、附加护盾、短暂无敌 | Defense / Heal / Buff |
| **状态操作** | 消费时操作已有状态或资源 | 引爆种子、刷新层数、获得充能、刷新闪避 | State / Consume / Charge |

**附加型 Effect 子类**：

| 子类 | 说明 | 示例 | 常用标签 |
|------|------|------|---------|
| **附加伤害** | 在核心技能命中点/目标处 spawn 一个独立伤害效果 | 附加范围爆炸、附加落雷、附加冲击波 | Damage / Area / Burst |
| **附加场物** | 消费时 spawn 一个持续存在的单位或区域 | 附加召唤傀儡、附加炮台、附加毒池、附加陷阱 | Summon / Object / Area |
| **附加位移** | 消费时给玩家附加一次位移 | 附加突刺、附加闪现、附加拉拽敌人 | Mobility / Position |
| **附加控制** | 消费时在命中点附加独立控制效果 | 附加眩晕、附加击退、附加冰冻 | Control / Debuff |
| **附加 DoT** | 消费时在命中点附加持续伤害区域 | 附加毒雾、附加火墙、附加雷域 | DoT / Area |

**字段语义双轨**：`ChainConfig.damage` 在两种子类下含义不同——增强型 = `damageMult`（乘到核心技能伤害上，1.2 = +20%），附加型 = 附加效果自身的伤害（附加落雷打多少）。Effect SO 需声明 `effectRole`（Enhancement / Addon），装配 UI 据此显示"增强"或"附加"角标。

**设计边界**：
- 链不再当主伤害来源。纯召唤 / 纯位移 / 纯范围 DoT 流派以**核心技能**为主体（详见 5.12），链只做附加或增强。
- 一个 Effect 应当能用一句话说清"消费后这次按键多出了什么"。
- 增强型与附加型可在同一链中由改造件互相转换（如"附加落雷 → 增强为链锁落雷"），但单个 Effect SO 只能是其中一种角色。

### 5.5 改造件分类 (Modifier Types)

改造件是原"宝石 / 槽位修饰"的重定位。它们不作为独立系统出现，而是作为增强链的第三层，调整**加成的形态与强度**。

| 子类 | 作用 | 示例 | 兼容规则 |
|------|------|------|---------|
| **形态改造** | 改变加成覆盖方式 | 爆炸 → 火墙；附加范围 → 环形范围；落雷 → 雷域 | 需要 Area / Projectile / Object 标签 |
| **目标改造** | 改变加成的目标选择 | 单体加成 → 链锁加成；最近敌人 → 最远敌人；前方 → 环绕 | 需要 Targetable 或 Projectile 标签 |
| **数量改造** | 改变加成的次数或投射物数 | 额外触发 1 次加成；投射物 +2；附加爆炸 +1 | 需要可重复执行的效果 |
| **节奏改造** | 改变 Proc / Consume 的节奏 | Single → Window；Stacks 上限 +2；Proc 概率 +20% | 需要 consumeKind 字段 |
| **状态改造** | 附加元素、异常或状态交互 | 加成附带火焰、寒冰、雷击、毒蚀、击退、易伤 | 需要 Damage / Control / State 标签 |
| **槽位改造** | 根据模块相邻位置改变收益 | 左侧强化、右侧强化、双重投射、上下联动 | 属于环境型改造件，需要读取槽位布局和相邻模块标签 |
| **代价改造** | 用风险换强度 | 消耗生命提高加成；延长重新 Proc 换范围；降低防御换连锁 | 必须明确代价、上限和 UI 提示 |

**设计边界**：
- 改造件不提供独立长期成长，长期强化交给局外解锁的模块 / 解锁节点。
- 改造件不单独占用一个系统入口，统一在技能模块界面内配置。
- 改造件可以来自局内掉落、模块经验标签解锁、前哨改造或特殊事件。
- 如果一个改造件只能写成 `伤害 +10%`，它就不该成为改造件；至少要改变形态、目标、节奏或策略。
- 改造件分为**依附型**和**环境型**。依附型只读取被连接模块；环境型可以读取相邻模块或槽位布局，但必须在 UI 上高亮影响范围。

> **V0.1.12 实现状态**：已落地改造件 SO 清单（8 个）——`M_伤害强化`(DamageScale, 数量改造, 伤害×1.4) / `M_扩散`(RadiusScale, 形态改造, 范围×N) / `M_连锁`(CountScale, 数量改造, 投射发数×N) / `M_额外飞弹`(ExtraProjectile, 数量改造, +N 发) / `M_链锁弹射`(TargetChain, 目标改造, 命中后寻敌反弹 2 次，搜索半径 9、伤害衰减 0.8/跳、不重复命中) / `M_环绕射击`(TargetSurround, 目标改造, 360° 均分环绕发射，至少 8 发) / `M_余烬地带`(Sustained, 节奏改造, 落点持续地带 4s/0.5s tick/每 tick 35% 技能倍率 DoT + 附加状态) / `M_延迟轰爆`(DelayedBlast, 节奏改造, 落点 0.8s 预警延迟重爆 ×1.5 + 元素 + 附加状态)。**V0.1.13 补齐**：`TargetFarthest`（`M_远锁`：挂载且非环绕时核心投射技锁定 22m 内最远敌，否则保持鼠标瞄准，化解语义冲突）与 `ShapeWall/Ring/Zone`（`M_火墙`平行成墙 / `M_火环` 360° 外散 / `M_火域` 飞弹落点生成持续区域，程序化表现）已全部落地，形态/目标改造件不再有 no-op。

### 5.6 消费模型 (consumeKind)

V0.1.12 用 `consumeKind` 取代 V0.1.11 的"被动 / 主动执行模式"。**所有增强都由玩家按键消费**，区别只在"就绪后能消费几次、持续多久"。这是模块链属性，由触发器声明，装配 UI 直接标注。

| consumeKind | Proc 后表现 | 消费方式 | 重新 Proc 时机 | 适用 Trigger |
|------|-----------|---------|--------------|---------|
| **Single** | 增强就绪，图标冒火 | 下次按下对应技能生效 1 次 | 消费后重新累计 Proc 条件 | 受击、暴击、击杀、每 N 秒 |
| **Window** | 增强就绪，图标边框出现倒计时环 | 就绪后 N 秒内按下都生效（仅首次按下消费） | 窗口结束（无论是否消费）重新累计 | 长 CD 周期、移动 N 米后、阶段事件 |
| **Stacks** | 增强就绪，图标显示当前层数角标 | 每按一次对应技能消耗 1 层、附加 1 次加成 | 持续 Proc 累层至上限 M | 连击 N 次、命中累加、持续战斗 |
| **Auto** | Proc 即自动释放绑定的核心技能（带增强） | 无需按键，自动消费 | 自动消费后重新累计 Proc 条件 | 挂机 build、辅助光环、低频自动补刀 |

**规则**：
- Single / Window / Stacks 由玩家主动按键消费，战斗主导权在玩家手里。**Auto 是例外**——保留 V0.1.11"条件满足自动释放"的被动 build 原型，玩家放弃手动择时机换取 hands-free 操作。Auto 链增强的仍是绑定的核心技能（自动触发该技能的释放 + 增强注入），不是链独立放自己的效果。
- 一条增强链的 `consumeKind` 由其触发器声明，整条链共享；效果器与改造件可以读取该字段调整自身行为（如"仅在 Single 模式下 +50% 强度"）。
- Demo 阶段不开放局内自由切换 `consumeKind`，由设计表绑定到触发器，避免 UI 与数值复杂度失控。
- 装配 UI 必须在链卡片上明确标注 `[单发]` / `[窗口 5s]` / `[叠层 ×3]` / `[自动]`，零猜测。

> 历史：V0.1.11 的"被动模式（条件满足自动释放）"在 V0.1.12 中保留为 `Auto` consumeKind，作为可选的挂机 build 原型；其余三种 consumeKind 把消费权交还玩家按键，解决"装配即战斗"的方向性问题。

> **V0.1.12 实现状态**：四种 consumeKind 状态机全部落地——Single / Window / Stacks 由 `TriggerTracker` 实现累计→就绪→消费循环；Auto 由 `ModuleSlotManager` 自动触发回调 → `PlayerCombat` 自动释放绑定技能 + 增强注入。`windowSeconds` / `maxStacks` 字段已支持。`TriggerTracker` 暴露 `ThresholdProgress` 供 HUD 读取充能进度。**V0.1.13 补齐**：consumeKind 身份加成三角已接线——Single 增伤 ×1.25 / Window 增伤 ×1.10 + 范围 ×1.20 / Stacks 中性（收益在层数）/ Auto 增伤 ×0.80，同源系数作用于增强+附加字段，装配 UI 链预览显示「◇ XX 联动」提示。

### 5.7 模块配置字段规范

后续策划表中，每个模块至少需要配置以下字段：

| 字段 | 说明 |
|------|------|
| **ID / 名称** | 唯一 ID 和展示名 |
| **模块大类** | Trigger / Effect / Modifier / Universal |
| **子类** | 使用上文分类，例如战斗行为触发、增伤输出、目标改造；万能件声明双面子类 |
| **标签** | 用于兼容、掉落、推荐和局外解锁 |
| **稀有度** | Common / Rare / Epic / Legendary，用于掉落价值和强度预期 |
| **基础参数** | 伤害、范围、持续时间、层数、冷却、触发阈值等；万能件需分别声明触发面/效果面参数 |
| **effectRole**（仅效果器） | Enhancement（增强型，改核心技能）/ Addon（附加型，spawn 独立效果）；决定 `damage` 字段语义 |
| **damage 双语义** | 增强型 = 伤害倍率（1.2 = +20%）；附加型 = 附加效果自身伤害 |
| **consumeKind**（仅触发器） | Single / Window / Stacks / Auto；Window 需配 `windowSeconds`，Stacks 需配 `maxStacks` |
| **兼容条件** | 可连接哪些模块标签，不能连接哪些模块标签 |
| **掉落来源** | 普通房间、精英房、商店、事件、Boss、前哨补给 |
| **解锁条件** | 默认开放、经验值解锁、Boss 解锁、剧情解锁 |
| **解锁项** | 局外解锁该模块所需的条件（当前模块不可数值升级） |
| **UI 描述** | 玩家能直接看懂的一句话效果 |

### 5.8 插槽与组合逻辑 (Socket Logic)

每条增强链**挂在 Q/E/R 三个核心技能槽位之一**。基础规则只允许一条清晰的模块链：

```text
[核心技能槽位] ← 挂载 ← [触发器 Trigger] → [效果器 Effect] → [改造件 Modifier 0-2 个]
```

| 连接方式 | 规则 | 是否属于基础规则 |
|---------|------|----------------|
| **链 ↔ 技能绑定** | 一条增强链挂在一个核心技能槽位；一个技能最多挂一条链 | 是 |
| **主链连接** | 1 个触发器连接 1 个效果器，形成可消费的增强 | 是 |
| **改造连接** | 0-2 个改造件依附在触发器或效果器上，改变加成行为 | 是 |
| **环境读取** | 环境型改造件读取相邻模块标签或槽位位置 | 是，但仅限明确标注的改造件 |
| **万能件占位** | 万能件可放入触发器槽或效果器槽，承担对应槽位职责 | 是 |
| **裸技能** | 未挂链的核心技能槽位仍可释放裸技能，无加成 | 是 |

普通增强链只产生模块描述中的基础加成。

> **V0.1.12 实现状态**：`ModuleSlotManager.EquipChain` 接受部分链（仅触发器 / 仅效果器）并持久化，但 `_hasChain[slot]` 与 `_trackers[slot]` 仅在链 `IsValid` 时才置真。允许装配 UI 显示「待补」状态，避免测试中误丢模块。

### 5.9 局内重组（自由拼装）

增强链上的每个模块都可在**非战斗状态下随时重组**，无需任何代价：

| 操作 | 规则 |
|------|------|
| **取出 / 替换** | 链上任意模块可取出到背包，空槽可放入任意同类模块（万能件可放入触发器或效果器槽） |
| **链 ↔ 技能换绑** | 整条链可从一个核心技能槽位换挂到另一个；一个技能最多挂一条链 |
| **丢弃** | 模块可扔到地上，作为可拾取场物保留，玩家可随时走过去捡回 |
| **时机限制** | 仅非战斗状态（含休息房）可重组；进入战斗后链锁定，避免战斗中临时换链破坏节奏 |
| **槽位约束** | 替换仍需满足槽位职责：触发器槽只接受触发器或万能件，效果器槽只接受效果器或万能件 |

> 设计意图：拼错零惩罚。玩家可大胆尝试任意增强组合，不满意的随时换、随时扔、随时捡回，鼓励自由探索而非保守取舍。

> **V0.1.12 实现状态**：`ModuleAssemblyUI` 已重做——卡片网格背包 + Q/E/R 三列竖向链布局；含全息预览、人类可读链效果预览、安装 toast（链激活 / 还差 X 成链）、三态配色（已激活 / 待补 / 空）、拖拽安装/卸载、明确「安装/卸载」提示；`GetBoundCoreSkillName` 显示链当前绑定的核心技能。`Demo1Setup` 保证开局 Q/E/R 三个核心技能无空窗（未配置则从 `Data/Skills` 兜底挑选）。**V0.1.13 补齐**：模块占位图标改为按子类单字字形 + 元素/类别配色兜底（仍非真图美术，但已有辨识度）；起始模板系统已实现——`StartTemplate` SO + `StartTemplateSelectUI`（UITK，主菜单「开始」弹出）+ 3 默认模板（近战爆发/元素范围/投射连锁），选中重装 3 技能 + 应用档案 + 发起手模块，取代旧化身开局差异化。

### 5.10 万能件 (Universal Module)

万能件是第四类模块，没有固定职责，**放入哪个槽就承担哪个槽的职责**，是自由拼装的核心扩展件。

**核心规则**：

| 规则 | 说明 |
|------|------|
| **槽位决定职责** | 放入触发器槽 → 当触发器（只提供 Proc 条件/状态载体，不含主要伤害）；放入效果器槽 → 当效果器（定义消费时附加的增伤/元素/控制等结果） |
| **双面配置** | 同一万能件内部同时声明"作为触发器时如何"与"作为效果器时如何"两段描述，只有匹配当前槽位的那段生效 |
| **职责守恒** | 当触发器时仍遵守 5.2/5.3 触发器边界（不负责主要伤害），当效果器时遵守 5.4 效果器边界；槽位裁剪其可用能力，不破坏现有分类规则 |
| **稀有度** | 因双面配置更灵活，默认偏高稀有度（Rare 起），避免开局满手万能件削弱流派感 |
| **不可改造件槽** | 万能件只能放入触发器槽或效果器槽，不能放入改造件槽 |

**例子**：
- 万能件"种子/引爆"放入触发器槽 → 当"种子生成"触发器，只显示种子落点、不造成伤害。
- 同一件放入效果器槽 → 当"种子引爆"效果器，消费时引爆种子状态造成伤害收割。
- 一条链 `万能件(当触发器: 闪避后·Window 5s) → 万能件(当效果器: 改为火属性)` 挂在「突刺」上 = 闪避后 5 秒内按下突刺附带火属性，整条链完全由万能件组成。

**设计边界**：万能件提供的是"同一件多用途"的便利与组合弹性，不应当作数值更强的双料件；当两个位置的能力不应同时生效。

### 5.11 操作模型

```
【近战普攻】—— 鼠标左键，三段连招
  → 三段连招：Attack1 → Attack2 → Attack3
  → 段伤害倍率：1.0 / 1.2 / 1.5
  → 基础动作时长：0.4s / 0.4s / 0.5s
  → 攻速加成上限：150%
  → 扇形判定：半径 2.5，角度 120°
  → 攻击中"霸体"：轻击受击不打断连招
  → 250ms 输入缓冲：流畅连段
  → 每段带前冲 Lunge 位移

【核心技能 × 增强链】—— Q / E / R 三个槽位
  → 每个槽位装一个核心技能（起始固定 3 个，关卡内可替换）
  → 每个槽位最多挂一条增强链：[触发器] + [效果器] + [改造件 0-2]
  → 战斗中走位/攻击/受击让某条链上膛（Proc），对应技能图标冒火
  → 玩家按下该技能消费增强（Consume），技能附带加成释放
  → 裸技能（无链）也可正常释放，无加成
  → 一个技能最多一条链；不同技能链互不干扰

【闪避】—— Space 键
  → 距离 5 单位，持续 0.2s
  → 无敌帧共 0.3s：闪避前摇 0.05s + 闪避持续 0.2s + 收尾 0.05s
  → 2 层充能，每层 CD 1.5s；模块可临时提高到最多 4 层
```

### 5.12 核心技能 (Core Skill)

核心技能是玩家**主动按键释放**的招式，是战斗的主导层。模块增强链挂在核心技能上做加成（详见 5.1）。

| 维度 | 规则 |
|------|------|
| **槽位** | Q / E / R 三个核心技能槽位 |
| **起始配置** | 测试版开局固定给 3 个核心技能（保证无空窗、即开即玩） |
| **关卡内获取** | 通过 SkillPickup 拾取新核心技能，可**替换**某个槽位的现有技能；旧技能丢弃到地上可捡回 |
| **链绑定** | 每个核心技能槽位最多挂一条增强链；换技能时链可保留或一并卸下到背包 |
| **裸技能** | 未挂链的核心技能可正常释放，仅无加成 |
| **核心字段** | 伤害倍率、动作时长、动画、目标选择基础规则（最近敌人 / 自身 / 方向锥等）、冷却 |

**核心技能池需覆盖 Build 原型**：V0.1.12 链永远依附一次核心技能按键，纯召唤 / 纯位移 / 纯范围 DoT 流派不再以链为主体，必须由对应的核心技能承载。起始 3 个 + 关卡内 SkillPickup 池应共同覆盖以下原型，避免某些 build 路线无核心技能可挂：

| Build 原型 | 对应核心技能示例 |
|------|---------|
| 直伤近战 | 剑气、横扫、突刺 |
| 直伤远程 | 落雷、火球、箭雨 |
| 范围 DoT | 毒雾、火墙、雷域 |
| 召唤 | 召唤傀儡、炮台部署 |
| 位移 | 闪现突进、拉拽牵引 |
| 控制 | 重击眩晕、冰冻震击 |
| 自益 | 治疗祷言、护盾姿态 |

每个原型至少 1 个核心技能可选；关卡内 SkillPickup 池按层数解锁更高级原型技能。

**核心技能 vs 增强链 的职责切分**：
- 核心技能决定"我按下 Q 大致会发生什么"（一个完整的招式：动画 + 基础伤害 + 基础目标选择）。
- 增强链决定"这次按键比平时多出了什么"（增伤倍率、附加效果、形态扩展）。
- 核心技能不依赖增强链存在；增强链离开核心技能无意义。

> **V0.1.12 实现状态（核心技能实现字段）**：

### 5.13 增强就绪视觉标识 (Proc VFX)

Proc → Consume 模型要求玩家**清晰感知"现在哪个技能可以爆了"**。视觉标识是这个模型的必要锚点，不是装饰。

**主指示器：角色旁三竖条（最小可玩版本核心）**

| 维度 | 规则 |
|------|------|
| **位置** | 角色右侧（或头顶）浮空，World Space Canvas，billboard 始终面向摄像机 |
| **结构** | 3 个竖条并排，左→右对应 Q / E / R；每条底部一个小字键名（Q/E/R） |
| **实现** | 1 个 World Space Canvas + 3 个 Image（Filled vertical）+ 3 个 Text；订阅 `ModuleChainChanged` 事件刷新；按 Effect 元素配色（火=橙红 / 雷=蓝白 / 冰=青 / 范围=黄 / 控制=紫） |

**状态映射**：

| 状态 | 表现 |
|------|------|
| 无链 / 未 Proc | 竖条暗灰 |
| `Single` 就绪 | 整条亮起，Effect 元素色，呼吸光（sin 驱动 alpha） |
| `Window` 就绪 | 整条亮起，填充从满到空随窗口倒计时下沉 |
| `Stacks` | 竖条按层数比例分段填充（1/M、2/M…M/M），每层一段 |
| `Auto` 触发 | 整条闪亮一次后熄灭（表示自动消费了） |
| 消费后 | 回到暗灰 |

**优点**：余光可一眼看出"哪个技能可以爆了"、三条同时可见信息密度高、按 Effect 元素配色统一认知、实现成本低。

**HUD 图标层（可选补充）**：技能图标在 HUD 上同步显示就绪状态（边框变色 / 角标 / 倒计时环 / 层数），供玩家需要精确查看时使用。如果与三竖条重复信息过多，Demo 阶段可只做三竖条、砍掉 HUD 图标变色以减少 UI 噪音。

**消费爆发层**（后续版本，最小可玩不做）：按下消费瞬间，对应竖条爆闪 + 角色身上特效一闪 + 屏幕轻微震动，作为爽点收尾。

**装配 UI 联动**：装配台预览链时，应静态展示该链 Proc 就绪后的三竖条样式（变色 + 填充），让玩家"装配时就知道战斗里会看到什么"。

> **V0.1.12 实现状态**：`ProcBarsHUD` 已落地——屏幕空间 overlay 跟随角色，按 Q/E/R 显示三竖条；状态映射实现无链/未 Proc（暗灰）、Single 就绪（元素色 + 呼吸光）、Window 就绪（填充随窗口倒计时下沉）、Stacks（按层数比例分段填充）、Auto 触发（闪亮一次后熄灭）、消费后（回暗灰）；元素配色 火=橙红 / 雷=蓝白 / 冰=青 / 范围=黄 / 控制=紫；由 `Demo1Setup.CreateHUD` 挂到 GameCanvas。**V0.1.13 补齐**：消费爆发层已实现——`PlayConsumeBurst` 在任意 Proc 被消费瞬间（Enhancement/Addon 皆触发）产生元素色爆闪点光 + 特效环 + 按 consumeKind 分级震屏（Single/Window 中震、Stacks/Auto 轻震），程序化零美术。

## 6. 局内协同（预留）

本版**暂不设独立的隐藏组合系统**。原"隐藏组合/Synergy"机制已移除，相关质变效果后续可通过以下途径承载（具体设计待定）：

- **特殊道具**：触发并升级某些特定模块组合。
- **装备系统**：通过装备的特殊机制产生组合质变。

普通模块链只产生模块描述中的基础效果，不再有"满足额外条件产生质变"的隐藏层规则。后续如恢复协同系统，再单列章节。

## 7. 关卡设计

### 7.1 房间类型

| 房间 | 作用 | 主要产出 |
|------|------|---------|
| **普通战斗房** | 基础战斗与模块掉落 | 普通模块、经验值 |
| **精英房** | 高风险高收益挑战 | 高稀有度模块、Boss 来源标签经验 |
| **事件房** | 提供取舍、代价、特殊模块线索 | 特殊模块、情报标签经验 |
| **商店房** | 消耗局内货币换模块或治疗 | 指定模块、回血、刷新机会 |
| **休息房** | 低压恢复和调整 Build | 治疗、模块替换、前哨补给 |
| **Boss 房** | 阶段目标和通关门槛 | 高倍率结算、Boss 标签经验、剧情推进 |

### 7.2 层级结构

一局暂定 6 层，每 2 层出现一次阶段返回点，第 6 层为 Boss 突破挑战。玩家可以在阶段返回点按 1.0x 结算离开，也可以继续推进获取更高通关倍率。

### 7.3 难度递增

- 敌人生命、伤害、数量随层数递增。
- 难度增长应主要来自行为变化，而不是单纯数值膨胀。

### 7.4 自适应怪物生态（反制系统）

怪物会根据玩家的 Build 进化出对抗机制，使"自适应怪物生态"从卖点落到具体规则。核心是不让玩家一套 Build 通关到底，但也不让 Build 直接报废。

**反制判定**：系统读取玩家当前已装配模块的标签（伤害来源、形态、节奏），从反制池中挑选匹配机制投放，随层数提高反制强度与频率。

| 玩家 Build 特征 | 可能投放的反制机制 |
|----------------|------------------|
| 远程 / 投射物为主 | 自动闪避投射物、投射物偏转、近身冲锋 |
| 召唤 / 场物为主 | 范围清场技能、对召唤物的溅射、召唤物上限削减 |
| 持续伤害 / DoT 为主 | 高频净化、移除状态、护盾抗持续伤害 |
| 高爆发 / 蓄力 | 打断施法、压制窗口、强制位移打断节奏 |
| 依赖触发条件（闪避/受击） | 反触发：骗触发后反制、降低有效触发次数 |

**三条设计边界**（防止反制把玩家逼死）：

1. **反制不等于免疫**：反制机制压制某类 Build 的效率（如降低命中、削减收益），但**不免疫**该伤害类型——玩家的核心输出仍能打掉血，只是更费力。绝不出现"纯远程 build 对某怪 0 伤害"的情况。
2. **反制有预告与窗口**：反制机制通过怪物行为预告（如蓄力姿态、特效），玩家可主动规避或换策略，而非隐形惩罚。
3. **反反制手段**：玩家可通过**局内重组换链**（5.9）调整 Build、或在掉落中获取针对性改造件 / 万能件应对；不要求玩家带"全 Build"以防被反制，鼓励动态调整而非预先堆抗性。

**投放节奏**：
- 普通房：偶发轻反制，提示玩家 Build 有盲区。
- 精英 / Boss：定向反制玩家主输出标签，但保留可被换链破解的弱点。
- Boss 阶段切换时可更换反制机制，考验玩家是否能在阶段间快速重组。

> 设计目标：让"自适应怪物"成为推动玩家**用自由拼装动态应对**的压力源，而不是惩罚特定流派的墙。反制的存在恰恰凸显 5.9 局内重组的价值。

## 8. 经济与资源

### 8.1 资源层级

| 资源 | 类型 | 是否带出本局 | 用途 |
|------|------|-------------|------|
| **经验值** | 局外通用资源 | 是，按结算倍率折算 | 模块解锁、剧情推进 |
| **来源标签** | 经验值标签 | 是 | 决定经验值倾向，例如模块、探索、Boss、情报 |
| **局内货币** | 本局临时资源 | 否 | 商店购买、刷新、治疗 |
| **模块** | 本局 Build 部件 | 默认否 | 构成本局技能链 |
| **情报** | 线索型来源标签 | 是 | 解锁 Boss 线索、特殊模块提示、剧情节点 |

### 8.2 模块掉落与推荐

模块掉落采用“基础权重 + Build 相关性 + 保底修正”的方式：

```text
最终权重 = 基础权重 × 稀有度权重 × 来源权重 × Build 相关性 × 保底修正
```

| 因素 | 规则 |
|------|------|
| **基础权重** | 每个模块表内配置 |
| **稀有度权重** | Common 高、Legendary 低 |
| **来源权重** | 普通房偏基础模块，精英 / Boss 偏高稀有度模块 |
| **Build 相关性** | 当前已装配标签越匹配，权重越高，但不超过 2.0x |
| **保底修正** | 连续 3 次未出现可用效果器时，提高效果器权重 |

推荐逻辑只影响候选池权重，不强制玩家进入固定流派。

## 9. 术语表

| 术语 | 定义 |
|------|------|
| **模块** | 局内 Build 部件总称，分触发器、效果器、改造件、万能件 |
| **触发器** | 定义发动条件或状态载体，不提供伤害、治疗、控制 |
| **效果器** | 定义发动后的结果，例如伤害、治疗、位移、控制 |
| **改造件** | 改变触发器或效果器的形态、目标、数量、节奏、代价 |
| **万能件** | 无固定大类的模块，放入触发器槽即当触发器、放入效果器槽即当效果器，槽位决定其职责 |
| **局内重组** | 非战斗状态下随时取出 / 替换 / 丢弃链上模块的自由拼装机制 |
| **前哨** | 局外配置、局内消耗的临时支援点，用于补给、休息或调整模块 |
| **容错强化** | 提高单局容错的局外成长项，例如复活次数、死亡后保留部分结算倍率 |
| **情报** | 来源标签之一，来自事件、Boss 线索、隐藏房和剧情节点 |
| **阶段返回** | 关卡中途主动结束本局并按 1.0x 结算 |

### 11.2 版本确认事项
每次进入新的版本制作时，需要与制作人员确认版本中可能会出现的问题，以及根据不明确和清晰的需求提出问题并且反馈回制作人员进行回答确认；

#### 11.2.1 表格使用说明
- **适用范围**：每次进入新版本（如 V0.1 → V0.2）时，由策划/程序将本轮版本中不清晰的需求、潜在风险、待确认设计点整理为问题条目；
- **流转方式**：提出问题 → 制作人员（策划/美术/程序对应方）在「确认结论」栏填写答复 → 答复确认后归档为设计依据；
- **状态字段**：`待确认` / `已确认` / `已搁置` / `已废弃`；
- **优先级**：`P0 阻塞` / `P1 重要` / `P2 一般` / `P3 优化`；
- **新增条目**：在对应版本表格末尾追加新行，**不要覆盖**已确认条目（已确认条目作为后续设计依据留痕）。

### 11.4 V0.4.1 版本计划
>本次V0.4.1版本主要围绕关卡调整，将本来的肉鸽关卡设计思路转变为《卡厄斯梦境》或《白荆回廊》这种培养出存档带出来在去另外一个关卡进行数值验证的模式；

简述：玩家开局在局外，随后选择进入肉鸽关卡，并在肉鸽关卡中选择随机出现的技能、模块等进行自己的BD构筑（流程与之前相似），随后玩家死亡或主动退出后，保留玩家在局内的BD构筑并带出至局外，随后该BD则作为类似装备的功能，而玩家带出BD后，即可参加局外额外新增的关卡，关卡设计需要类似《暗黑破坏神3》的大秘境模式，层数不限（局外BD验证），而通关大秘境还可以获得局外的强化材料、天赋点等等让玩家可以在肉鸽关卡中可以组合出更好的BD，从而形成循环，那么以下开始针对功能进行详细说明；

#### 11.4.1 局外调整
1. 目前仍旧维持局外的安全屋设计，但房间右边需要添加一个新的入口，也就是简述提到的大秘境关卡；
1.1 玩家初次进入游戏时无法进入大秘境关卡，必须要有局内BD后才可进入；
1.2 大秘境内部跟局内一样有一个缓冲区域，区域内全是大秘境相关的系统，目前暂先添加一个装备BD的系统功能，玩家可以通过该系统查看局内携带出的BD进行装备，完成装备后才可以进行大秘境挑战；

#### 11.4.2 存档功能

1. 现版本中没有存档功能，因此在该阶段可以开始进行制作，存档功能分为两种，一种是保存玩家所有进度的大存档，可以参考《苍翼默示录》的存档功能进行，玩家创建存档→进入游戏→保存当前数据，方式来进行设计；第二种则是简述中提到的局内BD存档，下面开始说明：

1.1 进度存档：保存玩家所有数据的存档功能，玩家在开始游戏后需要选择创建存档，完成创建后才可正式进行游戏；
- 1.1.1 玩家完成进度存档后，游戏开始界面的“开始游戏”上方需要多出“继续游戏”，玩家点击继续游戏后直接进入之前保存的存档；
- 1.1.2 玩家点击开始游戏后需要先进入一个新的创建存档的界面，界面会现实三个“新存档”，玩家点击其中一个即可完成存档创建，创建好的存档需要默认现实在左边第一个，玩家下次进入游戏后如果还点击开始游戏，则现实表现就变成“玩家存档”、“新存档”、“新存档”的顺序，玩家最多一次创建3个存档；
- 1.1.3 若在开始界面玩家点“开始游戏”后，此时玩家已经创建了一个存档在第一个，此时玩家在点击第一个存档，则要弹出提示“是否覆盖存档？”，若玩家点“是”则覆盖之前的存档，之前存档的所有数据都直接删除，若点否则回到原操作；
- 1.1.4 玩家在游玩过程中也需要有自动存档，目前先暂定进入“关卡”即默认触发自动存档，帮玩家覆盖当前进度；

1.2 局内BD存档：局内BD存档与1.1 进度存档 完全不同，局内BD存档指保存玩家在局内中刷去的所有战斗相关数据或者说能力，这项能力可以带出并去进行大秘境的局外挑战，但也仅限于局外挑战，若玩家重新进入局内所有内容还是会刷新；
- 1.2.1 玩家无法穿戴BD进入局内，局内默认为“挂空”状态（不会拥有任何技能，模组等）；
- 1.2.2 玩家局内带出的存档默认保存在“大秘境”缓冲区的装备系统中，可以进行查看和穿戴，但是范围仅限在缓冲区；
- 1.2.3 局内构筑的技能、模组所有内容在玩家达成条件后即可带出；
- 1.2.4 玩家需要完全通关或主动退出后即可完成带出存档操作，主动退出也可以带出BD存档，只是带出的仅是当前进度的BD存档（已有的东西）；

#### 11.4.4 局内调整；
1. 玩家现在初始状态改为无技能，并且当前功能有BUG，进入肉鸽关卡缓冲区后技能三选一的技能没有装备在技能上；
2. 商店添加模组可给玩家进行购买，商店的物品总数扩充至7个；
3. 商店添加通过消耗“基础货币”可进行刷新功能；

#### 11.4.5 局内关卡调整；
1. 局内关卡现在共3层，每层仍旧维持3跳路线，但每条路线需要确保玩家必须走过12个关卡，其中第12关为BOSS关卡，中间则可以是事件关、战斗关、精英关等，而在整条路线中精英关卡不能超过2个，而商店关不能超过4个；
2. 关卡内现改为不在掉落任何东西，每完成战斗、精英、事件后有概率会出技能或模组三选一，选择完毕后进入下一关，事件有固定的BD选项，而战斗和精英则是分别以70%和90%的概率出现三选一；
3. 技能或模组选时，玩家一定要做出选择后才可进入下一关，同时添加一个“退出”按钮用来退出三选一界面，玩家可以不选择任何技能或模组就直接进下一关；
4. 根据2中的设计，新增一个替换功能，若玩家此有装备技能，且已全部装备满，则可以通过按键选择来替换之前的技能，若出现此情况，则需要添加一个额外提示“是否替换当前技能？”若玩家选择是则完成替换，并根据替换折算成货币可以在商店使用，若选择否则无视替换操作；
