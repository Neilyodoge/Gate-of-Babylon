## 1. 产品定义

ProjectR 是一款 PC 单人 Roguelite 3D ARPG。玩家从家园直接选择一个不断变化的秘境区域，探索、战斗并结识灵宠，将它们直接附着到武器、术法与身法动作上，通过“产出／触发／改造”和多宠附着构筑战斗回路，并决定继续深入，还是带着新伙伴安全撤离。主角的种族、背景与身份等待重新设计。

> **当前命名约定**：玩家可见与策划正文统一称“灵宠”；程序类型、存档字段和历史技术记录暂保留 `Spirit*`／“器灵”，待产品命名稳定后再评估迁移。游戏正式名称未定，继续使用 `ProjectR`。

### 创意定位

ProjectR结合《梦之形》式局内技能组合、《宝可梦／洛克王国》式长期伙伴身份与生态亲和感，以及系统化游戏中“产出—触发—改造”的实验乐趣。差异点不是把技能换成宠物，而是让永久灵宠直接改变每局获得的动作，并让探索行为影响秘境区域中的灵宠生态。

### 核心幻想

灵宠是世界各地环境中产生的活性生命，也是拥有长期身份、性格与关系的伙伴。同一只灵宠附着到不同动作会显化为不同玩法，并能与其他灵宠形成新的战斗回路。

游戏持续制造两个问题：

1. 让这只灵宠附着到这个动作上，会发生什么？
2. 继续深入完善构筑，还是先把刚结契的伙伴安全带回家园？

### 目标玩家

- 喜欢探索、收藏、地图彩蛋和环境推理。
- 喜欢组合实验、动作反馈和创造个人Build。
- 喜欢长期伙伴关系，但不想维护复杂流水线。

### 设计支柱

1. 灵宠是完整机制，不是稀有度词条。
2. 构筑是一条能产生、响应、转化并闭合的回路。
3. 探索会改变相邻生态，而不只是选择房间奖励。
4. 灾相有多种解法，不是唯一进度钥匙。
5. 家园增加选择和关系，不提供无限强度。

设计取舍测试：

- 机制行为优先于更高数值。
- 环境线索优先于直接标明奖励。
- 主要成长选择必须改变回路、操作或组合关系。
- Boss准备可以降低门槛，但不能成为指定灵宠硬锁。

### 反支柱

- 不做个体值、完美胚子和强制繁殖。
- 不做三角色轮换战斗。
- 不做持续维护的自动化生产链。
- 不用大量百分比增伤冒充构筑。
- 不要求每局全清或必须击败Boss。
- 不做现实时间等待、永久死亡和强制休息。

### 📊 实现现状

- 已确认：ProjectR 全面替代旧《仙途秘境／秘境探索》产品方向。
- 已有：Unity URP工程、基础动作战斗、敌人、配置和UI基础。
- P0已建立：载体执行契约、Legacy增强快照适配、`CircuitEvent`因果载荷，以及独立的载体／回路／生态开关；该阶段尚未接管运行时行为。
- P1.1已建立：Q／E／R术法通过 `SkillCarrierAction`获得统一可回滚入口；开关默认关闭，具体技能效果仍委托现有实现。
- P1.2已建立：三个术法槽位的充能、逐格恢复、冷却缩减与上限加成由独立 `SkillChargeRuntime`维护；UI继续消费原 `SkillCooldownUpdate`事件。
- P1.3已建立：蓄力槽位、计时和等级推进由独立 `SkillChargeInputRuntime`维护；移动减速、动画和事件仍由兼容门面处理。
- P1.4已建立：`SkillEffectExecutor`接管术法类型分发、蓄力倍率和动画门控编排；具体效果副作用仍由 `PlayerCombat`宿主提供，载体开关关闭时保留Legacy分发路径。
- P1.5已建立：Buff、保命、乾坤倒转和治疗规则由 `ImmediateSkillEffectRuntime`执行；组件、事件与VFX仍通过兼容宿主落地。
- P1.6已建立：持续区域落点／随身判定与召唤参数由 `WorldSkillEffectRuntime`执行；场景查询、实例化和增强注入仍通过兼容宿主落地。
- P1.7已建立：位移距离、目标点、无敌和路径伤害分支由 `DashSkillEffectRuntime`执行；物理查询、移动和命中结算仍通过兼容宿主落地。
- P1.8已建立：范围伤害落点、半径、伤害来源、命中事件和增强追加分支由 `AreaSkillEffectRuntime`执行；物理命中、扣血、元素与世界实例仍通过兼容宿主落地。
- P1.9已建立：投射物目标覆盖、数量、散射、环绕与墙形排布由 `ProjectileSkillEffectRuntime`执行；目标查询、实例、组件初始化和增强注入仍通过兼容宿主落地。
- P1.10已建立：蓄力开始、结束和取消时的移速、进度事件与日志顺序由 `SkillChargeEffectCoordinator`协调；蓄力状态仍由独立输入运行时维护。
- P1.11已建立：普攻输入门控、命中窗口、单段判定锁和第三段回馈由 `MeleeAttackRuntime`编排；物理、伤害、动画与VFX仍通过兼容宿主落地。
- P1.12已建立：近战扇形伤害、伤害转治疗和远程普攻投射参数由 `BasicAttackEffectRuntime`执行；碰撞体、实际扣血、生命事件与实例仍通过兼容宿主落地。
- P1.13已建立：闪避输入优先、方向回退、动画门控、位移状态和逐格充能由 `EvadeCommandRuntime`执行；输入采样、角色移动、事件与无敌仍通过兼容宿主落地。
- P1.14已建立：普攻、Q／E／R和闪避在载体开关开启后分别通过武器、术法、身法 `ICarrierAction`入口；专用运行时继续负责实际规则和资源消费。
- P1.15已接管：载体运行时默认启用，武器、术法和身法正常启动即进入统一入口，G1通过；Legacy回退、回路关闭和生态冻结保持不变。

  → 选择一个秘境区域
  → 探索、战斗、结契

## 3. 玩家操作与基础数值

### 输入

- 普通攻击：当前武器动作。
- 特殊攻击：当前武器的资源、蓄力或姿态动作。
- 术法一、术法二：两个主动能力。
- 身法：闪避、格挡、瞬移或钩索。
- 交互：拾取、机关、结契和撤离。

灵宠不占用额外技能按钮。它们直接附着到已有动作，并在触发时显形、发声或留下清晰笔触。玩家无需理解“载体”这一中间概念。

### 数值原则

- 基础数值用于保证动作手感，不承担构筑深度。
- 主要成长选择必须改变动作、联动或组合关系。
- 局外生命和基础伤害成长总量约10%–15%，快速封顶。
- Boss难度以可观察机制、准备收益和操作空间为主，不以血量膨胀为主。

### 📊 实现现状

- 已有：生命、伤害、暴击、护盾、状态、投射物、HitStop、震屏和伤害数字。
- 待做：特殊攻击统一接口、身法载体化和回路来源追踪。

## 4. 灵宠与结契

灵宠永久保存种族、性格、羁绊、关键关系、动作适应、天赋树开放进度、外观和故事状态。种族决定机制，性格改变时机与风险偏好，不设置传统个体值；程序字段中的“载体适应”和旧悟法池结构暂为兼容命名。

获取路径：

- 战斗降服。
- 性格结契。
- 解谜或剧情结契。
- 腐化净化。
- 灵卵与残器。

局内新灵宠可以收入契匣、临时替换出战灵宠或留在生态区。临时使用的新灵宠只有成功撤离后才进入永久存档。

详见：[灵宠与结契](systems/器灵与结契.md)。

### 灵宠个体与外观变体

- 同一种灵宠可以出现不同花色、纹样、局部轮廓和显化笔触，满足长期收集与个体记忆。
- **普通花色**只改变外观，不影响强度。
- **特殊变体**除明显外观差异外，只允许改变1项技能侧重与1项性格倾向，例如更偏范围、更偏连续触发或更愿意冒险；不得重做整棵天赋树。
- 特殊变体是横向玩法选择，不是传统闪光稀有度的全面数值上位，也不设置反复刷取的个体值。
- 同种变体共享核心机制、动作适应和大部分天赋，只在少量专属节点、初始性格权重或显化表现上分化。

### 三类敌对单位

1. **野生灵宠**：因领地、护幼、饥饿或区域异常与玩家战斗；原则上可降服、安抚或结契，不默认邪恶。
2. **敌对结契者**：与灵宠共同战斗并用灵宠强化自身动作。双方可以是自愿伙伴，也可能强行建立能量连接；该类型与玩家遵循同一套“人行动、灵宠显化”逻辑。
3. **失控附身者（工作名）**：人类意识被异常灵宠或失衡回路压住，身体只剩本能行动。战斗目标优先是打断附身、救回双方，不把这种状态写成所有灵宠都会自然做的事。

首个反复登场的人类团体暂定名为 **“摘星队”**。他们追逐稀有灵宠、遗物和异常现象，行事招摇且经常越界；成员动机和手段并不完全一致，前期可作为麻烦制造者，后续保留“部分行为另有原因、组织并非单纯反派”的反转空间。

### 灵宠天赋树

- 每只灵宠拥有固定天赋树，局外通过共同探索、关系、专属事件和关键战斗永久开放更多可选节点。
- 进入秘境后，灵宠通过杀敌、战斗地点和区域目标获得局内经验；升级时获得天赋点，只能从已开放节点中点亮有限路线。
- 单局预计点亮5～7个节点并最多选择1个终极节点；局内等级、天赋点和点亮结果在单局结束后清空。
- 永久成长扩充可选范围，不让整棵树永久同时生效；原“撤离后保留一项随机悟法进入永久池”方案废止。
- 灵宠改附动作后保留本局天赋；若特定动作节点因此完全失效，可在安全地点免费重选。

详见：[灵宠天赋树](systems/灵宠天赋树.md)。

### 首批三只灵宠原型

以下名称均为工作名，先验证玩法，后续可继续改名：

- **新手初契**：三只幼宠显现后，界面压暗背景并依次只点亮灵宠卡、动作卡和应用按钮，帮助玩家完成第一次赋予。此后面板持续显示，三宠与`LMB / Q / SPACE`可随时切换；任意三种不同组合各在木靶上真实显化一次即可结契。只有确认结契才创建永久实例、写入契匣与序章进度。

- **火花狸〔产出〕**：附着动作直接命中时获得1点热度；3点热度生成1颗火花并清零。由联动追加的伤害不计为直接命中。
- **响响鸮〔触发〕**：友方生成火花时，消耗火花并向附近敌人发射1次回声攻击；首版带独立触发间隔，避免短时间连续刷屏。
- **弹弹胶〔改造〕**：将回声攻击改成可额外弹射1次的攻击；第二次命中后返还火花狸1点热度，但不能直接再次生成火花。

首批联动：

```text
玩家直接命中3次
  → 火花狸产出火花
  → 响响鸮消耗火花并触发回声攻击
  → 弹弹胶把回声攻击改成弹射
  → 第二次命中返还1点热度
  → 玩家再直接命中2次后进入下一轮
```

这是一条需要玩家继续操作才能循环的联动，不会脱离玩家输入无限自转。首批性格差异、专属合击和最终数值暂不确定。

## 5. 动作与回路

玩家拥有武器、术法和身法动作。动作负责玩家执行什么，灵宠负责该动作额外显化什么规则。

### 动作与灵宠的产品边界

- 玩家动作拥有按键、动画、基础目标、基础伤害和冷却；不附着灵宠也能使用。
- 灵宠显化不占独立按键，不能脱离所附着动作主动施放，只改变条件、范围、次数、元素或追加结果。
- 玩家语言统一使用“武器动作／术法动作／身法动作／灵宠显化／回路联动／天赋成长”，不使用“载体”或“灵宠技能”制造额外抽象层。
- 世界内没有通用载体装置。灵宠借结契者主动动作产生的明确意图，将异界规则翻译为当前世界可以接受的结果。

### 回路语言

- **产出**：制造可以被其他灵宠使用的火花、护甲、标记、回声或召唤物。
- **触发**：看到指定事件或产物后，追加一次明确动作。
- **改造**：不能单独启动，只改变正在发生的产物或追加动作。

程序内部枚举暂保留 `Source / Response / Transform`，玩家界面与策划说明不再使用“源／应／化”。

### 附着结构

- **分开附着（`1＋1＋1`）**：三只灵宠分别影响三个动作，联动覆盖面广。
- **双宠同挂（`2＋1`）**：两只灵宠集中改变一个动作，另一只负责接续。
- **三宠同挂（`3＋0`）**：一个动作拥有完整联动，其余动作保持原样。

首批版本中，同一动作挂多只灵宠只表示多条规则同时作用，不额外创造“融合技能”；专属合击等玩家理解基础联动后再设计。

### 局内成长

- 更换动作：改变玩家的基础操作。
- 改附动作：改变灵宠借哪个动作显化，本局已点亮天赋不丢失。
- 灵宠天赋：改变产出什么、怎样触发或如何改造；可选范围永久开放，实际节点局内点亮。
- 动作演变：改变动作本身。
- 灵宠联动：消费其他灵宠产物并累积默契。

通用规则覆盖约80%组合，约20%高契合组合获得专属动作、造型和名称。

详见：[动作与回路](systems/载体与回路.md)。文件名与程序内部 `Carrier*` 术语暂为兼容保留。

### 📊 实现现状

- 可复用：`GameEvents`、`ModuleChain`、`TriggerTracker`、`SkillData`和状态／投射物系统。
- 待重构：`PlayerCombat`拆分；旧模块UI和一技能一链规则。
- 待实现：带来源、标签、因果链和预算的回路事件。

## 6. 单局成长节奏

### 前期：寻找方向（0–10分钟）

获得新动作并完成第一次天赋选择，形成两段互动。改附与替换成本低。

### 中期：接通回路（10–25分钟）

获得更多局内天赋点、默契和特殊动作演变。三只灵宠形成完整连接，新结契灵宠可能迫使玩家重组队伍。

### 后期：觉醒与取舍（25–35分钟）

构筑进入高频循环、三灵共器或强力终结。玩家权衡挑战灾相、继续深入或带着新伙伴撤离。

目标体验：

```text
能互动 → 能连锁 → 能闭环 → 能产生受控的失控爆发
```

### 奖励原则

- 世界中的行为和地点决定主要奖励来源。
- 每2–3区提供一次整备和迁灵机会。
- 前期多给方向，中期多给连接器，后期集中给质变。
- 首个区域采用“世界拾取＋安全点选择”：小材料、动作和事件物直接拾取，路线级整备每完成2–3个地点集中选择一次。

## 8. 灾相

## 10. 美术与音频

整体视觉锚点为轻松、温暖的二维动画背景气质；3D／2.5D实机通过大块色面、圆润剪影和清楚明暗分组拟合该观感。“灵墨显形”负责回路特效辨识：

- 暖色低饱和3D／2.5D手绘箱庭承载世界，轮廓简洁、造型圆润，不走阴暗写实路线。
- 高彩灵宠、交互目标和关键回路承担焦点。
- 每只灵宠使用稳定轮廓、笔触、运动和音效编码。
- 附着的世界空间常驻表现只保留动作部位流动属性特效，不在角色、武器或身体部位显示灵宠图标；灵宠身份与附着关系由现有技能栏／HUD挂件承担。
- 失控附身沿用同一语法，只通过属性流动异常、能量溢出、失焦目光和僵硬动作表达异常。
- 回路传递以短暂墨线和统一符号表示方向。
- 战斗HUD采用紧凑边缘布局；中央战斗区尽量无遮挡。

## 15. 主要风险

- 组合丰富但难理解：回路预览与触发反馈必须与核心战斗同步制作；详细来源数据保留在可选战斗统计中。
- 内容成本乘法增长：通用规则覆盖多数搭配，只给少量高契合组合制作专属动作。
- 灵宠身份被效率吞没：性格、关系和共同经历进入机制，但不能随机破坏一局。
- 秘境探索拖慢节奏：控制地点尺度，提供模糊情报和快捷连接，以环境变化制造软压力。
- 局外成长破坏重置：永久成长主要增加选择，基础数值快速封顶。
