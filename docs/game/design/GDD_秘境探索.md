## 1. 产品定义

ProjectR 是一款 PC 单人 Roguelite 3D ARPG。玩家从家园直接选择一个不断变化的秘境区域，探索、战斗并结识灵宠，将它们直接附着到武器、术法与身法动作上，通过“产出／触发／改造”和多宠附着构筑战斗回路，并决定继续深入，还是带着新伙伴安全撤离。主角的种族、背景与身份等待重新设计。

> **当前命名约定**：玩家可见与策划正文统一称“灵宠”；程序类型、存档字段和历史技术记录暂保留 `Spirit*`／“器灵”，待产品命名稳定后再评估迁移。游戏正式名称未定，继续使用 `ProjectR`。

### 创意定位

ProjectR结合《梦之形》式局内技能组合、《宝可梦／洛克王国》式长期伙伴身份与生态亲和感，以及系统化游戏中“产出—触发—改造”的实验乐趣。差异点不是把技能换成宠物，而是让永久灵宠直接改变每局获得的动作，并让探索行为影响秘境区域中的灵宠生态。

### 核心幻想

灵宠是世界各地环境中产生的活性生命，也是拥有长期身份、性格与关系的伙伴。同一只灵宠附着到不同动作会显化为不同玩法，并能与其他灵宠形成新的战斗回路。

游戏持续制造两个问题：

1. 让这只灵宠附着到这个动作上，会发生什么？
2. 继续深入完善构筑，还是先把刚结契的伙伴安全带回家园？

### 目标玩家

- 喜欢探索、收藏、地图彩蛋和环境推理。
- 喜欢组合实验、动作反馈和创造个人Build。
- 喜欢长期伙伴关系，但不想维护复杂流水线。

### 设计支柱

1. 灵宠是完整机制，不是稀有度词条。
2. 构筑是一条能产生、响应、转化并闭合的回路。
3. 探索会改变相邻生态，而不只是选择房间奖励。
4. 灾相有多种解法，不是唯一进度钥匙。
5. 家园增加选择和关系，不提供无限强度。

设计取舍测试：

- 机制行为优先于更高数值。
- 环境线索优先于直接标明奖励。
- 主要成长选择必须改变回路、操作或组合关系。
- Boss准备可以降低门槛，但不能成为指定灵宠硬锁。

### 反支柱

- 不做个体值、完美胚子和强制繁殖。
- 不做三角色轮换战斗。
- 不做持续维护的自动化生产链。
- 不用大量百分比增伤冒充构筑。
- 不要求每局全清或必须击败Boss。
- 不做现实时间等待、永久死亡和强制休息。

## 2. 核心循环

```text
家园选择3只灵宠与准备
  → 选择一个秘境区域
  → 探索、战斗、结契
  → 获取并更换动作
  → 灵宠升级并点亮本局天赋
  → 接通三宠联动
  → 撤离／深入／挑战灾相
  → 提交灵宠、蓝图与材料
  → 家园关系、天赋开放与下局准备
```

单局目标时长25–35分钟。失败不会丢失已有灵宠；新结契灵宠必须成功撤离才能永久获得。

### 📊 实现现状

- 可复用：基地、场景切换、三槽存档、本局缓存和结算框架。
- 待替换：旧“模块发现—Boss通关—经验结算”循环。

## 3. 玩家操作与基础数值

### 输入

- 普通攻击：当前武器动作。
- 特殊攻击：当前武器的资源、蓄力或姿态动作。
- 术法一、术法二：两个主动能力。
- 身法：闪避、格挡、瞬移或钩索。
- 交互：拾取、机关、结契和撤离。

灵宠不占用额外技能按钮。它们直接附着到已有动作，并在触发时显形、发声或留下清晰笔触。玩家无需理解“载体”这一中间概念。

### 数值原则

- 基础数值用于保证动作手感，不承担构筑深度。
- 主要成长选择必须改变动作、联动或组合关系。
- 局外生命和基础伤害成长总量约10%–15%，快速封顶。
- Boss难度以可观察机制、准备收益和操作空间为主，不以血量膨胀为主。

### 📊 实现现状

- 已有：生命、伤害、暴击、护盾、状态、投射物、HitStop、震屏和伤害数字。
- 待做：特殊攻击统一接口、身法载体化和回路来源追踪。

## 4. 灵宠与结契

灵宠永久保存种族、性格、羁绊、关键关系、动作适应、天赋树开放进度、外观和故事状态。种族决定机制，性格改变时机与风险偏好，不设置传统个体值；程序字段中的“载体适应”和旧悟法池结构暂为兼容命名。

获取路径：

- 战斗降服。
- 性格结契。
- 解谜或剧情结契。
- 腐化净化。
- 灵卵与残器。

局内新灵宠可以收入契匣、临时替换出战灵宠或留在生态区。临时使用的新灵宠只有成功撤离后才进入永久存档。

详见：[灵宠与结契](systems/器灵与结契.md)。

### 灵宠天赋树

- 每只灵宠拥有固定天赋树，局外通过共同探索、关系、专属事件和关键战斗永久开放更多可选节点。
- 进入秘境后，灵宠通过杀敌、战斗地点和区域目标获得局内经验；升级时获得天赋点，只能从已开放节点中点亮有限路线。
- 单局预计点亮5～7个节点并最多选择1个终极节点；局内等级、天赋点和点亮结果在单局结束后清空。
- 永久成长扩充可选范围，不让整棵树永久同时生效；原“撤离后保留一项随机悟法进入永久池”方案废止。
- 灵宠改附动作后保留本局天赋；若特定动作节点因此完全失效，可在安全地点免费重选。

详见：[灵宠天赋树](systems/灵宠天赋树.md)。

### 首批三只灵宠原型

以下名称均为工作名，先验证玩法，后续可继续改名：

- **新手初契**：先通过日常与小事件建立人物和行动理由，再进入5～8分钟的初契与战斗玩法段；从以下3只中选择1只，立即写入永久契匣并设为出战成员，另外2只留给后续常规结契。选择前只展示少量性格与战斗倾向，不安排试玩；叙事开场等待世界观和主线前提确定后再冻结。
- **首次附着**：初契后永久获得可替换的基础Q术法“灵息弹”，并从当前有效的LMB武器动作、Q术法动作和SPACE身法动作中选择一个附着已选灵宠；动作决定触发时机，灵宠决定显化效果，第一次附着可在安全处更换。
- **火花狸〔产出〕**：附着动作直接命中时获得1点热度；3点热度生成1颗火花并清零。由联动追加的伤害不计为直接命中。
- **响响鸮〔触发〕**：友方生成火花时，消耗火花并向附近敌人发射1次回声攻击；首版带独立触发间隔，避免短时间连续刷屏。
- **弹弹胶〔改造〕**：将回声攻击改成可额外弹射1次的攻击；第二次命中后返还火花狸1点热度，但不能直接再次生成火花。

首批联动：

```text
玩家直接命中3次
  → 火花狸产出火花
  → 响响鸮消耗火花并触发回声攻击
  → 弹弹胶把回声攻击改成弹射
  → 第二次命中返还1点热度
  → 玩家再直接命中2次后进入下一轮
```

这是一条需要玩家继续操作才能循环的联动，不会脱离玩家输入无限自转。首批性格差异、专属合击和最终数值暂不确定。

## 5. 动作与回路

玩家拥有武器、术法和身法动作。动作负责玩家执行什么，灵宠负责该动作额外显化什么规则。

### 动作与灵宠的产品边界

- 玩家动作拥有按键、动画、基础目标、基础伤害和冷却；不附着灵宠也能使用。
- 灵宠显化不占独立按键，不能脱离所附着动作主动施放，只改变条件、范围、次数、元素或追加结果。
- 玩家语言统一使用“武器动作／术法动作／身法动作／灵宠显化／回路联动／天赋成长”，不使用“载体”或“灵宠技能”制造额外抽象层。
- 世界内没有通用载体装置。灵宠借结契者主动动作产生的明确意图，将异界规则翻译为当前世界可以接受的结果。

### 回路语言

- **产出**：制造可以被其他灵宠使用的火花、护甲、标记、回声或召唤物。
- **触发**：看到指定事件或产物后，追加一次明确动作。
- **改造**：不能单独启动，只改变正在发生的产物或追加动作。

程序内部枚举暂保留 `Source / Response / Transform`，玩家界面与策划说明不再使用“源／应／化”。

### 附着结构

- **分开附着（`1＋1＋1`）**：三只灵宠分别影响三个动作，联动覆盖面广。
- **双宠同挂（`2＋1`）**：两只灵宠集中改变一个动作，另一只负责接续。
- **三宠同挂（`3＋0`）**：一个动作拥有完整联动，其余动作保持原样。

首批版本中，同一动作挂多只灵宠只表示多条规则同时作用，不额外创造“融合技能”；专属合击等玩家理解基础联动后再设计。

### 局内成长

- 更换动作：改变玩家的基础操作。
- 改附动作：改变灵宠借哪个动作显化，本局已点亮天赋不丢失。
- 灵宠天赋：改变产出什么、怎样触发或如何改造；可选范围永久开放，实际节点局内点亮。
- 动作演变：改变动作本身。
- 灵宠联动：消费其他灵宠产物并累积默契。

通用规则覆盖约80%组合，约20%高契合组合获得专属动作、造型和名称。

详见：[动作与回路](systems/载体与回路.md)。文件名与程序内部 `Carrier*` 术语暂为兼容保留。

### 📊 实现现状

- 可复用：`GameEvents`、`ModuleChain`、`TriggerTracker`、`SkillData`和状态／投射物系统。
- 待重构：`PlayerCombat`拆分；旧模块UI和一技能一链规则。

## 6. 单局成长节奏

### 前期：寻找方向（0–10分钟）

获得新动作并完成第一次天赋选择，形成两段互动。改附与替换成本低。

### 中期：接通回路（10–25分钟）

获得更多局内天赋点、默契和特殊动作演变。三只灵宠形成完整连接，新结契灵宠可能迫使玩家重组队伍。

### 后期：觉醒与取舍（25–35分钟）

构筑进入高频循环、三灵共器或强力终结。玩家权衡挑战灾相、继续深入或带着新伙伴撤离。

目标体验：

```text
能互动 → 能连锁 → 能闭环 → 能产生受控的失控爆发
```

### 奖励原则

- 世界中的行为和地点决定主要奖励来源。
- 每2–3区提供一次整备和迁灵机会。
- 前期多给方向，中期多给连接器，后期集中给质变。
- 首个区域采用“世界拾取＋安全点选择”：小材料、动作和事件物直接拾取，路线级整备每完成2–3个地点集中选择一次。

## 7. 秘境区域

> **首区已解冻（2026-09-08）**：首个垂直切片区域“风痕林谷”的9地点网络、改水传播、目标池、教学撤离和盘根团块已冻结，可进入白盒。其他区域和复杂生态仍保持冻结。

玩家从家园直接选择一个秘境区域。一次探索由9–12个互联地点组成；玩家获得相邻地点的模糊情报，开闸、敲钟、净化、战斗和放生等行为会改变附近状态、灵宠迁移和结契条件。

首区“风痕林谷”使用9个地点和两个短环。旧导流遗构造成溪流倒灌，玩家选择让水回到灵宠栖息地、引入高风险蓄水坑或暂缓处理；该选择同步改变结契、资源、通路和可选灾相“盘根团块”的一处外壳机制。序章后的首次进入只开放5地点教学路线，完成一次安全撤离后再开放完整区域。

- 布局与故事／生态正交。
- Seed可复现。

- 房间状态回访不重抽。
- 实体、碰撞、提示与NavMesh结果一致。

## 11. 垂直切片

必须包含：

- 首批3只灵宠工作原型，验证后扩至4只，每只最终提供2种性格表现。
- 2套武器动作、4个术法动作、2个身法动作。
- 产出／触发／改造与三种附着结构。
- 1个秘境生态区域。
- 3种结契实例。
- 1名敌对御灵者精英。
- 1个失控聚合体灾相。
- 25–35分钟完整单局。
- 轻量家园与完整撤离提交。
- 回路预览、触发反馈和可选战斗统计。

不做繁殖、个体值、自动化生产链、联机、大型主线、多生态区长期内容和现实时间机制。

## 14. 垂直切片验证问题

1. 玩家能否快速说清“它造了什么、谁接着动、谁把动作变了”？
2. 同一灵宠附着不同动作是否明显改变玩法？
3. 三只灵宠能否形成可读且兴奋的联动？
4. 玩家是否愿意在更换动作时重新安排附着？
5. 生态变化是否让结契比普通房间奖励更有意义？
6. 玩家是否会记住具体灵宠个体，而非只比较效率？
7. 灾相回路能否被观察和拆解？

## 15. 主要风险

- 组合丰富但难理解：回路预览与触发反馈必须与核心战斗同步制作；详细来源数据保留在可选战斗统计中。
- 内容成本乘法增长：通用规则覆盖多数搭配，只给少量高契合组合制作专属动作。
- 灵宠身份被效率吞没：性格、关系和共同经历进入机制，但不能随机破坏一局。
- 秘境探索拖慢节奏：控制地点尺度，提供模糊情报和快捷连接，以环境变化制造软压力。
- 局外成长破坏重置：永久成长主要增加选择，基础数值快速封顶。
