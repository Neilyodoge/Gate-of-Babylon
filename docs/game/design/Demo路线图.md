## 项目整体定位（v0.6）

```text
《秘境探索》
= Roguelite ARPG
+ 长局模块化 Build
+ Hades 式局外成长结算
+ Trigger + Effect + Modifier 逻辑拼装
```

**当前取舍**：
- 不再把“搜打撤”作为核心卖点。
- 不再保留独立职业系统，改为起始模板。
- 不再保留独立天赋树，改为模块熟练度 / 解锁节点。
- 不再保留独立宝石系统，改为改造件 / 符文。
- 旧“修仙 / 五系 / 化身”设定只作为历史素材库，不反向约束玩法。

## Demo2 · v0.6 MVP

### A. 模块化技能系统

| 子系统 | 最小可用版 |
|------|-----------|
| **触发器 (Trigger)** | 条件型 + 状态型两类；状态型只提供无伤害状态展示 |
| **效果器 (Effect)** | 伤害 / 治疗 / 护盾 / 位移 / 召唤 / 控制 |
| **改造件 (Modifier)** | 连锁、扩散、次数、目标、范围、执行方式 |
| **主动 / 被动执行** | 被动满足条件自动触发；主动满足条件后点亮 Q/E/R |
| **模块 UI** | 能看懂“触发 → 执行 → 改造”的链路 |

### B. 起始模板

| 模板 | 起始模块 | 目标体验 |
|------|---------|---------|
| **播种者** | 种子生成 + 种子引爆 + 毒雾 / 扩散 | 铺垫后收割 |
| **刺客** | 闪避后 + 背击标记 + 突刺 / 连击 | 位置判断与爆发窗口 |
| **指挥者** | 傀儡计数 + 傀儡协同 + 护盾 / 分流 | 多单位协作 |
| **雷行者** | 移动 X 米 + 闪避成功 + 落雷 / 连锁 | 移动触发与连锁 |
| **守卫者** | 受击时 + 护盾破裂 + 冲击波 / 延时 | 防御反击 |
| **炼金师** | 时间间隔 + 拾取后 + 治疗 / 范围 | 节奏触发和续航 |

起始模板只决定开局，不限制局内转向。

### C. 统一局外结算

| 结算结果 | 经验倍率 | 设计目的 |
|---------|---------|---------|
| **死亡** | 0.5x | 保证失败也有成长 |
| **阶段返回** | 1.0x | 给玩家主动收手的节奏出口 |
| **通关** | 2.0x | 奖励完整长局和高风险挑战 |
| **完美通关** | 3.0x | 奖励高难度表现 |

局外收益统一叫“经验值”。来源标签只影响转化方向，例如战斗、模块、触发器流派、探索、情报、Boss。

### D. 模块熟练度

| 成长对象 | 解锁内容 |
|---------|---------|
| **触发器熟练度** | 条件降低、状态上限 / 持续时间 / 可见性增强、触发变体 |
| **效果模块升级** | 新技能效果、目标逻辑、质变效果 |
| **改造模块升级** | 范围、次数、连锁、延迟等形态变化 |
| **起始模板熟练度** | 开局替换模块、更多初始模块、推荐掉落权重 |

## Demo2 工作顺序

### Week 1-2：系统骨架

1. 定义 `TriggerModule / EffectModule / ModifierModule` 数据结构。
2. 搭 6 个起始模板。
3. 回收旧代码素材：
   - 青囊种子 → 状态型触发器。
   - 影刃位移 / 背击 → 条件与状态触发器。
   - 御物傀儡 → 召唤 / 协同触发器。
   - 剑魄完美时机 → 通用时机触发器素材。
4. 做最小 UI：玩家能看清当前模块链。

### Week 3-4：结算与成长

1. 死亡 / 阶段返回 / 通关统一进入经验结算。
2. 旧撤离点改文案为“返回基地 / 提前结算”。
3. GrowthUITK 回收为模块熟练度 UI。
4. 实现首批熟练度节点。

### Week 5-6：内容与手感

1. 首批模块池扩到可反复游玩的规模。
2. 改造件替代旧宝石/槽位修饰。
3. 模块池按“触发器 / 效果器 / 改造件”补齐掉落权重。
4. 做 8-12 个强记忆点隐藏组合。

### Week 7-8：反制与打磨

1. 自适应怪物第一版。
2. 模块 UI 引导。
3. 掉落权重调参。
4. 录制 Demo 视频。

## 当前决策点

1. 起始模板首批是否只做 3 个，还是补第 4 个“纯法术 / 远程触发”模板。
2. 阶段返回倍率与死亡倍率差距要多大，才能让“返回”仍有意义。
3. 模块熟练度是按单模块升级，还是按模块标签升级。
4. 改造件是否允许多个叠在同一效果器上，还是早期限制 1-2 个避免 UI 复杂。
