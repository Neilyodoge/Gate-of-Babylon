## 📌 项目定位（v0.5.4 重新明确 / 2026-05-28）

> **《仙途秘境》= 玄幻修真主轴（70%）+ 武侠辅料（30%）**
>
> **玩法定位**：**Roguelite ARPG + 搜打撤式秘境探索 + 洞府修炼 meta progression**

### 修仙亚类型选择

中国修仙题材有 6 个亚类型（正统道家 / 武侠仙侠 / 玄幻修真 / 洪荒流 / 现代修真 / 妖修），战斗 / 修炼特色完全不同。本项目**主轴聚焦"玄幻修真"**（《凡人修仙传》《斗破苍穹》《遮天》类型），辅以武侠武学：

| 元素 | 比重 | 体现 |
|------|------|------|
| 玄幻修真 | 70% | 境界（练气→筑基→金丹→元婴→化神→渡劫）/ 灵根 / 渡劫 / 心魔 / 奇遇法宝 / 洞府灵脉 |
| 武侠 | 30% | 化身（剑修 · 剑魄 / 影修 · 影刃 / 御物 · 御物）/ 剑气 / 内力 / 招式感 |

> **v0.5.4 重大调整（2026-05-28）**：彻底移除"现代凡人入梦"框架。原"秘境"改为单纯的修仙秘境（修仙者出洞府闯秘境历练，并非凡人做梦），所有"入梦/梦醒/魂伤"等术语换为修仙原生说法（入秘境/撤离/道伤）。

### 三大循环融合（v0.5 核心架构）

```
☀️ 洞府（闭关修炼 · 灵脉培养 · 长线慢节奏 · 真实修仙体验）
       ↑                    ↓
       │   带回历练值+素材    │   装备入秘境
       │   闭关转化修为       │   选化身 / 选功法
       │                     ↓
🌙 修仙秘境（搜打撤 · 短线高刺激 · Roguelike 战斗）
```

**单局节奏**：1~30 分钟（短局只闯 1~2 层撤离，长局完整通关 6 层 + 渡劫）
**战斗 vs 洞府比重**：约 **7:3**（战斗为主，洞府是补给 + 长线 meta progression）

详见 [Demo 路线图](Demo路线图.md)。

## 📌 阅读指引（v0.2 增量修订说明）

本文是"愿景版 GDD"，描述了《仙途秘境》在完整状态下应该是什么样子。
但项目当前处于 Demo1 阶段，只实现了愿景的一部分。

为了避免新读者把 GDD 误读成"已经实现的规则"，本次（2026-04-28）做了一次**增量修订**：

1. **原文章节保留**，不改设计意图。
2. **每章末尾追加**一个 `📊【实现现状】(2026-04-28)` 引用块，对账：
   - 当前代码做了什么
   - 与 GDD 设计的偏差
   - 调整建议（保留 / 修改 / 推迟）
3. **整章未实现的设计**在标题旁标 `[v0.x 暂未实现]`，方便快速跳过。
4. **末尾新增第 11 节 "GDD ↔ 代码现状对账总表"**，便于快速看全貌。

> **v0.5 深度重构修订（2026-05-16）**：把项目从"修仙皮 Hades Lite" 升级为"真正修仙原生玩法"——加入 4 大修仙独有系统 + 搜打撤秘境探索 + 洞府种田 meta progression。
>
> **v0.5.4 叙事框架重构（2026-05-28）**：彻底去除"凡人入梦"叙事包装。世界设定改为修仙者出洞府闯秘境历练，主角不再是"做梦的凡人"，秘境也不再是"梦境"。游戏名《仙途梦境》→《仙途秘境》。
>
> - **三大循环融合**：玩家在"洞府修炼"（长线慢节奏）和"秘境搜打撤"（短线高刺激）间循环。这是修仙叙事最核心节奏（出洞府 → 闯秘境 → 回洞府修炼），跟搜打撤 + 家园种田底层同构。
> - **灵物分两类**：局内灵物（现有，整局生效撤离后消失）+ 洞府素材（**新增**，需活着撤离才能带回，死亡丢失）。详见第 5 章重构。
> - **撤离机制**：每境界结束有【撤离点】，5s 蓄力撤离回洞府。死亡 → 失去所有洞府素材 + 10% 残念补偿。详见第 8 章重构。
> - **洞府 7 模块**：取代当前抽象 Hub，具体化为修仙概念 —— 灵田 / 炼丹房 / 炼器房 / 灵兽园 / 藏经阁 / 阵法台 / 悟道蒲团。详见第 9 章重写。
> - **修仙独有战斗系统**：~~A 灵气浓度~~（v0.5.4 移除）/ ~~B 顿悟系统~~（v0.5.4 移除）/ C 天劫渡劫 / D 心魔劫。详见第 6.8 章节。
> - **修仙亚类型定位明确**：玄幻修真主轴（60%）+ 武侠辅料（25%）+ 现代框架（15%）。
> - **撤销项**：火属性化身（业火 · 狂战之火）于 2026-05-16 整体撤销，留作未来用 4 大新系统作为载体重新设计。
>
> v0.5 是项目从"换皮 ARPG" 升级到"真正修仙原生 ARPG" 的分水岭。

> **v0.3.1 追加修订（2026-05-06）**：撤销原 v0.3 的"跨元素反应系统"（5.6）。
> - 5.6 节标记为 `已撤销`，保留段头作为撤销记录与替代方向说明。
> - 6.2 / 6.5.5 / 6.7.1 / 6.7.2 / 6.7.3 / 8.2 中所有"元素反应 / 蒸汽爆炸 / 感电 / 烈焰扩散 / 燃烧蔓延 / 导电领域 / 元素类奖励"条目同步移除或改写。
> - 设计上若仍需"跨元素化学反应"的体感，留作 7 章「双系/多系灵物概率触发」类协同来承载，**当前阶段不做**。

> **v0.3.2 追加修订（2026-05-11，2026-05-12 二次细调）**：第 4 章化身系统从"被动数值规则"重设计为"机制版核心机制 + 天赋树"。
> - **核心判定**：v0.3 那 5 个数值规则（穿透 / 清房回血 / 反伤 / 连杀叠攻 / 灵物护盾）本质是被动 BUFF，玩家手指做的动作完全一样，不算"改变玩法"。
> - **新基线**：每个化身的核心机制必须改变玩家"如何战斗"（操作时机 / 输入语义 / 战斗节奏 / 输出来源 / 战斗角色之一）。
> - **机制版**（v0.4.1 后）：金=完美收刀（多场景触发的灵压窗口·节奏/时机）、木=持续寄生（普攻播种 + 技能引爆收割·普攻↔技能强耦合）、水=影息斩（位移即输出）、土=御物斗法（永久傀儡军团 + 傀儡同步释放玩家技能 10% 强度）。火属性化身在 v0.4 实装"业火 · 狂战之火"后于 2026-05-16 撤销，留作未来设计。
> - **天赋树**：每个化身有 5~6 个可解锁天赋节点，强化或变体核心机制（如完美收刀的"大破 / 剑气波 / 流星断 / 御剑回锋"等）。
> - **过渡方案**：v0.3 已实现的数值规则**降级为副词条**（弱化版基础数值底座，不浪费已实现代码）。
> - **变异化身 → 高级化身**：原 4.3 五个变异化身（雷/冰/暗/混沌/无根）核心机制重写为更极端的版本，整体留作 Demo2+ 周目解锁。
>
> **2026-05-12 二次细调（围绕"化身不绑定起始技能"的解耦原则）**：
> - **金 · 灵压窗口扩大**：从"只在三段连招段间"扩大到"普攻段间 / 主动技能后 / 闪避后 / 剑心期间"多场景，玩家裸开也能频繁触发完美收刀。新增天赋节点"窗口绵延 / 窗口共振"。
> - **火 · 怒气主动键**：原"满 100 自动进狂火" → "满 50 主动按 V 开狂火"。**注：此细调于 2026-05-16 随业火化身整体撤销**（详见 v0.4.1 修订）。
> - **土 · 傀儡技能同步**：傀儡新增"玩家释放 Q/E/R 时同步在自身位置重放该技能（×10%）"——傀儡从"占技能位的累赘"变成"技能 build 的放大器"，**5 只满傀儡 ≈ 玩家所有技能 ×1.5 群伤倍率**。
> - **明确决策**：化身不绑定起始技能，由 Demo3 藏经阁负责局前选 1 个初始功法。三个核心机制的细调已确保所有化身在"裸开 + 没有技能"时也能玩出完整体验。
>
> **2026-05-12 第二轮二次细调（针对"普攻↔技能联动"的根本性问题）**：
> - **木 · 持续寄生 ← 御灵自动**：原"自动剑光半挂机"被判定为"主题表达浅 + 加剧 1.7 普攻/技能脱节"，重新设计为"普攻播种 + 技能引爆"——普攻种下种子（×0.1 攻击/s DoT），任意主动技能命中带种子敌人引爆所有种子（每颗 ×0.5 攻击 AOE）。
> - **副产品**：青囊本身成为 1.7 问题（功能缺口归档）的"绝佳样板"——技能数值不需要下调，但"光按 Q/E/R 不打普攻"会直接损失 50%+ 爆发，普攻↔技能强耦合自然形成。
> - **天赋树整体重写**：沃土 / 暴长 / 遍地生花（播种系）、百花齐放 / 死灵种 / 链锁绽放（收割系）、春风又生（节奏）、共生（续航）、绿意盎然（秘传·数量换质量）。
> - **"御灵自动 / 自动普攻"的去向**：保留为未来高级化身（4.6）或某个特殊天赋节点的设计参考，**不再作为青囊核心机制**。

> **v0.4.1 修订（2026-05-15）**：化身档案层 + 御物简化版 + 御物专属灵物
> - **化身档案层**：4 个化身已定稿——剑魄（金）/ 青囊（木）/ 影刃（水）/ 御物（土）。火属性化身在 v0.4 实装的"业火 · 狂战之火"于 2026-05-16 整体撤销，待未来重新设计。化身名 / 副标题 / 战斗幻想 / 推荐 build 是玩家面对的"角色"层（详见 4.3.6）。
> - **御物简化版**：移除 v0.4 设计的"主动 F 炼物 / -10% 最大生命永久代价"机制（操作负担重 + 新手难以评估性价比）。化身基础玩法保持"固定 2 傀儡 + 技能 ×10% 同步"，傀儡军团扩张能力**下沉到专属灵物 build 层**。

## 2. 世界观与叙事 `[v0.x 暂未实现]`

### 2.1 核心设定（v0.5.4 重写 · 修仙原生 / 2026-05-28）

> **设计原则**：本作不做"凡人入梦修仙"的现代框架包装，主角就是修仙世界中的一名修仙者，所有玩法都是修仙者的日常——出洞府历练、回洞府闭关、培养灵脉、解锁机缘。

**世界设定**：

修仙界中，散落着无数远古遗留的**秘境**——上古大能陨落之地、宗门废墟、灵脉异变区、天劫降临处……每一处秘境都封闭独立、内部诡谲莫测，但也蕴藏机缘、灵物、功法残页等修仙者所求之物。

主角是一名拥有自己**洞府**的修仙者，凭借自身根骨与道心，立志在仙途上走得更远——飞升、超脱、或是另寻他路。修仙者的日常即在两件事之间循环：

- **出洞府闯秘境**：探索未知、与妖兽厮杀、拾取灵物、积累历练
- **回洞府闭关修炼**：消化历练、淬炼修为、培养灵脉、迎接机缘

**死亡的解释**：秘境深处灵气紊乱，修仙者一旦在秘境中陨落，洞府的传送阵会自动将其**残念**牵引回来——但身上未经稳固的资源大多会散逸在秘境中，并落下"道伤"（短时间内无法再次入秘境）。

**随机性的解释**：秘境本身处于灵气流转的不稳定态，每次进入面貌都不同（自然契合 Roguelike 随机生成）。

### 2.2 双线结构

| 线 | 对应 | 内容 |
|----|------|------|
| 🌙 秘境线（局内） | Roguelike 战斗 + 探索 | 随机秘境、灵物获取、Boss 战、境界突破 |
| ☀️ 洞府线（局外） | 成长 + 叙事 + 经营 | 闭关修炼、灵脉培养、机缘事件、化身天赋、剧情推进 |

**双线互动**：

- 秘境中获得的历练值 / 素材 / 灵脉道具 → 影响洞府成长
- 洞府的修为 / 灵脉等级 / 已解锁天赋 → 影响秘境内的战力上限和品质

### 2.3 叙事核心：道心 / 因果 / 多结局

不做"哪边是梦"的元叙事悬念，改为**修仙者本身的抉择悬念**——你的修仙之路最终走向何方？

| 累积维度 | 玩家行为 | 影响 |
|---------|---------|------|
| **道心** | 善意选项、坚守抉择、舍己为人 | 高道心 → 触发"道心机缘"和"飞升"路线 |
| **因果** | 杀戮、强取、心魔诱惑 | 高因果 → 触发"宿敌劫"和"入魔"路线 |
| **缘分** | 与 NPC 互动、链式机缘选择 | 解锁"知交"路线和隐藏故事 |

**多结局方向**（Demo3）：

- **飞升**：道心圆满、渡过大劫 → 飞升上界
- **入魔**：因果深重、心魔反噬 → 化为反派 BOSS（新周目敌人）
- **凡途**：放下修炼、归于凡尘 → 隐藏温情结局
- **真道**：参透秘境本质、走出独立第三路 → 隐藏真结局

> **Demo3 反转空间保留**：秘境的真实本质（如远古修仙者的意识残留 / 试炼之地 / 某种轮回回响）作为真结局线索逐步揭示，但**不涉及"梦境"叙事**。

### 2.4 叙事设计优势

- **修仙叙事自洽**：所有玩法都能用修仙世界观自然解释，不需要"现代凡人做梦"作为外壳
- **死亡有代价但不出戏**：陨落 = 残念被洞府牵引回，符合修仙世界的传送阵 / 护身符设定
- **道心/因果累积驱动长期游玩**：多结局反向反推玩家每一次抉择都有意义
- **碎片化剧情**：通过机缘事件、NPC 互动、秘境深处的古卷遗物逐步展现世界观

### 3.2 Build 5 维框架

玩家 build 由 4 个来源 + 5 个耦合接口构成：

**4 个 build 来源**：
1. **化身**（局外洞府选定，整局固定）
2. **功法**（局内 Q/E/R 三槽，可装备/替换）
3. **灵物 · 局内类**（150+ 池，自由叠加 / 协同 / 质变）
4. ~~境界突破奖励 + 顿悟口诀~~ `[v0.5.4 移除]` —— 本局成长完全来自灵物 / 协同 / 修饰 / 化身天赋

- 化身 × 功法：化身核心机制对 Q/E/R 全部生效（详见第 4 章 + 6.7.4 融合层）

**meta progression（跨局长线）**：

## 4. 化身系统（角色选择） `[v0.3.2 重新设计：从"数值版"升级为"机制版 + 天赋树"]`

### 4.1 设计哲学（v0.3.2 重写）

> **化身不是"属性加成"，也不是"被动规则"，而是一条改变操作 / 输入 / 战斗节奏的核心机制。**
>
> 衡量标准：**关掉这个化身，玩家的手指会做不一样的动作吗？**
> - 如果只是数值变化（伤害多 / 血多 / 偶尔回血），不算"改变玩法"。
> - 如果普攻按键的语义、闪避的意义、攻击的节奏被替换，那才算"改变玩法"。
>
> 类比：
> - 以撒里 Lazarus（死后复活成强化形态）= 改变规则
> - 只狼的弹反 / DMC 的完美收刀 = 改变操作语法
> - Diablo 死灵法师 = 改变战斗角色（指挥官 vs 主角）
>
> 当前 GDD 第 4 章对标的就是后两类。

### 4.2 v0.3 数值版化身的反思（为什么要重新设计）

v0.3 阶段实现的 5 化身（金=穿透 / 木=清房回血 / 水=反伤 / 火=连杀叠攻 / 土=灵物护盾）虽然代码已经落地，但它们在玩家手感层面**只是不同的被动 BUFF**：

| 维度 | v0.3 数值版化身 | v0.3.2 机制版化身（本节目标） |
|------|---------------|---------------------------|
| 玩家手指动作 | 完全一致：左键 spam + 闪避 + Q/E/R | 因化身不同有显著差异（白光按键 / 自动普攻 / 闪避输出 / 怒气节奏 / 指挥傀儡） |
| 输出来源 | 玩家本体普攻 | 玩家 / 召唤物 / 完美时机 / 自动锁定 各不同 |
| 玩家关注点 | 走位 + 输出 + CD | 因化身而异（节奏 / 走位 / 闪避 / 战斗维持 / 指令） |
| "选哪个化身"决策深度 | 小（无非数值偏好） | 大（选了完全不同的玩法） |

**结论**：v0.3 数值版规则**保留作为"化身副词条"**（弱化版基础数值底座，不浪费已实现代码），但**核心机制全部用机制版替换**，并新增"化身天赋树"作为深度扩展。

### 4.3 基础化身（机制版 · v0.3.2 新设计）

每个化身由四层构成：

1. **核心机制**（必备）：改变玩家输入 / 节奏 / 输出来源的主玩法。
2. **普攻↔技能融合点**（必备 · v0.3.3 新增）：参见 6.7.4 节，每个化身有专属的"普攻↔技能强耦合"机制，使普攻和技能形成节奏循环，而不是各自独立。
3. **副词条**（继承自 v0.3 数值版）：少量基础数值偏向，做"补偿性手感"。
4. **天赋树**（参见 4.4）：4~6 个可解锁节点，进一步强化或变体核心机制。

| 化身 | 核心机制 | 普攻↔技能融合点（4.3.x 详） | 副词条（v0.3 弱化版） | 起始灵物 |
|------|---------|--------------------------|---------------------|---------|
| **剑魄** | 灵压同步 / 完美收刀 | 主动技能后必现灵压窗口 + `御剑回锋`天赋 30% 重置技能 CD 20% | 攻击微量穿透（v0.3 版减半） | 锈铁飞剑 |
| **青囊** | 持续寄生 / 播种收割 | 普攻种种子 → 任意技能命中引爆所有种子 ×0.5/颗 AOE | 清房回 3% 血（v0.3 版减半） | 聚灵草 |
| **影刃** | 影息斩 | 影息斩命中目标留下"水痕印"，技能命中带水痕目标 ×1.5 | 受击反伤 10%（v0.3 版减半） | 水盾符 |
| *(火属性化身)* | *(待重新设计，详见 4.3.4)* | — | 连杀叠攻 +8%×3（v0.3 版减半，作为火元素属性的副词条保留） | 火灵珠 |
| **御物** | 御物斗法 / 以命铸物 + 技能放大 | 傀儡同步玩家技能 ×10% 强度（5 只满 ≈ 技能 ×1.5 群伤） | 每 5 灵物 1 层护盾（v0.3 版保留） | 岩甲符 |

> **副词条作用**：用于"化身之间不要在零阶段上 0 数值差距"。选剑魄的玩家即便完美收刀经常失败，也能靠"轻微穿透"打过早期。它是个**保底底座**，不应该成为玩家关注核心。
>
> **普攻↔技能融合点的意义**：参见功能缺口归档 1.7。"技能数值过高 / 普攻成填充"是 v0.3 战斗手感的核心痛点；v0.3.3 把"普攻和技能必须形成耦合"作为**每个化身的硬性设计要求**，配合 6.7.4 的全局机制（三段连招减 CD）一起解决该问题。

#### 4.3.1 剑魄 · 灵压同步（完美收刀）

> **设计核心**：把"按键时机"提到玩家行为的第一优先级。所有重要动作（普攻 / 技能 / 闪避）结束后都可能开一个"灵压窗口"，玩家全程都在看头顶特效抓时机，不依赖任何具体技能配置。

**核心机制**：

```
【灵压同步窗口】出现条件 —— 在以下时机角色【头顶出现金色剑形特效】+【刀身白光闪烁】，
持续 0.15~0.2s：
  - 普攻三段连招的每一段收招瞬间（必现）
  - 释放任意主动技能（Q/E/R）后 0.3~0.8s 内（必现，时长有少量随机偏移）
  - 闪避结束后 0.2~0.5s 内（30% 概率出现）
  - 进入【剑心通明】期间，每 1s 自动出现一次

【灵压爆发】触发：
  - 在窗口内按下普攻键 → 即时触发：
      - 角色面前扇形 AOE（半径 2.5、角度 120°）伤害 = 玩家攻击 ×1.5
      - 命中目标进入【硬直】0.5s
      - 视觉：刀光带 + 命中处冲击波
  - 错过窗口（早按 / 晚按 / 不按）→ 当前动作正常完成，无任何惩罚

【完美连续】计数：
  - 连续 3 次灵压爆发（中间没有错过任何亮起的窗口）→ 进入【剑心通明】4s：
      - 普攻 +30%、暴击率 +25%
      - 剑心期间每次完美收刀额外触发一次"剑气溅射"（半径 3 圆形 AOE，×0.4 攻击）
  - 错过任意 1 次窗口 → 完美连续计数清零（不影响其他属性）
```

**改变了什么**：
- 普攻不再是"无脑左键 spam"，要看视觉提示 + 抓时机。
- 即使玩家**裸开没有任何技能**，也能凭三段连招的窗口频繁触发完美收刀，**前期不会偏弱**。
- 有技能后，每次 Q/E/R 都会带出一个新窗口 → 完美收刀频次密集，build 越深越爽。
- 高水平玩家 vs 低水平玩家差距可以非常大（理论可一直完美）。

**副词条**：所有攻击附带微量穿透（穿过第一个敌人对后方造成 25% 伤害，v0.3 版 50% → 减半）。

#### 4.3.2 青囊 · 持续寄生（播种与收割）

> **设计核心**：成长与收割。普攻在敌人身上种下种子，技能负责让种子瞬间开花/爆炸。
> - **普攻 = 播种**（数值不高，但是关键的"前置准备"）
> - **技能 = 收割**（爆发依赖于普攻铺垫）
> - 玩家像在战场上布置陷阱，每一次普攻都是为下一次技能爆发蓄势。
>
> 这个设计**直接解决了"技能数值过高 / 普攻↔技能联动太弱"的核心痛点**（功能缺口归档 1.7）——技能数值不需要下调，因为爆发本身依赖普攻铺垫，"光按 Q/E/R 不打普攻"会显著降低 DPS。

**核心机制**：

```
【寄生种子】（普攻播种）：
  - 每次普攻命中敌人 → 在该敌人身上种下 1 颗【寄生种子】
      - 持续 6s（每次播种刷新最长一颗的时长）
      - 单敌上限 5 颗
      - 视觉：敌人身上飘绿色叶子小标记，数量随种子数显示
  - 种子自身造成微量持续伤害：每秒 ×0.1 玩家攻击 / 颗
  - 敌人 1s 内不被攻击 → 自然萎缩（每秒掉 1 颗），鼓励玩家持续攻击维持种子

【引爆】（技能收割）：
  - 玩家释放任意主动技能（Q/E/R）的伤害事件命中带种子的敌人 → 立即引爆其所有种子：
      - 单颗种子引爆伤害 = ×0.5 玩家攻击
      - N 颗种子线性叠加：N 颗 × 0.5 攻击
      - 引爆触发小 AOE（半径 1.5 + 0.3 × N），波及周围敌人
      - 引爆消耗目标身上全部种子
  - AOE 命中其他带种子的敌人时**不连锁引爆**（防止滚雪球过头；天赋"链锁绽放"可改）
  - 技能命中无种子敌人 → 正常技能伤害，无引爆增益

【种子迁移】（自然机制）：
  - 带种子的敌人死亡时 → 种子随机迁移给半径 3 内最近的一名敌人（最多迁移 3 颗）
  - 鼓励战场不浪费种子
```

**改变了什么**：
- 战斗循环从"先 Q 再 E 再 R 普攻填充"变成"**普攻铺种 5 下 → 技能引爆 → 普攻铺种 → 技能引爆**"，普攻和技能形成强耦合。
- **打技能时机变成了决策**：种子刚种好就引爆 vs 等 5 颗满了再引爆 vs 等一波敌人都铺好再 AOE 引爆 → 三种节奏取舍。
- 让"技能数值高"反而成为优势——技能本身不调数值，但**必须配合普攻播种**才能打出全部潜力。
- 主题契合度极高：木 = 种植 / 生长 / 收割，每一次战斗都像是在战场上布置一个会爆炸的花园。

**副词条**：每清完一个房间回复 3% 生命（v0.3 版 5% → 减半），最大生命不再 -20%。

#### 4.3.3 影刃 · 影息斩

**核心机制**：

```
闪避结束后的 0.4s 内，做的下一次攻击触发【影息斩】：
  - 本次攻击 伤害 ×2
  - 自动锁定面前最近敌人（无视朝向）
  - 自带前冲位移（半径 4，类似"瞬步"）
  - 视觉：拖一道淡蓝色水痕
连续闪避（无 CD 时连按 Space）：
  - 第 2、3 次闪避允许，但都不能触发影息斩
  - 只有"上一次普攻 / 释放技能后的第一次闪避"才能为影息斩蓄势
```

**改变了什么**：
- 闪避从"撤退手段"变成"输出准备动作"。
- 玩家的战斗循环从"打→打→闪"变成"闪→打→闪→打"。
- 强迫玩家在敌人面前保持移动，鼓励高节奏对线。

**普攻↔技能融合点（v0.3.3 新增）**：
- 影息斩命中目标 → 在该目标身上施加【水痕印】，持续 5s（每次影息斩刷新时长，单敌上限 1 层）
- 玩家释放任意主动技能命中带水痕印的目标 → 技能伤害 ×1.5，并立即消耗水痕印
- 视觉：被标记目标身上有淡蓝色水波纹环
- **战斗循环**：闪避 → 影息斩"标记目标" → 技能集中爆破 → 闪避换位 → 标记下一个

**副词条**：受到伤害时，10% 伤害反弹给攻击者（v0.3 版 20% → 减半）。

#### 4.3.4 火属性化身 · 待重新设计 `[策划已撤销 / 2026-05-16]`

> **撤销状态**：原"业火 · 狂战之火"（怒气资源条 + 主动键 V + 狂火 BUFF + 强制爆发兜底）于 2026-05-16 整体撤销。
>
> **撤销理由**：用户判定"业火 / 狂战修罗"是 ARPG 经典套路（鬼泣 Devil Trigger / 暗黑野蛮人怒气吼叫 / War Machine 暴走模式 等），跟修仙调性不搭、独立游戏需要更新颖的玩法方向。多个替代方案（符箓师·陷阱式画符 / 普攻即画符 / 念咒入定 / 纸宝切换 / 三符五行合符 等）也都没达到"好玩"标准，整体搁置。
>
> **当前状态**：
> - 火属性作为元素分类（用于灵物 modTag、技能元素属性）依然保留——这是底层元素属性层，跟化身玩法解耦。
> - 化身列表暂时只有 4 个**已定稿**：剑魄 / 青囊 / 影刃 / 御物。
> - 火属性化身**留作未来设计**——等到有"真正好玩 + 真正修仙本质 + 跟其他化身完全差异化"的方向时再补。
>
> **v0.4 代码层处理**：`SpiritRootFireController.cs` 内的"怒气 + 狂火"代码保留为参考实现，但已无对应策划——可在 v0.5 清理时删除或保留作为后续设计的基础组件。

#### 4.3.5 御物 · 御物斗法（v0.4.1 简化版）

> **设计核心**：群战指挥官 + 技能放大器。**化身基础玩法保持干净**——固定 2 只傀儡同步玩家技能。**扩张能力通过专属灵物自然涌现**（炼魂蛊 / 御灵符 / 化形丹），符合 GDD "build 自然涌现"的核心卖点。
>
> **简化理由（v0.4.1）**：原"以命铸物"设计需要主动 F 键 + 永久最大生命惩罚 + 当前生命门槛，决策面虽然丰富但操作负担重，且新手很难评估"-10% 最大生命换 1 个 ×0.5 攻击伤害的傀儡"是否划算。新版把"扩张能力"从化身的核心机制剥离，作为**专属灵物驱动的可选路线**——选不到这些灵物的玩家依然是稳定的 2 傀儡指挥官，选到的玩家则获得 5~10 只傀儡的"军团流"。

**核心机制**：

```
开局自动召唤 2 只【土甲傀儡】环绕玩家（半径 3 内浮动）：
  - 攻击行为有两种：
    1. 【普攻同步】（被动持续）：每 0.8s 普攻一次范围内（半径 4）最近敌人
        - 伤害 = 玩家攻击 ×0.5（继承玩家暴击 / 协同 / 槽位修饰）
        - 攻击类型 = 近战剑击（可触发协同的"近战命中"条件）
    2. 【技能同步】（事件触发，v0.3.2 核心扩展）：玩家释放 Q/E/R 主动技能时，
       所有存活傀儡【在自身位置】同步释放同一个技能：
        - 伤害 = 该技能基础伤害 ×10%
        - 不消耗玩家的技能 CD / 充能
        - 继承玩家暴击 / 协同 / 槽位修饰（与衍生伤害走相同管线，参见 6.7.2）
        - 适用范围：所有【位置型】AOE 技能（落石术 / 三昧真火 / 万剑诀 / 天罡北斗阵 等）
        - 不适用：【位移型】技能（土遁术 / 缩地成寸 / 水镜术 等）—— 傀儡跳过这次同步
        - 不会触发"技能命中后再放一次技能"的连锁（防止滚雪球）
  - 傀儡 HP = 玩家当前最大生命 ×30%（与玩家最大生命联动）
  - 傀儡【与玩家同生死】——傀儡死亡后【不主动重召】，跟随玩家剩余路程
  - 死亡的傀儡留出一个"空槽"，玩家可通过下方扩张机制（精英赠物 / 灵物驱动）填补

【精英赠物】（被动 · 保留）：
  - 击杀精英怪 / Boss 后自动赠送 1 只傀儡，不消耗任何代价
  - 上限已满时不触发

玩家本体普攻削弱：
  - 普攻伤害 ×0.8（弱化主角，傀儡军团为主输出）

【没有主动炼物】：v0.4 之前的"主动 F 炼物 / -10% 最大生命"复杂代价**已撤销**。
  - 简化原因：决策面虽丰富但操作负担重，且新手难以评估"-10% 最大生命换 1 个 ×0.5 攻击傀儡"的性价比
  - 替代方案：扩张能力下沉到「灵物 build」层，详见 4.7 章节"炼魂蛊 / 御灵符 / 化形丹"3 件御物专属灵物
```

**改变了什么**：
- 玩家从"主角"变成"指挥官"，伤害来源 ~50% 来自傀儡（满 2 傀儡）/ 70%（拿到扩张灵物后满 5~10 傀儡）。
- **技能不再是单点输出，而是被傀儡数量乘以 1 + 10% × N**：
    - 基础 2 傀儡 → 技能整体威力 ×1.2
    - 拿到炼魂蛊 → 扩张到 5 傀儡 → 技能整体威力 ×1.5
    - 拿到化形丹（天品稀有）→ 扩张到 10 傀儡 → 技能整体威力 ×2.0
- 御物越深的玩家越倾向于堆"位置型 AOE 技能"，build 方向自然出现。
- 失去傀儡 = 实打实的资产损失（不会自动重召），鼓励玩家给傀儡 / 玩家分担伤害（参见天赋"神鬼莫测"）。

**副词条**：每持有 5 件灵物获得 1 层"地脉护盾"（吸收 1 次伤害，v0.3 版规则保留）。

**与"化身 → 起始技能"的关系**：因为傀儡 = 技能放大器，御物**比其他化身更依赖技能**——这反而是优势，把"化身 vs 技能"的耦合从"被动占位"转化为"主动协同"。当前 GDD 仍维持"化身不绑定起始技能"的解耦原则（参见 9.1 藏经阁条目）。

#### 4.3.6 化身档案总览（v0.4.1 新增）

> **化身**（Avatar）= 化身的"角色化包装层"。同一个化身机制 = 同一个"内核"，但化身给它打包了**名字 + 副标题 + 战斗幻想 + 推荐 build 方向 + 视觉色调**，让玩家选化身时获得清晰的"角色感"。
>
> **关系**：化身 ⊆ 化身 ⊆ 玩家可选条目。化身名 / 副标题层只是 UI 文案 + 玩家心智锚点，机制层完全继承底层化身。
>
> 化身名作为玩家面对的"角色名"，化身名（金/木/水/火/土）作为机制类别标识依然保留（用于代码、协同条件、灵物 modTag 等场景）。

| 元素属性 | 化身名 | 副标题 | 玩法标签 | 视觉色调 | 推荐 build 方向 |
|--------|------|------|--------|--------|------|
| 金 | **剑魄** | 执剑而行 · 时机大师 | 时机操作流 | 金光 + 白色刀光 | 飞剑灵物 + 暴击灵物 |

- 不拿这些灵物 → 玩家就是"稳定 2 傀儡指挥官"，干净直接
- 拿到炼魂蛊（玄品掉率 15%） → 解锁"军团流"，越打越多
- 拿到化形丹（天品掉率 1%） → 终极军团 build，10 只傀儡满场（满 ×0.1 加成下，所有傀儡伤害 ×2.0，技能整体威力 ×2.0）
- **build 自然涌现**：玩家不需要主动选"军团流派"，是看到了灵物自然决定怎么玩

> **后续**：本节其他 4 件愿景灵物（破军星辰 / 万灵幡 / 镜花水月 / 焚天令）作为 Demo2+ 内容，等机制版化身全部稳定后逐个补。

## 5. 灵物系统（道具体系）

### 5.1 设计哲学

> **所有东西统一叫"灵物"，获取后自动生效，没有装备栏的概念。**  
> 就像以撒一样：捡到就生效，叠加就完事。  
> 没有"装备"和"套装"的区分——灵物可以无限叠加（功法除外，最多3个）。

### 5.1.5 灵物两大用途分类（v0.5 新增 · 搜打撤核心）

> **v0.5 重构**：每件灵物在数据结构上额外有一个 `usage` 字段，区分"局内即用品" vs "洞府素材"。这是搜打撤循环的核心数据基础。

| 用途类别 | 字段值 | 描述 | 持续 | 死亡惩罚 | 例子 |
|--------|------|------|------|------|------|
| **🌙 局内灵物**（InRunOnly） | `InRunOnly` | 战斗中捡到立即生效，整局参与 build；撤离时消失 | 整局 | 失去本局 build（与 Roguelike 一致） | 飞剑、火灵珠、寒玉髓、紫霄雷印 |
| **☀️ 洞府素材**（CaveResource） | `CaveResource` | 战斗中捡到背在背包；**必须活着撤离**才能带回洞府转化为永久资源；死亡丢失 | 跨局保留 | **全部丢失**（残念补 10%） | 灵药、灵矿、妖兽内丹、古籍残页、灵植种子、阵法符、玄铁 |

**搜打撤的精髓**：在秘境里捡到的不只是"装备"（局内灵物），还有"原材料"（洞府素材）——原材料必须**活着带出去**才能用。

#### 5.1.5.1 设计原则

1. **不混淆视觉**：UI 上局内灵物和洞府素材有明显视觉差异（前者亮色，后者带"未提炼"暗色 + 背包包裹图标）
2. **拾取时立即提示**：玩家捡起洞府素材时弹出小提示"已加入背包 · 撤离后带回洞府"
3. **背包容量限制**：洞府素材的背包容量初始 10 格（可通过洞府 · 储物柜升级），鼓励玩家做"带哪些" 的取舍
4. **死亡 10% 残念补偿**：避免玩家完全绝望——但残念只能换通用资源（灵气），不能换具体素材

#### 5.1.5.2 跟现有 17 件灵物的关系

当前 v0.4 实装的 17 件灵物全部是 `InRunOnly` 类型（继续保留 build 行为不变）。
**v0.5 新增的洞府素材是新增类型**，不冲突现有体系。

### 5.5 叠加规则

同一灵物可以重复获取，效果叠加：

**线性叠加：**
- 火灵珠 ×1：攻击附带灼烧，每秒5点伤害
- 火灵珠 ×2：灼烧伤害变为每秒10点
- 火灵珠 ×3：灼烧伤害每秒15点 + 灼烧扩散至周围敌人

**质变叠加（达到一定数量触发质变）：**

### 5.6 元素反应 `[v0.3.1 已撤销]`

> **v0.3.1 决策（2026-05-06）**：原 v0.3 设计的"跨元素反应"系统（蒸汽爆炸 / 过载爆裂 / 感电 / 烈焰扩散 / 燃烧蔓延 / 导电领域）**整体撤销**。
>
> **撤销理由**：
> 1. 反应表与质变 / 协同 / 槽位修饰之间的边界不清，玩家很难在战斗中感知到"是哪条规则在叠加生效"。
> 2. 跨元素反应需要敌人侧维护"元素附着列表 + 反应触发器 + 同帧防爆链"等额外机制，工程成本高且容易和现有 `StatusEffect` 框架/伤害管线产生冗余。
> 3. v0.3 阶段更应集中验证"基础化身 + 槽位修饰 + 境界突破"三件事的乐趣，避免再叠一层耦合系统。
>
> **替代方向（未来再考虑）**：
> - 若需要"火 + 冰"这种化学反应感，**改放到第 7 章「隐藏组合」中**，按"双系/多系灵物概率触发一次性效果"形态出现。
> - 例：携带任意一件 Fire + 任意一件 Ice 灵物时，普攻命中有 X% 概率触发一次"蒸汽爆炸"AOE（直接走协同管线，不依赖跨元素状态机）。
> - 例：双系灵脉（Demo2 灵脉系统中可考虑）激活时获得本系×对系的特殊副词条。
>
> **保留 / 仅作语义沿用的内容**：
> - `StatusEffect.elementTag`（Fire / Ice / Thunder / Wind / Wood / Water / Earth）字段保留，作为协同检测、UI 分类、技能修饰判定（GDD 6.5）的元数据，不再驱动反应触发器。
> - `Burn / Freeze / WetGround / MeteorDot` 等单元素状态依旧存在，由灵物 / 技能直接施加。
> - 5.5「质变叠加」与未来「双系协同」依旧正交，互不影响。

> **与原文档的链接处理**：原 5.6 的反应表 / 落地约定段落整体删除；6.7.1（StatusEffect）、6.7.2（召唤物伤害管线）、8.2（境界突破奖励池）中所有"元素反应"相关条目同步移除。

## 6. 主动技能系统（功法）

### 6.1 操作模型

> v0.2 修订：已从"远程灵力弹"改为 **Hades 风格近战连招 + 三槽位技能**。

```
【近战普攻】—— 鼠标左键，三段连招
  → 三段连招：Attack1 → Attack2 → Attack3
  → 段伤害倍率：1.0 / 1.2 / 1.5（最终段有"收尾一击"感）
  → 扇形判定：半径 2.5，角度 120°（面前 120° 扇形范围内的敌人全部命中）
  → 攻击中"霸体"：轻击受击不打断连招（但仍扣血）
  → 250ms 输入缓冲：下一段未到时按下左键也会接上，连招不断，3s未进行三段连招则重置
  → 每段带前冲 Lunge 位移（朝向当前攻击方向短距冲刺）
  → 灵物可改变：攻击附带灼烧 / 暴击率 / 穿透次数 / 攻速 / 击杀回血
  → 元素修饰词条（见 6.5）：根据技能槽位中的灵物改变机制
  → 移动不会打断近战攻击，但会出现0.1s停顿（每段攻击都会停顿），停顿也不会打断移动操作

【主动技能】—— Q / E / R 三个槽位，手动释放，有 CD
  → Q 槽位：攻击型（落石、御剑、雷击……）
  → E 槽位：位移 / 辅助型（土遁、缩地……）
  → R 槽位：大招 / 终极型（剑阵、天火……）
  → 充能层：每个槽位独立维护 1~3 层充能，CD 一好恢复一层
    - 灵物槽位可提供充能上限 +N
    - 满充能时技能有特殊边框提示
  → 蓄力（部分技能支持）：长按键蓄力，松手释放
    - Lv1（默认）：伤害 ×1.0，范围 ×1.0
    - Lv2（蓄力 ≥ 0.5s）：伤害 ×1.5，范围 ×1.0
    - Lv3（蓄力 ≥ 1.5s）：伤害 ×2.5，范围 ×1.3
    - 蓄力期间移速 ×0.4；闪避 / 死亡取消蓄力
    - 灵物槽位可提供蓄力速度加成 / 蓄力伤害加成
  → 每个槽位下方 2 个"灵物槽"（共 6 个）
    - 普通词条：充能上限、蓄力速度、蓄力伤害加成、CD 缩减
    - 元素修饰词条（见 6.5）：改变技能的机制行为

【闪避】—— Space 键
  → 距离 5 单位，持续 0.2s（速度 25 单位/s）
  → 全程无敌帧 0.3s（比闪避动作更长，覆盖落地一小段）
  → 2 层充能，每层 CD 1.5s
  → 可打断除"死亡"外的一切动作（最高优先级）
  → 充能耗尽时 250ms 输入缓冲，动作结束自动闪避
  → 灵物可附加机制效果：
    - 御风残影（风灵珠 ×5）：闪避后留下攻击敌人的残影
    - 火墙轨迹（风火轮 Synergy）：闪避路径上生成持续火墙
```

### 6.5 功法与灵物的交互（核心机制）

> **这是我们区别于《梦之形》数值宝石的核心差异化设计。**
> 灵物不只是数值加成，而是"修饰词条"——放在某个技能的灵物槽位中，会从根本上改变该技能的行为。
>
> v0.2 修订：本节新增完整的设计规格（方案 A：槽位限定触发）。

---

#### 6.5.1 设计理念

```
《梦之形》宝石 = 往血糟里加数字
本游戏灵物    = 往技能行为里注入修饰语
```

**同一件灵物，放在不同技能的槽位里，会给不同的技能赋予完全不同的变体**：

- 火灵珠放在落石术槽位 → 落石变陨石，落点留火焰地带
- 火灵珠放在土遁术槽位 → 破地而出时引燃周围敌人
- 火灵珠放在金钟罩槽位 → 护盾期间使攻击者着火

这一层决策（灵物放哪个槽）是比"拿哪件灵物"更深的 build 策略层，也是每局体验不同的核心驱动力之一。

---

#### 6.5.2 触发规则（方案 A：槽位限定）

**条件**：某件灵物的 `modTag` 匹配该技能的 `modifierDef.requiredTag`，且灵物在**该技能下方的 2 个灵物槽**中。

> 仅槽位内的灵物能激活机制修饰。背包中同类灵物不触发。

```
Q 槽位
├── [落石术]
├── 灵物槽 0：[火灵珠]   ← modTag = Fire → 激活"陨石修饰"
└── 灵物槽 1：[雷灵珠]   ← modTag = Thunder → 激活"雷石修饰"
                         → 两个修饰同时激活 → 落点留火焰地带 + 落下时引发雷击

E 槽位
├── [落石术（如果也装在这）]
├── 灵物槽 2：[火灵珠]   ← 同一件灵物放不同槽，修饰的是 E 槽技能
└── 灵物槽 3：空
```

---

#### 6.5.3 数据结构（设计侧理解，无需写代码）

**灵物侧**：每件灵物有一个 `modTag`（元素/类型标签）

| modTag | 代表灵物 |
|--------|---------|
| Fire | 火灵珠、血珊瑚、引魂灯（灼烧系） |
| Ice | 寒冰玉髓 |
| Thunder | 雷灵珠 |
| Wind | 风灵珠 |
| Pierce | 锈铁飞剑（穿透系） |
| Life | 灵藤草（生命系） |

**技能侧**：每个技能的配置里填写"接受哪些修饰词条 + 修饰后行为"，**纯 Inspector 配置，零代码**：

```
落石术.modifierDefs:
  [0] requiredTag = Fire,    requiredCount = 1
      leaveZone = true, zoneDuration = 3s, zoneDmgMul = 0.3×atk
      detonateExisting = true, detonateMul = 1.5
      modifiedName = "陨石术"
  [1] requiredTag = Ice,     requiredCount = 1
      leaveZone = true, zoneDuration = 2s（冰面减速）
      modifiedName = "冰晶落石"
  [2] requiredTag = Thunder, requiredCount = 1
      leaveZone = false, addThunderStrike = true（落点引发额外雷击）
      modifiedName = "天雷落石"
  [3] requiredTag = Fire + Thunder（双修饰）
      detonateMul = 2.0, addThunderStrike = true
      modifiedName = "天罚陨星"
```

### 6.7 战斗扩展机制（v0.3 新增）

#### 6.7.1 StatusEffect（BUFF / DEBUFF 通用框架）

> **目标**：当前 `BurnEffect / 嗜血 / 冻结` 都是一锤子写死的 MonoBehaviour，相互不能叠加、不能查询、扩展成本高。引入 `StatusEffect` 通用容器后，所有"持续生效的效果"统一存进同一份列表，便于 UI 显示、协同设计、技能修饰判定（参见 6.5）。

**数据模型（设计侧）**：

```
StatusEffect
├── id              : string         (例如 "Burn", "Freeze", "Bloodlust", "ComboKill")
├── kind            : Buff / Debuff
├── elementTag      : Fire / Ice / Thunder / Wind / Wood / Water / Earth / None
├── stacks          : int            (堆叠层数，无限叠则为 1 + 刷新)
├── duration        : float          (剩余秒数；< 0 表示常驻直到主动移除)
├── tickInterval    : float          (周期触发用，例如灼烧每 0.5s)
├── modifiers       : StatModifier[] (临时词条修正：atk +x、ms ×y、reduction +z)
├── onApply / onTick / onExpire 钩子
└── source          : object         (产生方，便于 UI 归类)
```

**关键约束**：
- 所有数值类临时增益（如"嗜血攻速 ×2"、"连杀攻击 +15%"、"风火轮移速 +10%"）改走 `modifiers`，不再直接 `Stats.attackSpeed *= 2f`。
- `RecalculateStats` 在统一管线最后追加一步 `ApplyStatusEffectModifiers`，与协同 / 质变并列。
- 每个状态默认有 UI 标记（HUD 顶部小图标 + 倒计时）。

**Demo1+ 第一批 StatusEffect**：

| ID | 元素 | 类型 | 效果 |
|----|------|------|------|
| `Burn` | Fire | DoT | 周期掉血 |
| `Freeze` | Ice | 控 | 移速 ×0.5 / 完全无法移动 |
| `Shock` | Thunder | DoT + 减速 | 雷系灵物 / 技能附着的麻痹+持续伤害 |
| `WetGround` | Water | 地形 | 进入受导电伤害 |
| `Bloodlust` | None | Buff | 攻速 +X |
| `ComboKill` | None | Buff | 短时间内连续击杀叠 atk |
| `Shielded` | None | Buff | 护盾层数 |
| `MeteorDot` | Fire | 地形 | 陨石落点燃烧地带 |

#### 6.7.2 召唤物 / 衍生伤害 继承玩家属性

> **当前问题**：焚天冲击波 / 剑阵 / 御风残影 / 元素爆发 / 火墙 / 玉碎冲击波 直接 `_player.Stats.attackDamage * x` 算伤害。这导致：
> - **永远不会暴击**（CalculateDamage 没被调用）。
> - **协同 / 质变的乘区只对玩家本体普攻生效**，召唤物不享受。
> - **元素附着 / 协同条件触发走不到**（衍生伤害没经过 `OnDamage(DamageInfo)`）。

**解决方案（v0.3）**：
1. 所有召唤物 / 衍生 AOE / 残影攻击都改走统一伤害构造：

   ```
   DamageInfo info = playerStats.Build(
     baseRatio = 0.3f,            // 该衍生攻击的基础倍率
     elementTag = Fire,            // 携带的元素
     sourceTag  = "FireBurst",     // 用于飘字 / 协同识别
     inheritCrit = true,           // 是否继承玩家暴击
     inheritOnHit = true)          // 是否继承玩家"命中触发"灵物效果
   ```
2. `BuildDamageInfo` 内部会读取当前 `_playerStats` 的 attack / critRate / critDamage / `+%` 类协同，乘上 `baseRatio`，再判定一次暴击。
3. 衍生伤害的"元素附着"也由本步骤统一处理（不再各处自己 `AddComponent<BurnEffect>()`）。

**对照表（Demo1+ 改造范围）**：

| 现有伤害源 | 当前问题 | 改造目标 |
|-----------|---------|---------|
| 焚天冲击波 | hardcode 0.5×atk，不暴击 | 走 `Build(0.5, Fire, inheritCrit=true)` |
| 剑阵环绕飞剑 | hardcode 0.2×atk，不暴击 | 走 `Build(0.2, Pierce, inheritCrit=true)` |
| 御风残影攻击 | hardcode 0.3×atk，不暴击 | 走 `Build(0.3, Wind, inheritCrit=true)` |
| 元素爆发 | hardcode 0.4×atk，不暴击 | 走 `Build(0.4, 随机元素)` |
| 火墙 | hardcode 5 固定伤害 | 走 `Build(0.25, Fire, +Burn)` |
| 玉碎冲击波 | 仅击退，无伤害 | 维持击退；可选附加 `Build(0.6, Earth)` |

#### 6.7.3 明确不做的部分（v0.3 决策）

| 项 | 决策 | 原因 |
|----|------|------|
| 弹反 / 完美格挡 | **不做** | 与 Hades 派系闪避 + 输入缓冲已能形成攻防节奏；弹反的判定窗口和奖励曲线需要大量试错 |

#### 6.7.4 普攻↔技能融合层（v0.3.3 新增）

> **设计动机**：解决功能缺口归档 1.7「技能数值过高 / 普攻只是 CD 填充」的根本性问题。v0.3 的战斗系统中，普攻和主动技能是两套并列的输出系统，玩家自然倾向"先 Q 再 E 再 R 然后等 CD"。本节定义"让普攻和技能在三个维度上有机融合"的整体架构。

##### 整体架构

```
                        ┌─────────────────────────────┐
                        │   普攻 ↔ 技能 融合层        │
                        └─────────────────────────────┘
                                      │
              ┌───────────────────────┼───────────────────────┐
              │                       │                       │
        【维度一】              【维度二】               【维度三】
        资源循环                 状态钩子                 动作衔接
     (普攻为技能充能)         (印记与引爆)            (派生与变招)
              │                       │                       │
       Demo1 + Demo2          Demo1 / 化身专属          Demo2+ 愿景
```

##### 维度一 · 资源循环（"普攻为技能充能"）

| 子方案 | 描述 | 阶段 |
|--------|------|------|
| **A · 三段连招减 CD（全局通用）** | Attack3 命中至少 1 个敌人 → 随机选 1 个 CD 中的 Q/E/R 技能，减少其当前 CD 的 10% | 🔴 **Demo1+ / v0.4 实施** |
| B · 灵力潮汐（积攒型） | 主动技能消耗灵力，普攻每击 +1、Attack3 额外 +5 灵力 | 🟡 Demo2 灵力觉醒（10 章已规划） |

**A 方案落地规格**：

```
事件钩子：OnAttack3Hit (玩家三段连招的第三段命中至少 1 个目标时触发)
处理：
  - 收集当前所有 cdRemaining > 0 的主动技能 (Q/E/R)
  - 若集合为空 → 不触发
  - 否则随机选 1 个 → cdRemaining -= cdRemaining * 0.10
  - 飘字 / HUD 提示："冷却 -X.Xs"
特殊规则：
  - 不影响"闪避"等独立按键的 CD（v0.4 曾包含业火"狂战"按键，已于 2026-05-16 随化身撤销）
  - 大招 R 槽位的减免效果相同（不分轻重）
  - 与天赋"窗口共振 / 御剑回锋"等化身专属 CD 减免叠加（独立乘区）
```

> 这是**全局通用机制，所有化身共享**，给普攻一个"无论选哪个化身都值得做"的普世价值。

##### 维度二 · 状态钩子（"印记与引爆 / 技能附魔"）

| 子方案 | 描述 | 阶段 |
|--------|------|------|
| **A · 化身印记 + 引爆** | 每个化身有自己的"印记 + 引爆"循环 | 🔴 **Demo1+ / v0.4 实施**（与化身机制版同步） |
| **B · 技能附魔普攻**（v0.3.3 新增） | 主动技能释放后短窗口内，普攻被附魔为该技能元素 | 🟡 Demo1+ / 走 6.5 槽位修饰扩展 |

**A · 化身印记 + 引爆 一览**（每个化身的融合机制）：

| 化身 | 印记 / 触发条件 | 引爆 / 收割机制 |
|------|---------------|---------------|
| 金 · 完美收刀 | 主动技能后必现灵压窗口 | 完美收刀触发灵压爆发 + `御剑回锋`天赋 30% 重置技能 CD 20% |
| 木 · 持续寄生 | 普攻命中目标种【寄生种子】 | 任意技能命中带种子敌人引爆所有种子 ×0.5 攻击/颗 AOE |
| 水 · 影息斩 | 影息斩命中目标留【水痕印】 | 任意技能命中带水痕目标 ×1.5 伤害（消耗水痕） |
| 火 · *(待重新设计)* | — | 火属性化身于 2026-05-16 整体撤销，融合点待化身重新设计后再补 |
| 土 · 御物斗法 | 玩家释放技能时事件钩子 | 所有存活傀儡在自身位置同步释放该技能（×10% 强度） |

> **统一格式**：所有化身都有"普攻↔技能强耦合"的明确接口；功能缺口归档 1.7 的问题在所有化身都得到解决。

**B · 技能附魔普攻 落地规格（v0.5+）**：

走 GDD 6.5 槽位修饰系统的新修饰类型 `affectsBasicAttack`：

```
ModifierDef:
  - requiredTag: <element>  (如 Thunder)
  - skillSlot: <slot>       (如 E)
  - affectsBasicAttack: true
  - postSkillWindow: 3s     (技能释放后 3s 内)
  - basicAttackCount: 3     (附魔下 3 次普攻)
  - 修饰效果: 普攻附加该元素元素事件 (如 Thunder → 链锁闪电 / Ice → 减速)

示例：雷灵珠槽内 + 缩地成寸 (E)
  → 释放缩地后 3s 内 / 下 3 次普攻 = 附加雷电链锁
```

> 实施时机：等 GDD 6.5 槽位修饰系统完成后再扩展该字段；当前阶段不阻塞。

##### 维度三 · 动作衔接（"派生与变招"）—— Demo2+ 愿景

#### 6.8.3 系统 C · 渡劫战（本体境界突破专属）`[v0.5.4 重设计]`

> **v0.5.4 重设计**：渡劫不再绑"秘境逐层推进"（旧的"躲 5 道雷"已废），而是**本体境界突破的专属大事件**——在洞府闭关石室「冲击境界」时触发，进入专属渡劫战场景。这是**渡天劫 + 渡心魔**的合体战。

**渡劫战 = 心魔（主对手）+ 天劫（环境威胁）同场：**

- **心魔（主对手）**：你的镜像分身（复用 6.8.4 心魔），强度随目标境界提升。**击败它 = 渡劫成功**
- **天劫（环境威胁）**：场景持续降下天劫（雷区收缩 / 雷网 / 追踪雷球），逼你不能站撸、要边打边走位
- **借劫修炼（贪婪点）**：主动承受一道天劫（高风险）→ 加速心魔虚弱 / 提升渡劫**成色**，但中弹多会压低成色甚至失败

**前易后难 + 逐步随机：**

| 突破 | 强度 | 形式 |
|------|------|------|
| 炼气→筑基 | 极简（教学） | 单一轻量天劫，几乎必过 |
| 筑基→金丹 | 简单 | 天劫领域生存（纯走位） |
| 金丹→元婴 | 中 | 天劫 + 心魔镜像 |
| 元婴→化神 | 难 + **随机** | 随机天劫类型（雷 / 火 / 风）+ 心魔变体，每次不同 |
| 化神→渡劫 | 极难 | 大天劫（多重劫）+ 强化心魔，生死大关 |

**结果：**
- 击败心魔 → **晋升本体境界**，成色由表现决定（无伤 = 完美，详见 9.1.8 境界成色）
- 失败（被心魔击败 / 中弹过多）→ 突破中止：重伤但不直接死，修为留着可再来
- ※ 渡劫战中血归零 → 按**身死道消**处理（8.3.4 转世）

**视觉**：闭关石室震动 → 进入异空间渡劫场（乌云雷光 + 血色心魔）→ 渡过后境界突破光效（成色越高越盛）。

#### 6.8.4 系统 D · 心魔（两种出场）`[v0.5.4 重设计]`

【心魔值】（隐藏 0~100）被动累积：受重伤（血 <30%）+15 / 久不杀敌 +5/s / 房间最后存活 +10 / **功利抉择（低道心）大幅 +**。**道心高 → 抑制累积；因果高 → 加速累积**（接 2.3 道心 / 因果叙事）。

心魔以两种形式出场：

**① 渡劫心魔（里程碑 · 可控）**
- 本体境界突破渡劫战的主对手（见 6.8.3）
- 必然、可预期 —— 是"渡心魔"的正式考验

**② 乱入心魔（惩罚 · 条件触发）**
- 心魔值满 100 **且**正在打秘境 Boss → 心魔分身**乱入** Boss 战，变"双线作战"
- 惩罚性：长期苟血 / 功利 / 低道心的玩家，会在最糟的时机被心魔反噬
- 镜像分身：同化身 / 同 build，血 = 玩家 ×1.2、攻 = 玩家 ×0.8，简化版玩家 AI
- 击败 → 心魔值清零；被击败 → 走火入魔（按身死道消处理）；主动撤离 → 心魔值保留到下次

**意义**：① 修仙独有，心魔是修仙者最大的敌人 ② 解决"玩家越强难度越低"——心魔随玩家强度成长 ③ 对抗自己的镜像，戏剧性 ④ 把"道心 / 因果"接入实际战斗后果。

#### 6.8.5 修仙战斗系统跟搜打撤的协同 `[v0.5.4 精简]`

玩家的修仙战斗体验：

  【秘境内】
  1. 越往深层 → 环境境界越高 → 境界压制越强（要本体境界撑得住，见 8.2）

## 8. 境界系统（两条境界轴）

### 8.1 两条境界轴（v0.5.4 重构）

> **v0.5.4 关键重构**：原"局内秘境层 = 练气→渡劫，每局重置 + 境界突破 3 选 1"的设计废弃。境界拆成**两条正交的轴**：

| 轴 | 名称 | 性质 | 作用 |
|----|------|------|------|
| **纵向 · 持久** | **本体境界** | 跨局累积（历练值突破；身死道消、转世归零） | 你的"真实功力"——决定**能走多深 / 根基多稳**（详见 9.1.8） |
| **横向 · 局内** | **秘境层深度** | 每局推进（闯层 / 撤离） | 秘境的探索深度；每层挂一个"环境境界"标签，与本体境界比 → **境界压制** |

#### 8.1.1 本体境界阶梯（跨局持久）

```
炼气 → 筑基 → 金丹 → 元婴 → 化神 → 渡劫（6 阶）
```

- **靠历练值突破**（渡劫战，详见 6.8 + 9.1.8），跨局保留
- **身死道消**：陨落则本体境界归零，转世重修（详见 8.4）
- 每阶有**成色**（瑕品 / 凡品 / 上品 / 完美），成色决定该境界增益强度——"完美金丹"远强于"凡品金丹"（详见 9.1.8）

#### 8.1.2 秘境层深度 + 环境境界（局内）

- 秘境按深度分层（Demo2 暂定 **6 层 / 3 区域**），靠闯层推进，每局从第 1 层开始
- 每层挂一个**环境境界**标签：第 1 层 = 练气级秘境 … 第 6 层 = 渡劫级秘境——这是秘境的**品级 / 凶险度**，**不是**玩家境界
- 玩家**本体境界**与**当前层环境境界**比较 → **境界压制**（见 8.2）

### 8.2 境界压制（替代旧"境界突破 3 选 1"）

完整压制档位表见 **9.1.8 · 本体境界的三大作用 ①**。要点：
- 本体境界 **≥** 当前层环境境界 → 契合（正常发挥，高 ≥2 阶有小幅碾压加成）
- 本体境界 **<** 环境境界 → 越级压制（低 1 阶 -20% 输出 / +25% 受伤；越低越狠，低 3 阶+ 九死一生）
- **是减益、不是硬锁**：低境界也能强闯深层（贪），但极险 —— 这是搜打撤"稳 vs 贪"的纵向版

> **设计意图**：想稳吃深层战利品 → 先回洞府把本体境界修上去；想搏命越级闯深层 → 高风险高回报。"我能走多深"由修为决定，而不是由这一局的运气决定。

### 8.3 撤离机制（v0.5 搜打撤核心）

> 每层秘境通过后，出现一个【撤离点】，玩家做出"撤离 / 继续" 的取舍。这是搜打撤系统的核心戏剧 —— **稳健 vs 贪心**（横向）。

#### 8.3.1 撤离点的视觉与位置

```
每境界最后一个房间（Boss 战或精英怪击败后）：
  → 房间中央自动 spawn 一个【撤离点】（视觉：泛光的古镜 / 道门 / 灵窍泉眼）
  → 同时 spawn 通往下一境界的传送门（视觉：紫色光柱）
  → 玩家选择走向哪个
```

#### 8.3.2 撤离流程

```
玩家走近【撤离点】（半径 2.5m 内）：
  ↓
  按 [F] 开始撤离
  ↓
  进入【撤离蓄力】状态（5 秒倒计时）：
    - 玩家无法移动
    - 期间可被发现的敌人攻击 → 中断撤离 → 需要重新按 F
    - 屏幕边缘出现金色"秘境瓦解" 渐进效果
  ↓
  5 秒后撤离成功：
    - 黑屏 1 秒 + 修仙者醒来动画
    - 进入洞府场景
    - 弹出"撤离成果"面板：本局获得的所有洞府素材 + 悟性
    - 局内灵物 build 在此清空（撤离时消失）
```

#### 8.3.3 6 个撤离点（v0.5.4：移除局内逐层渡劫）

> **v0.5.4 变更**：旧设计"每层结束触发小天劫"已移除——**渡劫现在专属于本体境界突破**（在洞府触发，详见 6.8 + 9.1.8），不再绑在秘境逐层推进上。秘境层推进只有"撤离 vs 继续"的抉择 + 越来越强的**境界压制**作为难度门槛。

| 秘境层 | 环境境界 | 撤离点位置 | 撤离奖励额度 | 继续 |
|--------|---------|-----------|------------|------|
| 第 1 层 | 练气级 | Boss 后 | 100%（基础） | → 第 2 层 |
| 第 2 层 | 筑基级 | Boss 后 | 105% | → 第 3 层 |
| 第 3 层 | 金丹级 | Boss 后 | 110% | → 第 4 层 |
| 第 4 层 | 元婴级 | Boss 后 | 120% | → 第 5 层 |
| 第 5 层 | 化神级 | Boss 后 | 140% | → 第 6 层 |
| 第 6 层 | 渡劫级 | 通关后 | **200%**（完整通关） | — |

> 越深的层环境境界越高 → 本体境界跟不上就被压制（8.2）。所以"敢不敢继续往下"同时取决于**本局状态**（血量/build）和**本体境界**（能不能扛住压制）。

#### 8.3.4 死亡 = 身死道消 · 转世传承（v0.5.4 路线 B）

```
秘境中陨落（任意层 / 房间）：
  ── 身死道消（清零）──────────────────────────────
  → 本体境界归零（回到炼气前）+ 累积修为清零
  → 局内 build 全失 + 本局未撤离的历练值 / 洞府素材丢失
  ── 洞府家业（传承保留）──────────────────────────
  → 灵脉等级、已解锁天赋 / 功法 / 灵物池、洞府库存、灵气 全部保留
  ── 转世重修 ────────────────────────────────────
  → 新一世从炼气重修，洞府家业加持 → 重修远快于首世
  → "转世宿慧"：转世次数越多，重修起步略有加成（轮回流，可选）
  → "道伤" debuff（一段时间无法入秘境，可消耗灵气解除）
```

> **立意**："你这一世的道消了，但你经营的洞天家业，留给了下一世。"——既保住"身死道消"的修仙重量，又不废掉洞府种田 meta。

#### 8.3.5 设计意图

| 体验目标 | 实现机制 |
|------|------|
| **稳健玩家**：拿了好东西想保住 → 提前撤离 | 浅层撤离奖励 100~110%，安全 |
| **贪心玩家**：想博更大收益 → 闯更深层 | 深层奖励至 200%，但环境境界高 → 压制强，需本体境界撑住 |
| **戏剧时刻** | 撤离蓄力 5s 被攻击中断 → 紧张感拉满 |
| **死亡有真重量** | 身死道消（本体境界 + 修为归零）—— 但洞府家业传承，不绝望、有"东山再起"的盼头 |

## 9. 局外成长系统 · 洞府 7 模块（v0.5 重写 / 取代抽象 Hub）

> **v0.5 核心改动**：原"现实线 Hub" 的抽象设施升级为**修仙化的具体洞府系统**。
>
> **v0.5.2 核心新增**：**闭关修炼 + 灵脉培养 + 机缘事件**三大系统，让洞府不再只是"加工素材的基地"，而是**真正的修炼之所**。历练值在入秘境时积累，回府后玩家选择将历练值投入修为（自身变强）还是灵脉（洞府变强），形成修仙小说中"下山历练 → 回府闭关"的核心节奏。
>
> **修仙叙事根据**：修仙者本就在"洞府"中修炼——出关下山闯秘境，平安归来在洞府闭关修炼、培养灵脉。这是修仙小说核心节奏，跟搜打撤的"撤离回基地"循环天然契合。
>
> **跟搜打撤的关系**：洞府所有输入资源（历练值 / 洞府素材 / 悟性 / 灵脉道具）都来自秘境——没去闯秘境就没历练值，没历练值就修不了为，玩家**必须不停出入秘境**形成完整循环。

### 9.0 洞府总览

```
玩家从秘境撤离 → 进入洞府场景（开放式 3D 场景，可走动）：

  ┌──────────── 洞府核心 ────────────┐
  │  🧘 闭关修炼（历练值 → 修为 → 本体境界） │ 纵向：能走多深 / 根基多稳
  │  💎 灵脉（历练值 → 灵脉等级）      │  品质：秘境掉落 + 机缘品质
  │  🎲 机缘事件 → 天赋分支解锁        │  灵脉越高，好机缘越多
  └──────────────────────────────────┘

  🌱 灵田                 ⚒️ 炼器房              🐉 灵兽园
  （种灵植 → 灵药/辅料）    （灵矿+妖兽材料 → 解锁灵物）  （幼崽 → 战斗坐骑）

  📜 藏经阁               ⛩️ 阵法台              🧘 悟道蒲团
  （古籍残页 → 功法）       （阵法符 → 入秘境 BUFF）  （悟性 → 永久解锁化身天赋节点）

核心循环：入秘境历练 → 获得历练值 → 闭关提升本体境界 / 注入灵脉 → 再入秘境（走更深）
时间机制：
  - 游戏内时间流逝（玩家在线时才推进，避免 P2W）
  - 加速按钮（消耗灵气立即完成 → 灵气来自秘境中战斗）
  - 部分模块允许同时处理多个（如 5 块灵田并行种）
```

### 9.1.8 闭关修炼（历练值 → 修为 → 本体境界）`[v0.5.4 重设计 / 2026-05-29]`

> **设计根据**：修仙者的核心日常就是**闭关修炼**——出去历练，回洞府把历练所得淬炼为修为、提升本体境界。
>
> **v0.5.4 重设计（关键）**：修为**不做**"开局选方向"（方向已由**化身**承担），也**不做**"永久属性加点"（build 深度已由**悟性 → 悟道蒲团天赋**承担）。修为回归它在修仙世界里最本真的含义——**本体境界（功力深浅）**，是一条纯**纵向**成长轴：决定你"**能走多深、根基多稳**"，而不是"这把怎么打"。
>
> **职能分工一图**：
>
> | 系统 | 轴向 | 回答的问题 |
> |------|------|-----------|
> | 化身 | 横向 | 这把**怎么打** |
> | 灵物 / 协同 / 槽位修饰 | 横向 | 这把 **build 怎么搭** |
> | 悟性 → 天赋 | 深度 | 我**永久拥有什么能力** |
> | **本体境界（修为）** | **纵向** | 我**能走多深 / 根基多稳** |
> | 灵脉 | 品质 | 我**每趟收益多好** |

#### 历练值（秘境中获取）

| 维度 | 内容 |
|------|------|
| **获取方式** | 秘境中战斗击杀、探索未知房间、完成奇遇事件、击败 Boss、成功渡劫等 |
| **获取公式** | 基础值 × 层数加成 × 难度系数（越深层越多） |
| **死亡保留** | 30%（死亡代价要大，才有撤离紧张感） |
| **撤离保留** | 100% |
| **上限** | 单局无上限；累积池有上限（需要闭关消化后才能继续高效积累） |

#### 闭关突破（历练值 → 修为 → 本体境界）

| 维度 | 内容 |
|------|------|
| **交互** | 走到闭关石室 →「闭关」消耗历练值积累修为；攒满阈值可「突破」本体境界 |
| **修为** | 历练值淬炼成的经验值（累积型），用于突破下一境界 |
| **本体境界** | 炼气 → 筑基 → 金丹 → 元婴 → 化神 → 渡劫（6 阶，与秘境层同名同序） |
| **突破阈值** | 递增（炼气→筑基最低，越往后越高），鼓励持续历练 |
| **突破方式** | 攒满阈值后，在闭关石室「冲击境界」→ 进入**渡劫战**（详见 6.8.3）。渡过 → 晋升；中止 → 修为留着、可再来 |

#### 境界成色（突破质量 · "完美金丹"）

突破不是二元成败，**渡劫战的表现决定这一阶境界的成色**，成色决定该境界增益的强度：

| 成色 | 渡劫表现 | 境界增益系数 | 额外 |
|------|---------|------------|------|
| **瑕品** | 勉强渡过（重伤 / 吃满天劫） | ×0.7 | — |
| **凡品** | 普通渡过 | ×1.0 | — |
| **上品** | 漂亮渡过（少受创 / 限时达成） | ×1.3 | — |
| **完美** | 无伤 / 满足隐藏条件（如吃满"借劫"仍无伤） | ×1.6 | 解锁该境界**专属特性**（如完美金丹得一个金丹期独有机制） |

> "境界增益" = 本阶本体境界给的纵向收益（降低境界压制、渡劫底力、道伤减免——见下"三大作用"），成色越高，这些收益越强。**完美金丹**实打实强过凡品金丹 → 给玩家"追求漂亮渡劫"的动力。结合转世，可再冲更高成色，构成 roguelite 长期目标。

#### 凝实（历练值的次要 sink · 可选）

已突破的境界，平时可在闭关石室消耗历练值**打磨成色**（瑕品 → 凡品 → 上品，**完美需靠渡劫表现、不可打磨**）。

> 意义：给历练值一个"安全的渐进 sink"——不想冒险渡劫的玩家也能稳步变强；想冲新境界的玩家则把历练值留给突破。又是一层"稳 vs 进"的取舍。

> **本体境界 ≠ 秘境层境界**：
> - **秘境层境界**：每局从练气爬到渡劫的"局内推进"（6 层，每局重来）
> - **本体境界**：跨局累积的"真实功力"（修为突破而来，永久保留）
>
> 两者同名，关系见下方"境界压制"。

#### 本体境界的三大作用（全部挂在已有系统上，0 新机制）

##### ① 境界压制（核心 · 复用 6 层秘境）

秘境每层有"环境境界"（第 1 层 = 练气 … 第 6 层 = 渡劫）。比较玩家**本体境界**与**当前所在秘境层的环境境界**：

| 差值 | 状态 | 效果 |
|------|------|------|
| 本体 ≥ 环境 | **契合** | 正常发挥（本体高 ≥2 阶：小幅"高屋建瓴" +5% 全伤，可选） |
| 本体低 1 阶 | **越级** | 受到伤害 +25% · 造成伤害 -20% |
| 本体低 2 阶 | **险境** | 受到伤害 +50% · 造成伤害 -40% |
| 本体低 3 阶+ | **九死一生** | 受到伤害 +100% · 造成伤害 -60% |

- **是减益、不是硬锁**：低修为也能强闯深层（贪），但极险 —— 保留搜打撤"稳健 vs 贪心"的核心张力
- **意义**：修为 = "我能稳定深入到第几层"。想稳吃深层战利品 → 先把本体境界养上去；想搏命越级 → 高风险高回报
- **新手引导自然**：新玩家本体境界低，前几层无压制玩得顺；越往深越需要"先回去修炼"，形成天然节奏

##### ② 渡劫底力（复用天劫渡劫 6.8.3）

本体境界**每高于**当前秘境层 1 阶：天劫伤害 -15%、渡劫应对窗口 +0.2s；**每低于** 1 阶则反向加码。

> 修为深 = 渡劫稳。这也给"渡劫期（第 6 层）"一个明确的准备目标：本体境界没到化神/渡劫，硬冲大天劫会非常吃力。

##### ③ 道伤减免（复用道伤 debuff）

秘境中陨落 → 落下"道伤"（一段时间无法入秘境，可消耗灵气解除）。**本体境界每提升 1 阶，道伤时长 -10%**（化神 / 渡劫期几乎无道伤）。

> 修为深 = 容错高、回秘境快。给"变强"一个直接服务搜打撤节奏的回报。

#### 核心抉择：历练值 → 修为 vs 灵脉

```
每次从秘境带回历练值后，玩家在两条纵线间分配：

  历练值 ──┬──→ 🧘 修为（本体境界）：纵向"深度 + 底力"
           │      → 能稳定深入更深层（境界压制↓）+ 渡劫稳 + 道伤短
           │
           └──→ 💎 灵脉：每趟"收益品质"
                  → 秘境掉落质量↑ + 机缘品质↑（解锁天赋分支）

  ◆ 修为：让我「敢深入、扛得住」
  ◆ 灵脉：让我「每趟捞得更好」
  二者有张力 —— 灵脉高让深层更值得去，修为高让深层去得起；
  历练值有限，逼玩家按当前瓶颈取舍（"我是死太快，还是嫌掉落差？"）。
```

> **设计自洽点**：高灵脉鼓励你往深层走（深层收益好），但深层有境界压制 —— 逼你也得养修为。两条线互相拉动，形成正向循环而非二选一死局。

### 9.1.9 灵脉系统（历练值 + 灵脉道具 → 收益品质）`[v0.5.4 重设计 / 2026-05-29]`

> **设计根据**：修仙者选洞府第一件事就是看灵脉品质。灵脉好的洞天福地，修炼事半功倍。
>
> **v0.5.4 重设计**：灵脉聚焦"**每趟收益品质**"——影响两个核心维度：**秘境掉落品质** + **机缘事件品质**。灵脉差 = 秘境里东西差 + 好机缘不来。
>
> **v0.5.4 变更说明**：原 v0.5.3 的"修为发挥率"维度移除——因为修为已重定义为"本体境界"（纵向资格，详见 9.1.8），不再是"可被灵脉放大的 buff 数值"。修为与灵脉现在是两条**并列的纵线**（深度 vs 收益），由历练值争夺。

#### 灵脉强度

| 维度 | 内容 |
|------|------|
| **定义** | 洞府灵气等级，影响秘境掉落品质、机缘品质、洞府模块效率 |
| **等级** | 枯脉 → 凡脉 → 灵脉 → 福地 → 洞天（5 级） |
| **初始状态** | 枯脉 |
| **提升方式** | ① 消耗历练值注入（跟修为争夺同一资源）② 秘境中灵脉道具 ③ 机缘事件 |

#### 灵脉的两维影响（核心价值）

| 灵脉等级 | 秘境掉落品质 | 机缘品质 |
|----------|------------|---------|
| **枯脉** | 掉落品质低 | 仅低级机缘 |
| **凡脉** | 基准掉落 | 基础机缘 |
| **灵脉** | 稀有灵物掉率 +15% | 可触发中级机缘 |
| **福地** | 可进入隐藏层 | 可触发高级机缘（**天赋分支解锁**） |
| **洞天** | 天品灵物掉率 +10% | 可触发传说机缘（**唯一故事线**） |

> **设计意图**：灵脉是"每趟捞得多好"的天花板。它鼓励玩家往深层走（深层 + 高灵脉 = 最好收益），但深层有"境界压制"（9.1.8）逼你同步养修为——两条线互相拉动，形成正向循环。

### 9.1.10 洞府机缘事件`[v0.5.3 重设计 / 2026-05-28]`

> **设计根据**：修仙小说中，主角很多关键转折发生在日常中——灵兽闯入洞府、地下遗迹浮出、天降异象。
>
> **v0.5.3 重设计**：机缘事件的核心产出从"随机资源"改为**天赋分支解锁 + 故事线推进**——这是机缘事件的**独占价值**，其他系统给不了。只有灵脉达到一定等级才能触发高级机缘（天赋解锁），所以灵脉也有了实际意义。

#### 触发机制

| 维度 | 内容 |
|------|------|
| **触发时机** | 每次从秘境撤离回洞府时，按概率触发 |
| **触发概率** | 受灵脉等级影响：枯脉 5% / 凡脉 10% / 灵脉 15% / 福地 20% / 洞天 30% |
| **保底机制** | 连续 5 次未触发 → 第 6 次必定触发 |
| **呈现方式** | 回到洞府时弹出事件卡片 |

#### 机缘分级（灵脉门槛）

| 机缘等级 | 灵脉要求 | 核心产出 | 设计意图 |
|---------|---------|---------|---------|
| **低级** | 枯脉+ | 资源（灵矿、灵药、灵脉碎片） | 基础补给，让新玩家也有惊喜 |
| **中级** | 灵脉+ | 稀有道具 + NPC 故事推进 | 开始有叙事价值 |
| **高级** | 福地+ | **天赋分支解锁令** + 稀有灵兽 | 真正的战力突破——只有养灵脉才能拿到 |

#### 链式机缘

部分机缘不是独立事件，而是**跨多局的连锁事件**：

```

### 9.2 时间机制（v0.5 新增）

```
洞府时间流逝规则：
  - 玩家在线时游戏内时间正常流逝（1 真实分钟 = 1 游戏内分钟）
  - 玩家离线时时间冻结（避免 P2W / 反人性）
  - 加速按钮：消耗"灵气" 资源（秘境中战斗产出）可立即完成
    - 立即完成 1 株灵植：消耗 50 灵气
    - 立即完成 1 件灵器：消耗 500 灵气
  - 关闭加速时长（暂停游戏 → 关掉电脑 → 重开）：时间归到关闭时

设计意图：
  - 玩家可以"种好灵植 / 开始炼丹" 后出去闯秘境 → 回来收获 → 形成有机循环
  - 加速消耗灵气 → 玩家不耐烦时可烧资源跳过
  - 没有真实时间挂机 → 不让玩家因为"挂机几天"而被超车
```

### 9.3 跟原"现实线 Hub" 的差异

| 维度 | 原 Hub（v0.4.1 之前） | 洞府 v0.5 |

## 12. 关卡设计（Demo2 规格书 · 2026-05-23）

> **设计概述**：关卡以独立房间为基本单元，通过**事件驱动 Boss 形态**实现叙事与战斗的动态绑定。玩家在推进过程中触发的事件会累积"Boss Flag"，最终 Boss 房读取 Flag 组合决定启用哪套战斗模板。参考《暖雪》《哈迪斯》等有叙事成分的 Roguelike 进行核心基础设计。
>
> **单向阀原则**：玩家对事件做出选择后不可修改（Flag 一旦写入即锁定）。如果设计上需要反悔，须通过**消耗型道具**实现（例如"逆命符"，清除最近一条 Boss Flag），而非系统层面允许回退。

### 12.1 关卡说明

关卡设计的重心在**最终 Boss 房**：玩家在各类房间中有概率碰到影响 Boss 的事件，玩家对事件的选择最终决定 Boss 的战斗形态（不同的攻击模组 / 不同阶段 / 不同援军）。

#### 12.1.1 核心机制：Boss Flag 系统

##### 【流程说明】：
在简化的关卡流程中，BOSS房间A和B并非指代两个不同的BOSS房，而是因为事件不同的触发，影响了BOSS不同的型态，而事件A和事件B则像是一种解锁方式的开关，若玩家解锁事件A则BOSS使用第一套战斗模组，反之解锁第二套，而BOSS有多少阶段设计具体交由战斗进行设计后关卡在配合设计事件；

```
数据结构（运行时）：

BossFlagSet
├── flags : Dictionary<string, int>    // Flag名 → 值（0/1 布尔 或 累计数值）
├── Set(flagName, value)               // 事件触发时写入
├── Has(flagName) → bool               // Boss 房读取时判断
└── GetValue(flagName) → int           // 数值型 Flag（如杀戮计数）

示例 Flag：
  "betrayed_yeXiu"    = 1     ← 事件"击败叶修后选择使用他"
  "saved_yeXiu"       = 1     ← 事件"击败叶修后选择埋葬他"
  "kill_count_elite"  = 3     ← 本区域击杀精英数量
  "karma_debt"        = 2     ← 因果债累计（来自 GDD 因果系统）
```

**Flag 来源分三类**：

| 来源 | 写入时机 | 示例 |
| :--- | :--- | :--- |
| **事件选择** | 玩家在事件房 / 战斗房动态事件中做出选择后立即写入 | `betrayed_yeXiu = 1` |
| **战斗行为** | 战斗房 / 精英房结束时根据行为统计写入 | `kill_count_elite += 1`、`no_damage_clear = 1` |
| **系统联动** | 因果系统 / 道心系统等跨系统写入（详见 12.4） | `karma_debt = 因果系统.debt`、`daoxin_state = "入魔"` |


#### 12.1.2 实际流程
```

│   │  · 精英房 → 精英战 → 结算 → (概率)触发动态事件             │                  │

**流程说明**：
- Boss 房 A 和 B 并非两个不同的物理房间，而是同一个 Boss 房读取不同 Flag 组合后启用不同的战斗模板
- 事件 A 和事件 B 像"开关"，写入不同的 Flag；Boss 有多少套战斗模板由战斗设计决定，关卡配合设计对应事件
- 单个区域内 Flag 独立；跨区域的 Flag 通过因果系统（12.4）传递

| 区域 | 对应境界 | 房间数 | Boss | 特殊规则 |
| :--- | :--- | :--- | :--- | :--- |
| Act 1 | 练气期 → 筑基期 | 12~18 | 区域 Boss 1 | 新手友好，事件较少（1~2 个） |
| Act 2 | 金丹期 → 元婴期 | 18~24 | 区域 Boss 2 | 事件密度提升（3~4 个），开始出现跨区域因果 |
| Act 3 | 化神期 → 渡劫期 | 24~30 | 最终 Boss + 大天劫 | 事件密度最高（4~6 个），Boss 形态变化最复杂 |

每个区域**必须包含**：1 个起点 + 1 个 Boss 房。其余房间按权重随机分配。

#### 12.1.4 房间类型全集定义
> 目前就先参考《梦之形》的房间量来定义房间类型，每个区域有12~30个小型房间，一共3个区域；

| 房间类型（RoomTag）| 核心功能与玩法逻辑 | 房间类型 |

| **精英房** | 会带1~2只精英和复数小怪的房间，可触发局内动态事件（可影响BOSS） | 常规房 |
| **商店房** | 可以通过局内收集的基础货币购买局内强化（或其他） | 特殊房 |

### 12.2 核心功能逻辑梳理

以下根据一个关卡的游玩流程进行顺序说明；

#### 12.2.1 关卡选择方式

> 玩家进入局内后，以《杀戮尖塔》的树状图方式进行关卡选择。后续可替换为"仙山舆图"等更修仙化的表现形式，但底层数据结构不变。

##### 【关卡选择方式】：
* 玩家进入"起点"场景时，场景出现"传送门"，走近后弹出"F"交互提示
* 按下交互键弹出树状关卡图，玩家在当前层的可达节点中选择下一个房间（2~4 选 1）
* 树状图的结构由 `Map_Structure_Config` 表定义，节点内容由 `Room_Socket_Group_Config` 表定义
* 树状图上每个节点显示**房间类型图标**（剑=战斗、骷髅=精英、金币=商店、问号=事件、王冠=Boss），但不显示具体内容

##### 【树状图生成算法】：

```
输入：Map_Structure_Config 的一行记录（ActID, MaxFloor, MinNodes, MaxNodes, ...）

1. 创建 MaxFloor 层节点网格
2. 第 0 层 = 起点（固定 1 个节点）
3. 最后一层 = Boss 房（固定 1 个节点）
4. 中间每层：
   a. 节点数 = Random(MinNodes, MaxNodes)
   b. 每个节点的房间类型 = 从 RoomPoolID 引用的房间池中按权重抽取
   c. 约束检查：
      - 精英房不连续出现（相邻两层同一路径上不连续精英）
      - 商店房每区域至少 1 个
      - 特殊事件房每区域至少 1 个
5. 连线规则：
   a. 每个节点至少有 1 条入边和 1 条出边（保证可达）
   b. 跨层连线不超过 1 层跨度（不能跳层）
   c. 路径分叉鼓励出现（增加选择感）
6. 输出：节点列表 + 连线列表 → 渲染树状图 UI
```

##### 【路线表格】：
> 表格名称：`Map_Structure_Config`

| 表头名称 | 名称 | 功能说明 |
| :--- | :--- | :--- |
| **ID** | ID | 自增主键 |
| **ActID** | 区域 ID | 标识当前区域（1 / 2 / 3），用于跨区域引用 |
| **MaxFloor** | 总层数 | 控制该区域树状图从起点到 Boss 共多少层（含起点和 Boss） |
| **MinNodes** | 每层最小节点数 | 中间层的最少可选房间数 |
| **MaxNodes** | 每层最大节点数 | 中间层的最多可选房间数 |
| **NormalWeight** | 常规房权重 | 战斗房 + 精英房的总权重占比（如 75） |
| **SpecialWeight** | 特殊房权重 | 商店房 + 事件房的总权重占比（如 25） |
| **EliteMinCount** | 精英房最小数 | 该区域精英房至少出现几次 |
| **EliteMaxCount** | 精英房最大数 | 该区域精英房至多出现几次 |
| **EventMinCount** | 事件房最小数 | 该区域特殊事件房至少出现几次 |
| **ShopMinCount** | 商店房最小数 | 该区域商店至少出现几次 |
| **RoomPoolID** | 房间池 ID | 指向 `Room_Socket_Group_Config` 的多个 ID，表示该区域可以生成哪些房间 |

> 表格核心目的是制定可控的随机规则，后续会扩充可控范围（如"事件房不出现在第 1 层"等条件约束），程序实现时应预留扩展字段。

#### 12.2.2 房间设计

> 一个房间由**场景底板**（美术制作的固定平台）+ **动态生成内容**（表格驱动）组成。

##### 【房间内可包含的元素】：

| 元素 | 说明 | 关联表格 |
| :--- | :--- | :--- |
| **事件** | 绑定房间触发，根据选择写入 BossFlagSet 或产生其他变化；特殊事件房必定触发，战斗房 / 精英房概率触发 | `Event_Story_Config` |
| **资源** | 金币、强化素材、局外养成材料等掉落物 | `Item_InRun_Config` / `Material_CaveRes_Config` |
| **局内强化** | 随规则出现，与战斗密切相关；部分强化与事件绑定 | `Item_InRun_Config` |
| **敌对单位** | 刷怪配置（小怪波次 / 精英 / 环境怪） | `Enemy_Squad_Config`（待建） |

##### 【房间生成规则】：

1. 美术提供固定场景底板，底板内预埋若干 **Socket 点位**（Prefab 插槽）：
   - `SpawnPoint_Enemy`：怪物刷新点（可多个）
   - `SpawnPoint_Item`：道具 / 资源掉落位
   - `SpawnPoint_Event`：事件触发器位（NPC 或物件）
   - `SpawnPoint_Shop`：商店摊位位
2. 关卡系统根据房间类型 + `Room_Socket_Group_Config` 表，将对应内容实例化到 Socket 点位上
3. 同一个场景底板可被多种房间类型复用（通过 Socket 内容差异化）

##### 【房间表格】：
> 表格名称：`Room_Socket_Group_Config`

| 表头名称 | 名称 | 功能说明 |
| :--- | :--- | :--- |
| **ID** | ID | 自增主键 |
| **SceneName** | 场景名 | 填写场景文件名，用于加载对应的场景底板 |
| **RoomType** | 房间类型 | 对应 12.1.4 的数字编码（0=起点 / 1=战斗 / 2=精英 / 3=商店 / 4=事件 / 5=Boss） |
| **EnemySquadID** | 怪物配置 ID | 引用怪物波次表（战斗房 / 精英房填，其他填 0）；可多填逗号分隔，运行时按权重随机选一组 |
| **ItemDropIDs** | 掉落物 ID 列表 | 引用 `Item_InRun_Config` / `Material_CaveRes_Config` 的 ID，逗号分隔 |
| **ItemDropWeights** | 掉落权重列表 | 与 ItemDropIDs 一一对应的权重值 |
| **EventID** | 事件 ID | 引用 `Event_Story_Config` 的 ID；0 = 无事件 |
| **EventTriggerRate** | 事件触发概率 | 0~100 整数。战斗房建议 15~30，精英房建议 30~50，事件房固定 100 |
| **Weight** | 自身权重 | 该房间在所属区域池中被选中的权重 |

> 补充：关卡表格并非绝对设计，可根据实际需求调整到最优解。程序实现时每个字段应留下修改空间。

```

### 12.3 Boss 形态系统

> Boss 形态系统是关卡设计的**终点**——所有事件 Flag 在这里汇聚，决定玩家面对的最终战斗。

#### 12.3.1 Boss 形态配置表

> 表格名称：`Boss_Phase_Config`

| 表头名称 | 名称 | 功能说明 |
| :--- | :--- | :--- |
| **ID** | ID | 自增主键 |
| **BossID** | Boss 标识 | 每个区域的 Boss 有唯一 ID |
| **PhaseName** | 形态名 | 如"常规形态"、"狂暴形态"、"悲悯形态" |
| **RequiredFlags** | 触发条件 | 格式：`flagA=1&flagB>=2`，支持 AND 组合；满足条件则启用该形态 |
| **Priority** | 优先级 | 多个形态都满足时，取 Priority 最高的；优先级相同取第一个满足的 |
| **DialogueLines** | 出场对白 | 逗号分隔的多行对白文本，支持变量替换 |
| **SkillSetID** | 攻击模组 ID | 引用 Boss 技能配置表，决定 Boss 使用哪套技能 |
| **StatModifier** | 数值修正 | 格式 `hp*1.2,atk*1.5,spd*0.8`，在 Boss 基础数值上叠加 |
| **SummonSquadID** | 援军配置 | 引用怪物波次表的 ID；Boss 进入该形态时召唤援军；0 = 无援军 |

#### 12.3.2 Boss 形态选择逻辑

```
Boss 房加载时：
    ↓
读取当前区域的 BossFlagSet
    ↓
遍历 Boss_Phase_Config 中 BossID 匹配的所有记录：
  对每条记录，检查 RequiredFlags 是否全部满足
    ↓
收集所有满足条件的形态 → 按 Priority 降序排列
    ↓
选取 Priority 最高的形态作为【主形态】
    ↓
（可选）若存在第二高 Priority 的形态 → 作为【P2 阶段形态】
       （Boss 血量 <50% 时切换）
    ↓
加载 SkillSetID 对应的攻击模组
应用 StatModifier 数值修正
准备 SummonSquadID 援军
拼接 DialogueLines 出场对白
    ↓
Boss 战开始
```

#### 12.3.3 Boss 形态示例（Act 1 · 测试用）

假设 Act 1 Boss 为"青云宗长老"，有 3 套形态：

| 形态 | RequiredFlags | Priority | 效果 |
| :--- | :--- | :--- | :--- |
| **常规** | 无（默认） | 0 | 标准技能组，标准数值 |
| **震怒** | `betrayed_yeXiu=1` | 10 | 对白："叶修是我座下弟子！" → HP ×1.3 / ATK ×1.5 / 召唤 2 名弟子援军 |
| **悲悯** | `saved_yeXiu=1` | 10 | 对白："你...埋葬了他？" → ATK ×0.8 / 但新增"悲悯反击"技能（受击时概率全屏 AOE） |

- 玩家在事件中选择"使用叶修" → `betrayed_yeXiu=1` → Boss 进入震怒形态（更硬更猛）
- 玩家选择"埋葬叶修" → `saved_yeXiu=1` → Boss 进入悲悯形态（攻击低但有反击机制）
- 两个事件都没触发 → Boss 常规形态

### 12.4 与现有系统的集成

> 第 12 章关卡设计不是孤立系统，需要与 GDD 中已定义的修仙原生系统打通。

#### 12.4.1 因果系统 → Boss Flag

因果系统在关卡层面的接入方式：

| 因果行为 | 写入的 Flag | Boss 读取效果 |
| :--- | :--- | :--- |
| 杀戮债 ×3（本局杀了 3 个 NPC） | `karma_kill >= 3` | Boss 对白拼接"煞气冲天"片段 + HP ×1.2 |
| 盗宝债（偷了 NPC 物品） | `karma_steal = 1` | Boss 召唤"讨债鬼兵"援军 |
| 辜负债（见死不救） | `karma_ignore = 1` | Boss 新增"道义审判"技能（每 15s 全屏 AOE） |
| 入魔债（入魔状态下杀人） | `karma_demon = 1` | Boss 开局即进入狂暴形态（跳过 P1） |

#### 12.4.2 道心系统 → 事件 & Boss

道心值（0~100）在关卡层面的影响：

| 道心状态 | 对事件的影响 | 对 Boss 的影响 |
| :--- | :--- | :--- |
| 入定（80~100） | 事件中可能出现"入定专属选项"（如"以理服人"化解冲突，不写杀戮 Flag） | 无直接影响 |
| 清明（50~80） | 标准事件选项 | 标准 Boss |
| 心摇（20~50） | 事件中可能出现"暴力专属选项"（伤害更高但写入更多因果债） | Boss 有概率出场嘲讽："你的道心已乱" → 玩家受击概率 +20% |
| 入魔（0~20） | 部分 NPC 事件直接跳过对话进入战斗（无法选择和平选项） | Boss 对白："你已入魔" → Boss ATK ×1.3 |

#### 12.4.3 命格系统 → 事件池 & 掉落

隐藏命格（开局随机 · 玩家不可见）对关卡的影响：

| 命格 | 对关卡的隐藏影响 |
| :--- | :--- |
| 天命之子 | 特殊事件房出现概率 +20%，但精英房也 +1 个 |
| 凡夫俗子 | 无额外影响（最标准的体验） |
| 大凶之徒 | 因果债 Flag 写入值 ×1.5（同样行为累积更多因果）；Boss 掉落奖励 ×1.5 |
| 道祖转世 | 事件中 NPC 对话有细微变化（如"前辈请"）；商店价格 -20% |
| 妖族遗孤 | 妖修 NPC 事件出现友好选项；正道 NPC 事件出现敌对选项 |

#### 12.4.4 寿元系统 → 事件代价

事件选项中的代价可以包含寿元消耗：

```
事件示例："古修遗宝"
  选项 A："以寿元换取" → 消耗 10 年寿元，获得天品灵物
  选项 B："放弃"       → 无代价无奖励
  选项 C："强行夺取"   → 触发战斗，胜利获得灵物 + 因果债 +1
```

这让寿元成为事件层面的"另一种货币"，丰富选择的权衡维度。
