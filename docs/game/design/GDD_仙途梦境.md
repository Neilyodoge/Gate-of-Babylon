## 1. 游戏概述

### 1.1 一句话描述

> 一款修仙题材的 Roguelike Top-down 3D ARPG（参考《梦之形》视角风格），玩家在梦境与现实的双线叙事中，通过自由组合灵物和功法构建无限可能的 Build，探索仙途的终极真相。

### 1.2 核心卖点

| 卖点 | 说明 |
|------|------|
| **以撒式自由 Build** | 无固定流派，150+ 灵物自由组合，Build 自然涌现 |
| **机制型 Synergy** | 灵物不只是数值加成，而是改变技能机制（区别于《梦之形》的数值宝石） |
| **灵根 = 规则修改器** | 不同灵根改变游戏基础规则，同一道具不同灵根体验完全不同 |
| **梦境×修仙双线叙事** | 梦境线（局内战斗）+ 现实线（局外成长），终极悬念驱动长期游玩 |
| **100+ 隐藏组合** | 发现道具间的化学反应是核心乐趣，社区讨论热点 |

### 1.3 参考作品分析

**《Shape of Dreams / 梦之形》的不足（我们要解决的问题）：**

| 问题 | 我们的解决方案 |
|------|--------------|
| Build 多样性有限，几局后见过所有东西 | 150+ 灵物 + 100+ 隐藏组合，理论 Build 数近乎无限 |
| 宝石系统偏数值，缺乏机制深度 | 灵物附着到技能上改变机制，而非单纯加数值 |
| 敌人与 Boss 设计单一 | *（TODO：敌人/Boss 设计）* |
| 叙事/世界观薄弱 | 梦境×修仙双线叙事，碎片化剧情 + 终极悬念 |
| 缺乏长期目标（Meta Progression） | 完整的局外成长系统：感悟天赋树 + 居所建设 + 秘术解锁 |
| 重玩价值低 | 多灵根 × 随机灵物 × 隐藏组合 = 每局体验差异化 |

## 2. 世界观与叙事 `[v0.x 暂未实现]`

### 2.1 核心设定（方案E：梦入仙途）

主角是一个生活在凡间的普通人，每晚入睡后会进入一个名为 **"仙途"** 的梦境世界。

梦中的一切都无比真实——修炼、战斗、法宝、妖兽……  
梦中死亡 = 惊醒，但修炼的"感悟"会留在记忆中。  
每次入梦，仙途的面貌都不同（Roguelike 随机性）。

随着入梦次数增加，主角逐渐发现：
- 梦境和现实的边界在模糊
- 现实中开始出现不可思议的事情
- 仙途可能不是梦，而是另一个真实的世界
- **最终谜题：到底哪边才是"梦"？**

### 2.2 双线结构

| 线 | 对应 | 内容 |
|----|------|------|
| 🌙 梦境线（局内） | Roguelike 战斗 + 探索 | 随机秘境、灵物获取、Boss 战、境界突破 |
| ☀️ 现实线（局外） | 成长 + 叙事 + 经营 | 感悟天赋树、居所建设、剧情推进、秘术解锁 |

**双线互动：**
- 梦境中获得的资源 → 影响现实（解锁能力、推进剧情）
- 现实中的选择 → 影响梦境（改变秘境内容、难度、事件）

### 2.3 叙事设计优势

- **致敬原作**《梦之形》的梦境主题
- **死亡毫无违和感**——做梦醒了而已
- **双线叙事拓展空间极大**——现实线可以做轻度经营/社交/剧情
- **终极悬念**驱动长期游玩——"真相是什么？"

## 4. 灵根系统（角色选择） `[v0.3 基础 5 灵根 MVP 已落地]`

### 4.1 设计哲学

> **灵根不是"属性加成"，而是一条独特的"游戏规则"。**  
> 它不会限制你拿什么道具，但会影响你怎么玩。  
> 类比以撒：灵根 ≈ 角色选择（不同角色 = 不同起始道具 + 不同被动规则）。

### 4.2 基础灵根（初始可选）

| 灵根 | 被动规则 | 起始灵物 | 设计意图 |
|------|---------|---------|---------|
| **金灵根** | "锐金之体"：所有攻击附带微量穿透（穿过第一个敌人，对后方敌人造成50%伤害） | 锈铁飞剑 | 适合新手，直觉式强化 |
| **木灵根** | "生生不息"：每清完一个房间回复5%生命；但最大生命值-20% | 聚灵草 | 鼓励快速清怪，高风险高回报 |
| **水灵根** | "上善若水"：受到伤害时，伤害的20%转化为对攻击者的反伤 | 水盾符 | 防御反击型玩法 |
| **火灵根** | "燎原之火"：击杀敌人后3秒内攻击力+15%（可叠加3层） | 火灵珠 | 鼓励连续击杀，滚雪球 |
| **土灵根** | "厚德载物"：每持有5件灵物，获得一层"地脉护盾"（吸收一次伤害） | 岩甲符 | 鼓励大量收集道具 |

### 4.3 变异灵根（局外解锁，规则更极端）

| 灵根 | 被动规则 | 起始灵物 | 解锁条件 |
|------|---------|---------|---------|
| **雷灵根** | "天雷淬体"：移动速度+30%，但站立不动超过2秒会受到自伤 | 紫霄雷印 | 累计移动距离达到100km |
| **冰灵根** | "绝对零度"：所有攻击附带减速；但自身也被减速10% | 寒玉髓 | 累计冻结敌人500次 |
| **暗灵根** | "噬魂"：击杀敌人回复灵力，但商店价格+50%，且无法回血（只能靠护盾） | 蚀骨珠 | 不回血通关1次 |
| **混沌灵根** | "万象"：每进入一个新房间，随机获得一个临时灵物（离开房间消失） | 混沌珠 | 单局获得20件以上灵物 |
| **无根之体** | "凡人之躯"：没有任何被动规则，但初始3件灵物可自选 | 自选×3 | 通关10次 |

### 4.4 灵根专属灵物

每个灵根有 **2-3 件专属灵物**，只有该灵根能激活。这些灵物和灵根的被动规则产生强烈的化学反应：

**金灵根专属：**

## 5. 灵物系统（道具体系）

### 5.1 设计哲学

> **所有东西统一叫"灵物"，获取后自动生效，没有装备栏的概念。**  
> 就像以撒一样：捡到就生效，叠加就完事。  
> 没有"装备"和"套装"的区分——灵物可以无限叠加（功法除外，最多3个）。

### 5.2 灵物分类

分类仅用于内部标签和掉落权重，玩家不需要关心分类：

### 5.5 叠加规则

同一灵物可以重复获取，效果叠加：

**线性叠加：**

### 5.6 元素反应（v0.3 新增）

> v0.3 修订：原"元素反应"在代码侧只是"叠加质变"——同一元素堆数量产生质变，但跨元素之间没有真正的反应。本节定义跨元素的**反应机制**：先给敌人附着一个元素状态，被另一种元素再次命中时**立即触发一次性大型效果**。

**核心规则**：
1. 元素附着 = `StatusEffect`（参见 6.7.1）。每个元素附着是一份独立的、有持续时间的状态。
2. 当敌人**同时携带 2 个可反应元素**，且**新触发的伤害源**带其中之一时，立即触发对应反应：
   - 反应消耗 2 个元素状态（双方都被消耗）。
   - 反应自身造成一次伤害事件（走统一伤害管线，可暴击）。
3. 一个敌人同帧最多触发 1 次反应（防止链式爆炸）。

**第一批反应表（Demo1+）**：

| 触发组合 | 反应名 | 效果 | 备注 |
|---------|-------|------|------|
| 火 + 冰 | **蒸汽爆炸** | 半径 3.0 的 AOE，伤害 = `0.8 × 玩家 atk` | 在敌人位置爆开，附带 0.5s 短停 |
| 火 + 雷 | **过载爆裂** | 单体伤害 ×1.5，并对周围 1.5 半径附加 0.5s 雷麻痹 | "群伤导火索" |
| 冰 + 雷 | **感电** | 4s 持续点状伤害 = `0.3 × 玩家 atk / s`，移速 ×0.7 | 软控 + 持续伤害 |
| 风 + 火 | **烈焰扩散** | 当前火灼烧半径扩散到 3.0 半径，并刷新灼烧持续时间 | 把单体灼烧变 AOE |
| 木 + 火 | **燃烧蔓延** | 命中目标周围 2.5 半径内所有敌人附加 4s 灼烧 | 群体清场 |
| 水 + 雷 | **导电领域** | 在地上留 3s 导电水域（半径 3），敌人进入受 0.4× atk/s | 配合冰系冻结地形 |

> **代码层落地约定（与 6.7 节一致）**：
> - 每个 `StatusEffect` 需带 `elementTag`（Fire / Ice / Thunder / Wind / Wood / Water / Earth）。
> - `IDamageable.OnDamage` 命中时按 `元素先后到达` 检查反应表。
> - 反应造成的伤害不再是"hardcode 直接掉血"，而是经过统一伤害管线（包含暴击、属性聚合、护甲）。

> **与 5.5 的关系**：
> - 5.5「质变叠加」描述的是**单个灵物多份**触发的**自身放大**。
> - 5.6「元素反应」描述的是**不同灵物之间**触发的**跨元素新机制**。
> - 二者正交：火灵珠 ×8（焚天大成）会让你打出更高伤害的火，仍然可以和冰灵珠的"冰附着"产生蒸汽爆炸。

## 6. 主动技能系统（功法）

### 6.1 操作模型

> v0.2 修订：已从"远程灵力弹"改为 **Hades 风格近战连招 + 三槽位技能**。

```
【近战普攻】—— 鼠标左键，三段连招
  → 三段连招：Attack1 → Attack2 → Attack3
  → 段伤害倍率：1.0 / 1.2 / 1.5（最终段有"收尾一击"感）
  → 扇形判定：半径 2.5，角度 120°（面前 120° 扇形范围内的敌人全部命中）
  → 攻击中"霸体"：轻击受击不打断连招（但仍扣血）
  → 250ms 输入缓冲：下一段未到时按下左键也会接上，连招不断
  → 每段带前冲 Lunge 位移（朝向当前攻击方向短距冲刺）
  → 灵物可改变：攻击附带灼烧 / 暴击率 / 穿透次数 / 攻速 / 击杀回血
  → 元素修饰词条（见 6.5）：根据技能槽位中的灵物改变机制

【主动技能】—— Q / E / R 三个槽位，手动释放，有 CD
  → Q 槽位：攻击型（落石、御剑、雷击……）
  → E 槽位：位移 / 辅助型（土遁、缩地……）
  → R 槽位：大招 / 终极型（剑阵、天火……）
  → 充能层：每个槽位独立维护 1~3 层充能，CD 一好恢复一层
    - 灵物槽位可提供充能上限 +N
    - 满充能时技能有特殊边框提示
  → 蓄力（部分技能支持）：长按键蓄力，松手释放
    - Lv1（默认）：伤害 ×1.0，范围 ×1.0
    - Lv2（蓄力 ≥ 0.5s）：伤害 ×1.5，范围 ×1.0
    - Lv3（蓄力 ≥ 1.5s）：伤害 ×2.5，范围 ×1.3
    - 蓄力期间移速 ×0.4；闪避 / 死亡取消蓄力
    - 灵物槽位可提供蓄力速度加成 / 蓄力伤害加成
  → 每个槽位下方 2 个"灵物槽"（共 6 个）
    - 普通词条：充能上限、蓄力速度、蓄力伤害加成、CD 缩减
    - 元素修饰词条（见 6.5）：改变技能的机制行为

【闪避】—— Space 键
  → 距离 5 单位，持续 0.2s（速度 25 单位/s）
  → 全程无敌帧 0.3s（比闪避动作更长，覆盖落地一小段）
  → 2 层充能，每层 CD 1.5s
  → 可打断除"死亡"外的一切动作（最高优先级）
  → 充能耗尽时 250ms 输入缓冲，动作结束自动闪避
  → 灵物可附加机制效果：
    - 御风残影（风灵珠 ×5）：闪避后留下攻击敌人的残影
    - 火墙轨迹（风火轮 Synergy）：闪避路径上生成持续火墙
```

### 6.5 功法与灵物的交互（核心机制）

> **这是我们区别于《梦之形》数值宝石的核心差异化设计。**
> 灵物不只是数值加成，而是"修饰词条"——放在某个技能的灵物槽位中，会从根本上改变该技能的行为。
>
> v0.2 修订：本节新增完整的设计规格（方案 A：槽位限定触发）。

---

#### 6.5.1 设计理念

```
《梦之形》宝石 = 往血糟里加数字
本游戏灵物    = 往技能行为里注入修饰语
```

**同一件灵物，放在不同技能的槽位里，会给不同的技能赋予完全不同的变体**：

- 火灵珠放在落石术槽位 → 落石变陨石，落点留火焰地带
- 火灵珠放在土遁术槽位 → 破地而出时引燃周围敌人
- 火灵珠放在金钟罩槽位 → 护盾期间使攻击者着火

这一层决策（灵物放哪个槽）是比"拿哪件灵物"更深的 build 策略层，也是每局体验不同的核心驱动力之一。

---

#### 6.5.2 触发规则（方案 A：槽位限定）

**条件**：某件灵物的 `modTag` 匹配该技能的 `modifierDef.requiredTag`，且灵物在**该技能下方的 2 个灵物槽**中。

> 仅槽位内的灵物能激活机制修饰。背包中同类灵物不触发。

```
Q 槽位
├── [落石术]
├── 灵物槽 0：[火灵珠]   ← modTag = Fire → 激活"陨石修饰"
└── 灵物槽 1：[雷灵珠]   ← modTag = Thunder → 激活"雷石修饰"
                         → 两个修饰同时激活 → 落点留火焰地带 + 落下时引发雷击

E 槽位
├── [落石术（如果也装在这）]
├── 灵物槽 2：[火灵珠]   ← 同一件灵物放不同槽，修饰的是 E 槽技能
└── 灵物槽 3：空
```

### 6.7 战斗扩展机制（v0.3 新增）

#### 6.7.1 StatusEffect（BUFF / DEBUFF 通用框架）

> **目标**：当前 `BurnEffect / 嗜血 / 冻结` 都是一锤子写死的 MonoBehaviour，相互不能叠加、不能查询、扩展成本高。引入 `StatusEffect` 通用容器后，所有"持续生效的效果"统一存进同一份列表，便于元素反应、UI 显示、协同设计。

**数据模型（设计侧）**：

```
StatusEffect
├── id              : string         (例如 "Burn", "Freeze", "Bloodlust", "ComboKill")
├── kind            : Buff / Debuff
├── elementTag      : Fire / Ice / Thunder / Wind / Wood / Water / Earth / None
├── stacks          : int            (堆叠层数，无限叠则为 1 + 刷新)
├── duration        : float          (剩余秒数；< 0 表示常驻直到主动移除)
├── tickInterval    : float          (周期触发用，例如灼烧每 0.5s)
├── modifiers       : StatModifier[] (临时词条修正：atk +x、ms ×y、reduction +z)
├── onApply / onTick / onExpire 钩子
└── source          : object         (产生方，便于 UI 归类)
```

**关键约束**：
- 所有数值类临时增益（如"嗜血攻速 ×2"、"连杀攻击 +15%"、"风火轮移速 +10%"）改走 `modifiers`，不再直接 `Stats.attackSpeed *= 2f`。
- `RecalculateStats` 在统一管线最后追加一步 `ApplyStatusEffectModifiers`，与协同 / 质变并列。
- 每个状态默认有 UI 标记（HUD 顶部小图标 + 倒计时）。

**Demo1+ 第一批 StatusEffect**：

| ID | 元素 | 类型 | 效果 |
|----|------|------|------|
| `Burn` | Fire | DoT | 周期掉血 |
| `Freeze` | Ice | 控 | 移速 ×0.5 / 完全无法移动 |
| `Shock` | Thunder | DoT + 减速 | 元素反应"感电"产物 |
| `WetGround` | Water | 地形 | 进入受导电伤害 |
| `Bloodlust` | None | Buff | 攻速 +X |
| `ComboKill` | None | Buff | 短时间内连续击杀叠 atk |
| `Shielded` | None | Buff | 护盾层数 |
| `MeteorDot` | Fire | 地形 | 陨石落点燃烧地带 |

#### 6.7.2 召唤物 / 衍生伤害 继承玩家属性

> **当前问题**：焚天冲击波 / 剑阵 / 御风残影 / 元素爆发 / 火墙 / 玉碎冲击波 直接 `_player.Stats.attackDamage * x` 算伤害。这导致：
> - **永远不会暴击**（CalculateDamage 没被调用）。
> - **协同 / 质变的乘区只对玩家本体普攻生效**，召唤物不享受。
> - **元素反应触发不了**（衍生伤害没经过 `OnDamage(DamageInfo)`）。

**解决方案（v0.3）**：
1. 所有召唤物 / 衍生 AOE / 残影攻击都改走统一伤害构造：

   ```
   DamageInfo info = playerStats.Build(
     baseRatio = 0.3f,            // 该衍生攻击的基础倍率
     elementTag = Fire,            // 携带的元素
     sourceTag  = "FireBurst",     // 用于飘字 / 协同识别
     inheritCrit = true,           // 是否继承玩家暴击
     inheritOnHit = true)          // 是否继承玩家"命中触发"灵物效果
   ```
2. `BuildDamageInfo` 内部会读取当前 `_playerStats` 的 attack / critRate / critDamage / `+%` 类协同，乘上 `baseRatio`，再判定一次暴击。
3. 衍生伤害的"元素附着"也由本步骤统一处理（不再各处自己 `AddComponent<BurnEffect>()`）。

**对照表（Demo1+ 改造范围）**：

| 现有伤害源 | 当前问题 | 改造目标 |
|-----------|---------|---------|
| 焚天冲击波 | hardcode 0.5×atk，不暴击 | 走 `Build(0.5, Fire, inheritCrit=true)` |
| 剑阵环绕飞剑 | hardcode 0.2×atk，不暴击 | 走 `Build(0.2, Pierce, inheritCrit=true)` |
| 御风残影攻击 | hardcode 0.3×atk，不暴击 | 走 `Build(0.3, Wind, inheritCrit=true)` |
| 元素爆发 | hardcode 0.4×atk，不暴击 | 走 `Build(0.4, 随机元素)` |
| 火墙 | hardcode 5 固定伤害 | 走 `Build(0.25, Fire, +Burn)` |
| 玉碎冲击波 | 仅击退，无伤害 | 维持击退；可选附加 `Build(0.6, Earth)` |

## 7. 隐藏组合系统（Synergy）

### 7.1 设计哲学

> **没有"流派"这个概念。没有"你是剑修"这种标签。**  
> 只有：灵物 + 灵物 = 效果，效果 + 效果 = Build。  
> 玩家的 Build 是自然涌现的，不是选择出来的，而是"拼"出来的。

## 8. 境界系统（局内成长线）

### 8.1 境界阶段

```
练气期 → 筑基期 → 金丹期 → 元婴期 → 化神期 → 渡劫期
```

> v0.3 修订：原"每层固定解锁 +10% 数值"被判定为"鸡肋数值递增"——玩家无感且没有决策。
> 重设计为：**每次进入下一境界时，弹出"境界突破"3 选 1 奖励**，由玩家主动选择风格（参考 Hades 神器 / Risk of Rain Artifact）。

### 8.2 境界突破：3 选 1 奖励

每次过渡到下一层时，触发一次「境界突破」事件：
- 系统从该境界的"突破奖励池"中随机抽 3 个，玩家挑 1。
- 选定后效果**整局生效**（不可重置）。
- 同一奖励本局内只出 1 次。

**突破奖励分类**：

| 类别 | 设计意图 | 举例 |
|------|---------|------|
| 数值类 | 直白增强 | 攻 +15% / 血 +20% / 暴击 +10% |
| 机制类 | 解锁新规则 | 灵物槽位 +1（成 7 槽） / 闪避充能 +1 / 普攻第三段附加 1 个气波 |
| 结构类 | 改变局内系统 | 商店折扣 30% / 战斗房怪物数量 -1 但保留奖励 / 协同激活阈值 -1 件 |
| 风险类 | 高风险高回报 | 最大血 -30% 但攻 +60% / 灵力碎片 ×2 但每次拾取扣 5% 血 |
| 元素类 | 强化元素反应 | 元素反应伤害 ×2 / 反应触发不再"耗 2 状态" |

**境界突破池（按层位排序，体现节奏）**：

| 境界 | 主题 | 池中候选数 | 备注 |
|------|------|-----------|------|
| 练气期 → 筑基期 | 基建期：以"数值类 + 机制小补充"为主 | 8~10 | 给玩家平稳进入战斗节奏 |
| 筑基期 → 金丹期 | 武装期：开始引入"结构类" | 10~12 | 决策窗口拉开 |
| 金丹期 → 元婴期 | 强化期：风险类首次大量出现 | 12~14 | 决定本局滚雪球曲线 |
| 元婴期 → 化神期 | 极化期：元素类、双倍机制类 | 12~14 | 让"流派"自然涌现 |
| 化神期 → 渡劫期 | 终局：仅给"决战级"奖励 | 6~8 | 低数量保证选择有重量 |

**突破奖励第一批（Demo1+，v0.3）**：

|--------|------|------|---------|

### 📌 Demo2 规划（资源系统 · 灵力觉醒） `[v0.x 暂未实现]`

> **Demo1 采用纯 CD 模型**，不涉及任何资源消耗。以下内容全部归入 Demo2 阶段实现。

#### 核心概念

- **局外解锁**：玩家凑齐第一组完整记忆碎片后，在秘术系统中解锁"灵力觉醒"
- **可开关**：解锁后玩家可在居所·轮回池中自由开启/关闭，关闭则回到纯 CD 模型
- **觉醒后变化**：功法增加灵力消耗，CD 整体缩短约 30%；操作上限更高，更考验资源管理

#### 灵力基础规则（觉醒后默认资源）

| 要素 | 规则 |
|------|------|
| 灵力上限 | 基础 100，随境界提升（练气100→筑基120→金丹150→元婴200→化神250→渡劫300） |
| 灵力回复 | 自动回复（每秒3点）+ 普攻命中（+2）+ 击杀（+5） |

#### ② 灵根系统是核心差异化卖点，但完全未实现

- **代码端**：无角色选择 / 无被动规则系统
- **GDD 端**：第 4 章是"灵根 = 规则修改器"，被列入 1.2 核心卖点

  - 这是 Demo1+ 阶段的**头号优先级**。
