# ProjectR 垂直切片

> 目标：专业单人4–6个月  
> 单局：25–35分钟  
> 目的：验证器灵×载体×回路，而不是证明完整内容量  
> 上位设计：[ProjectR GDD](../design/GDD_秘境探索.md) · 执行待办：[开发待办](../design/开发待办.md)
> 程序实施：[程序模块规划](../architecture/程序模块规划.md) · 检查机制：[变更影响检查](../architecture/变更影响检查.md)

> **范围暂停（2026-09-02）**：M3中的关卡结构与蜂巢生态、M4中的灾相关卡和出口方案等待后续策划讨论，当前不进入实施排期；其余器灵、载体、回路、结契、存档与洞府工作可独立推进。

## 完成定义

玩家能从洞府选择3只器灵进入一局，在蜂巢生态区获取并替换载体、获得悟法、完成至少一种新器灵结契，形成三灵回路，选择撤离或挑战失控聚合体，并正确提交永久进度。

## 内容预算

- 4只器灵，每只2种性格表现。
- 2种武器、4种术法、2种身法。
- 源／应／化悟法。
- `1＋1＋1`、`2＋1`、`3＋0`附着结构。
- 1个蜂巢生态区。
- 战斗、性格、解谜结契各1个。
- 1名敌对御灵者精英。
- 1个失控聚合体灾相。
- 轻量洞府、契匣、悟法池和3项准备。
- 回路预览、触发反馈和战后来源分析。

## 切换闸门

旧系统只在替代能力验证后删除：

1. **G1 · 载体接管**：载体运行时替代旧核心技能执行。
2. **G2 · 回路接管**：回路运行时替代模块链玩家路径。
3. **G3 · 蜂巢接管**：蜂巢状态替代旧双阶段关卡路径。
4. **G4 · 提交接管**：契匣和撤离提交替代旧发现／结算路径。
5. **G5 · UI接管**：新HUD替代旧模块装配UI。
6. **G6 · 完整切片**：25～35分钟垂直切片通过验收。
7. **G7 · Legacy删除**：G1～G6全部通过、影响复查和Unity引用检查完成后，才分批物理删除旧路径。

## 砍减顺序

进度不足时依次削减：

1. 洞府环境表现。
2. 额外剧情事件。
3. 第二个特殊结契事件。
4. 招牌融合数量。

不能削减：

- 三灵组合。
- 换载体流程。
- 源／应／化反馈。
- 回路预览。
- 撤离提交闭环。

## 发布前硬门槛

- 无阻断编译错误、缺失引用和粉色材质。
- 同一Seed与输入能复现关键房间和生态状态。
- 新器灵在撤离前后、死亡和读档中的归属正确。
- 回路不存在无限递归和不可追溯伤害。
- 平均单局和洞府时长落在目标区间。
