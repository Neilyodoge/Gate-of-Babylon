# ProjectR 游戏测试清单

> 每轮测试只验证少量明确假设。记录行为、犹豫点和误解，不用口头解释替代游戏反馈。  
> 验证范围：[ProjectR GDD](../design/GDD_秘境探索.md) · [垂直切片](../delivery/垂直切片计划.md)

## 测试前

- [ ] 记录版本、Seed、配置和测试设备。
- [ ] 明确本轮最多3个验证问题。
- [ ] 清空或固定测试存档。
- [ ] 确认伤害来源、回路事件和区域状态日志可导出。
- [ ] 确认撤离、死亡和强退恢复路径。

## 首次理解

- [ ] 玩家能在5分钟内解释载体与器灵的区别。
- [ ] 玩家能指出一条“源—应—化”关系。
- [ ] 玩家知道器灵不额外占技能按钮。
- [ ] 玩家知道新结契器灵必须撤离才能永久获得。

## 构筑

- [ ] 玩家主动尝试过更换载体。
- [ ] 玩家能看懂迁灵后保留了什么。
- [ ] 玩家形成至少一条两段互动。
- [ ] 玩家在中后期形成三灵回路。
- [ ] `1＋1＋1`、`2＋1`、`3＋0`至少各被一名测试者主动选择。
- [ ] 玩家能从反馈判断是哪只器灵触发了结果。
- [ ] 战后来源分析与玩家主观理解一致。

## 探索与生态

- [ ] 玩家根据模糊情报做过路线选择。
- [ ] 玩家观察到一个区域行为改变邻区。
- [ ] 玩家能在结果出现前形成基本预测。
- [ ] 秘境躁动产生压力但没有让玩家停止思考。
- [ ] 玩家能找到撤离点和候选出口。
- [ ] 玩家理解Boss不是唯一进度钥匙。

## 结契与伙伴

- [ ] 玩家理解至少两种结契方式。
- [ ] 玩家能解释某只器灵的性格。
- [ ] 玩家在成熟回路与新器灵之间做过真实取舍。
- [ ] 玩家记得至少一只具体器灵，而非只记得颜色或强度。

## 灾相

- [ ] 玩家能识别Boss的产生、响应或转化节点。
- [ ] 探索准备明确改变Boss机制。
- [ ] 直接挑战和准备后挑战都可完成。
- [ ] 不存在必须携带指定器灵的硬锁。
- [ ] Boss战不退化成纯血量检验。

## 洞府与结算

- [ ] 正常整备时间为3–5分钟。
- [ ] 玩家能完成编队、悟法池和3项准备。
- [ ] 已拥有器灵不会因失败丢失。
- [ ] 新器灵只在成功撤离后进入永久契匣。
- [ ] 玩家能说清本局获得和失去的内容。

## 技术观察

- [ ] 无无限递归、事件风暴或明显掉帧。
- [ ] 无伤害来源缺失。
- [ ] 同一Seed能复现关键地图和生态状态。
- [ ] 回访房间不重新抽取遭遇。
- [ ] 门、碰撞、NavMesh和场景状态一致。
- [ ] 强退恢复不会复制结契器灵或奖励。
