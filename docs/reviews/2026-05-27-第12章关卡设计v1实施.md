# 第 12 章关卡设计 v1 + v2 + v3 + v4 实施说明（2026-05-27）

> **v4 增量**（2026-05-27 当日继续推进）：走格子 UI 取代 3 选 1 卡片，作为进门时的默认选路方式。
> - `EnterNextRoomWithChoice` 优先调用 TreeMapUI（"仙山舆图" 走格子）；TreeMap 缺失时退化到 RoomChoiceUI 3 选 1 卡片
> - 走格子的节点类型自动映射回 Minimap.RoomType（Battle/Elite→Battle / Shop / Event→Treasure / Boss→Boss）
> - TreeMap Boss 节点正确映射为 Boss 房间；`_fixedLayout` 的槽位由 `OnRoomCleared` 动态扩展以匹配 TreeMap 实际节点数
> - **F8 手动打开 TreeMap 的快捷键已删除**：跨房间手动按 F8 会让 TreeMap.CurrentNode 状态错乱（自动选完节点不进门），且体验冗余。走格子的入口统一为"走入传送门"
> - 注：原 F9/F10/F11/F12 调试键也一并移除，预留入口给 `DebugConsole`（Tab 打开）后续接入 Level Design 命令

> **v3 增量**（2026-05-27）：让玩家在房间间自由选路。
> - 新增 `RoomChoiceUI` —— 杀戮尖塔/哈迪斯式 3 选 1 卡片（v4 后退化为 TreeMap 缺失时的 fallback）
> - `GameManager` 增加 `useTreeMapFlow` 开关 + `OverrideNextRoomType` 接口
> - `OnRoomCleared` portal 回调改为 `EnterNextRoomWithChoice`
> - Boss 房 / 境界末尾的撤离流不弹任何选路 UI（保持线性叙事 + 不破坏现有撤离逻辑）

> **v2 增量**（2026-05-27）：把 v1 骨架接入主循环。
> - Boss 形态实际生效：`EnemyBoss.Spawn` 末尾调用 `LevelDesignDirector.ApplyBossPhase` 修正 HP/ATK/移速 + 播报出场对白
> - 事件自动触发：`LevelDesignBootstrap` 订阅 `RoomCleared` 事件，按线性事件调度表（境界, 房间索引）自动触发
> - 新调试键 **F11**：切换自动事件触发开关
> - 跨区域 Flag 重置：`OnRealmBreakthrough` 在境界 0/2/4 切换时调用 `BeginAct(1/2/3)`

## 二、玩家现在能体验什么（v2 全流程）

**v2 = 自然涌现模式**：玩家正常游玩 v0.5 线性流程时，第 12 章功能**自动接入**——清场时按调度表弹事件，Boss 出场时按 Flag 选形态。同时保留 v1 调试键供单点验证。

### 调试快捷键

| 按键 | 效果 |
|---|---|
| **Tab** | 打开 `DebugConsole`（项目原有调试入口；Level Design 命令后续接入此） |

> v4 后所有 F8~F12 单点调试键已删除。走格子统一通过"走入传送门"自动触发；
> 玩家无需任何手动操作；策划/测试如需单点验证某事件 / Flag，后续会在 DebugConsole 加专属面板。

### 自然游玩验证流程（v2 + v3 + v4）

1. 启动游戏 → 进入 Demo1 场景
2. 推进到 **练气期第 2 个房间**（清场后）→ 自动弹出"叶修之死"事件
3. 选"取走风灵珠" → 道心 -5 / 因果 +1 / Flag `betrayed_yeXiu=1` 写入
4. **走入传送门** → **自动弹出仙山舆图（走格子 UI）** → 玩家点 / 按数字键 1/2/3 选下一节点 → 下一房间生成
5. 继续推进到第 6 层渡劫期 → Boss 房生成时 **自动选定"震怒"形态**：
   - 屏幕下方出现古风字幕"叶修……是我座下亲传弟子！"
   - Boss HP ×1.3 / ATK ×1.5 / 移速 ×1.1（控制台日志可见）
6. 反过来，若选"将他埋葬" → 筑基期跨入时仍有机会触发"灵药宝库"条件事件（前置 `saved_yeXiu=1`），Boss 进"悲悯"形态（ATK ×0.8）

### 选路模式优先级（v4）

| 优先级 | 模式 | 触发条件 | 状态 |
|---|---|---|---|
| 🥇 1 | **TreeMap UI** | `useTreeMapFlow=true` + `LevelDesignDirector.CurrentMap` 存在 + 当前节点有 Next | ✅ v4 默认 |
| 🥈 2 | **RoomChoiceUI** 3 选 1 卡片 | TreeMap 不就绪时的退化方案 | ✅ v3 fallback |
| 🥉 3 | **v0.5 线性** | `useTreeMapFlow=false` 或下一间是 Boss | ✅ 兜底 |

### 三层叠加体系（背景）

| 模式 | 触发逻辑 | 状态 | 开关 |
|---|---|---|---|
| **v0.5 线性骨架** | 按 `_fixedLayout` 固定 16 房间推进 | ✅ 始终生效 | — |

## 三、还没做的（需要继续推进）

### 3.1 改造 GameManager — ✅ **v4 已完成**

TreeMap 现在完整驱动一个 Act 的关卡流转：
- `OnRoomCleared` 动态扩展 `_levelRooms` 槽位，TreeMap 有后续节点时不触发境界切换
- `TryShowTreeMapNavigation` 回调将 TreeMap 节点类型映射为 Minimap.RoomType（含 Boss）并写入 `OverrideNextRoomType`
- `LevelDesignBootstrap` 用 `_actAlreadyStarted` 保证每个 Act 只初始化一次 TreeMap
- Boss 节点被击败后无子节点 → 不扩展 → `levelComplete = true` → 正常境界切换

### 3.2 Boss 形态实际生效 — ✅ **v2 已完成**

`EnemyBoss.Spawn()` 末尾自动调用 `LevelDesignDirector.ApplyBossPhase(boss, bossID:1)`：
- 表格未配置 / 未匹配到形态 → 无副作用（向下兼容）
- 匹配到形态 → 应用 `StatModifier` 字段（hp*1.x,atk*1.x,spd*1.x），刷新 currentHp，播报 DialogueLines

后续多 Boss 的扩展只需在 `Boss_Phase_Config.json` 加 `BossID=2/3/...` 的形态，并在 `EnemyBoss.Spawn` 调用处传入正确的 bossID 即可。

### 3.3 真实系统接入（依赖各系统先落地）

`PlayerStateHooks` 目前是占位 —— 数值容器可用，但**没有玩法层效果**。等以下系统落地后接入：
- **因果系统**：杀戮债 / 盗宝债 / 辜负债 / 入魔债 区分 + 跨局保留
- **道心系统**：4 状态对应技能形变（GDD §道心 × 技能形变）
- **命格系统**：5 命格的实际效果（事件池修正 / 掉落 / 商店折扣）
- **寿元系统**：自动燃烧寿元 + 主动寿燃术

## 四、关键设计决策记录

| 决策 | 理由 |
|---|---|
| **JSON + Resources.Load** | Unity 原生支持，无需第三方依赖；后期可改为 Excel 导出 |
| **整局 vs 区域 Flag 分离** | BossFlagSet.ClearAct() 每区域清空，避免 Flag 堆积；跨区域状态通过 PlayerStateHooks 单独维护 |
| **PlayerStateHooks 占位层** | 因果/道心/命格/寿元真实系统未做时先开数据口子，事件配置可正常写 KarmaChange 等字段 |
| **IMGUI 临时 UI** | 复用 RealmRewardSelectUI 模式，避免 prefab 依赖；正式版可替换为 UGUI |
| **不动 GameManager** | v1 只搭骨架，避免破坏现有可玩流程；v2 再做主循环替换 |
| **RuntimeInitializeOnLoadMethod** | 不需要在场景中放置 Bootstrap 物体，全自动 |

## 七、Bug 修复 + 体验调整（2026-05-27 当日后续）

v3 自然游玩验证过程中暴露了一系列**预存缺陷**和**体验问题**，全部已修复。

### 7.1 新 Input System 兼容（5 个键位）

**症状**：按 F8 抛 `InvalidOperationException: trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package`

**根因**：项目 Player Settings 已切到新 Input System，但我 v1 / v3 用的是老 `Input.GetKeyDown` API。

**修复**：3 个文件改用 `Keyboard.current.fNKey.wasPressedThisFrame` 和 `Keyboard.current[Key.Digit1 + i].wasPressedThisFrame`（与项目其他文件如 `PauseMenu.cs` / `RoomExitTrigger.cs` 一致）：

| 文件 | 涉及键 |
|---|---|
| `LevelDesignBootstrap.cs` | F8 / F9 / F10 / F11 / F12 |
| `UI/RoomChoiceUI.cs` | 数字键 1~9 |
| `UI/TreeMapUI.cs` | 数字键 1~9 |

### 7.2 `useTreeMapFlow` PlayerPrefs 持久化

**症状**：F12 切换的开关 重启游戏后失效，回到 Inspector 默认值。

**根因**：`[SerializeField] private bool useTreeMapFlow` 由 Scene 序列化值覆盖 C# 代码默认。

**修复**：`GameManager.Awake` 读取 `PlayerPrefs.GetInt("GoB.UseTreeMapFlow")` 覆盖 Inspector 值；`UseTreeMapFlow` 属性 setter 写回 PlayerPrefs。首次运行（无键时）强制开启，让玩家立刻看到 3 选 1 卡片。

### 7.3 「玩家出生即在 trigger 内部」批量 bug 排查 + 修复

**症状**：宝箱永远不开启 → F 退出被静默拦截；灵泉永远不治疗；悟道宗师 F 提示不显示。

**根因**：Unity 的 `OnTriggerEnter` 只在 Collider **跨越**边界进入时触发；玩家通过 `TeleportPlayer(roomSpawnPoint.position)` 直接出生在房间中心，若 trigger 也在中心附近（半径覆盖玩家位），永远不会触发 Enter。

**系统性排查** —— 用 explore subagent 扫描了 11 个 `OnTriggerEnter` 文件，结果：

| 文件 | 触发器位置 | 玩家距离 | 状态 |
|---|---|---|---|
| `TreasureRoom.ChestTrigger` | (0,0,0) r=3 | **0m** | 🔴 **CONFIRMED BUG → 已修** |
| `RestRoom.SpringTrigger` | (0,0.15,0) **r=8** | **0m** | 🔴 **CONFIRMED BUG → 已修** |
| `UpgradeRoom.UpgradeInteractTrigger` | (0,1,2) r=3 | ~2.2m | 🔴 **CONFIRMED BUG → 已修** |
| `ShopRoom.ShopInteractTrigger` | (0,1,3.5) r=3 | ~3.5m | 🟡 临界（防御性加固） |
| `VillageHub.TriggerBridge` | 7~12m | 安全 | 🟡 结构性脆弱（防御性加固，覆盖 7 洞府 + 山门 + NPC） |
| 其他 6 个文件（拾取 / 投射物 / 路由器 etc） | — | — | 🟢 安全 |

**统一修复 pattern**（与 `RoomExitTrigger` / `PortalTrigger` 一致）：

```csharp
private void OnTriggerEnter(Collider other) => TryEnter(other);
private void OnTriggerStay(Collider other) => TryEnter(other);  // 兜底关键

private void TryEnter(Collider other)
{
    if (_inside) return;                          // 防止重复触发
    if (!other.CompareTag("Player")) return;
    _inside = true;
    /* 实际逻辑 */
}
```

### 7.4 自动交互 → 手动 F 交互（设计变更）

**用户反馈**：自动开宝箱 / 自动满血"鸡肋" + 头顶 hint UI 销毁不彻底，导致出口被卡。要求"全部改手动"。

**改造**：
- `TreasureRoom.ChestTrigger` 改为实现 `IInteractable` 接口 + 接入 `InteractionRouter`（与商店 / 悟道台同一框架）
- `RestRoom.SpringTrigger` 同样改造
- Hint 文字从 "宝箱·靠近开启" → "按 [F] 开启宝箱"；"灵泉·靠近恢复生命" → "按 [F] 沐浴灵泉"
- Hint UI 跟随 `IsRoutedActive` 显隐，**交互完成后立即销毁**（不会出现幽灵 UI 卡住出口）

**优先级矩阵更新**：

| 交互体 | InteractionPriority |
|---|---|
| 商店商人 | 40 |
| 悟道宗师 | 35 |
| **宝箱（新增）** | **30** |
| **灵泉（新增）** | **30** |
| 功法拾取 | 25 |
| 灵物拾取 | 20 |
| 房间出口 | 5 |

宝箱开启 / 灵泉使用后 `IsInteractionAvailable = false` → 路由器自动跳到拾取 → 然后跳到房间出口，形成自然交互链。

| `Babylon/Assets/1Game/Scripts/Items/ItemInventory.cs` | `RecalculateStats` 入口加空值保护（防 StoryEvent 奖励道具时 NRE） |

### 7.6 TreeMap 地图重置 Bug（v4 后续修复）

**症状**：第一次选完路径后，打完当前关再选路时发现地图被重置成全新的。

**根因**：`SpawnCurrentRoom()` 每次执行都发布 `RealmBreakthrough` 事件，而 `LevelDesignBootstrap.OnRealmBreakthrough` 收到 `NewRealmLevel==0` 就无条件调用 `StartNewRun()`，覆盖整个 TreeMap。

**修复**：`LevelDesignBootstrap` 加 `_actAlreadyStarted` HashSet，每个 RealmLevel 只初始化一次。新一局（Level 0）时清空旧记录重新开始。

### 7.7 固定布局槽位不足 → 一章没走完就跳到下一章

**症状**：TreeMap 一个 Act 有 5-6 个节点，但 `_fixedLayout` 每层只有 2-3 个房间槽位（如练气期只有 `[Battle, Shop]`）。走完 2 个房间后 `_currentRoomInLevel >= layer.Count` 被判为"本境界通关"，触发境界切换。

**修复**：`GameManager.OnRoomCleared` 增加 TreeMap 动态扩展逻辑——当 TreeMap 当前节点还有后续子节点（没到 Boss），自动往 `_levelRooms` 追加占位槽位。Boss 被击败后（无子节点）不再扩展，正常触发境界切换。

**同步修复**：`TryShowTreeMapNavigation` 回调中移除了 `if (mapped == Boss) mapped = Battle` 的强制降级——TreeMap 的 Boss 节点现在可以正确生成 Boss 房间。

### 7.8 RoomExitTrigger 缺少 OnTriggerStay 兜底

**症状**：部分情况下走到出口按 F 无反应。

**修复**：`RoomExitTrigger`（通用组件）加上 `OnTriggerStay → TryEnter` 兜底，与其他触发器一致。所有使用 RoomExitTrigger 的房间（宝藏/商店/休息/升级等）自动受益。

### 7.9 StoryEventService 奖励物品时 ItemInventory NRE

**症状**：`NullReferenceException: Object reference not set to an instance of an object` at `ItemInventory.RecalculateStats()`

**根因**：`StoryEventService.GrantItemReward` 通过 `FindObjectOfType<ItemInventory>()` 找到背包实例后调用 `AddItem` → `RecalculateStats`，但 `_playerStats` 尚未通过 `Initialize()` 赋值。

**修复**：`RecalculateStats()` 入口加空值保护 `if (_playerStats == null || _baseStats == null) return;`。

### 7.10 设计原则沉淀

**新增到团队约定**：

> **凡是会被 TeleportPlayer 直接传送进去的 trigger，必须用 OnTriggerEnter + OnTriggerStay 双兜底 + 自身 idempotent 状态机。**
> 
> Pattern 参考：`RoomExitTrigger` / `LevelTransition.PortalTrigger` / `TreasureRoom.ChestTrigger`（修复后）。

> **TreeMap 驱动的关卡流程中，固定布局 `_fixedLayout` 只是初始骨架，实际房间数量由 TreeMap 动态决定。** `OnRoomCleared` 会自动扩展槽位，`levelComplete` 仅在 TreeMap Boss 被击败后触发。

未来新增任何房间内交互（如阵法启动器 / 妖兽蛋孵化器 / 局内事件 NPC），先检查 spawn 位是否与 trigger 重叠，统一走 IInteractable + Stay 兜底范式。
