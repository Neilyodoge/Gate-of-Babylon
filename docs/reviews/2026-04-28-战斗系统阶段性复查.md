## 二、当前战斗循环（实测）

```
PlayerController.Update
  └─ 闪避(Space) 最高优先级，2 层充能 + 250ms 输入缓冲
  └─ WASD 移动，鼠标瞄准（攻击中朝向锁定，连招间窗口短暂解锁）
PlayerCombat.Update
  └─ 鼠标左键 → PlayerAnimator.RequestAttack(attackSpeed)
  │     └─ 三段连招：第0段→第1段→第2段
  │        - 攻击中开启"霸体"，轻击不打断；重击/HeavyHit 可打断
  │        - 每段攻击触发前冲 Lunge 脉冲（4/5/7 单位/秒，120ms）
  │        - 连招窗口由动画事件 OnComboWindowOpen/Close 控制
  │        - 攻击判定窗口由动画事件 OnHitWindowOpen/Close 控制
  └─ Q/E/R 技能：充能层（1~3 层）+ 蓄力 Lv1/2/3（伤害/范围倍率）+ 蓄力期间 ×0.4 移速

动画事件 OnHitWindowOpen → PlayerCombat.CheckMeleeHit
  └─ Physics.OverlapSphere(meleeRange) → 角度过滤(扇形 120°)
  └─ CombatStats.CalculateDamage()  ← 暴击在这里判，但 isCrit 不外抛
  └─ × 连招段倍率(1.0/1.2/1.5)  ← 来源 GameConfig
  └─ IDamageable.OnDamage(damage, hitPoint, attacker)

受击方 CombatStats.TakeDamage = raw × (1 - damageReduction)
  └─ 飘字 / 闪白 / 硬直(0.3s) / 击退 / 顿帧(HitStop) / 受击概率闪避

并行支线：
  - BurnEffect DoT，每 0.5s 一跳
  - QualitativeEffectRunner：焚天/玉碎/御风/剑阵/涅槃/嗜血/火墙/元素爆发
  - SynergySystem.CheckSynergies：每次 AddItem/RemoveItem 触发

死亡 → OnDeath → 清 Tag → 概率掉灵物/功法 → 击杀回血 → 击杀顿帧 → 缩小消失
```

## 三、问题清单（按优先级）

### P0：影响战斗正确性的 BUG

#### P0-1. 三套加成同时改 `_playerStats`，互相覆盖（属性系统不稳定）

**症状**：拾取一个新灵物会触发 `ItemInventory.RecalculateStats`，把基础值清零再叠加。这会把以下来源的乘性效果**静默丢失**：
- `SpiritSlotSystem.ApplyItemEffect` 的增量加成
- `SynergySystem.applyEffect` 的增量加成（如疾风骤雨 `attackSpeed *= 1.3f`）
- `ItemInventory.ApplyQualitativeEffect` 写在 `_playerStats` 上的乘性效果（焚天大成、万剑归宗、灵藤缠身、摄魂夺魄、星移斗转、照妖真眼）

**位置**：
- `Babylon/Assets/1Game/Scripts/Items/ItemInventory.cs:115` `RecalculateStats()`
- `Babylon/Assets/1Game/Scripts/Items/SpiritSlotSystem.cs:149` `ApplyItemEffect()`
- `Babylon/Assets/1Game/Scripts/Items/SynergySystem.cs:33` `applyEffect / removeEffect`
- `Babylon/Assets/1Game/Scripts/Items/ItemInventory.cs:243` `ApplyQualitativeEffect()`

**建议**：统一为单一 `StatsCalculator`：所有加成源（背包、槽位、协同、质变）都注册为"加成项"，每次任意源变化时按
```
final = (base + Σflat) × (1 + Σpct) × ∏(1 + mult_i)
```
重算。质变效果改成"标记位 + 在重算时读取"。

- [x] 已修复（2026-04-28）

> **修复要点**：单一写入入口落在 `ItemInventory.RecalculateStats()`，且**只把"当前在 `SpiritSlotSystem` 槽位中的灵物"**作为全局数值来源（背包仅作为"持有数量表"）。`SpiritSlotSystem` 不再直接改 `CombatStats`；`SynergySystem` 拆分为"机制激活 + `ApplyActiveSynergyStatModifiers` 数值聚合"两步，并接收"槽位灵物字典"做协同检测；质变乘区数值改为在 `ApplyQualitativeStatModifiers` 中按"槽位中的该灵物 + 持有数量达阈值"的组合条件统一施加，原 `ApplyQualitativeEffect` 仅负责提示与一次性满血标记。机制类质变由 `SyncQualitativeMechanisms` 按槽位状态统一激活 / 停用，槽位 `SetSlot/SwapSlots` 会主动调 `RecalculatePlayerStats` 触发重算 → 灵物离开槽位时其全局数值与机制贡献都会归零。详见 [灵物系统 §8](../game/tech/灵物系统.md#8-属性聚合管线p0-已修复)。

#### P0-2. 暴击信息丢失，下游表现不准

**症状**：
- `CombatStats.CalculateDamage()` 内部判暴击但只返回数值，调用方拿不到 `isCrit`。
- `PlayerCombat.CheckMeleeHit` 调 `OnDamage(damage, …)` 时不传 `isCrit`。
- `EnemyBase.OnDamage` 用 `actual > damage * 0.9f && damage > stats.attackDamage` 来"猜"是否暴击 → 飘字暴击不准。
- 焚天冲击波 / 剑阵 / 御风 / 元素爆发 / 召唤物攻击 → 直接 `_player.Stats.attackDamage * x` 计算，**永远不会暴击**。

**位置**：
- `Babylon/Assets/1Game/Scripts/Combat/CombatStats.cs:45` `CalculateDamage`
- `Babylon/Assets/1Game/Scripts/Combat/IDamageable.cs:11` `OnDamage` 接口
- `Babylon/Assets/1Game/Scripts/Items/QualitativeEffectRunner.cs:329` `TriggerFireBurst` 等

**建议**：引入 `DamageInfo { amount, isCrit, source, isHeavy, type }` 结构在伤害链里传递；`CalculateDamage` 返回 `DamageInfo`；扩展 `IDamageable.OnDamage(DamageInfo)`。

- [ ] 已修复

#### P0-3. `BurnEffect` 叠加规则与文档相反

**症状**：
- `docs/game/tech/战斗系统.md` 写"取较高 DPS"。
- `BurnEffect.Apply` 实际"直接覆盖最新调用方传入的 DPS，刷新持续时间"。
- 多个独立来源（如普攻总 DPS、焚天冲击波 0.3× DPS、未来火墙）相互覆盖，效果取决于调用顺序。

**位置**：
- `Babylon/Assets/1Game/Scripts/Combat/BurnEffect.cs:22` `Apply`
- `Babylon/Assets/1Game/Scripts/Combat/BurnEffect.cs` 注释 vs `docs/game/tech/战斗系统.md` 描述

**建议**：实现"取最高 DPS + 取最长持续时间"，并以代码为准更新文档。

- [ ] 已修复

#### P0-4. 质变乘法效果在重算时丢失

**症状**：`ApplyQualitativeEffect` 里 `_playerStats.attackDamage *= 1.5f`、`maxHp *= 1.2f` 等是写入 `_playerStats` 而非 `_baseStats`。下一次拾取灵物触发 `RecalculateStats` 后，这些乘性效果被覆盖。

**受影响灵物**：火灵珠 ×8（焚天大成）、锈铁飞剑 ×8（万剑归宗）、灵藤草 ×4、引魂灯 ×2、破镜碎片 ×3、星辰尘 ×2，以及"分类共鸣"中的所有乘性效果。

**位置**：`Babylon/Assets/1Game/Scripts/Items/ItemInventory.cs:243-386` `ApplyQualitativeEffect`

**建议**：与 P0-1 一并解决，迁移到 `StatsCalculator` 的乘性加成项。

- [x] 已修复（2026-04-28，随 P0-1 一并）

#### P0-5. `damageReduction` 多源 Clamp01 后溢出无提示

**症状**：`ItemInventory` 与 `SpiritSlotSystem` 都各自 `Clamp01(... + bonus)`，多源叠加后过高减伤被截断到 1.0（无敌）或被静默丢弃。

**位置**：
- `Babylon/Assets/1Game/Scripts/Items/ItemInventory.cs:164`
- `Babylon/Assets/1Game/Scripts/Items/SpiritSlotSystem.cs:156`

**建议**：改为乘法叠加 `1 - ∏(1 - rᵢ)`，或在 UI/Debug 中提示已截断。

- [ ] 已修复

#### P0-6. `DamageFlash()` 协程覆盖导致无敌帧异常

**症状**：多敌人同帧打到玩家会启动多份 `DamageFlash`，每份独立翻转 `_invincible`。短期连击时，前一份提前结束会把 `_invincible` 设回 `false`，理论上能让某些攻击无视无敌帧。

**位置**：`Babylon/Assets/1Game/Scripts/Player/PlayerController.cs:510-526`

**建议**：保存 `Coroutine` 引用，每次新受击只 `StopCoroutine` + `StartCoroutine` 一份。

- [ ] 已修复

## 四、当前优势（值得保留 / 继续放大）

1. **数据驱动骨架扎实**：`IDamageable` / `CombatStats` / `ItemData(SO)` / `SkillData(SO)` / `GameEvents` / `ObjectPool` 这一整套，扩展灵物/功法零代码，符合"100+ 灵物"的目标。
2. **动画优先级系统是 Hades 流派里写得相当完整的**：完整实现优先级矩阵 + 250ms 输入缓冲 + 状态超时兜底 + 动画事件丢失自动修复 + 攻击/技能霸体 + 连招窗口 + Lunge 前冲 + 朝向锁定/连招间解锁。
3. **闪避做到了 Hades 级宽容度**：可打断一切（除死亡）+ 多层充能 + 输入缓冲 + 同帧拦截攻击输入。
4. **质变效果机制化**：玉碎/焚天/御风/剑阵/涅槃 不是单纯加属性，而是跑机制（冲击波、残影、环绕飞剑、复活无敌），是当前最有"梦之形"味道的部分，应重点扩展。
5. **打击感链路完整**：顿帧 + 攻击前冲 + 受击闪白 + 顿帧分级 + 屏幕边缘脉冲 + 击退 + 飘字。
6. **敌人 AI 已超出"小怪追着打"**：Strafe、概率闪避、攻击预警；远程会 kite；冲锋有蓄力 + 红色范围预警。
7. **协同系统设计思路清晰**：分类计数 → 自动检测 → 同时具备数值加成 + 机制效果。

## 五、当前劣势（必须直面）

1. **GDD 与代码严重脱节**：GDD 的"灵力系统 / 五种共鸣资源 / 化身 / 双线叙事 / 100+ 隐藏组合 / 境界突破"，代码端基本只实现了战斗骨架 + 10 个 Synergy + 几个质变。下一步将从 GDD 与现有代码出发，重新整理 GDD（参见后续工作项）。
2. **属性系统是当前最大的不稳定源**（P0-1/4/5）。每加一个新灵物/协同/质变都可能踩雷。
3. **伤害链缺统一结构**（P0-2）。暴击信息要在飘字、护甲、协同、质变、UI 里都能拿到，目前各处自己猜。
4. **三种敌人 AI 三套写法**（P2-2）。改一次受击/闪避/硬直规则要改 6 遍。
5. **Demo 调试代码进入了 release 路径**（P2-3）。所有"无 VFX 时跑 CreatePrimitive"是默认体验。
6. **战斗维度比较扁平**：5 个动作（左键 + Q/E/R + Space），无重击/格挡/弹反/处决，普攻三段都是"挥刀"，远程怪种类只有"弓箭手"投射物。Demo 数小时之后会进入"只用 Q + 普攻 + 滚"的疲劳期。
7. **资源系统空白导致技能策略性弱**：纯 CD + 蓄力 = CD 一好就甩，没有"留资源应急"的决策。GDD 中的灵力系统正是为这层服务，缺失后技能体系显得"花哨但没有取舍"。
