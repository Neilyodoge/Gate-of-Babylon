# MT 批处理导出：角色本体 + 骨骼动画

外部 Python 面板管理任务，按所选快捷方式启动普通 `3dsmax.exe`，自动打开 MAX 并导出 FBX。无需先手动打开 Max，也无需记录选择或操作。

面板名称为 **传政今天牙掉了没 (ಡωಡ)**，采用中文暗色界面。

## 启动与使用

1. 双击 **启动工具.cmd**。需要 Python 3.9+（带 Tkinter）和已安装、可以正常使用的 3ds Max。启动文件会自动寻找 Python。
2. 在 **高级设置 → 使用哪个 Max（快捷方式） → 选择快捷方式…** 中，选择平时启动所需版本的 Max 快捷方式。固定使用该版本，无需查找安装目录。然后选择源 MAX 文件夹、FBX 输出文件夹。
3. 选择两个 **3ds Max 内部保存的 FBX 导出预设（`.fbxexportpreset`）**。先在 Max 的 FBX 导出窗口设置参数并保存预设，再来这里选择。工具自动查找 Max 预设目录，首次优先选择“蒙皮”和“动作”；也可浏览文件。FBX 对话框里尚未保存为预设的临时改动不会被读取。
4. 直接点击 **开始全部导出**，工具按命名自动分类并处理整个文件夹。也可以先点 **扫描文件** 查看分组，再选中若干行点 **导出选中**（Ctrl 多选）。不需要先手动处理第一个文件。
5. 已存在的 FBX 会跳过。需要补跑失败或中途未完成的文件时点击 **重试失败项**。

返回主界面、关闭工具或开始导出时，会将快捷方式、目录、预设和选项保存到工具目录的 `last_config.json`。

## 牙崩掉了fbx

勾选“导出到”右侧的 **牙崩掉了fbx**，自动将源文件夹上一级的 `fbx` 文件夹作为导出路径。例如源文件夹是 `D:\角色\MAX`，则导出到 `D:\角色\fbx`。开始导出时自动创建该文件夹；已经存在则直接使用，已有 FBX 仍会跳过。

勾选期间更换源文件夹，导出路径会一起更新。取消勾选会恢复之前手动填写的路径；直接点击“选择文件夹”指定输出位置，也会切回手动模式。这个选项会随导出配置一起记住。角色本体和动作在 `fbx` 内仍按原来的角色分组结构保存。

## 高级设置里的两个数字

- **角色默认姿势帧**（原“角色取帧”）：用第几帧的姿势导出角色本体，默认 `0` 表示第 0 帧。只影响不带动画的本体，不影响动作文件的范围；工具不会自动把该姿势变成 T-Pose。
- **最长等待时间（分钟）**（原“启动 / 单文件超时”）：等待 Max 启动或处理单个文件的时间上限，默认分别为 10 分钟，不是整批文件合计 10 分钟。某个文件超时会记为失败、重启 Max 并继续其余文件；Max 启动超时则结束本批。大场景可调到 20 或 30 分钟。

这两项通常保留默认即可。高级设置中也可以调整骨骼根节点名称和使用的 Max 快捷方式。预设选择框默认显示预设名，鼠标停留可查看完整路径。

## 换一台电脑使用

复制整个工具文件夹，双击“启动工具.cmd”，在高级设置中选择这台电脑上要使用的 Max 快捷方式（`.lnk`）。选一次即可记住；需要换版本时重新选择对应的快捷方式。支持直接粘贴快捷方式的完整路径，也兼容直接选择 `3dsmax.exe` 或 `3dsmaxbatch.exe`。

工具不再自动搜索 Max 安装版本。每次开始导出时，读取指定快捷方式的目标、启动参数和“起始位置”，使用该版本普通 `3dsmax.exe` 运行导出脚本，不再替换成 `3dsmaxbatch.exe`。旧配置中的 Batch 程序路径会转换成同目录的普通 Max 程序，不会换版本。

会单独启动一个 Max，连续处理整批文件，完成后退出。通常在后台运行；某些版本或插件可能显示 Max 窗口，处理期间不要操作这个专用窗口。工具不会接管或关闭你已打开的 Max，每次启动都校验进程编号和本次任务标记。源 MAX 不保存修改。

快捷方式需直接指向 Max 程序，支持普通启动参数（如语言、插件配置）；如果它已经指定 `-U` / `-mxs` 启动脚本或 `-batch`，会提示冲突。中转启动器、脚本快捷方式、要求提权的快捷方式不保证兼容。目标或“起始位置”失效时会提示错误。

如果“手动双击正常，工具却弹 Autodesk 登录／许可窗口”，请先更新到本版并重新选择同一个普通 Max 快捷方式。本版修正了启动程序、参数和工作目录的差异；仍需要该电脑有可正常使用的许可。若仍弹窗，请保留导出日志中的 `launch_01.json`，其中记录实际启动命令和工作目录，便于继续核对。工具不自动处理登录或许可证选项。

对方仍需安装带 Tkinter 的 Python 3.9+ 和可正常使用的 3ds Max，并选择自己电脑上的两份 FBX 导出预设。

## 自动分组规则

`SM_TL_Hero_Warrior.max` 是角色本体；同目录的 `SM_TL_Hero_Warrior@attack.max`、`@run.max`、`@skill1.max` 是对应动作。多个角色可以一起扫描，勾选子目录后保留相对目录。

输出示例：

```text
输出目录/
  SM_TL_Hero_Warrior/
    Model/
      SM_TL_Hero_Warrior.fbx
    Animations/
      SM_TL_Hero_Warrior@attack.fbx
      SM_TL_Hero_Warrior@run.fbx
      SM_TL_Hero_Warrior@skill1.fbx
  _MT_logs/
```

动作可以独立导出，不要求文件夹内或选中列表中存在角色本体。角色文件夹直接按文件名 `@` 前面的部分命名，例如只有 `SM_TL_Hero_TieJiang@attack.max`，也会导出到 `SM_TL_Hero_TieJiang/Animations/SM_TL_Hero_TieJiang@attack.fbx`。只导出动作时，只需填写动作预设。本体与动作都在导出列表中时，每组先处理本体，再处理动作。

## 导出内容与预设

**角色本体**：导出场景中的模型网格（包括配件）、`Root` 和其下的骨骼，不带动画。必须存在 Skin / Physique 蒙皮模型。场景里的参考网格也属于网格，请将本体 MAX 整理成要导出的角色。除 `Root` 外的辅助对象全部排除，相机和灯光也不主动导出。

**动作**：只导出唯一的 `Root` 及其下的骨骼；排除其余全部辅助对象，以及模型网格（包括挂在骨骼下面的武器网格）。`Root` 即使本身是 Point / Dummy 辅助对象也保留。支持常规 Bone、Biped 和常见 CAT 骨骼的识别逻辑；已实际验证常规 Bone 与 Point 根节点。特殊自定义骨骼需先试跑。两种导出的根名称匹配都不区分大小写，`Root`、`root`、`ROOT` 均可，自定义名称也适用；节点原名保持不变。若存在仅大小写不同的多个匹配节点，会提示重名，可在面板修改根名称。

- 中间的辅助父节点会跳过，下级骨骼连接到保留的上级节点。动作会先采样再重建关键帧，以保留原来的位置、旋转和缩放；范围沿用烘焙预设（启用跟随时间轴时采用 MAX 范围），未启用烘焙时采用 MAX 时间轴。辅助控制器仍留在后台场景中供动作求值，源 MAX 不保存修改。
- 如果辅助对象本身被 Skin / Physique 用作蒙皮骨骼，或专用控制器无法在跳过父节点后保持姿势，文件会明确报错，避免生成丢失蒙皮或动作的 FBX。需要先整理该文件的蒙皮骨架。

- 本体预设必须关闭 Animation，打开 Skin，关闭 Animation Only。动作预设必须打开 Animation。设置不符合用途时会报错，不会偷偷改写这几个预设选项。
- 每个文件先重置 FBX 导出器，再加载对应预设，避免上一文件的设置残留。其他导出参数沿用预设；关闭警告弹窗以便无人值守。
- “动作范围跟随 MAX 时间轴”默认开启：预设启用 Bake Animation 时，将烘焙起止帧替换为当前 MAX 的时间轴范围。不会强制打开烘焙，也不会更改场景帧率。关闭该选项则沿用预设里的帧范围。
- 角色默认取第 0 帧，可以修改。本体 MAX 应事先处于你需要的默认姿态；工具不会自动把动作姿态修正成 T-Pose。
- 如果骨骼链中间夹着非骨骼网格，工具会报错，避免 FBX 自动补齐父级时混入网格。FBX 自身仍可能为保持变换添加必要的父级节点。

## 运行、停止和恢复

- 同时只运行一个后台 Max 进程，并连续处理文件。某个文件崩溃或超时后，记录失败，重启后台 Max 继续剩余文件。启动失败（版本、授权、插件等原因）会结束本批任务，避免反复重启。
- 启动和单文件处理默认超时 10 分钟，可调整。大场景或重烘焙任务应适当增大。
- **完成当前后停止**是正常停止；Max 卡住时可用 **立即终止**。终止范围通过 Windows Job Object 限定为本工具创建的进程及其子进程，不按程序名查杀，不影响你另开的 Max。
- 关闭面板时先请求正常停止；当前文件未结束时窗口保持打开，也可立即终止。
- 不修改、保存源 MAX。后台工作进程不使用你当前打开的场景。
- 已有 FBX 自动跳过；同名配套资源（如 `.fbm`）冲突也不会覆盖。要重新生成已成功输出的文件，请使用新输出目录。
- 每次运行在 `_MT_logs/时间编号/` 保存计划、结果、Max 日志和本次预设副本；中途修改原预设不会影响该批次。
- FBX 在临时目录生成后再发布，源文件不变。强制终止可能留下 `.mt-stage-*` 临时目录，它们不作为最终输出；确认没有后台任务运行后可自行清理。
- 基于文件存在与成功记录续跑，不会自动判断已有 FBX 是否对应最新 MAX 或新预设。

## 文件说明

双击 **启动工具.cmd** 打开工具。其余 7 个 `.py` 文件均为运行所需，请与启动文件放在同一个文件夹。

运行后会生成 `last_config.json`，用于记住目录、预设和高级设置。日志在导出目录的 `_MT_logs` 文件夹中。
