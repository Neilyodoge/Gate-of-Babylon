# 3ds Max 平滑法线 UV 工具

默认将平滑法线写入第三套 UV（Max Map Channel 3 / Unity UV2 / TEXCOORD2）。工具可以选择第 2~8 套 UV；不修改切线，不需要 Unity 导入脚本。

## 使用

完整解压并运行 Launch.ms，选择模型，按需要选择角色/场景和目标 UV（默认第三套），点击“烘焙选中模型”按钮。日志右侧的“清空日志”只清除记录，不修改模型。日志按模型显示结果，绿色成功、红色需要处理；汇总也只显示在日志中。

孤立点自动跳过；几何退化面不参与平滑方向或切线计算。它们的点、面、UV 和 Skin 权重均保留，不需要先清理。退化面使用原始法线方向编码，日志记录忽略面数和跳过孤立点数。有效面的相互抵消法线、无法生成有效切线的第一套 UV、非均匀缩放/负缩放/错切仍会阻止烘焙，不能通过忽略几何问题绕过。

角色模式把第二套 UV 设为单个全零占位；场景模式保留已有第二套 UV，缺失才补占位。目标通道已有普通数据时默认跳过；需要替换时勾选允许覆盖。本工具已有 U+2/试验 U+4 数据可重新烘焙。

自动塌陷默认开启，只整理本工具修改器并保留 Skin；无法安全塌陷时保留修改器栈并记录原因。烘焙可 Ctrl+Z 撤销，修改拓扑、UV、法线或变换后重新烘焙。其它自定义修改器不因烘焙而被任意塌陷。

导出选中对象为 FBX，保留 UV、三角化和平滑组。Unity：Normals Import、Tangents Calculate Mikktspace、Bake Axis Conversion 关闭。默认第三套与随包 Shader 一致，选择其它通道需自行修改 Shader。

## 编码与 Shader 通道

版本定义统一如下：旧版是 Unity 中以 `_SmoothN` 结尾的 Mesh，在第二套 UV （Unity UV1 / TEXCOORD1）的 xyz 中直接存切线空间平滑法线，不使用 U 偏移标记。旧版仍按原 TBN 逻辑描边，无需为本次兼容重新烘焙。

新版是正在推进的 Max 烘焙工具，默认第三套 UV（Unity UV2 / TEXCOORD2），用二维八面体编码保存切线空间平滑方向，统一使用 U+2 标记：U 在 2~3、V 在 0~1。单位法线有两个自由度，两个数可以保存完整球面方向，不是直接丢弃 z。

Shader 优先读取第三套 U+2；没有新标记时读取第二套旧 SmoothN.xyz。新数据使用普通 NORMAL/TANGENT 构建 TBN，能够跟随蒙皮或合批变换。标记存在但切线无效时回退原始法线，不误读第二套光照 UV。旧分支沿用原非零判断，因此第二套必须实际存 SmoothN；普通 UV 无法仅凭该判断可靠区分。

本次修正前已生成的新版 U+2 资源也应重新烘焙，以更新退化 UV 面的切线基。先前试验生成的 U+4 数据可由工具自动覆盖并重新烘焙为 U+2；这类试验数据不称为“旧版”。标记统一不改变切线空间数学。

切线由第一套 UV 和原始显式渲染法线计算，使用随包提供的官方 MikkTSpace。工具直接读取局部网格与 Edit Normals；不能用 snapshotAsMesh/getFaceRNormals 替代显式法线，后者在部分 FBX 上会重算法线，并引入逐面角浮点差异。工具不写入切线，硬边、镜像 UV 或接缝两侧保留各自切线空间方向，相同编码复用 UV 点。修改第一套 UV、原始法线、平滑组或拓扑后必须重新烘焙。第一套 UV 完全退化、无法生成有效切线时会拒绝烘焙。

工具预览解码所选通道，默认第三套与当前 Unity Shader 一致。第三套专门用于描边法线，普通贴图 UV 应避免位于识别标记范围。不要对法线 UV 进行归一化、打包或截断。Unity Mesh Compression 建议 Off。

### 孤立点和几何退化面

孤立点是没有被任何面使用的顶点；跳过计算不改变顶点编号或 Skin 权重。几何退化面是顶点重合、零边长或共线三角面；保留面并从平滑法线和切线计算中排除，写入切线空间 +Z，代表原始法线方向。只要存在可烘焙的有效面，其它有效面正常写入描边法线。

贴图 UV 退化与几何退化不同；有效几何仍须能生成正确的 MikkTSpace 切线。所有面都退化、有效面的法线抵消或切线无效时，不报告烘焙成功。

清理算法仍保留为 Python 内部 API；界面保留烘焙、查看通道、预览描边 / 顶点色 A 和清空日志；检查、清理及忽略选择按钮已移除。

## Unity 设置

- 默认写第三套及更高时，可以启用 Generate Lightmap UVs。Unity 会生成第二套光照 UV，第三套法线保留。建筑已有合适的第二套光照 UV 时，可以直接使用它。
- 选择第二套存法线时，必须关闭 Generate Lightmap UVs，该通道不能同时存光照 UV。
- Bake Axis Conversion 保持关闭（Unity 默认，已验证流程）。切线空间编码同时依赖方向和 TBN，不再硬编码 Max 到 Unity 的轴翻转。
- Normals 必须 Import，保留烘焙所用原始法线。Tangents 使用 Calculate Mikktspace，确保与 Max 烘焙的切线帧一致。不要使用 Legacy、None 或未经验证的 FBX Import 切线。工具不使用切线存法线，也不覆盖普通切线。
- 非均匀缩放、负缩放和错切在绑定前完成 Reset XForm。已绑定的模型先回到绑定姿态，避免直接对整套骨骼或 Skin 对象执行 Reset XForm。修改拓扑、第一套 UV 或普通法线后重新烘焙。
- 工具添加 Turn to Mesh、UV Mapping Paste 和 Edit Normals 修改器固定三角面、存 UV 和保留普通法线，支持 Ctrl+Z 撤销。数据未变化时跳过重复写入，不再持续叠加；数据更新时保留旧修改器依赖，避免删除 UV Paste 导致 FBX 通道丢失。

旧切线版导出的模型若已覆盖切线，请在 Unity 改为 Calculate Mikktspace 恢复普通切线，再用本工具烘焙。旧的“第二套为空就复制第一套”流程已取消。

## 骨骼旋转与蒙皮注意事项

### 直接选 Mesh，工具临时停用 Skin

有 Skin 的模型可以直接选中 Mesh 烘焙。工具在读取和写入时临时停用 Skin，使用 Skin 之前的网格，处理后恢复 Skin 原来的开关状态；无需手动隐藏 Skin。保留原 Skin 修改器实例、骨骼和权重，后续仍可在原 Skin 中修改权重。清空第二套 UV 也按同样方式处理。没有 Skin 的模型可以先烘焙，再添加 Skin。

单个带 Skin 的模型处理后自动回到原 Skin 编辑面板。读取普通法线和刷新预览时，也恢复原来的对象选择、修改器面板和子对象编辑层级，避免临时 Edit Normals 把当前编辑对象切走。批量处理保持原来的多选对象；需要编辑权重时选中其中一个角色的 Skin。如果原来关闭了 Skin，工具保留关闭状态，查看变形时自行开启。

绑定姿态是 Skin 的初始参考姿态，不一定是第 0 帧或 T 字形。工具停用 Skin 只排除这个修改器的变形，不会重设骨骼或动画。如果还有其它变形或拓扑修改器，仍需核对 Skin 输入网格是否为正确参考状态；模型对象的缩放检查不能替代完整修改器栈检查。

### 为什么新版能跟随骨骼旋转

UV 数值本身不会随骨骼旋转。早期对象空间试验版本把固定方向直接当作对象空间法线，骨骼旋转后描边方向可能仍停在原方向。新版 U+2 存储平滑方向在普通切线空间中的分量，Shader 使用蒙皮后的 NORMAL 和 TANGENT 重建方向，所以能够跟随刚性旋转。早期对象空间试验数据需要重新烘焙，仅换 Shader 或改切线导入设置无法升级；旧 Unity `_SmoothN` 继续使用原第二套 UV.xyz。

Unity 使用 Normals = Import、Tangents = Calculate Mikktspace，并保持 Bake Axis Conversion 关闭（默认值）。切线烘焙按这一 FBX 导入坐标约定计算；开启 Bake Axis Conversion 或使用其它导出轴约定需要另行验证。第三套 UV 保持原数据，不能当作贴图 UV 再打包、归一化或截断。没有第三套 U+2 标记时，Shader 先按旧版第二套 SmoothN.xyz 逻辑判断；第二套也无有效数据时才使用普通法线。第三套新标记存在但切线无效时直接使用普通法线，硬边处仍可能裂开。

### 多骨骼混合变形的限制

已经验证单骨骼 Z 轴旋转 90° 后方向正确，参考画面像素差为 0。多骨骼混合测试已复现方向接缝，不能保证所有动画无缝；BlendShape 和骨骼缩放尚未验证。

多骨骼加权变换通常不是一个纯旋转。Shader 将变形后的普通法线和切线归一化、正交化，再通过叉积重建副切线；这与直接对原平滑法线做相同的加权蒙皮并不总是等价。硬边或 UV 接缝两侧的原始切线基不同，混合变形后可能出现方向差异。当前实现不会在每个动画帧重新计算变形几何的平滑法线。

同位置拆点的骨骼索引和权重也应一致，否则动画后它们的位置或方向本来就可能分离。检查时播放实际动画，重点看肩、肘、膝、扭转部位及硬边接缝。若必须保证这些部位的动态连续性，需要另外验证或实现平滑方向参与蒙皮的方案，不能仅靠重新烘焙 UV 保证。

2026-10-13 复查使用 3333 网格，所有顶点均赋予相同的双骨骼各 50% 权重，两根骨骼分别绕 X、Z 旋转 60°。Unity BakeMesh 后按当前 Shader 的算法解码，2143 个同位置组中有 1377 组方向不一致，最小点积 0.9470922；与直接加权蒙皮平滑方向相比，最大方向差约 16.41°。这是用于确认限制的人工压力测试，不代表该建筑实际具有这套蒙皮，也不是三角面或 UV 丢失。结果文件为 tests/artifacts/review_mixed_skin_unity.json。

### 修改器顺序、缩放与导出

- 工具会保留 Skin，把生成的三角化、UV Paste 和 Edit Normals 修改器放在 Skin 下方。不要随意移动到 Skin 上方，也不要直接删除旧 UV Paste；模型已经依赖它保存 UV 通道。
- 在最终拓扑和贴图 UV 确定后烘焙。Skin 上方存在改变顶点数、三角面或 UV 的修改器时，先整理流程再处理；本工具的验证不覆盖任意修改器组合。
- 在绑定前处理负缩放、非均匀缩放和错切。骨骼非均匀缩放、负缩放或接近零缩放会使切线基失真甚至退化，当前工具不检查每根骨骼的变换。
- 本工具保存法线 UV，不负责导出、烘焙动画或修改权重。使用 Max 自带 FBX 导出时包含需要的骨骼层级，并检查 Skin/Deformations 和 Animation/Bake Animation 设置。只选 Mesh 导出的角色测试曾在 Unity 中变成静态 Mesh；包含骨骼后恢复 32 根骨骼和权重。
- Max 预览是读取当前选择时的静态快照，不能代替 Unity 中完整动画的验证。完整包附带 Unity Shader 和材质；Core 包也包含本 README。

## 预览

点击主窗口“查看通道”打开 Max 原生通道信息；点击“预览描边 / 顶点色 A”恢复独立效果预览。勾选预览中的“显示顶点色（A）”查看 Alpha 灰度；无需第一套贴图 UV，孤立点和几何退化面保留。

独立 3D 窗口支持已烘焙法线 UV 解码、实时平滑和原始法线对照。左键拖动旋转，滚轮缩放。“显示顶点色（A）”显示 Alpha 灰度：0 黑、1 白，中间值为灰色，无 Alpha 按 1；“使用顶点 Alpha 控制宽度”独立调制描边宽度。

距离自适应默认开启，其余初始参数参考原 Unity 材质：宽度 0.022，颜色 (0.33725497,0.11372497,0.027450997,1)，最近/最远距离 1/10，倍率 0.5/2。手动读取 .mat 使用材质实际参数。Max 系统单位换算为一米，预览不写回材质，不增加场景对象。

## 失败定位与无 Skin 验证

失败日志现在区分阶段并报告具体位置：UV/顶点色通道名称、三角面编号、面角、几何顶点编号，以及校验前后数值和最大差值。切线失败还显示第一套 UV 的 UV 顶点编号、UVW 和原始法线；有效面平滑法线抵消会指出顶点和关联三角面。三角面编号以烘焙时评估的三角网格为准。
