# n的美术祖谱

一个服务于游戏美术的 Skill：帮助AI制定方向、比较方案、评审和制作资产，并把真实任务里的选择与反馈保存为以后能使用的资料。

它覆盖 2D、3D、场景、材质与灯光、色彩脚本、UI 和 VFX。增加审美校准后，还可以逐步理解你的个人偏好，并检验这些记录是否帮助后续判断。

## 它如何工作

```text
你的目标 + 实际作品
        ↓
识别项目、用途、观看条件和制作阶段
        ↓
读取相关专业参考 + 项目决定 + 个人偏好
        ↓
独立判断 / 比较方案 / 提出或执行修改
        ↓
你的选择和反馈 + 实际修改结果
        ↓
保存案例，区分个人偏好、项目决定、通用经验
        ↓
在新任务中读取相关记录，用新案例复测
```

这是一套由文件和工作流程支持的记忆机制。它不会直接改变模型权重，也不会因为安装了 Skill 就在后台自行学习。实际执行仍依赖模型能力、可用工具、资料访问与任务授权。

## 四种常用方式

下面的内容可以直接作为请求；提供真实作品和目标即可，不需要先填写整套表格。

### 1. 按目标评审或制作

> 用 n的美术祖谱评审这个角色。它会出现在手机上的俯视战斗镜头里，我希望它显得笨拙但可靠。先给最重要的修改建议。

AI先看真实画面，再读取相关参考和已有记录，说明值得保留的决定、主要问题、具体修改与检验条件。有工具和素材且任务要求制作时，会推进实际修改。

### 2. 比较方案，校准审美

> 比较A、B两版，先给出你的推荐和理由，再预测我会选哪个。等我公布选择后，记录我们的分歧。

AI会先留下初判，再接收你的选择。已知道答案的比较会标为复盘，不会伪装成预测。你没有反馈时，案例停在“待反馈”。

不仅比较是否清楚或符合规格，也可以比较气质、节奏、独特性、情绪张力，以及哪些不完美值得保留。主观判断会明确标注。

### 3. 记录偏好或项目决定

> 记录一下：这个项目的旅馆要拥挤、温暖、有生活感，不要做成整洁的精品酒店。

这句话会按其范围保存为本项目决定，不会自动变成你在所有项目中的喜好。

如果你明确表达长期个人倾向，可以保存为个人偏好。只有“这次我选B”时，先保留本次选择；AI进一步归纳的规律标为候选。

### 4. 检验是否学会

> 用这些没参与学习的新方案，检查最近的审美记录有没有帮助。先保存判断，再看我的答案。

AI会记录技能/规则版本、输入与比较条件，分开保存题目和答案。在可比条件下看偏好预测、关键理由和实际修改效果；没有旧版基线就先建立基线，不宣称已有提升。

模型自己觉得更好，只能算自评；有用户反馈或实际测试后，再记录相应结果。

## 三类判断，分别保存

| 类别 | 示例 | 使用范围 |
| --- | --- | --- |
| 个人偏好 | 用户明确偏爱某种形体节奏 | 原话限定的个人审美范围 |
| 项目决定 | 本项目旅馆采用拥挤、温暖的方向 | 当前项目与有效版本 |
| 通用经验 | 在指定镜头条件下，某种轮廓调整改善识别 | 证据支持的适用条件 |

以上例子只是说明，不会预先写成你的偏好。

当前用户指令优先；明确的项目决定优先于宽泛的历史个人偏好。通用经验和个人偏好产生冲突时，AI会说明代价及推荐依据。

## 记录会保存什么

- 原目标、项目/镜头/设备/制作阶段，以及实际看到的素材位置。
- AI事先判断、用户原话与选择，两者分别保存。
- 修改前后版本、验证条件，以及用户反馈、测量或AI自评。
- 适用条件、反例、未完成项和下一步。
- 记录编号、状态，以及关联的旧规则和其他案例。

明确表达的偏好可以立即按范围保存。通用经验需要多例可比或实际资产验证支持，才进入稳定指导；一次局部成功不会变成普遍规律。旧判断被修订时保留原因与证据。

| 文件或位置 | 谁使用、做什么 |

| references 中各专项 | 2D、3D、渲染、色彩脚本、UI、VFX等专业指导 |
| [研究与学习循环](references/research-loop.md) | 外部作品研究、来源核对和经验升级 |
| [存储配置示例](config/storage.example.json) | 字段说明；实际路径填写到本机 config/storage.local.json |
| [空白索引模板](templates/memory-index.md) | 首次创建记忆库时使用，不覆盖已有索引 |
| memory_root 下的 INDEX.md | 先找相关记录，再按需读取正文 |
| memory_root 下的分类文件 | preferences、projects、cases、rules、evaluations，首次记录时创建 |
| research_root | 既有研究计划、日志、队列和兼容反馈收件箱 |

本机将共享记忆放在正式技能目录下的 memory 中；安装副本通过同一配置读取这一个主库。修改运行配置或换电脑时，要核对实际目录，不能假定旧路径仍然有效。

现有研究历史保留原位置，按主题、URL或规则编号检索；新索引没有假装已经迁移全部历史。读取不到记录时会明确说明，临时记录会标记“待归档”。

## 在另一台机器上使用与 Git 同步

1. 把 config/storage.example.json 复制为 config/storage.local.json，填写本机实际路径。示例中的 null 表示未配置；source_root 和 memory_root 用于定位正式技能与共享记忆，没有安装副本或研究历史时其余两个目录可以暂留 null。
2. memory_root/INDEX.md 不存在时，用 templates/memory-index.md 初始化。模板内专业参考路径相对 source_root 解析；已有记忆继续使用，不要覆盖。
3. 安装副本读取同一套本机配置，指向同一个 memory_root。跨电脑分别配置实际位置，不直接沿用另一台电脑的绝对路径。

仓库保存技能正文、专业参考、README、配置示例和空白索引模板。本机配置与技能目录内的 memory 已由 .gitignore 排除，后续个人偏好、私有项目决定和评测答案不会因普通添加这个技能目录而进入提交。若主动分享具体案例，应先选择允许分享的内容和范围。

当前机器的本机配置与记忆索引已初始化；本次发布仅补充可迁移模板，不重置已有配置、记录或研究日志。

## 如何开始积累

1. 选一个真实任务，给出作品和你希望产生的感受。
2. 让AI先做独立选择或修改建议。
3. 告诉它你的选择和具体原因；需要保存时可以直接说“记录这次选择”。
4. 有修改条件时比较前后结果。
5. 后续任务读取相关记录，再用新案例检查是否有效。

无需每次调用都生成报告。只有明确的记录请求或有价值的实际反馈才留卡；不会把教学示例、沉默或AI的猜测当成你的确认。

## 外部学习与自动化

外部学习会实际查看作品或制作材料，分开记录可见事实、作者陈述和AI推断。热度、奖项、搜索摘要不能代替作品和验证。

研究得到的观察先进入学习卡或候选经验。缺少实际测试时，仍可以提出有边界的视觉建议，但不会声称已证明玩家读速、导航或战斗效果。

定时运行需要另行配置的自动化。Skill不会自动旁观其他聊天；反馈由实际执行美术任务的聊天生成。本次技能更新不启停既有自动化，也不迁移其正在使用的运行标记和日志。

## 怎样判断它有没有进步

看新任务中的表现：是否更准确地理解你的取舍，建议是否具体，修改是否更接近目标，以及规则是否能在新案例中成立。

格式校验和文件链接检查只证明技能可被正确读取，不能证明审美能力提高。本版新增了训练与记录机制；个人偏好和真实效果需要在实际使用中逐步积累。
