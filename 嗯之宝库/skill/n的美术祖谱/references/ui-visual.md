# 游戏 UI 视觉

用于 HUD、菜单、图标、字体、提示、世界空间界面及其动效的**视觉语言**。若问题主要是任务流程、按钮位置或交互逻辑，结合 UX 证据处理；美术方向仍需说明信息怎样在游戏画面中被看见、辨认和理解。

## 接手资料

先看实际游戏截图或录屏、界面的全部状态、目标分辨率/设备、输入方式、语言和项目美术规范。缺少游戏背景时，至少把 UI 放到有代表性的明暗与复杂背景上；孤立的 Figma/PSD 画板不足以证明游戏内可读。

## 视觉系统

- **层级与焦点**：区分持续存在、按需出现和紧急打断的信息。用尺寸、明度、位置、对比、留白与动效建立读取顺序，不让装饰框或稀有度光效压过当前操作。
- **图标语法**：规定抽象层级、轮廓/填充、笔画重量、内部空隙、视角、光源与色彩用途。拿最容易混淆的一组图标在实际显示尺寸和相同背景上并排比较，检查形状差异能否独立于颜色成立。
- **字体与数字**：在目标语言检查字形、字重、行距、数字宽度、标点与本地化后长度；CJK 文本不要沿用只验证过英文的字号与排版。长文本、极短标签、倒计时和快速变化数值分别试。项目若允许放大字体、图标或 HUD，分别检查默认档与最大档的实际画面：文字重排、控件间距、按键提示、战斗信息及背景变化；不能只把默认稿等比放大。
- **状态与运动**：列出默认、聚焦、选中、禁用、冷却、警告、完成等实际需要的状态。动效要交代状态变化和响应时机；静态稿无法证明动态信息清楚。
- **与世界的关系**：HUD 可借用场景的形、材质或时代感，但首先要清楚。世界空间 UI 还须查镜头距离、透视、遮挡、深度冲突和玩家移动时的跟随行为。

## 评审与交付

在目标设备上检查实尺寸、边缘安全区、最拥挤画面、不同亮度场景、控制器或触屏焦点，以及信息激增时的遮挡。颜色是辅助线索；关键状态应有形、文字、图案或运动的冗余表达。若声称无障碍合格，须按项目适用标准和实际玩家测试核实。

交付可是一页 UI 视觉规则与少量关键组件：颜色/字体/边框/图标的用途、必要状态、动效意图和反例；资产化时再给切图、九宫格、缩放与引擎实施条件。评审意见应指出具体屏幕、状态和冲突，而不是笼统要求“更有游戏感”。

上述缩放检查来自两款已发行游戏的不同证据：[Santa Monica Studio 的 Ragnarök 官方默认/XX-Large 与图标大小对照](https://blog.playstation.com/2022/05/19/god-of-war-ragnarok-accessibility-features-revealed/)可直接看到文本重排和图标放大；[Zach Bohn 的制作访谈](https://80.lv/articles/a-deep-dive-into-god-of-war-ragnar-k-s-user-interface)解释其动态布局；[Naughty Dog 的《最后生还者 第二部》官方说明](https://blog.playstation.com/2020/06/09/the-last-of-us-part-ii-accessibility-features-detailed/)列出独立的 HUD 尺寸、背景和颜色选项，未展示同机位布局前后图。这些案例支持把缩放视为需复核的状态，不证明某一档位已通过玩家可读性测试。
