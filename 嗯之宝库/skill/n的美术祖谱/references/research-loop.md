# 研究与学习循环

目的：把外部作品的具体做法变成有条件、可复查的游戏美术判断。学习结果存在文件里，不意味着模型权重会自行改变。适用于一次性参考研究，也适用于用户开启的定期学习。

## 选择问题与来源

自动化指定活跃研究目录时，先读运行标记，再查共享记忆索引、当前队列项和最近学习复盘；历史日志按 URL、主题或规则编号检索并读取相关段落，不逐轮通读全部历史。运行标记决定是否启动与本轮续接，封存对象和拒绝范围不由摘要代替。上一轮仍在正常学习就跳过，不并发启动或重复写入。没有指定活跃目录时，按[记忆与证据](memory-and-evidence.md)核配置的研究位置，再从 [研究队列](research-queue.md) 选题。

自动化派视觉代理前，逐项核运行标记的封存网址与当前拒绝范围，再用活跃日志核候选是否已看、已阻或待媒体修复；把本轮禁访的精确对象和停线写进代理任务。封存的是对象，不因来源站点仍可访问而失效。

定期学习用三种互补入口，按当前证据缺口选择，不固定为单题检索：

- **基础查漏**：对照 2D/3D、造型设计/画风、场景、材质与光、美术渲染、UI、色彩脚本、VFX、制作交接的现有规则和案例，找出只有术语、缺示范或缺实际试评的基础。选一个会影响评审的缺口，读可靠教学或制作材料，并用小图、同屏比较或可用资产检查，而不是按教材目录堆概念。
- **网页驱动**：定期查看 80 Level、ArtStation 等站当时实际可用的分类、新作、热门、趋势或编辑精选列表，记录入口和查看日期；榜位、点赞、评分及算法不明的排序只用于发现候选，不证明质量。挑能明确作者、作品、用途和阶段的完整文章或原作页，围绕同一页的证据提出少量相关判断点，分别核设计、画风及制作条件；看完一页可以形成多个有边界的观察，不把标题、卡片或封面当作品。
- **问题驱动**：从队列选会改变决策的未解问题，例如“俯视镜头下，复杂服装怎样保留职业识别”，先写现有判断、可能推翻它的观察与最少证据。阅读时遇到紧密相关的衍生问题，若同轮来源和预算足以回答就一并核；否则写明缺什么证据与重开条件，不为凑答案扩展到无关材料。

一轮以一个完整来源、同件资产组或紧密相关的问题束为锚。每个判断点独立记图像事实、作者自述、推断和未验证范围；同一网页可以支撑多个点，但不能把多个阶段、作者或游戏硬并成同一结论。静态资料回答不了动态或因果问题时收窄到静态可答范围，或记下解锁证据后换题。先用最小来源核身份、归属和图像可读性，再扩展对照。

用户常用的 [ArtStation](https://www.artstation.com/) 与 [80 Level](https://80.lv/) 是优先入口。ArtStation 适合看作者原作、序列图、转面、过程稿与最终展示；80 Level 适合核对作者/团队的制作拆解和取舍。网页驱动时，记录榜单/栏目名称和时间，只把排名当寻源线索；文章仍要打开完整直达 URL，作品仍要实际目视。按问题扩展到公开的艺术家与工作室网站、官方开发日志、专业美术媒体、教学拆解、作品集、[ArtStation Magazine](https://magazine.artstation.com/category/art-skills/)、[The Rookies](https://www.therookies.co/blog/breakdowns/)、[Interface In Game](https://interfaceingame.com/) 及游戏内录屏、开发者演讲。公开检索页可以帮助定位原文；检索卡、摘要和缩略图只算线索。上述来源是候选，不构成本轮浏览授权；依当前任务的用户授权和工具审批决定匿名只读范围，不登录用户账号，也不通过其他入口取得已被明确拒绝的对象。作品集展示、访谈自述、引擎截图和玩家测试回答的问题不同，不能互相冒充。UI 图库提供可见案例，不自动证明交互有效；离线渲染的做法也不能直接当成实时游戏预算。

优先研究可核对发行版表现的作品。若发行版画面暂不可得，也可用未发行项目、独立练习或较早案例研究造型、构图、材质和制作方法，但注明来源性质、版本与展示条件；不把它们升级为普通玩家实际效果。

## 单轮研究

时间分配可随来源调整，不为凑数量提前结束：

1. 读上次记录，选基础查漏、网页驱动或问题驱动入口；写清本轮锚点、目标媒介、用途、阶段，以及要解决的几个相关判断点。
2. 实际打开完整原作或游戏画面。对每点分别观察大形、明度、色光、材质、构图、动效和上下文；把**设计**（身份、功能、结构、空间／信息安排）与**画风**（形体概括、笔触、色光、材质受光与运动语法）分开问，再记录确有交叠之处。
3. 核作者、图注和制作拆解，确认每张图的职责、阶段、原因与限制。页面自然引出的衍生问题，能在本轮安全核实的就一并回答；需要另一机位、版本、作者或玩家动态时加入队列，标明证据门槛。
4. 对每个已回答点写出可迁移条件与失效情境；有可用项目资产时，优先在任务工作目录的副本或截图上用缩略、灰度、剪影、同屏或引擎画面试评。没有试验就标为假设，不因同页得到多个点而自动升级为稳定规则。
5. 保存学习卡、已解与未解衍生问题及下一步；来源受限、网站空白或只看了封面时如实记录范围，换合法来源，不绕过访问限制。视频只在能保持后台、静音且不抢占用户前台时查看；无法保证时记录限制，改用静图或文字来源。

媒体或访问暂不可用时，可在本轮授权范围内改用公开只读文本或已核本地记录继续研究，并留“待复看”粗卡：记可核标题、作者／发表日期、原 URL、实际读到的文字、图片／视频未看范围、具体障碍，以及复看时要验证的画面问题。文字可记录作者自述和制作问题，不能产生形、色、明度结论，也不代替完整作品图或玩家镜头。只有普通访问或安全观看条件确有可核变化后才回原页复看；明确审批拒绝的对象按拒绝范围封存，不借文本接口、缓存或其他站点间接获取。

原页因登录层、GIF、可播嵌入或自动播放风险而停图时，该页在 img、srcset 或 noscript 中给出的 CDN 直图仍属于同一受阻材料，不能改走这些地址补画面；另选独立、可正常打开的完整静态原作。

每轮可研究多份材料，但质量优先于数量。点赞、流行度、奖项和精修程度不证明方法适合当前游戏。

反复缺同件锚点、可访问来源或可控试验的题，在活跃队列写清已查范围与重新开启条件，暂停到有新证据时再查。定期回看相近学习卡，比较成立条件和反例；只补实已有规则的观察保留在日志中。

阶段性研究后，按[审美校准](aesthetic-calibration.md)选择一次已有案例比较、可控改稿或未曝光案例复测，记录本轮知识实际改变了哪个选择。材料或反馈不足时留下具体的下一实验；不以阅读数量、更多限制条款或AI自评替代行为收益。图像观察、主观审美比较、机制归因和玩家效果各自使用相应证据，允许明确标注的视觉假设进入试作。

## 真实任务反馈

当实际任务调用本 skill 完成设计、制作或评审时，先交付用户所需结果；用户要求记录，或反馈能形成有用的偏好、项目决定或经验候选时，按[记忆与证据](memory-and-evidence.md)留卡。个人偏好与项目决定按用户表态及范围记录，不必先满足通用规则的升级门槛。不为每次调用写例行报告；不能自动旁观其他对话，反馈由正在执行该任务的对话生成。

本机路径由 config/storage.local.json 定位，字段见[存储配置示例](../config/storage.example.json)。新记录按[记忆与证据](memory-and-evidence.md)写入 memory_root 的对应分类，每项用独立 Markdown 文件并关联索引；旧 research_root/field-feedback 保持为兼容入口，先读实际反馈、按路径或编号去重，不把 TEMPLATE.md 当学习成果。记录原任务证据位置、目标镜头/设备/阶段、用户原话、AI归纳、原判断、实际修改或测试结果、可能的其他成因、适用与失效条件及候选修订。只搬运可共享的抽象结论；未经许可不复制其他对话的私有素材、完整截图、用户身份或未公开项目细节。若共享目录不可写，在当前任务可写目录留候选卡并给出路径，标记待归档，不声称已写入共享记忆。

通用经验收件箱中的单条先记为候选，不等于技能已学会；个人偏好和项目决定使用各自的状态。先按索引与相关日志去重并找反例；多例可比或真实资产试评显示稳定收益后，才局部修订正式源与安装副本、记录来源/边界并验证。证据仍不足则标待追证；与旧规则冲突时保留两者各自成立条件或说明撤销理由。用户暂停的定时学习不主动巡检其他对话；恢复后把收件箱作为高优先级证据入口。

## 学习卡格式

研究过程继续记在自动化指定的可写持久目录；未指定时使用配置的 research_root，不可用时按[记忆与证据](memory-and-evidence.md)回退并标记待归档。需要复用的案例、偏好和经验另以独立卡及索引关联，不复制整份历史日志。保持原链接，不复制整张受版权保护的作品作为素材；用户自有或获准留存的素材可按授权范围保存原图、标注与前后版本。

```markdown
### 日期｜锚点与相关问题｜领域｜状态：观察/假设/已实测
- 入口：基础查漏 / 网页驱动 / 问题驱动；榜单发现时记栏目和查看日期
- 来源：标题、作者/团队、发表日期、URL、类型、实际查看范围
- 判断点 A/B…：各自的画面事实、作者自述、推断、设计/画风关系与证据边界
- 衍生问题：本轮已解什么；未解什么，缺哪一种证据，何时重开
- 可迁移条件 / 失效情境 / 对照来源；若有冲突，列旧判断与新观察各自的条件
- 决策影响：本轮改变了哪个选择/修改；没有改变则写仍缺什么证据
- 本地验证：检查了什么画面，结果如何；用户反馈、测量、AI自评分开；未测则写“待验证”
- 对 skill 的影响：仅记笔记 / 加入专项参考 / 修订入口，及理由
- 下一轮：
```

只有来源支持且在多例对照或真实资产上表现有用的判断，才升入稳定资料。新观察与已有判断冲突时，先写明各自的证据和适用条件，再用可定位的已发行游戏画面或真实资产试评复核；记录版本、镜头、视距、背景、光照和玩法状态等会改变结果的条件。若两者分别在不同条件下成立，保留两条有边界的判断和反例；若多个独立、可比的验证在旧判断原本声称适用的条件下持续反证它，且条件差异无法解释，就修订或撤销旧判断，留下原文、来源和理由。证据不足时标为未解决，不机械追加“必须”或把新个例升级为规则。修订后运行 skill 格式验证并检查引用；格式通过不等于审美提升，行为收益按[审美校准](aesthetic-calibration.md)复测。正式源与已安装副本若无法同步，留下待同步记录并说明障碍；同步指令和配置，不以安装副本覆盖共享用户记忆。无可靠新发现时更新进度即可，不生成例行报告。
