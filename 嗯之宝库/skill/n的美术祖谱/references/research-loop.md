# 研究与学习循环

目的：把外部作品的具体做法变成有条件、可复查的游戏美术判断。学习结果存在文件里，不意味着模型权重会自行改变。适用于一次性参考研究，也适用于用户开启的每半小时定期学习。

## 选择问题与来源

从 [研究队列](research-queue.md) 续接，优先挑一个尚薄弱且会改变实际决策的问题，例如“俯视镜头下，复杂服装怎样保留职业识别”，不要泛泛地“研究好看的角色”。每轮只聚焦一个问题；上一轮仍在进行时续做或跳过，避免并发写入和重复检索。

用户常用的 [ArtStation](https://www.artstation.com/) 与 [80 Level](https://80.lv/) 是优先入口。ArtStation 适合看作者原作、序列图、转面、过程稿与最终展示；80 Level 适合核对作者/团队的制作拆解和取舍。也可按问题找艺术家或工作室日志、[ArtStation Magazine](https://magazine.artstation.com/category/art-skills/)、[The Rookies](https://www.therookies.co/blog/breakdowns/)、[Interface In Game](https://interfaceingame.com/) 及游戏内录屏、开发者演讲。作品集展示、访谈自述、引擎截图和玩家测试回答的问题不同，不能互相冒充。UI 图库提供可见案例，不自动证明交互有效；离线渲染的做法也不能直接当成实时游戏预算。

## 单轮约 30 分钟

时间分配可随来源调整，不为凑数量提前结束：

1. 开始时读上次记录，选问题并写明目标媒介、用途和阶段。
2. 实际打开原作或游戏画面，观察大形、明度、色光、材质、构图、动效与上下文；需要时找不同作者的对照。
3. 找制作拆解或作者原文，核对为什么这样做、实际流程与限制。查不到时保留“原因未核实”，不从成品反推动机。
4. 提炼一个能指导修改的条件判断，写出可能失效的情境；有本地资产时用缩略、灰度、剪影、同屏或引擎画面做一次小试验。没有试验就标为假设。
5. 在约半小时边界保存学习卡与下一步；来源受限、网站空白或只看了封面时如实记录范围，换合法来源，不绕过访问限制。后台视频优先静音看文字或画面，避免打扰用户。

每轮可研究多份材料，但质量优先于数量。点赞、流行度、奖项和精修程度不证明方法适合当前游戏。

## 学习卡格式

在自动化指定的可写持久目录记录，若无指定目录则记录到 skill 的可写研究日志；保持原链接，不复制整张受版权保护的作品作为素材。

```markdown
### 日期｜问题｜领域｜状态：观察/假设/已实测
- 来源：标题、作者/团队、发表日期、URL、类型、实际查看范围
- 画面所见：可定位的形、明度、色光、材质、构图或时间变化
- 作者自述：目标、做法、约束；未说明的部分标“未核实”
- 判断：视觉做法 → 玩家可能看到/理解什么 → 可执行的修改或检查
- 适用条件 / 失效情境 / 对照来源：
- 本地验证：检查了什么画面，结果如何；未测则写“待验证”
- 对 skill 的影响：仅记笔记 / 加入专项参考 / 修订入口，及理由
- 下一轮：
```

只有来源支持且在多例对照或真实资产上表现有用的判断，才升入稳定资料。优先收窄原规则的适用条件或替换失效规则，不机械追加“必须”。修订时保留原作者和链接，检查是否与现有规则矛盾，运行 skill 验证；正式源与已安装副本若无法同步，留下待同步记录并说明障碍。无可靠新发现时更新进度即可，不生成例行报告。
