# 2D 视觉开发

用于角色、生物、场景、道具概念，宣传/叙事插画，游戏内 2D 美术与逐帧动画。先区分画面的任务：**探索可能性**、**让团队定方向**、**让下一位制作成员照着做**，或**直接在游戏里使用**。一张气氛很好的图未必足以说明背面结构、可动关节和材质；一份规范图也不必像宣传画那样精修。

## 从概念到可用设计

| 用途 | 优先判断 | 需要交代给下一阶段的内容 |
| --- | --- | --- |
| 角色/生物 | 玩法视距下的职责识别、比例和重心、姿态与负空间、关键道具和可动部位是否互相妨碍 | 主视角及关键侧/背面、尺度参照、表情与动作范围、材质分区；未知面明确待设计 |
| 场景 | 玩家先看到什么、可走与不可走空间、导航地标、可互动对象与背景细节的层级 | 可复用的建筑/自然形体、比例与连接方式、重要视点、区域状态变化；单视角画作的透视巧合要在空间里重查 |
| 道具 | 使用/拾取时的朝向、抓握与功能部件、世界观中的制造和磨损逻辑 | 关键视角、拆件关系、材质与标识、手持/地面/图标等不同尺度的读法 |
| 插画/叙事画面 | 视线如何按剧情顺序移动、角色关系与情绪能否从姿态和光线读出 | 画幅、裁切安全区、字幕或叙事 UI 留白、需要持续一致的角色和场景设定 |
| 游戏内 2D/逐帧 | 实际尺寸与运动速度下是否认得动作、状态和交互点 | 轴心/对位、状态与方向、遮挡顺序、透明边缘、帧间体积稳定性；像素美术还要核对像素密度和缩放方式 |

先用少量缩略草图比较**整体质量分布**：大形与小形、明暗块、焦点位置、留白和细节密度。颜色进入前，可以暂时用灰度或单色查视觉重心；但不要把灰度或黑剪影当作最终裁决。若目标信息本来依赖颜色、动作或光，须在这些条件下再测。更重要的是在**真实玩法镜头与背景**中看它是否被找到、被分辨、被理解。

角色和生物设计要辨认“标志性形”是否在转身、受击、装备变化时仍存在；服装、角、翅膀、武器等多个外扩部件容易在同一轮廓区互相吞没。检查它们的连接、活动余量和遮挡次序。若有多视图设定，逐一对应同一部件在不同视角的尺寸、连接、材质和前后层级；自然透视变化不算错误，无法解释的结构才需补图。场景概念则需查视觉焦点是否把玩家引向应去之处，材质噪声、装饰和灯光是否把非交互物误抬成目标。道具应同时在展示图与拾取/操作尺度下成立。

## 创作与评审的产物

- **探索阶段**：给出真正不同的形体、明度或构图方向，说明各方向的体验收益与制作风险；不要用仅换颜色的图冒充多方案。
- **方向确定**：把参考拆成“取形、取光、取材料、取情绪”等局部决定，并注明不取的部分。用清楚的正/反例说明风格边界，不照搬某个作者的完整设计。
- **制作交接**：标出结构、接缝、活动范围、材质和尺度；若仍需 3D 化，明确哪些线条只是透视/笔触效果，哪些必须成为真实体块。需要场景色彩跨镜头连续性时另读[色彩脚本](color-key.md)。
- **游戏内检查**：把候选图放进真实背景或引擎截图，按目标屏幕尺寸与缩放方式看清晰度；静帧过关后再看动作和状态切换。

评审意见要指出画面中的具体区域和失效条件，例如“在战斗镜头下，肩甲与翼根合成一团，主武器轮廓不再突出；先缩小肩甲外沿并留出负空间，用同尺寸灰度录屏比较”。不要只说“细节太多”“对比不够”或“做得更高级”。
