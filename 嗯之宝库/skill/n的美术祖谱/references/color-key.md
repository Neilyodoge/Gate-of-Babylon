# 色彩脚本：从画面节奏到引擎呈现

用于单场景的关键色彩画面，也用于把多个 key 排成章节情绪、昼夜变化、过场与可玩区域的色彩脚本。连续的 color key 表达的是玩家经历中的**画面关系**，不是一组孤立的好看配色。概念图、3D 灯光、后处理与 UI/VFX 都要接受同一节奏检验。

## 先确定序列

- 列出玩家实际会经过的节点、镜头和停留方式：进入、探索、冲突、休息、揭示、退出。若只做单幅 key，也要看进入前后或可能的光照变体。开放世界要列典型路线与可能的非线性顺序，而不是假设所有玩家只走一条线。
- 每个节点写清希望玩家先看见什么、要识别什么、情绪如何相对上一节点变化。把导航、敌我、可交互物和叙事焦点作为色彩与明度的功能约束。
- 区分作品的固有材质色、场景照明色、雾/空气透视、曝光与调色。概念图里一个暖色块，可能来自灯、材质或后期；传给 3D 时必须说明是哪一种。

## 制作与评审

1. 用同一构图比例做小幅 key，先组织主明度组与焦点，再处理色相、冷暖和饱和度。对比相邻 key 的视觉重心、最亮/最暗区域、留白密度和变化速度；重复要有意图，反差也要为节奏服务。
2. 给每幅 key 标注场景/镜头、时间天气、主要光源、玩家路线、视觉焦点、关键色的用途及前后转场。写相对关系即可；没有显示设备、色彩空间和项目规范时，不凭空指定最终 HEX 值。
3. 同屏查看所有 key，并单独抽出灰度版。检查关键交互与危险信息在不同色调环境仍可被识别；若信息只靠色相区分，增加形、亮度、运动或文字等独立线索。
4. 进入 3D 后用目标相机复拍对应场景，核对材质受光、反射、雾、曝光、色调映射和自发光是否保留概念里的层级。夜景、逆光、室内外过渡、动态天气要看过渡过程，不只看单帧。
5. 同时检查 UI 与 VFX 是否夺走或支持焦点。想要压暗环境营造情绪时，仍须保证可玩区域的导航、攻击预警和文本信息可读。

## 交付形态

最小交付是一幅 key 或按体验顺序排列的一组 key，并为每幅写一句视觉意图；制作交接再附光源/材质/后期的来源说明，以及概念图与引擎截图的对应对照。若关键节奏尚未实际试玩，标为视觉假设，安排目标显示设备、玩法视距和真实转场下的验证。
