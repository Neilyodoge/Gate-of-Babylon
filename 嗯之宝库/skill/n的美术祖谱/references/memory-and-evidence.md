# 记忆与证据

用于读取历史偏好、记录选择、保存比较实验，以及维护规则索引。审美训练步骤见[审美校准](aesthetic-calibration.md)。这里定义记录协议，实际读写由执行任务的AI通过可用文件工具完成。

## 定位资料

本技能存在 config/storage.local.json 时读取本机配置；字段见[存储配置示例](../config/storage.example.json)。示例中的 null 表示尚未配置，不能当成可读写路径。配置只定位目录，不赋予额外访问权限：
- `memory_root`：个人偏好、项目决定、案例、规则和评测的共享资料根目录。
- `research_root`：既有研究计划、日志、队列和 `field-feedback` 的位置。
- `source_root`、`installed_root`：正式指令与安装副本的位置；用户记录仅写入 `memory_root`，不分别写两套。

当前任务明确指定资料目录时使用指定目录，并在交付中说明该覆盖范围。未指定时使用有效的本机配置；配置缺失或目录不可用时，可使用用户已选定的项目资料目录，或在当前任务可写工作目录留下临时记录并明确“待归档”。不得声称临时记录已经跨会话生效。变更永久位置时更新配置，避免默默形成多个主库。

在新的机器或复制技能后，先核对路径；不存在的旧机器路径不自动创建。持久记录需明确 source_root 与 memory_root；没有安装副本或研究历史时，installed_root 与 research_root 可以暂留 null。用户已经指定这些位置时可直接配置，无需重复确认；信息不足时先留临时记录。

配置完成后，memory_root/INDEX.md 尚不存在时，用[空白索引模板](../templates/memory-index.md)初始化；模板中的专业参考路径相对 source_root 解析。已有索引继续使用，不用模板覆盖。config/storage.local.json 和技能目录内的 memory 已由本技能 .gitignore 排除；上传技能时提交配置示例和空白模板。记忆库放在别处时也应核对该目录的版本管理范围，实际用户记录不随技能发布自动上传。

写入权限不足时保留可交付的候选内容，完成不依赖写入的任务，准确说明未保存的部分。

## 按需读取

普通任务先读 `memory_root/INDEX.md`，再按项目、用途、镜头、阶段和主题读取相关记录。没有相关偏好时，依作品目标评审，不杜撰用户喜好。

索引只保存编号、范围、状态、简短描述和文件位置；保留候选/撤销/失效状态，不把候选当稳定依据。使用记录前核正文，冲突时以原始证据和当前用户指令为准。相关未索引卡可按关键词查找，不能把“索引没找到”等同于“从未记录”。

历史研究按 URL、主题或规则编号搜索，读取命中附近内容及最近复盘，不要求每次通读全部日志。封存对象和访问限制仍以运行标记为准，不因索引遗漏而解除。研究队列中只读取当前相关项，历史完成记录保留在归档层。

评测初判阶段跳过答案、结果和会泄露答案的索引描述，按[留出案例复测](aesthetic-calibration.md#留出案例复测)执行。

## 记录类型与位置

记录目录在第一次实际写入时创建，不靠空模板冒充积累。单次事件可以关联多种记录，但避免复制一遍完整事实。

| 前缀 | 类型与位置 | 成立条件 |
| --- | --- | --- |
| P | 个人偏好，`preferences/` | 用户明确表达的倾向可标“用户明确”；AI归纳标“待验证”，注明范围 |
| D | 项目决定，`projects/` | 当前项目已经作出的选择、原因、代价和版本；不外推到其他项目 |
| C | 案例，`cases/` | 原图或方案、目标、AI初判、用户原话、修改和结果；只填实际发生的部分 |
| R | 通用经验，`rules/` | 观察/假设/局部实测/可复用/撤销，关联证据、适用与失效条件 |
| E | 效果评测，`evaluations/` | 输入、版本、曝光情况、评判方式和真实结果；问题与答案分别保存 |
| — | 研究历史，配置的 `research_root` | 原有计划、队列、浏览记录和学习卡，按原运行流程接续 |

编号示例：`C-20261116-1430-character-01`。使用实际日期和时间；同名已存在时换唯一后缀，不覆盖其他任务记录。编号不依赖文章标题或网页图片排序。

现有专项参考作为已有专业指导继续使用。索引可直接链接原文，不必把全部内容重新包装成“新学到的规则”。

## 通用记录格式

使用最小必要字段；没有发生的阶段写“未进行”，不要填假数据。

```markdown
# 编号｜主题
- 类型、状态、创建/修订日期：
- 范围：项目、媒介、用途、阶段、镜头/设备及其他成立条件
- 来源：当前任务可复查的位置、原作者/链接、实际查看范围
- 用户原话：逐字保留相关部分；没有则写未提供
- AI归纳：与用户原话分开
- 关联记录：

## 选择或判断
原目标、候选方案及实际选择；有初判时保留原文和时间。

## 依据、取舍与边界
可见事实、主观判断、机制推断分别写；记录例外和冲突。

## 后续结果
实际修改、验证条件、用户反馈/测量/AI自评；未完成项及下一步。
```

P 记录补充：偏好是用户明确还是AI推断，适用于何处，什么新表态修订了它。`这次选A`仅证明本次选择；`这个项目以后都用A方向`可以确认为 D。明确说出的长期个人倾向才按其原有范围写入 P，不能悄悄扩大范围。

D 记录补充：所选与放弃方案、选择原因、允许变化、影响资产和有效版本。

C 记录补充：A/B等素材定位、AI事先推荐、用户选择预测及把握、用户公布答案的时间、修改前后定位。事先没有预测就写“未预测”；已公开的初判不能改写成正确答案。

R 记录补充：一句可执行判断、适用与失效条件、支持与反证案例、局部验证结果、升级/撤销理由及替代记录。

E 输入文件只放目标、素材、比较条件和允许使用的资料；答案/结果文件另存用户选择与评判。记录技能修订号或文件哈希、规则版本、可取得的模型信息、基线来源、样本量和曝光情况。未完成结果不计为通过。

## 图像与证据定位

保留原作者、原链接、版本及具体图号/时间点。使用用户自有或获准留存的素材时，可保存稳定的原图、标注图和前后版本；记录保存范围。外部参考按现有研究规则保留来源，不把完整作品复制成可再利用素材。

图号可能变化，补充图注或可识别的画面描述。页面失效、图片未看、证据只在原任务内可核时如实标注；有文字记录不等于下次已经重新看到原图。未经许可不把私有项目素材复制进共享库。

## 写入与维护

先完成用户所需工作。用户要求记录，或实际反馈足以形成有用的偏好、项目决定或候选经验时再留卡；一般调用不生成例行报告。记录个人偏好不要求先达到通用经验的升级门槛。

先写独立卡，再更新索引。更新前重读索引并合并其他新增项；无法安全合并或有并发编辑时，仅留下独立卡，交付路径并标记待索引，后续维护时补入。不要覆盖整库或并发追加同一大文件。修订保留旧结论、变更原因和对应证据。

既有 `research_root/field-feedback` 是兼容入口：先核现有卡，按原路径或编号去重，再关联入索引。模板不是反馈，日志数量不是已验证经验数量。初次建立索引不声称历史已全部迁移。

正文保留稳定、可操作的指导，详细来源核对和实验过程留在案例中。同步技能时同步指令、参考和配置，不用空白初始索引覆盖已有记忆，也不复制出第二套用户记录。运行状态、定时计划和封存范围由原研究流程管理，记忆维护不改变它们。
