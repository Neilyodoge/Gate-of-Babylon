# 3D 资产与场景

用于角色/生物、道具、模块场景的建模、材质、灯光、动画和引擎呈现。先确认目标游戏的相机、投影方式、常见视距、平台及已有渲染风格；漂亮的展示转台只能证明展示条件下的效果，不能替代游戏内检查。

## 先让形体和空间成立

- **Blockout**：把角色、道具、场景放到实际镜头与相邻资产旁，检查尺度、主要体块、通行/战斗空间、遮挡和地标。问题若出在形体关系，细雕与纹理不会解决。
- **角色与生物**：核对正、侧、背、三分之四视角以及关键动作姿态。头饰、翅膀、背包、武器、肩部等是否在玩法镜头重叠；连接与关节是否允许预期动作。造型夸张可以故意偏离真实解剖，但重心、受力和动作需服从作品自身的形体逻辑。
- **场景与模块**：检查模块边界、转角、上下层、重复频率和装饰变化；单件模型成立不代表拼成关卡后仍有节奏。区分导航地标、可互动物与背景填充的视觉权重，检查玩家视线和通道是否被无意遮住。
- **道具**：在世界、手持、拾取提示或背包展示的实际尺度下分别看。抓握点、开合/攻击轨迹、碰撞体和表面磨损应与用途相符。

把 2D 设计转成 3D 时，先确定必须保留的**识别特征**：体块比例、关键负空间、面向镜头的轮廓、明度关系和材质对比。概念图的单视角透视、笔触与不可能结构需要重新设计隐藏面和厚度；不要为逐像素贴近原图牺牲转台、变形或玩法镜头。用草模转台和游戏机位一起比较，先解决体积，再进入细节。

## 表面、灯光与动态

- **材质**：区分底色、粗糙度、金属感、法线尺度、半透明/发光等对外观各起什么作用。材质应在项目常用光照下仍能分辨；风格化项目可偏离物理写实，但同类材料的响应应有一致规则。不要只用一张高反差材质球照定稿。
- **灯光**：先在中性光下看体块和材质本身，再放进目标场景的主光、环境光、后期处理和天气/时段中看焦点。补光若只为展示图服务，不能证明游戏内可靠。
- **动画与形变**：用实际动作速度检查预备、打击、收势、接触和停顿的读法，以及衣物/皮肤/硬表面的穿插。静态姿势中的漂亮轮廓可能在动作中消失。
- **技术约束**：仅在能看到源网格、UV、贴图或引擎数据时评论拓扑、缝线、法线、LOD、纹理密度、透明过绘和性能。三角面数、贴图尺寸与切换距离应由平台预算及实测决定，不从展示渲染猜测，也不套跨项目定值。

## 交接与验证

需要制作规格时，交付目标相机截图、关键视角/动作、尺寸参照、材质意图和已知约束；角色可加变形/装备组合，场景可加模块拼接、转角及昼夜示例，道具可加握持与状态变化。只要求当前任务实际需要的材料。

评审按阶段抓真正能改变后续成本的问题：草模看尺度与轮廓，精模看形体和运动交界，表面阶段看材质层级，整合阶段看同屏一致性和性能。最后以引擎内的实际视距、同屏资产及目标设备核对结果；若无引擎访问，明确“尚未做游戏内验证”。每条修改意见写出视角/动作、具体冲突、改动方向和复查画面。
