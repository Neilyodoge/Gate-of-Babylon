# 3D 资产与场景

用于角色/生物、道具、模块场景的建模、材质、灯光、动画和引擎呈现。先确认目标游戏的相机、投影方式、常见视距、平台及已有渲染风格；漂亮的展示转台只能证明展示条件下的效果，不能替代游戏内检查。

## 先让形体和空间成立

- **Blockout**：把角色、道具、场景放到实际镜头与相邻资产旁，检查尺度、主要体块、通行/战斗空间、遮挡和地标。问题若出在形体关系，细雕与纹理不会解决。
- **角色与生物**：核对正、侧、背、三分之四视角以及关键动作姿态。头饰、翅膀、背包、武器、肩部等是否在玩法镜头重叠；连接与关节是否允许预期动作。造型夸张可以故意偏离真实解剖，但重心、受力和动作需服从作品自身的形体逻辑。
- **会在场地中转向的生物**：大型体躯或外扩肢体先在目标场地灰盒里检查转弯路径、落脚／接触点、障碍碰撞和攻击展开空间；站姿与直线转台成立，不代表追击时也成立。[Guerrilla 的机器 AI 复盘](https://www.guerrilla-games.com/read/beyond-killzone-creating-new-ai-systems-for-horizon-zero-dawn)指出巨型机器脚滑更显眼、路径曲率须匹配全身动画；[《DREDGE》怪物制作访谈](https://80.lv/articles/tidal-terrors-designing-the-monsters-of-dredge)记述浅水、转弯与碰撞会推翻早期设计。此项用于实时移动且受地形约束的生物；转弯半径、动画时长和性能规格由目标项目实测。
- **场景与模块**：检查模块边界、转角、上下层、重复频率和装饰变化；单件模型成立不代表拼成关卡后仍有节奏。区分导航地标、可互动物与背景填充的视觉权重，检查玩家视线和通道是否被无意遮住。
- **跨图配位**：对照套件陈列、建成场景或同场景多机位图时，用开口／断口的具体形、支承关系和相邻地标等非通用组合锚点，先核同一布景或构型；相似材质、通用砖缝与文件名只作候选。视觉配位不自动证明同一模块实例、同一 mesh 或玩家可走路线；要论具体构件与接缝，补构件标识／组装记录，要论路线再看目标玩家镜头。[《Assassin’s Creed Shadows》GateWalls](https://www.artstation.com/artwork/wrB896)的展示门楼与建成图可配构型，未证相同 mesh；[《Avowed》环境原作](https://www.artstation.com/artwork/QK5ZvZ)两组洞室异机位可凭结构与邻接物配位，未给孤立构件或连续玩家路线。
- **道具**：在世界、手持、拾取提示或背包展示的实际尺度下分别看。抓握点、开合/攻击轨迹、碰撞体和表面磨损应与用途相符。

把 2D 设计转成 3D 时，先确定必须保留的**识别特征**：体块比例、关键负空间、面向镜头的轮廓、明度关系和材质对比。概念图的单视角透视、笔触与不可能结构需要重新设计隐藏面和厚度；不要为逐像素贴近原图牺牲转台、变形或玩法镜头。用草模转台和游戏机位一起比较，先解决体积，再进入细节。

## 表面、灯光与动态

- **材质**：区分底色、粗糙度、金属感、法线尺度、半透明/发光等对外观各起什么作用。材质应在项目常用光照下仍能分辨；风格化项目可偏离物理写实，但同类材料的响应应有一致规则。不要只用一张高反差材质球照定稿。
- **灯光**：先在中性光下看体块和材质本身，再放进目标场景的主光、环境光、后期处理和天气/时段中看焦点。补光若只为展示图服务，不能证明游戏内可靠。
- **实机画面归因**：比较生物展示图与战斗镜头时，分清模型体块/材质、场景光、扫描/锁定 UI 和命中/状态特效。若要说某部件靠资产本身就能辨认，尽量核未扫描、未命中的相近镜头；只有叠加后的画面时，只评价该合成状态。[《Horizon Forbidden West》Tideripper 公开战斗录像](https://www.youtube.com/watch?v=iLNBGAbAQu8)可见扫描面板与 Weak Spot Hit 提示，[《Dead Space》官方展示片](https://store.steampowered.com/app/1693980/Dead_Space/)可见射击后的血雾遮挡。这些画面提示了归因问题，不能证明玩家辨认率、贴图内容或 LOD。
- **跨来源外观对齐**：用角色展示图评估玩家镜头里的辨识特征时，先核同一服装／皮肤、装备、版本与观察方向；外观明显不同或特征位于背向镜头的一面时，只评共有的大形，不把某饰件缺席归因于灯光、画质或 LOD。[Marvel Rivals 团队的 Cyclops 三角度图](https://80.lv/articles/inside-marvel-rivals-character-art-vfx-destruction-pipeline)有蓝金衣、背部金 V、胸 X 与红色眼罩；[CJR Gaming 的普通对局](https://www.youtube.com/watch?v=4TF5Xj69qis)后视仍见相近蓝金背 V，而[另一段选中 Cyclops 的对局](https://www.youtube.com/watch?v=9STi4thWjNM)可见裸臂、灰红背架与蓝短裤，不能用后一画面断言金 V 在实战中失效。两段录像未核具体皮肤名、构建或玩家辨认率。
- **制作职责归因**：读制作拆解时按原作正文和图注分开记录系统研发、单件资产、关卡布局／摆放与灯光；一张场景展示图不自动证明发布者独自制作图内所有内容。[Benjamin Lindquist 的《Alan Wake 2》环境 R&D](https://www.artstation.com/artwork/yDPyrO)自述分层材质和 PBR checker，却把几张场景图标为“Art is not mine”或署名 Nazareno Urbano；[Rún Creagh-Peschau 的植被页](https://www.artstation.com/artwork/NymdAP)展示 Alaska onion grass 资产与流程；[Nazareno Urbano 的 Cauldron Lake 页](https://www.artstation.com/artwork/kQ3VGn)自述关卡布局、布景与材质制作。这些来源分别支持各自职责，仍不能将具体同幅材质、灯雾或普通玩家镜头逐项归给某人。
- **动画与形变**：用实际动作速度检查预备、打击、收势、接触和停顿的读法，以及衣物/皮肤/硬表面的穿插。静态姿势中的漂亮轮廓可能在动作中消失。
- **技术约束**：仅在能看到源网格、UV、贴图或引擎数据时评论拓扑、缝线、法线、LOD、纹理密度、透明过绘和性能。三角面数、贴图尺寸与切换距离应由平台预算及实测决定，不从展示渲染猜测，也不套跨项目定值。

## 交接与验证

需要制作规格时，交付目标相机截图、关键视角/动作、尺寸参照、材质意图和已知约束；角色可加变形/装备组合，场景可加模块拼接、转角及昼夜示例，道具可加握持与状态变化。只要求当前任务实际需要的材料。

评审按阶段抓真正能改变后续成本的问题：草模看尺度与轮廓，精模看形体和运动交界，表面阶段看材质层级，整合阶段看同屏一致性和性能。最后以引擎内的实际视距、同屏资产及目标设备核对结果；若无引擎访问，明确“尚未做游戏内验证”。每条修改意见写出视角/动作、具体冲突、改动方向和复查画面。
