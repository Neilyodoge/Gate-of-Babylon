# 视觉系统与制作

用于全项目风格、跨 2D/3D/UI/VFX 的一致性、Art Bible 与资产管线。先读已有设计目标和实际游戏画面；不要只凭概念图规定最终效果。

## 把审美方向写成可制作的视觉语法

一句风格形容词不能指导资产取舍。对真正影响项目的维度写出**目标效果 → 操作规则 → 允许变化 → 检验场景**：

| 维度 | 应解决的问题 | 可记录的规则 |
| --- | --- | --- |
| 形与比例 | 玩家如何区分角色职责、阵营、建筑和交互物 | 大形、负形、夸张部位、轮廓家族及例外条件 |
| 明度与焦点 | 玩法信息在复杂背景中何处先被看到 | 主体/背景的明度组织、细节密度、边缘软硬 |
| 色与光 | 情绪、空间层级、状态反馈如何衔接 | 主从色关系、光源逻辑、饱和度分配、场景转场 |
| 材质与笔触 | 不同媒介为何仍属于同一世界 | 粗糙度/反射特征、纹理频率、笔触或像素语法 |
| 构图、镜头与运动 | 静图的设计怎样进入实际游玩 | 玩法相机、运动方向、UI 占屏、VFX 遮挡与节奏 |

不要把“圆形安全、红色危险”等例子升为跨项目规律。若游戏有意识地反用惯例，就写明如何让玩家学会新规则。色值、模型面数、纹理分辨率和帧预算从目标设备、镜头与性能测量确定；未知时写检查方法与待定项。

## 参考板与谱系

按**要解决的问题**组织参考，如轮廓、色光、材质、空间尺度、界面图形、动效节奏。美术作品、摄影、建筑、电影和现成游戏画面都可用；游戏截图尤其能检验视觉如何服务实际阅读。每条标注原作者与链接、作品媒介、要借鉴的具体机制、不要借鉴的部分及迁移所需条件。概念美图与游戏内截图分开看，避免把离线渲染的精度当成实时预算。多个来源共同解释一个方向，避免拼贴成对某位作者的临摹。

在视觉探索阶段可以用小样并列比较方向；方向定下后留下“为什么选它”及被放弃方案的关键原因。反例只在能说明边界时保留，不做装饰性图片墙。

## Art Bible 的最小有效内容

根据项目规模取必要章节，不填空白模板。至少让接手者知道：

- 目标玩家体验、目标镜头/平台、视觉支柱及当前有效版本。
- 角色、场景、道具、UI、VFX 分别怎样落实相同的形、明度、色、材质与运动规则。
- 已批准的图像与游戏内例子：各自证明什么、在哪些情境失效。
- 资产规格与交付：命名、源文件/导出、材质、尺寸或预算如何由项目决定。
- 决策记录：变更原因、影响到的资产和需要重新检查的画面。

对单件资产的交接可用短卡片：**用途和镜头 → 当前阶段 → 保留的视觉决定 → 要修改的区域与动作 → 参考依据 → 验收画面**。有分歧时比较对玩家识别、情绪、风格一致性和制作成本的影响，不凭职位或作品热度定输赢。

## 分阶段评审

1. **探索**：用缩略构图、剪影、明度块或粗模型比较不同方向；先检验目标功能和情绪是否可见。
2. **定稿/块面**：固定主体比例、镜头内层级、模块尺度、关键色光和跨资产关系；从这里发现的问题不要推迟到精修。
3. **制作**：检查造型、材质、纹理、动画和 UI/VFX 规范在连续资产间是否一致，记录需要技术美术或程序支持的具体目标。
4. **整合**：以游戏内目标视角、实际设备、相邻资产和性能数据复查。单件精美但抢走任务焦点时，调整其在场景中的角色。

评审关卡随项目流程增减。不要给没有上下文的资产判“通过率”，也不要让风格指南阻止有证据支持的改进；修订规则时说明新条件及受影响资产。
