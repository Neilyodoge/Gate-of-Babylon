# n的全能游戏设计师：迭代计划

建立日期：2026-11-02。当前版本是首版研究型 skill。后续阶段由相关任务、真实试玩、用户反馈或后台自动研究触发；定期阅读若没有实质发现，就不为更新而更新。

## 迭代顺序

1. **首版：建立可用底座。** 固定“体验目标→玩家行动→规则与反馈→可观察结果”的分析链，收入不同类型游戏、书籍/论文和 GDC 一手材料，同时写清阅读范围与不能外推的地方。验收：不看外部资料也能产出可试玩的方案，引用时能追到原始出处。
2. **真实任务校准。** 用至少三类真实问题检验本 skill：开放式创意、已有系统修订、关卡或新手体验诊断。记录它是否抓错目标、过度套模板、遗漏规则边界，或把建议停留在口号。验收：每类任务至少有一个可执行方案和一个能推翻关键假设的测试；根据问题作定点修订。
3. **扩展案例，加入反例。** 继续研究不同平台、品类、团队规模及受众的作品；每轮优先加入一手复盘、玩法实证和一个未达到预期的设计。成功案例记录机制如何起作用及依赖条件，失败案例记录条件失效的证据。验收：每条案例都有来源、实际阅读/观看范围、可迁移原则和不宜照搬的条件；不靠案例数量衡量质量。
4. **补齐跨专业交接。** 在真实从设计进入制作的任务里，检查程序、美术、音频、UX、叙事、数值和制作成本的交接是否让团队能继续执行。验收：参与者无需猜核心规则、反馈意图或原型范围；原型成本与内容管线风险在取舍前可见。
5. **根据试玩形成稳定方法。** 对至少两轮实际原型或试玩，记录原假设、观察、玩家原话/行为、改动与复测。提炼能复用的验证方法，只把重复有效的原则留在入口。验收：能指出哪些判断被支持、哪些仍是假设，且修订后更容易产生有区分力的测试。

## 资料维护规则

新增书籍、论文、演讲或游戏案例时，记录作者/讲者、准确标题、年份、原始链接、实际接触范围、材料类型、得出的设计启发与局限。书籍目录、摘要、演讲幻灯片、完整录像和玩家实测不是同一强度的证据。链接失效时找原始来源的新地址并记录变化；对已被反证的原则先修订边界。每次更新优先解决一个真实使用缺陷，不为了显得“全能”扩大入口。

当前选题优先独立游戏、单机和联机合作；大型持续运营网游只在回答具体设计问题需要对照时少量研究。后台浏览视频须先静音并保持静音，优先阅读文字稿；若无法取得可读内容，就记录范围并继续下一项。

后台研究按[持续学习队列](research-queue.md)接续。完成一个来源后，记录它试图解决的问题、为何采用该设计、规则到行为的作用链、证据、适用与失效条件，再选对照来源或下一个未完成条目；在单次运行的时间或资源限额内继续，不因完成一篇就停止。无法核实的原因留为问题，不用成功结果反推。下次从上次进度继续，避免重复阅读。
