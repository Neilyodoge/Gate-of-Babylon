# 相关专业的协作

本 skill 的职责是让设计意图能被其他专业实现与检验，不替代专业制作。只检查当前方案真正涉及的接口。

## 交接检查点

- **程序与技术设计：** 交代输入、状态、事件顺序、存档/重连需求、随机性与可复现方式、性能或联网限制。涉及程序化内容时明确哪些性质必须保证，哪些可随机变化。若玩家手册、题面或规则文本必须与程序判定严格一致，设计同源生成或版本核对机制，避免文档与执行规则错版。若玩家可持续绘制或改写场景，约定可保存的规则状态与渲染表现分别是什么，最小输入粒度怎样影响谜题判定、手感和性能。不要把技术原型能运行等同于体验成立。
- **美术与动画：** 标出玩家必须在多短时间内辨认的对象、威胁、交互点和结果；按信息层级与镜头距离决定轮廓、颜色、动画时序。美术风格可以承载体验目标，也可能改变规则的可读性。若玩家能改色或覆盖画面，关键交互还须靠稳定的轮廓、形状或其他通道辨认，并用极端配色核对。
- **音频与触觉反馈：** 为关键行动、成功、受击、危险与状态改变定义反馈目的、优先级和触发时机；考虑静音与低音量场景，避免只靠声音传达必要信息。若环境声承担发现线索，检查配乐与其他音效是否遮蔽它；若音乐承担情绪或节奏，标明出现段落并在实际混音中验证。少配乐也不等于环境声零成本。
- **UI/UX 与无障碍：** 检查目标、可行动作、代价、结果、下一步是否能被玩家发现；区分希望玩家探索的谜题与本应清楚的操作说明。参照微软 [Xbox Accessibility Guidelines](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines)，按“是否适用→玩家障碍→可实现选项→测试点”核查重映射、字幕、字号、对比度、颜色以外的信息通道、操作负担等。方向、位置等提示还要注明相对参照和触发时机，并核对玩家实际怎样理解；在不同辅助配置与练习阶段实测。设计低压或辅助模式时，分开检查致死与重试、强制躲避、可见性和氛围，确认目标玩家希望降低哪种阻碍。辅助选项的入口、命名和分布也要让目标玩家在遇到障碍时自己找到、解释并组合，不能只在告知菜单位置后测试功能。触屏移植要在画面最拥挤的局面测试目标操作的精度、误触和恢复。指南是设计与测试参考，不能代替相关玩家的实测或充当认证。
- **叙事与世界：** 确定故事信息怎样通过玩家行动、空间、角色与反馈被发现；不要让文案单独承担玩法应该兑现的情绪。若知识本身是奖励，要区分“帮助记录已知信息”和“替玩家完成推理”。重复对白允许快进时，说明已见状态按整场、选项分支还是剧情变体记录，检验跳过是否越过新信息。
- **数值、经济和商业化：** 画出资源来源、消耗、积累上限和时间尺度；让不同阶段玩家解释每种资源推进什么目标、多久可得。收藏系统要区分拿到任意新内容与定向拿到所需内容的成本；若强化角色或卡牌，还要核对它是否对应玩家实际使用的对象，以及改变哪项局内选择或战力。随机奖励若意在让每局出现新打法，追踪非首选奖励取得后是否实际使用并改变行动；若玩家只追指定目标，计算其他结果的价值、重复抽取的时间与货币成本。展示节奏也要按奖励频率核对，避免高频领取反复打断游玩。检查最优策略是否迫使玩家回避核心乐趣，或为了奖励反复做非目标行动；竞技战力成长还要核对模式等级封顶与过渡期。调整资源赠额或礼包价格时，分别核对留存、首次付费人数与金额、资源实际使用、局数、通关与收入，并按玩家原有付费层级拆开；总体均值可能掩盖相反方向。分析付费或留存时，同时评估玩家价值、可理解的承诺与可能的压力，不以在线时长代替体验质量。
- **多人协作与对抗：** 分开检查个人目标和团队目标、分工与沟通成本、等待时间、互相妨碍、胜负归因和公平感。先确定同伴参与是否必需；若必需，说明依赖来自信息、行动、能力或资源，并写清缺席或离开后能否继续。角色锁定或队伍配比先估各职责的自然供需，并把等待时间、补位压力和中途应变空间一起观察；若按职责匹配，还要看同职责对位差，不只看整队均值。双人或团队体验要把整组玩家当作试玩单位，记录口头交流和无言行动配合，不把说话多或分工模式变化多直接当作协作成功；判断连续游玩对表现的影响时，按局序和经验分层。合作升级还要看谁操作、谁参与决策和谁等待；一人操控菜单不能直接判另一人闲置。鼓励试新组合时核对替换代价，强制轮岗时核对理解成本与岗位空缺。
- **数据、研究与运营：** 埋点事件必须对应具体设计假设，保留玩家分群、版本与任务情境。用访谈、观察与行为数据互相解释，避免只凭总体均值或单次评价确定原因。功能自愿开启时分开看启用率、启用者的继续使用或回退，以及未启用者的理由；启用者不是全体玩家的随机样本。
- **制作与内容管线：** 指出验证核心体验所需的最小内容、后续内容生产方式、关键依赖和返工风险。一个机制若需要大量专属关卡、动画或文本才能成立，要把这种成本写进取舍。

## 推荐的最小交接信息

若用户需要策划规格，优先交付：体验目标；一段典型玩家流程；规则与异常；视听/交互反馈；内容与技术依赖；原型范围；观察指标和决策点。已有团队模板时遵循团队模板，不额外套一份。
