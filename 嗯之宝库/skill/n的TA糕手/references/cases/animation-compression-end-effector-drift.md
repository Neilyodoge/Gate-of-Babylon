# TA-42 · 动画压缩：手脚脱离接触，先量末端与接触面的距离

**制作决定**：压缩后手离开道具、脚踩地时滑动，先用同帧未压缩动作做参照，在真正接触的帧段测手、脚、挂点的位置偏差。若问题集中在少数挂点或长链末端，优先提高这些点及影响它们的骨骼的保真度，再看是否需要收紧整条动画；只有混合、重定向或 IK 启用后才滑时，先检查这些运行阶段。

## 原始对照

- **同一段格斗过场，换压缩版本。** Nicholas Frechette 的 [Matinee fight scene performance](https://github.com/nfrechette/acl/blob/develop/docs/fight_scene_performance.md) 使用同一段 66 秒过场、5 个剪辑、30 FPS。ACL v2.0.0 → v2.1.0：压缩结果 8.18 → 8.06 MB；骨周误差 P99 0.0201 → 0.0094 cm，最大值 0.0635 → 0.0235 cm；生成压缩数据的时间 3.86 → 5.27 秒。此时间是离线编码，不能推断播放时解码速度。误差测点在骨骼周围 3 cm，不是每帧真实道具接触点。
- **同一动画库，整体统计和最坏帧会分离。** 作者的 [Paragon 插件基准](https://github.com/nfrechette/acl-ue4-plugin/blob/develop/Docs/paragon_performance.md) 在 6558 个剪辑上对照 ACL 插件 v2.1.0 与 UE v5.2.0 自动压缩，报告 183.98 vs 391.66 MB；统一按 ACL 方法复测的 P99 为 0.0197 vs 0.0358 cm，但两者最大值仍分别为 1.2065 和 1.2169 cm。双方配置的容差不同（0.01 vs 0.1 cm），也另有 UE 自己的误差口径；此表说明为何要区分整体误差和局部峰值，不能推出等容差的普遍压缩比，也没指出超标样本一定来自脚或手。
- **公开实现方法。** [ACL Transform error metric](https://github.com/nfrechette/acl/blob/develop/docs/error_metrics.md) 按运行时的组合方式将局部变换累乘到对象空间，比较原始与压缩变换作用于骨周代理点的位置；这是比直接比较单关节局部角度更接近实际画面的误差代理。[Epic 的 ACL Bone Compression Reference](https://dev.epicgames.com/documentation/unreal-engine/animation-compression-library-in-unreal-engine#aclbonecompressionreference) 说明 Optimization Targets 可提供实际 Skeletal Mesh 改善对蒙皮的估计；带 socket 或命中末端命名规则的骨可采用 Safe Virtual Vertex Distance。大型道具仍应量真实 socket 和接触点，不要把代理距离或文档默认阈值当验收值。
- **尺度算例，非实测。** 上游骨绕垂直于力臂的轴偏 1°，且其他变换相同，距转轴 70 cm 的点移动约 2 × 70 cm × sin(0.5°) = 1.22 cm；近处若只观察距轴 3 cm 的点，则约 0.052 cm。这里隔离了一个上游关节旋转，不能用两个距离换算整条骨链或 ACL 基准的真实误差。

## 怎样取舍与验收

1. 同一个角色、动画源、采样时刻和根运动，抓未压缩／当前压缩两组。先在 IK、混合与重定向之前看差值，再恢复实际播放组合查最终接触。脚掌接触窗口量地面切向漂移和垂直穿透；双手道具量副手相对道具上的握点，避免测量插槽与其自身子节点得到恒定零差值。接触窗口报峰值、出错帧及超标时长，必要时复核两帧之间的插值。
2. 仅关键接触点失败时，优先试关键骨策略、受影响的上游轨道或更能代表实际形变的网格；全身多个接触和轮廓都超标时，再比较更严的整段误差容差。若原始动画也有同样的偏差，转查源动画、根运动或约束，别靠调压缩掩盖问题。
3. 每组分别记录烘焙后的剪辑大小、加载后的驻留字节、目标机同样角色数与采样条件下的运行时解码 CPU 时间，以及最终接触误差。不用编码时间充当播放开销，也不用压缩后的字节数代替最终安装包增量。
