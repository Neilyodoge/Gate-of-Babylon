# TA-155 · 多个角色的贴地假阴影重叠成一团黑

**制作决定。** 同一种黑色贴地假阴影只需扩大覆盖、不需叠加深度时，多张透明片逐张压暗会累乘。硬边、同强度的阴影可先对照模板占位；柔边和强度不一致时，优先测试把线性遮罩取逐像素最大值，再压暗地面一次。不同光源、颜色或透明介质需要真实叠加时，这个规则不通用。

## 公开证据

- **原始复现 · [Unity Discussions / Overlapping shadow](https://discussions.unity.com/t/overlapping-shadow/865418)，2021。** 开发者给角色使用纯黑、0.5 透明度的 sprite 和标准 sprite shader，描述两个角色靠近时交叠区更暗。求的是交叠和单张同样深，而不是用更深的暗部表达多个独立遮挡。这是开发者报告，未取得定量抓帧。
- **公开候选 · [手绘阴影原帖第 3 楼](https://discussions.unity.com/t/2d-issue-with-overlapping-transparent-objects/597558/3)，2015。** 回复给出的 Shader 先对片元做 `clip`，再用 `Stencil Comp NotEqual / Pass Replace` 限制同组同像素只混合一次。代码证实它保存的是是否占位，不比较两张阴影的暗度；弱柔边已通过并写入模板后，后来更强的阴影也可能被挡。这是根据代码得到的边界，不是原帖声称验证过的动态结果。
- **运算依据 · [Unity 6000.0 ShaderLab BlendOp](https://docs.unity3d.com/6000.0/Documentation/Manual/SL-BlendOp.html)。** `Max` 保留源和目标中较大的值。手册同时说明不同 API 和硬件处理不支持的混合操作的方式不同：GL 可能跳过，Vulkan 和 Metal 可能回到 Add。故要在目标格式和设备上确认结果确实是 Max，不能仅看 Shader 编译成功。

## 线性底色算例

纯黑遮罩的不透明度是 `a`，底色 `C` 每次乘 `1−a`。两张 `a=0.5` 顺次画，交叠处只剩 `0.25C`，单张是 `0.5C`；把遮罩先取最大再合成，交叠仍是 `0.5C`。若两张遮罩为 0.25 和 0.5，则先到先占位可能得到 `0.75C` 或 `0.5C`；Max 得 `0.5C`，次序无关。计算以线性空间为前提；Max 表示美术规则采用较强一笔，不是两条光路的物理合并。

## 最小对照

1. 固定曝光、光照、接收地面和视角，两个角色分别用均匀 0.5 和带梯度的假阴影片。逐帧移动其中一个角色，依次试独立 Alpha 混合、只画一次的模板方式、先 Max 后合成。采干净地面、单片、双片中心和两条交错柔边的线性像素；固定画面互换提交顺序，验弱边是否错误压住强边。模板方式要限制使用的位和清理范围，并明确透明到什么程度才允许占位。
2. Max 候选可先把单通道线性遮罩清成 0，以相同的接收过滤写入暗度，再让接收面只压暗一次；例如支持时对实际写入的通道使用 `Blend One One` 和 `BlendOp Max`，避免把原场景色当暗度目标。核对格式与混合支持，用两张 0.5 检查累积结果仍为 0.5，不能只目测。斜坡、台阶、角色本体和上下楼层另验接收范围，低分辨率遮罩上采样可能越过边界。
3. 在玩法距离上比较稀疏与拥挤镜头的新增遮罩写入、读取及合成帧时。若以半宽、半高的 960×540 R8 遮罩做例子，单份内容约 0.49 MiB；这只是名义纹理占用，不是每帧带宽。实际还要查目标切换、平台格式回退和片上存储；几张阴影偶尔相交时，要核实多一次遮罩是否值得。
