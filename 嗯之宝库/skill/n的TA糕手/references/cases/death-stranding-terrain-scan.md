# VFX-18 · 《死亡搁浅》：扫描波和涉水风险标记

**问题与制作决定。** 第三人称接近水面时，玩家要先知道扫描是否扫到对岸，再决定哪里下水。让移动亮边交代扫描进度，波前离开后继续显示不同位置的风险标记。用波前离开后的画面验收选路提示；波峰再亮，也补不了结果显示太短的问题。

## 公开证据

- **玩家画面 · [《过河请提前扫描》](https://www.bilibili.com/video/BV1RC4y197k2/)，B 站页面署名 freeink3，2023-12-06。** 后台静音、正常速度回放并取离散帧，时间码为视频时间。约 0:13.5，角色已入水，对面大石及其前方河面没有成排标记。约 0:13.9，近处出现一道蓝色亮边；0:14.1，亮边跨到远石附近，背后出现成排的红色记号及侧面的黄环。波前此处也有红色亮区，单看这一刻容易把短促的扫光当成整片判定结果。
- 约 0:14.6 与 0:15.3，原先那道亮边已不在大石附近，石前红色标记与两侧黄环仍可辨。同一段到约 0:17.4，镜头已随角色转动，仍能看到红色标记和右岸附近的黄、蓝小环；角色附近水花、漂浮货物和「被水流冲走时」的 HUD 提示同时可见。约 0:26.7 的另一时点还可在同一画面区分河中的红色密集区域与靠岩岸的黄、蓝环。该后续时点未核对是否再次扫描，不能据此计算首次扫描的留存时间。
- **官方正文 · [PlayStation 首发攻略](https://blog.playstation.com/2019/11/07/hit-the-ground-running-with-these-day-one-death-stranding-tips/)，2019-11-07，Delivery Tips。** 攻略说齐腰涉水或陡坡攀爬时，稳住身体可以恢复耐力。它支持涉水有实际体力代价；没有给出上述颜色图例、水深或水流判定门槛。玩家录屏只支持红色标记与这一次被冲走的场景同现，未逐色走过，更未证实每色的通行条件。

## 候选做法与最小对照

波前走独立计时，只在移动边缘加亮；依据玩法给出的风险级别铺局部标记，独立控制出现和退场。先给关键危险区保留形状及明度差，激浪、白色反光和货物提示叠加时仍要认得出来；若强红扫光淹没局部区别，先压波峰或收窄亮边。这个分工只解决提示可读性，游戏中的风险级别仍应来自玩法判定。

固定机位、水面相位、玩法判定和波速，从岸上扫描同一路段：A 让标记随波前退场，B 让标记在波前离开后多留一个选路窗口。分别记第一次选的入口、波前退去后能否指出危险水域，再用斜视或亮反光重复；先检查单个窗口的读取，再测标记覆盖与 GPU 开销。此处是候选设计，尚未本地复现或做玩家与目标设备测试；录屏未说明游戏的渲染实现、颜色图例、准确触发帧或留存秒数。

## 斜视河面时的点阵过滤与危险边界

**制作决定。** 点宽不足一像素时，若格距还读得出，先滤单点覆盖，保住节奏；格距也快不可分辨时，按各轴投影逐步减少周期细节，最后只留由玩法危险遮罩决定的淡色区。周期图案提供质感，危险遮罩负责边界。别用同一条距离曲线把两层一起淡没。

**公开来源 · Ben Golus，2023-10-20。** [《The Best Darn Grid Shader (Yet)》的摩尔纹对照](https://bgolus.medium.com/the-best-darn-grid-shader-yet-727f9278b9d8#1d80)里，右边的远处细线比左侧纹理网格更早合成均匀灰，近处格线仍可见；这是一张静图。[固定版 PristineGrid.shader](https://gist.github.com/bgolus/d49651f52b1dcf82f70421ba922ed064/raw/13ef3e78fd19721f5af9286aa6308ebf2a97d092/PristineGrid.shader) 第 70–85 行，在折叠周期坐标前用 `ddx/ddy` 求每轴导数长度；薄线放宽后乘目标宽度／绘制宽度，每轴再用 `saturate(uvDeriv * 2 - 1)` 在约 0.5–1 格／像素之间过渡到该轴线的平均覆盖。最后 `lerp(grid2.x, 1, grid2.y)` 合并的是两组线的并集，不能当作点阵。作者的阈值是线网格的做法，未验证为这里的危险点阵或游戏源码。

**可复算对照。** 每单位重复一个轴对齐方点，边长为格距的 1/4。对于轴对齐像素足迹，矩形点是两轴脉冲交集，分别求交长再相乘；两轴都覆盖一整格时，面积为 1/16 = 6.25%。若把源码的线并集直接当作点阵远景，同宽会得到 7/16 = 43.75%，是点阵平均覆盖的 7 倍。若像素只沿两轴分别跨过 0.5 格和 0.125 格，点宽投影为 0.5 × 2 像素，而格距仍是 2 × 8 像素；单点不满一像素不能推出整格都不可辨。

| 一像素内的条件 | 硬采样像素中心 | 把被危险遮罩截断的真实点面积积分 | 淡色区：6.25% × 危险覆盖 |
| --- | --- | --- | --- |
| 在危险区内部，两帧点阵相位不同 | 0 或 100% | 两帧均 6.25% | 两帧均 6.25% |
| 边界穿过中心，左半危险，点随相位完全在左或右 | 随相位与边界取样规则而变 | 6.25% 或 0 | 两帧均 3.125% |

第二行说明，精确积分点覆盖仍会让边界随点阵相位变亮或消失；淡色区刻意跟危险面积，放弃逐点的真实覆盖。这只是轴对齐盒形足迹的 CPU 算例；斜交、透视下足迹扭曲时，将两轴覆盖直接相乘未必精确。不同危险类别交界时保留各自遮罩或一条独立的轮廓，别混成未定义的新危险级别。

**玩法镜头对照。** 固定路线、光照、分辨率、危险遮罩以及波前退场时刻，只替换硬裁、覆盖过滤、覆盖过滤加远处淡色区三版。稳定后给镜头一个小幅横移，看边界哪一侧可走、边界是否随相位跳动；再验反光把淡色区压得看不见时是否需要轮廓。未做引擎抓帧、设备 GPU 或玩家读取测试。

## 动态分辨率下用哪一层像素

**制作决定。** 点阵若画进上采样之前的场景颜色，就用该 Pass 的内部像素足迹控制抗混叠；输出像素只用于设定观感上的过渡区间。若必须让危险区在换档时外观稳定，先把轮廓与纹样分开；在最小内部比例也无法分辨周期的区域，可以提前让所有档位都用淡色区。代价是高档少一些远处细节。

**公开依据 · Unity 6000.0／URP 17.0.4 Render Graph。** [URP Asset 手册](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/universalrp-asset.html)的 Render Scale 调整游戏的渲染目标，低于 1 时上采样。[固定源码的场景描述符](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.universal/Runtime/UniversalRenderPipelineCore.cs#L1544-L1585)对普通相机用缩放宽高；[透明绘制](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.universal/Runtime/UniversalRendererRenderGraph.cs#L1399-L1417)写入场景当前颜色，[最终后处理](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.universal/Runtime/Passes/PostProcessPassRenderGraph.cs#L1752-L1822)再处理缩放并输出。这里的参考路径是全屏相机、场景透明 Pass 和空间上采样。[HLSL `ddx`](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-ddx)定义为相对着色时的屏幕 X 坐标的导数；它不会预先按之后输出的网格取样。

**尺度与反例。** 设 `sx = 有效内部宽 / 输出视口宽`，`sy` 同理；同投影、局部线性时，用 `length(float2(ddx(u), ddy(u)))` 估计每内部像素跨几格。若另算输出侧的外观过渡，求 `length(float2(sx * ddx(u), sy * ddy(u)))`，另一 UV 轴同算。[Unity 的动态分辨率说明](https://docs.unity3d.com/en-us/engine/6000.0/manual/cameras/resolution-scale/dynamic-resolution/introduction)指出硬件动态分辨率可只用原目标的一部分；这里应取当帧实际绘制视口或抓帧确认的等效尺寸，不把整张分配纹理的宽高当作有效区域。相机栈、局部视口和自定义后置 Pass 要分别核对其输入输出。

固定输出为 1920 × 1080，选一处沿屏幕轴的格距恒为 1.2 个输出像素。沿用前节的示例过渡 `t = saturate(2 * 导数 - 1)`，0 保留周期，1 只留平均覆盖作为淡色区：

| 内部比例 | 格距：内部像素 | 每内部像素跨过的格数 | 按内部像素的淡色权重 | 仅按输出像素的淡色权重 |
| --- | --- | --- | --- | --- |
| 100% | 1.20 | 0.833 | 0.667 | 0.667 |
| 85% | 1.02 | 0.980 | 0.961 | 0.667 |
| 70% | 0.84 | 1.190 | 1.000 | 0.667 |

70% 时，仅按输出尺度仍保留三分之一的周期权重。它已在内部采样前变成不足一个像素的间距，空间上采样不能辨认哪个波形才是原始点阵。上表仅复算过渡权重，不是混叠幅度、实际 GPU 结果或通用阈值。可用内部尺度决定最低需要多强的过滤，另让有必要稳定的远处区域按支持的最小比例预先过渡；二者都继续用独立危险遮罩给出边界。

**验证计划。** 固定相机、输出和水面相位，先用 Bilinear 且关时域历史，跑 100% → 85% → 70% → 100%，在场景色与最终色各抓一帧。对照仅按输出尺度、按内部尺度、按最小比例预先过渡三版，分别观察远处条带、换档跳变及危险边缘。最后才换 STP 或目标设备的硬件动态分辨率，比较历史恢复、渲染目标有效范围和 GPU 时间。已核对公开源码、文档与算例，未抓帧或跑引擎及真机。
