# VFX-16 · Illett 传送门：把门洞轮廓和内纹的亮度分开

**问题与结论**：石门里的发光效果要让人先看清开口，再看出里头的层次。斜视时先核对亮边和石框内沿是否对得上；门洞形状够清楚后，把内层从整片亮白调回有明度差的纹理，给由边向内的流动留出可见空间。

## 来源与画面观察

Daniel Illett，[Million Particle Portals in Visual Effect Graph](https://danielilett.com/2020-06-14-tut5-8-urp-vfx-portal/)（2020-06-14，Unity URP／VFX Graph）。本轮读正文，并目视两张作者的制作步骤图：

- [Particle Circle](https://danielilett.com/img/tut5/part8-particle-circle.jpg)：斜视石拱时，细的暖白粒子环有一段压在石框前，底部两端在台面上方收住。孔内仍能透见天空和台面。亮环标示了特效的范围，但它的轮廓和石门内沿并不处处重合。
- [Filled Portal](https://danielilett.com/img/tut5/part8-portal-filled.jpg)：镜头更接近正面，白色填充的外形顺着石拱内沿一直落到地面，拱形门洞容易辨认。内部几乎是一块白，单看这张图读不出内纹的方向或纵深。两张图的机位和制作阶段都不同，不能当作同机位的亮度 A/B。

## 作者实现与用法边界

作者让加色软粒子从与石门框相交的圆边往圆心走，再沿寿命用 HDR 色带从较亮的紫色过渡到更冷、更暗的颜色。正文另给了让粒子往门后移动、使粒子分布往里收窄的选项。本轮未播放嵌入视频，未目视核验径向运动、沿门洞深度的运动或启闭过程。画面也没有证实可通行状态。

**候选做法**：由石框内沿和贴合的亮边交代开口范围，内层保留由边向心的明度梯度，避免内层高光连成一块白。先只调现有粒子输出的色带；若仍显得像平面，再单独对照门框遮挡或向后偏移。亮背景下加色内纹能否保住对比、透明覆盖和泛光的成本都待测。与 [VFX-02](smoke-portal-stable-entry.md) 的烟雾遮挡不同，这里优先查的是内层自己过亮时是否丢掉纹理。

## 最小对照

固定石框、粒子运动与种子、边缘亮度、曝光和 Bloom。A 用较亮的平坦内段；B 只压低内段的亮度，保留向圆心的衰减。先在同一正视机位比 A/B，再在同一斜视机位重做；以玩法分辨率和正常速度记录门洞边界能否一眼画出、能否指出内纹的运动方向。亮背景另用相同 A/B 复验。本轮未做本地复现、镜头对照或真机测量。

## 亮背景压缩加色门纹

**公开源码 · Unity 6000.0／URP 17.0.4，HDR Grading、SDR 输出、Neutral。** [Common.hlsl](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.universal/Shaders/PostProcessing/Common.hlsl#L113-L124) 先乘后曝光，再用 LogC 坐标读内部 LUT；[LutBuilderHdr.shader](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.universal/Shaders/PostProcessing/LutBuilderHdr.shader#L189-L240) 在 SDR 分支将调色结果送入 Neutral。HDR 显示输出另走映射分支。这个版本用于演示诊断过程，不据此判断 Illett 的旧演示用了哪个映射器。

**灰阶算例。** 取线性背景 B，加色源在门纹像素实际贡献 0.25，含可能的 Alpha 权重；无遮挡，曝光倍率为 1。按 [Color.hlsl](https://github.com/Unity-Technologies/Graphics/blob/52dcb5726277b769559de8bf0155f7b021bea913/Packages/com.unity.render-pipelines.core/ShaderLibrary/Color.hlsl#L522-L562) 算连续曲线 T(x) = w × NeutralCurve(w × x)，w = 1 / NeutralCurve(5.3) ≈ 1.313386，省略 LUT 插值、额外调色与 Bloom。输出差以线性值计，尚未转 sRGB 码值：

| 线性背景 B | 混合后的门纹像素 | T(B) → T(B + 0.25) | 映射后差值 |
| ---: | ---: | ---: | ---: |
| 0.18 | 0.43 | 0.18167 → 0.37352 | 0.19185 |
| 2.00 | 2.25 | 0.83884 → 0.87000 | 0.03115 |
| 4.00 | 4.25 | 0.99835 → 1.00951 | 0.01115 |

三个背景在混合阶段的绝对增量一样，B = 4 的映射差只有 B = 0.18 的约 1/17。若再把结果限于 0–1，B = 4 的显示线性余量只有约 0.00165，继续增亮也超不过这点余量。作为候选，先在门洞内以 50% 的 0.18 灰覆盖 4.00 的背景，再叠同一个 0.25，背景输入变为 2.09，映射差回到约 0.02936。代价是削弱透景；覆盖应限制在门洞内，并另验透明排序和成本。

**下一步怎么判。** 固定曝光、输出设置和粒子种子，关 Bloom，两块明暗灰底跑同一个门纹。开关门纹，分别记同一像素在映射前与输出编码前的差值：前者也变小就先查混合和软粒子的深度衰减；只有后者大幅缩小才查曲线和余量，优先试局部压背景。数值为 CPU 曲线对照，未抓 Unity 帧、未目视验证读图或测目标设备。

## 斜视时尾锥会超出门框

**画面观察 · Illett 的 [particle-trail 原片](https://danielilett.com/img/tut5/part8-particle-trail.mp4) 0:00 暂停首帧。** 斜视时，右边近柱挡住一部分紫白亮边，石拱依然勾出开口。半透明的亮楔从圈边延伸到画面左侧，在石框外收成很细的亮尖；它给出了一个与门面不同的延伸轴，同时也形成了几乎和门洞同样抢眼的大形。只采用播放前看到的暂停画面，未取得同机位的无尾对照，不能从首帧判断粒子的运动方向、启闭或读图时间。

**作者实现与候选做法。** [原文末段](https://danielilett.com/2020-06-14-tut5-8-urp-vfx-portal/#portal-particles) 用额外的局部 Z 速度让粒子分布向门后收窄。若玩法重点是认出门洞，先在最斜的常见机位检查尾锥有没有抢走轮廓；必要时先试缩短轴向尾长，保留一点侧面延伸。正视时越长越深、斜视时一定读成光束，这两种判断都还没验证。

**最小对照。** 固定门框、圈边、径向运动、曝光和粒子输入，只改变可达的最大轴向位移。用相同正视和斜视机位分别比长尾、短尾，记录尾端在画面里离门洞多远，以及首次看到的人先指出开口还是尾尖。没有本地 A/B、目标视距读图或真机结果。

## 正交和透视的尾尖越界角

**制作决定。** 先在实际玩法相机里把尾尖和同一侧的门洞边缘投到屏幕，再查它是否被石框挡住。只按侧角缩短尾锥，可能把透视中仍在门洞内的尾部也裁掉。

**几何算例。** 圆门洞半径 R，尖端沿门轴向后 L；相机水平绕门，朝着门心，θ 是视线与门面法线的夹角（正视为 0°）。正交时尾尖相对门心的横移为 L sinθ，孔宽为 2R cosθ，越过同侧内沿的条件是 L tanθ > R。透视时令相机距门心 D > R，用焦距归一化横坐标：尾尖为 L sinθ / (D + L cosθ)，同侧近边为 R cosθ / (D − R sinθ)，异侧远边为 −R cosθ / (D + R sinθ)。因此近远两边在门心投影两侧不等宽，越界不能仅用「横移超过半个屏幕孔宽」判断。

固定 R = 1、L = 0.6，透视取 D = 3。下表用从门心出发的横移除以整个屏幕孔宽；是否越界则另与同侧内沿比较。

| 视角 | 正交：横移／孔宽 | 透视：横移／孔宽 |
| ---: | ---: | ---: |
| 30° | 17.3%，在内 | 14.4%，在内 |
| 60° | 52.0%，越界 | 43.3%，在内 |
| 75° | 112.0%，越界 | 95.4%，越界 |

本例正交约 59° 越界，近透视约 69° 才越界。75° 的透视视线穿过门面时距门心约 1.263（D L sinθ / (D cosθ + L)）。若门面有不透明石环覆盖半径 1.00–1.30，这条视线会撞上石环；投影越界的尾尖会被挡住，而非一定露在门外。这是理想薄环与轴上点的算例，未包含石框厚度、粒子宽度或泛光。

**本地对照计划。** 用 Unity 6000.0 [Camera.WorldToScreenPoint](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/camera/worldtoscreenpoint#remarks-1) 取门洞轮廓和尾端的像素坐标，排除相机裁剪范围外的点。先关 Bloom，分别对照有／无石框深度遮挡，再恢复实际粒子和后处理，判断可见尾部是否抢过开口。数值已计算，未测 Illett 的原机位、Unity 场景或真机。
