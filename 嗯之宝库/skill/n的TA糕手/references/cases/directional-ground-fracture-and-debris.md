# VFX-09 · 地面碎裂怎样交代冲击方向

**问题与结论。** 地刺、冲击波或地面破坏要让观众读出冲击往哪走时，先用灰模做清楚贴地推进的破裂前缘和少数大块，再用小颗粒补速度感与尺度。若地面与大块本身读不出方向，先改前缘的形和推进次序；同时增加闪光和碎屑会让问题更难定位。

按「n的美术祖谱」的 VFX 方法，这段灰模最值得保留的是**位置与大小的对照**：左侧较大的残留形体给视线一个参照，较低的前缘贴着地面向右延伸。两帧能读出破裂带展开的方向；还不能据此判断单个碎块的飞行方向。作者在演示中拖动时间线，视频时间差不能换算为模拟速度，也不能据此评定完整的起裂、爆发和退场节奏。贴地前缘可能在俯视远景缩成一条细纹，连续的大块也可能挡住角色或让玩家误判伤害范围。

## 可以怎么试

先把受击侧和推进路径做成可控输入。在灰模里依次检查起裂位置、沿途新抬起的前缘、仍能追踪的少数大块。小碎屑可降低到不会盖住前缘的密度，再打开闪光、灰尘和镜头反馈；若它们削弱方向，先回退装饰层。只需要可控方向和重复播放的地面技能，可以先试离线烘焙的网格动画；需要受角色或场景扰动时再比较实时刚体和简化代理。玩法伤害带应单独检查，避免把仅用于装饰的飞散范围画成同等强度的危险提示。

**最小对照。** 固定镜头、分辨率、曝光、碎块形体及随机种子，关闭闪光和震动，先只切少量大块初始速度的方向分布（沿前缘推进 vs. 近似径向）；再固定大块做小颗粒无／低／高密度对照。在原速低角度和目标玩法机位分别看，记录能否指出起裂侧、推进侧，以及爆发过后是否还能读出方向；再让它与角色和另一个高亮特效同屏，检查角色和伤害边界是否被盖住。实际开销另记可见碎块、粒子覆盖与设备帧时。

**状态。** 已看作者灰模取样及部分节点画面，已核对 SideFX 文档；尚未在 Houdini 或游戏引擎复现，未做上述 A/B、目标玩法镜头、连续节奏或实机验证。

## 约束首次断开时只发射一次

**技术续查。** 地面已经裂开后，持续接触不应让同一条裂缝每帧重新喷出碎石。把**第一次断开**做成带约束 ID 和时间的单次事件；碰撞火花和持续冒出的尘则各自取符合其职责的信号。

- [SideFX · RBD Bullet Solver 的 Constraints](https://www.sidefx.com/docs/houdini/nodes/sop/rbdbulletsolver.html#constraints)（Houdini 22.0）：断裂约束默认删除，开启 Export Broken Constraints 后留在 `broken` 组。组成员表示已经断开，文档没有把它定义为只在断开那一步出现的事件。Break Thresholds 还支持 Switch to Next Constraint：达到阈值可能改到 `next_constraint_name`，而非彻底脱开。先定义效果在第一层连接失效还是完全脱开时发生。
- [同页 · Impact Data](https://www.sidefx.com/docs/houdini/nodes/sop/rbdbulletsolver.html#impact-data) 的 Time Threshold、Impact Threshold、Distance Threshold 分别按时间间隔、冲击强度和空间距离筛选冲击点，还可限定碰撞对象。适合做碰撞反馈的采样；提高时间阈值可减少点数，但不提供“每条约束只一次”的身份。该页未说明 `OUT_IMPACT_POINTS` 在所有子步配置下的精确保留时长；不要假定每个点就是一条新断开的约束。
- [SideFX · Debris Source 的 Release 与 Attributes](https://www.sidefx.com/docs/houdini/nodes/sop/debrissource.html#release) 提供另一种用途：在碎裂内壁撒点，分离超过距离阈值才释放；释放后 Age 从零开始，Life Span 控制活跃窗口，也可按寿命衰减密度。它能让尘跟着真正张开的缝持续一小段时间；这个活跃窗口不是“每帧重播一次碎石爆发”。

**实现候选。** 给输入约束写入稳定的唯一 ID，并核对求解输出确实保留它；不要用可能重排的 primitive number，或只能标识碎块对、无法区分平行约束的名字组合。每个求解步在已断集合里找此前未见的 ID，当步登记并记下首次断开的模拟时间，让发射端对同一事件只消费一次。仅需比较相邻步且 `broken` 单调累积时，可直接取当前减上一步；若有筛选、分块或一帧多次取样，维护本次播放已发集合或离线烘焙唯一事件。跳读缓存先恢复检查点的已发集合或按烘焙时间定位；显式重播才重新初始化，拖动预览不触发。会生成或重建的同名约束如果应分别喷发，ID 要带实例代次。缺了上一状态又不是从开头播放时，不能把第一次读到的每条历史断裂都当成新生。

**CPU 算例。** 每次发射 8 颗，三帧输出分别为 `{}`、`{C7}`、`{C7}`。直接把组成员当发射源得到 `0 / 8 / 8`；按已发 ID 得到 `0 / 8 / 0`。在多步输入 `{}`、`{C7,C7}`、`{C7}`、`{C7,C8}` 中得到 `0 / 8 / 0 / 8`；恢复第 22 帧前已发的 C7 再读取为 0，重置后从头播放仍为 `0 / 8 / 0`。这些是脚本对假设数据的结果。引擎对照可用两块几何、一条可控断裂约束和一次后续触地，记录每步约束 ID、断裂或换型、冲击点数及新生粒子数；另切换 Global Substeps、复读缓存、重播，验证首裂计数和时刻。尚未在 Houdini、游戏引擎或真机复现。
