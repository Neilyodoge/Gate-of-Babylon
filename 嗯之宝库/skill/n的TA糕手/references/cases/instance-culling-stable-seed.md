# TA-92 · 实例剔除重排后的随机色与风相位闪跳

**制作决定。** 镜头一转，同一株草的位置正确但纹理、颜色或风相位突然变，先查材质是否还把本次绘制的实例下标当成随机种子。先经可见列表查到原实例；原数据槽保证不换时，可用原槽作种子。实例池会重排、流送时，改用随实例保存的种子或稳定身份。

## 公开证据

- **同类现象和修法。** Cyanilux 的 [GPU Instanced Grass Breakdown（2025-10-05 更新），Unity 6 Shader Graph 代码](https://www.cyanilux.com/tutorials/gpu-instanced-grass-breakdown/?tab=Unity6#frustum-culling-shader-changes) 在剔除时追加原数据索引，绘制用 `_VisibleIDs[InstanceID]` 查回原实例。作者明确说，原来直接接到 `Random Range` 的 Instance ID 在剔除后会让叶片随机格闪烁，于是再用 `VisibleID_float` 给材质返回原索引；作者也指出，若原实例缓冲会变，应把随机值存到实例数据。这是作者对纹理格闪烁的报告，本轮未目视动态对照。风相位使用同类种子时的表现是以下算例推导。
- **多个绘制批也有这层间接映射。** [Vulkan Guide 的 Compute based Culling](https://vkguide.dev/docs/gpudriven/compute_culling/) 用批次的 `instanceCount` 原子加一预留槽，把 `objectID` 写到 `firstInstance + countIndex`，顶点着色器再经该槽取回对象。不要把某个 API 的起始实例计算直接搬到另一管线；先核对读写要不要叠加基址、以及 LOD 或各绘制 Pass 用的是哪份表。

## 算例与最小对照

- **只变可见集合。** 用植株标签表示列表：`[11,42,99]` 变成 `[42,99]`，42 号始终可见，绘制下标却由 1 变 0；即使列表始终按相同规则排序也会发生。以 `下标 × 120°` 做调试相位，42 号由 120° 跳到 0°；改用随 42 号保存的相位后不变。关闭风动画计时、固定 LOD 和光照，只转镜头把 11 号移出视锥；给 42 号同时显示本次绘制下标、源槽和材质种子。再恢复风计时验实际画面。
- **再只重排原实例池。** 原池从 `[11,42,99]` 变成 `[99,11,42]` 时，42 号的原槽由 1 变 2。若流送回来仍是同一植株，用持久的地块与出生点编号或随数据保存的随机值复原；若复用槽生成的是新植株，按需求分配新身份，别把上一株的动画历史带过去。再固定可见集合，单验重排、流送重入及 LOD 切换。
- **代价。** 用已有的源槽或已存随机值可不增加种子字段；若额外存一份紧凑的 32 位种子，50 万实例净字段数据约 1.91 MiB，实际步长、读取和缓存开销另测。若整个植株本身在视锥边缘消失，先查剔除边界是否覆盖风摆后的几何，见 [TA-18](vegetation-instancing-cull-granularity.md)；换种子不会修复漏画。

**验证状态。** 已核对作者对纹理格闪烁的说明、两份公开实现，并在 CPU 上复核列表下标、相位和字节算例；未做本地渲染、运动镜头或真机测试。
