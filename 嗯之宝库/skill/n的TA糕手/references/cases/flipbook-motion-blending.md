# Flipbook 双轮廓：什么时候值得做运动引导插帧

**一句话结论**：在目标镜头冻结到两帧之间；如果主要轮廓在两张原帧的位置明显分开，普通淡化只会调整两道边的权重。近景慢放可以试先移动再混合；快消失、突然出现或形变很大的区域对不上时，优先试保留更多原帧，别用更强向量硬拉。

## 证据与条件

- **同相位画面对照**：[Tuatara TFlow WebGL 演示](https://tflow-demo.tuataragames.com/)。选 `Explosion - 16 frames - 256x256`，暂停到界面显示 `Frame = 1.4`，时长为 3.0 s；分隔线拉到右端看 Raw，拉到左端依次看 Alpha Blending 和 Optical Flow，禁用 Motion Blur。Raw 的火团较小；拖到 `Frame = 2.0` 可见它扩张后的外缘。回到 1.4，普通淡化的亮内缘与暗外圈同时存在，光流版呈现更连续的外扩火团。这个对照定位了一个有用的相位；演示未提供相同相位的高帧率真值，也没给设备计时或通用位移阈值。
- **作者拆解与原图**：[Klemen Lozar（2015-03-16），Motion vector data、Current/Next Frame、Cross Blend](https://www.klemenlozar.com/frame-blending-with-motion-vectors/)记录 UE4 中的做法：对前后两帧分别采样同一张向量图，按插值相位将两张颜色图往中间移，再混合。作者发现单用 FumeFX 模拟速度时，轮廓外的像素推不出去，所以用画面估计的运动填足边缘；[向量原图](https://www.klemenlozar.com/wp-content/uploads/2015/03/Vectors_Final.jpg)左边是画面估计层，右边叠加了模拟速度。这是另一实现的边界，不意味着 TFlow 演示用了同样的合成。作者用 8×8 图集，4096 色图配 512 线性未压缩向量图；这是参考起点，实际纹理格式和尺寸应按素材验证。

## 成本怎么算

- 按 Lozar 的双分支做法，单张 RGBA 图集时，直接取帧要 1 次颜色采样；普通淡化要 2 次；运动混合示意为 2 次颜色 + 2 次向量采样，并加解码、偏移。复用同一张向量图能减少资源种类，当前帧和下一帧还是各读一次。这里数的是这套做法的 Shader 采样调用，不是 TFlow 的内部实现或硬件带宽。
- **预算算例**：256×256 的色帧，假设 ASTC 8×8，16 帧紧排成 1024×1024，在基础 mip 为 256 KiB；32 帧紧排为 2048×1024，512 KiB。16 帧方案若每帧用 64×64 的 RG8 向量，向量图 256×256，128 KiB，合计 384 KiB；若用 128×128 的向量帧，向量图 512×512，512 KiB，合计 768 KiB。只计算无补边的基础 mip，不假定视觉相等。这说明少一半色帧也可能更费内存；核算时用[实际压缩、导入尺寸和平台回退](mobile-texture-compression-and-packing.md)，把 mip 和补边也算进去。

## 落地时怎么选

1. 固定素材、播放时间和镜头尺寸，挑边缘位移接近或超过自身可见宽度的快段，也挑慢段。先看无混合、普通淡化、光流三组，再加高帧率原序列作真值。量最明显边缘在画面里的位移和宽度，检查中间相位的双边、变薄或拉伸；局部的出现、消失、遮挡和循环首尾单独验。
2. 光流版仍有断边时，先查向量的坐标方向、位移单位、零值、线性导入、解码和边缘覆盖。用无运动帧和单轴平移确认方向与量级；确认偏移后的采样不会读到邻格，必要时按[图集串色案例](flipbook-atlas-mip-bleeding.md)检查补边和 mip。局部内容本来没有对应点时，增加源帧或在那几帧退回普通方案比盲目放大向量更容易验。
3. 同屏很多且显示小的效果，先看直接取帧或普通淡化是否已经够用；只有慢放或大画幅的缺陷能在玩法镜头看见时，才对比「更多原帧」和「少帧加向量」的相同画质预算。固定覆盖和粒子数，在目标设备测分配字节、Draw GPU 时间和场景帧时，记录分辨率、格式、mip 与图形 API。
