# TA-119 · 细节法线叠加后凹凸方向失真

**制作决定。** 给同一材质叠微小凹凸，先用平法线检验叠加是否保留底层。若平法线通过，但斜纹或压花在底层凹凸较强处仍会压平、转向，固定同一组输入对照 Whiteout 和 RNM（重新定向法线混合）。Whiteout 保留平层测试的结果；RNM 让细节跟着底层法线转。材质之间的权重过渡可以用归一化插值，验收目标不同。

## 公开证据

- Colin Barré-Brisebois、Stephen Hill 的 [《Blending in Detail》](https://blog.selfshadow.com/publications/blending-in-detail/)（2012-07-10），见 “Linear Blending”“Whiteout Blending”“Reoriented Normal Mapping”。作者用圆锥基础法线叠细节，讨论直接平均产生的细节减弱；RNM 用把切线空间的 +Z 转到基础法线的最短弧旋转重定向细节。文章另外指出，量化、压缩、取 mip 和过滤后，采样法线未必是单位向量；实际用于光照时应检查归一化。RNM 结果也可能落到负 Z；若将混合结果烘回只存 XY 且按正 Z 重建的贴图，须单独验这个限制。
- [Unity Shader Graph 17.0 · Normal Blend Node](https://docs.unity3d.com/Packages/com.unity.shadergraph@17.0/manual/Normal-Blend-Node.html) 给出生成代码。Default 归一化 `(A.xy+B.xy, A.z*B.z)`，对应 Whiteout；Reoriented 将 A 作为底层、B 作为细节，计算 `t=A+(0,0,1)`、`u=B*(-1,-1,1)`，再得到 `(t/t.z)*dot(t,u)-u`。两输入应先解码到约定一致的切线空间；把不同投影基的样本直接交给节点不能纠正坐标错误，参见 [TA-28](triplanar-material-seams-and-sampling.md)。

## 数值对照与验收

CPU 对照取单位基础法线朝切线 +X 倾 50°，细节沿同一轴取 −25°、0°、+25°；角度都以切线空间 +Z 为零。同一方向光朝 +X 倾 70°。单元格为输出角度和未加材质项的 `N·L`：

| 细节输入 | 归一化等权平均 | Whiteout | RNM |
| --- | --- | --- | --- |
| −25° | 12.50° / 0.537 | 30.52° / 0.772 | 25.00° / 0.707 |
| 0°（平） | 25.00° / 0.707 | 50.00° / 0.940 | 50.00° / 0.940 |
| +25° | 37.50° / 0.843 | 63.89° / 0.994 | 75.00° / 0.996 |

等权平均连不加凹凸的 0° 输入都会改变底层。Whiteout 能过这个测试，却把 ±25° 压成相对底层的 −19.48°/+13.89°；这个算例下 RNM 保住了两边的角度。若把 +25° 细节改向 +Y 倾斜，交换 RNM 两输入会让两个结果相差约 9.59°；应把插槽按底层、细节接。

1. 在同一平面网格上先测贴图输入：平底有细节、斜底配平细节、斜底配真实细节。先看编码后的调试法线方向，再用同相机和同一盏方向光看凹凸，仅改混合方式。若翻面随镜像 UV 出现，先查切线手性与法线解码。细节强度从零升起时，先调细节法线相对平法线的强度，再做叠加。
2. 实时组合两张图时固定采样、分辨率、压缩和 mip，只换混合，观察游戏镜头里的画面再决定是否用 RNM；GPU 时间要靠目标设备比较。离线合成时，额外检查合成前后法线 Z 和回读误差；例如同向 70° 底层叠 30° 细节会输出 100°，正 Z 重建无法原样表示。

**验证状态。** 已核对作者原文和 Shader Graph 17.0 生成公式，运行 CPU 算例核对输出角度、固定光方向和交换输入的影响。未在引擎制作同材质 A/B，未做压缩回读或真机验证。
