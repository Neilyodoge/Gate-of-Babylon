# TA-139 · 天空盒反射只在粗 mip 露出立方体接缝

**制作决定。** 从同一条立方体面边选一段方向弧，用不受材质粗糙度影响的调试着色器逐个 mip 采样。mip 0 就有断层时先查六面输入、朝向与颜色解释；粗 mip 才出现时，分别对照生成该级时是否跨面过滤，以及绘制时是否开启正确的立方体跨面采样。不要只靠关模糊或给最终倒影做平滑掩掉断层。

## 公开证据

- **AMD 的同图对照。** [CubeMapGen 档案](https://gpuopen.com/archived/cubemapgen/) 比较同一 Cubemap 的 4×4 mip：在[逐面生成的原图](https://gpuopen.com/images/cubemapgen4.vBF0UFd-.jpeg)中，左侧铜色头像前额高亮下方和中间头像太阳穴有明显的硬分界；[跨面角域过滤＋边缝处理的原图](https://gpuopen.com/images/cubemapgen5.DwU0VUtS.jpeg)中，同一区域的过渡更连续但仍保留明暗方向。AMD 说明角域过滤用方向范围定义采样、可取其它面上的 texel；另一阶段逐 mip 做边缘平均与平滑。两张图比较的是两项处理合起来，不能单独归因给其中一项，也没有给现代设备计时。
- **离线实现如何跨面。** [Filament v1.56.0 · Cubemap::makeSeamless](https://github.com/google/filament/blob/v1.56.0/libs/ibl/src/Cubemap.cpp#L94-L134) 按相邻面的正确方向填充面外一圈采样 texel，角点用相邻的三个值；这是工具内部插值的辅助边界，不是把六面的图像内容整体磨平。[CubemapIBL::roughnessFilter](https://github.com/google/filament/blob/v1.56.0/libs/ibl/src/CubemapIBL.cpp#L425-L455) 为目标像素先求方向、围绕该方向展开样本，再按每个世界方向在源 Cubemap mip 上三线性采样和加权。过滤的角域可跨面，不能用六张各自的 2D 模糊替代。
- **运行时有另一层规则。** [Khronos Vulkan · Cube Map Edge Handling](https://docs.vulkan.org/spec/latest/chapters/textures.html#textures-cubemapedge) 说明启用正常跨面边缘处理时，线性过滤越过单条边会重映射到相邻面；`NEAREST` 在当前 mip 不做这类相邻面读取，角点也没有唯一邻面。跨面读取重组的是现有 mip 的值，不能恢复生成粗 mip 时已丢失的方向贡献；反过来，粗 mip 面边存值不全相等，也不能直接断言最终的跨面采样一定有硬线。

## 算例与验收

一维 CPU 对照取跨边的两个面各两个样本：左面 `[0,0.5]`、右面 `[0.5,1]`，相接边都为 0.5。两面各自缩成一个粗 texel 得 0.25／0.75，单面夹边的读取可显示差 0.50；跨面等权读取正中得到 0.50，也与这四个样本组成的对称跨边窗口均值相同。这个相等只在此测试的边正中成立，不能据此判断邻近方向的卷积分布也正确；这不是 Vulkan 角点规则、立方体立体角积分或 GGX 的数值实现。

1. 用线性高动态范围的连续方向渐变，以及横穿一条面的单个亮斑各制作一张测试图。关掉曝光变化和其它探针，固定取样方向，逐整数 mip 扫边的两侧及角点；对比真正的 Cubemap 采样和只夹当前面的调试路径。用同一个资源便能隔离采样差异；若只在角点异常，把它单列，不用某条边的结论代替。
2. 采样路径固定后，以同一源贴图分别生成独立面 mip 与按方向跨面预滤波的 mip，用相同曝光、格式和显式 LOD 对照。先用未压缩图，后只改实际平台压缩；若仅着色材质里有缝，核对运行时映射到哪个粗糙度 mip、使用的是哪张环境，以及探针是否在换权重。
3. 只有重新预滤波能改变同一级的亮斑形状时，优先修生成流程；可对照逐 mip 边缘修整的收益和亮度损失。回到真实粗糙材质转动反射方向，记录接缝对比、亮斑扩散和粗糙度过渡。不要只验面边正中。

**验证状态。** 已看 AMD 的两张 4×4 静态原图，查了 Filament 固定版本和 Vulkan 规范，并复算一维样本；未本地生成 Cubemap、抓目标 API 或做真机验证。
