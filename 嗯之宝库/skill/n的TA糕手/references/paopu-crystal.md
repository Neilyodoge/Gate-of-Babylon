## 可以确认的内容

**正文明确说明：** 技术美术 Mirza Beig 与模型作者 Hoon / magic_chromatic 合作，将 Kingdom Hearts 的 Paopu 果实做成风格化晶体。文章将 Shader 描述为全程序化、无贴图、全参数化、体积效果，包含类似 Grease Pencil 的轮廓、用于模拟次表面光照的透光，以及 GPU 动画。这里的“无贴图”不代表已核查整个场景、环境光或后处理都不使用纹理。

**画面可见：** 五角星轮廓和叶片保证物体辨识度；内部有大块明暗与碎片式亮面，主体偏橙粉，边缘叠加明亮的冷暖色细线与光晕。场景截图有多个灯光图标。最终观感应连同灯光、背景与后处理检查，不能全归因于单个材质。

**动图可读的技术线索：**

## 落地时怎样使用

以下是根据案例整理的实现候选与验证方法，不是作者工程复刻配方。

### 1. 先建立切面，再增加内部层次

先在固定光照下确认模型轮廓、基础颜色和大块切面。对应图示量化链的标量或分量运算可表达为 `q = round(x * k) / k`，其中 `k > 0`；这里量化的是信号，`k` 不是 raymarch 步数。

若尝试量化法线分量，需在一致坐标空间内运算，并检查下游是否要求单位法线。重新归一化时处理零向量；若量化的是高度或颜色，则不要套用法线归一化。检查镜头运动和光照变化时的跳变，避免把离散切面变成无控制的闪烁。

内部层次先做可开关的独立模块。近景需求可评估程序化体积噪声与步进；远景或移动端可比较少层视差、烘焙纹理与简化表面噪声。后几种是替代实现，不保证保持相同的体积视差或遮挡效果。

### 2. 分开调试透光、边缘着色和描边

- 透光负责背光处的颜色与明暗关系。可先评估简单背光透射近似；原文只称模拟次表面光照，没有提供物理 SSS、厚度贴图或真实折射的证据。
- Fresnel 候选可从 `pow(1 - saturate(dot(N, V)), p)` 开始，`N`、`V` 为同空间单位向量，`p > 0`。该公式是起点，未证实为作者实现。分别控制亮度与边缘范围，检查正面、侧面和掠射角。
- 手绘轮廓单独验证线宽、断续、偏移和动画节奏；候选可以是壳层描边、额外线条几何或屏幕空间方法，原资料无法确定采用哪一种。Fresnel 边缘着色本身不能替代全部轮廓线效果。
- 调参时比较关闭与开启后处理的画面。保留星形尖角、叶片和内部明暗；亮边与光晕过强时会掩盖切面。

### 3. 动画要有空间依据与可控节奏

先决定噪声跟随物体还是固定在世界中：物体空间有利于让内部图案随道具移动，世界空间适合穿行于外部场的效果。转动、平移和缩放模型检查纹理是否游动或拉伸。

若需要停格或手绘节奏，可把 `tq = floor(t * fps) / fps` 作为候选时间输入，要求 `fps > 0`，暂停应单独处理。不要据面板上的 `Noise Animation FPS` 认定作者使用了该公式。比较连续与离散动画在实际屏幕尺寸下的稳定性，检查噪声切换是否使高光、轮廓和切面同时跳动。

## 视觉收益、成本与失效条件

| 模块 | 希望获得的收益 | 主要成本或失效点 |
| --- | --- | --- |
| 程序化噪声与法线量化 | 不依赖手绘细节贴图的变化与切面感 | ALU、重复噪声求值、法线不稳定；远景高频细节易闪烁 |
| 内部体积步进 | 晶体内的纵深、层次与动态变化 | 覆盖像素数 × 实际步数 × 单步计算；减步可能分层、跳变或破坏视差 |
| 明亮边缘与手绘描边 | 轮廓识别、冷暖层次、手绘气质 | 额外 pass / 几何或屏幕处理，线宽随距离变化，细线混叠 |
| 透光与场景灯光 | 背光下的通透与色彩丰富度 | 光照求值、阴影及灯光配置；不能从光源图标推算帧耗时 |
| 光晕与闪烁 | 魔法道具的发光感与活力 | 过曝吞掉切面；若实际采用透明叠层，还需查排序和 overdraw |

移动端先按目标镜头和同时可见数量验证收益，再决定是否保留内部步进。对比程序化、预计算和简化版本的 GPU 时间、带宽及稳定性，不能凭“无贴图”或面板上的最大步数直接给出性能结论。降级时优先保留辨识轮廓、大块切面和关键边缘色，按实际画面收益减少内部细节、动画频率与描边层次。

## 最小验证集合

准备目标视距和近景的同角度对照，逐项开关法线量化、内部层次、透光、描边和后处理，确认每项贡献。测试正面、掠射角、逆光及模型移动；有缩放需求时检查非均匀缩放。若采用透明表面或叠层，增加物体交叠和深度遮挡测试。

在实际 Unity 版本与目标渲染管线检查编译、阴影和绘制 pass，再用目标设备 GPU 测量决定质量档。只有复现、画面或性能证据明确的结论才升级为项目已验证经验；记录当前未验证项，不继承展示图的一次性参数。
