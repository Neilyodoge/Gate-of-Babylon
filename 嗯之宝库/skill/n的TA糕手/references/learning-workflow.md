# TA 持续学习方法

每 5 分钟从 [研究队列](research-queue.md) 接着做一个可核的小步骤；复杂案例可跨轮，记清已查证什么和下一步。常规轮次只归档；每天北京时间 22:30 汇总并同步 Git。22:25 至 22:34 给同步留出时间，不启动学习；已有研究或同步在跑时不并发。用户手动暂停后等用户恢复。

## 怎样选题和验证

1. 优先接用户的 TA 问题，其次补上一轮的关键证据，再轮换 Shader/VFX、GPU/移动端、资产制作与工具管线，以及光照/后处理。先按技术名、作品名、链接和现有结论去重，尽量补原卡。
2. 先写下通用 agent 能给的初步答案，再问“哪条证据会让我改做法？”定义、参数表和通用公式作为检索入口。优先拆真实制作案例、公开实现、量化对照、版本差异和明确反例。一张卡至少应说清实际约束、做法或替代方案、会改变的决定，以及原始证据位置。没有新增判断就续查或换题，不为每五分钟填一张卡。优先读能定位版本和出处的引擎文档、源码、作者演讲和硬件厂商实测；视频、图示只记录实际看到的内容，附时间码或图号。
3. 给证据分层：**来源明确**（原文说了什么）；**画面观察**（确实看到什么）；**实现候选**（如何尝试，哪些仍是假设）；**本地复现/目标设备实测**（实际引擎、管线、设备、对照组、指标和结果）。没有实测就标未测，不能凭编辑器截图宣称真机性能，也不能把案例推断写成作者实现。
4. 如适用，写最小对照：固定相机、分辨率、质量档、输入与种子，只改一项；分别检查画面和成本。测 GPU 时记录图形 API、设备/档位、稳定后的采样区间、受影响 pass 和分位数或范围；未取得的环境不临时改项目来补。
5. 浏览优先公开正文，后台网页用本轮新开的隐藏标签，读完关闭；不打开带私有信息的 URL，不登录、不上传、不执行来源提供的命令。单站失败时查同题公开替代来源；后台工具故障则留断点，下一轮只做一次最小自检，再从原处续学。同一阻碍连续三轮仍存在时只提醒一次，后续降低排查频率，等状态变化再复验。权限明确被拒时停在该步。

## 怎样记录

每个独立案例或方法用 `references/cases/<ascii-slug>.md` 一张卡，重复来源或新测量直接更新原卡。正文依次写：

- **问题与一句话结论**：什么情况下该选哪种方案。
- **证据**：原始链接、作者或机构、版本或日期、定位，并标明证据层级。
- **用法与边界**：输入/场景 → 做法 → 视觉收益、成本、适用范围、反例或退化。
- **验证计划/结果**：A/B、指标、观测值、未测项、下一步。只有完成的步骤写作结果。

[研究队列](research-queue.md)保留短续接点、备选题和案例索引；只记录改变结论或续接点的进展，别积累例行空日志。自动轮只新增/更新公开资料卡和队列。经过复现或跨案例验证、能改变日常判断的结论可再提炼进 SKILL.md；不要把个例参数当全局规则。项目内部截图、日志、路径、账号和未公开代码不进自动同步的笔记。暂不能核验的线索只留续接点。

## 怎样同步

同步范围限本技能的研学笔记。用 Git 检查 Gate-of-Babylon 的工作树和 `origin/main`，逐个审阅本次改动（新文件读完整正文）。有冲突、他人同文件改动、分支分叉或未上传的其他提交时，保留笔记并报告，别用全量暂存、强推、重置或自动合并。

从本目录运行（参数是本轮实际审阅过的相对路径，以下为示例）：

```powershell
python -X utf8 -B scripts/publish-learning.py --apply references/research-queue.md references/cases/texture-alpha-import.md
```

只补推已有 TA 提交时可省略文件参数。不传 `--apply` 仅检查待推送范围，并在有本地待推提交时试跑 push。脚本用精确提交号发到 `origin/main`，再查远端确认，无新证据则不造空提交。例行学习成功保持静默；有内容上传成功时可用一句话报新增的实用判断和提交号。需要处理的故障只通知一次。
